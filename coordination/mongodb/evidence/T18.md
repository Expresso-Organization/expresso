# T18 검증 증적

## CI·운영 구성

- backend CI와 local/server Compose를 인증된 MongoDB 8 replica set, migration 선행 구조로 전환했다.
- 배포 스크립트는 `MONGODB_CUTOVER_APPROVED=true` 없이는 운영 전환하지 않는다. MySQL 볼륨·데이터를 삭제하는 명령은 추가하지 않았다.
- MongoDB archive, Redis RDB, media, commit/prefix/config metadata와 checksum을 함께 백업하고 별도 컨테이너·볼륨·DB에 복원하는 절차를 구현했다.

## 실제 리허설

- staged rollout: API·Worker build, migration 0001~0004, readiness, signup, 77 collections/chunks 검증 통과. 증적 `T18-staged-rollout.log`.
- backup/restore: 격리 원본과 별도 57117 restore 인스턴스의 77개 collection count가 일치하고 공고 4개 컬렉션 hash가 일치했다. 증적 `T18-backup-source-report.json`, `T18-restore-report.json`, `T18-restore-rehearsal.log`.
- snapshot verifier: 정상 2-chunk 참조 통과, bytes 변조 시 거절. 증적 `T18-chunk-valid.log`, `T18-chunk-corruption-rejected.log`.
- 성능: read p95 225.35ms, write 11.05ms, event 7.63ms, queue registration 7.15ms; 공고 1,000건 board 120.43ms; 9MiB snapshot write/read 83.73/61.03ms; generation guard docs/keys 1/1. 증적 `T18-performance-detailed.log`.
