# T09 · 인터뷰와 답변의 기록 반영

코디네이터 직접 구현·검토. MongoInterviewService와 답변 저장 전용
mongo-answers 경계를 추가하고 기존 InterviewApi·Worker processor를 유지했다.

- 공고 요건의 원문 code point 범위를 다시 검사한 뒤 missing·partial 요건과
  수치가 없는 선택 기록만 질문 근거로 사용한다.
- 세션 version guard와 활성 순번 unique index로 질문 교체를 직렬화한다.
  질문·답변을 다른 세션이나 사용자에 연결할 수 없다.
- 답변, interview 원본 기록, 파생 변경, record.cleanup outbox를 한 트랜잭션에
  저장한다. 동일 멱등 요청은 답변·파생 변경을 각각 하나만 남긴다.
- 정리기는 트랜잭션 밖에서 실행한다. 완료 시 답변 저장 시점의 기록 version을
  조건으로 갱신하여 정리 중 사용자 편집이나 검증 완료 기록을 덮지 않는다.
- record.cleanup Worker의 첫 실패·재시도 성공을 실제 processor로 검증했다.

검증:
- MongoDB 대상 interview·질문·career HTTP E2E: 4개 파일, 15 통과·3 MySQL 사례 스킵.
- grounded 질문, 순번 교체, pause/resume, 멱등 답변, 타 세션·타 사용자 차단,
  정리 경합, Worker 재시도를 포함한다.
- 전체 typecheck 통과.
- 격리 MySQL/Redis 전체 회귀 통과.
- `git diff --check` 통과.

`test/e2e/brewing-flow.test.ts`의 MongoDB 전체 흐름은 Recipe Mongo 구현에 의존하므로
T10 확인 지점에서 인터뷰와 함께 실행한다. 운영 연결·데이터 변경 없음.
