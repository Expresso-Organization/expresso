# T05–T06 · 커리어 기록 MongoDB 전환

코디네이터가 직접 구현·검토했다. 외부 에이전트 검토는 실행하지 않았다.

- CRUD·카테고리·뷰·프로필과 링크·스킬·휴지통·복원을 MongoDB로 구현했다.
- 사용자 쓰기는 lifecycleVersion, 기록 참조는 referenceVersion으로 삭제와 경쟁한다.
  공개 편집 version은 참조 추가 때문에 바뀌지 않는다.
- 목록과 요약은 같은 필터의 facet을 사용한다. 모든 정렬의 동점 페이지 경계,
  정규식 문자의 문자 그대로 검색, 타인 범위와 인용 수를 검사했다.
- 기존 career·record-list·profile HTTP 테스트를 두 엔진에서 재사용했다.
  T04의 카테고리 HTTP 검증 유보도 제거했다.
- 휴지통은 기존 인용/배포를 보존한다. 원래 SQL trigger가 막던 것은 **물리 삭제**다.
  계획의 삭제 제한은 이 의미로 적용했고, 만료 후 purge는 인용이 있으면 409다.
  인용이 없는 연결 블록은 원문을 보존한 채 detached로 바뀐다.
- 추가한 페이지네이션 테스트가 기존 MySQL의 updated_asc 반복 버그를 발견했다.
  ISO 커서 문자열을 MySQL 바인더가 Date로 바꿔 비교 형식이 달라지던 원인이다.
  JSON 문자열 바인딩으로 커서의 원래 문자열을 보존해 회귀 테스트를 통과시켰다.
- 전체 실행에서는 동시 fixture 마이그레이션이 10초를 초과했다. 다른 Mongo suite와
  동일하게 준비 hook에 60초 제한을 적용했고 재실행에서 통과했다.

- 격리 MySQL/Redis 기존+추가 통합 테스트 통과. DB는 실행별 난수 이름만 생성·삭제했다.
