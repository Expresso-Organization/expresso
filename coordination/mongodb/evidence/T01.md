# T01 검증 기록

2026-08-29. 독립 검토 2회차 승인 및 통합 검증 완료.

## 변경과 검증

- 공식 드라이버 `7.5.0`은 두 패키지에 정확한 버전으로 고정했습니다.
- MongoDB 8.0 이미지와 keyfile 생성 이미지의 실제 digest를 Compose에 고정했습니다.
- 빈 프로젝트 볼륨(`expresso-mongodb-test-fresh`)에서 최초 초기화 컨테이너의 종료 코드 0을 확인했습니다. 같은 설정 재실행도 0입니다. 다른 프로젝트의 데이터·keyfile 볼륨을 공유하지 않습니다.
- `hello.isWritablePrimary`를 확인한 뒤 계정을 생성합니다. 기존 replica set·계정 역할 충돌을 덮어쓰지 않습니다.
- 테스트 전용 DB를 임의 생성하고 자신이 만든 DB만 삭제합니다. 입력 URI의 DB 내용은 수정하지 않습니다.
- 실제 MongoDB 검사 **6건 통과**: bootstrap 재실행, 지연 연결 실패, 인증 실패, standalone 거부, 트랜잭션 취소, Docker의 실제 mongod 재시작 후 문서 보존.
- 런타임 CRUD 허용, 인덱스 생성·validator 변경·validator 우회·컬렉션 삭제 거부, migration 계정의 DDL 허용을 실제 서버에서 확인했습니다. keyfile 소유자/그룹/권한은 `999:999:400`입니다.
- MongoDB `insert` 권한은 빈 컬렉션 생성도 허용합니다. 이를 차단했다고 주장하지 않으며 스키마 적용은 마이그레이션 프로세스만 수행합니다. [공식 권한 목록](https://www.mongodb.com/docs/manual/reference/privilege-actions/)
- Windows Node runner의 실제 빌드·필터 실행을 확인했습니다. 별도 capture harness로 제공된 URL 보존, MySQL 변수 제거, 공백·`&` 포함 필터의 정확한 전달을 확인했습니다.
- 전체 `pnpm typecheck`: 통과.
- 새 root runner를 사용한 격리 MySQL 통합 테스트: **155건 통과 / 9건 건너뜀**.
- 전체 `pnpm test`: backend **222건 통과 / 기존 Windows Codex fixture 4건 실패 / 172건 건너뜀**. 기존 실패를 감추지 않았으며 T18에서 다룹니다.

## 검토와 보정

- 1회차 독립 검토는 5개 P1을 확인했습니다. [원본 verdict](T01-review-1.json)
- 조정자가 한 보정 단계에서 mongosh 옵션, 인증 반환값, rs.status 필드, base64 keyfile, 재시작 검사를 수정했습니다.
- 실제 최초 기동에서 추가로 확인한 쓰기 가능 primary 대기도 같은 보정 단계에서 반영했습니다.
- [2회차 검토](T01-review-2.json)는 추가 지적 없이 승인했습니다. 검토자는 실제 소스 스냅샷을 검토했고 인프라 검증은 조정자가 수행했습니다.
- 통합 커밋 `566e790`의 Windows 체크아웃에서 셸 파일이 CRLF로 변환되는 실패를 재현했습니다. `a80d548`에서 해당 디렉터리의 `.gitattributes`에 LF 규칙을 추가했습니다. 이는 검토 예산 종료 후 조정자의 통합 수정이며 3차 검토를 만들지 않았습니다.
- 통합 체크아웃에서 타입 검사·backend 빌드·Mongo 6건 검사·실제 권한/재시작 검사를 모두 다시 통과했습니다. 로그는 `T01-integration-{typecheck,build,mongo,permissions}.log`입니다.
- 작업자의 샌드박스 내 pnpm 버전 다운로드 재시도가 반복되어 작업자를 종료했습니다. 보존된 소스와 검토 스냅샷의 SHA256 일치를 확인했습니다. 보안·서명 검사를 완화하지 않고 설치·실제 인프라 검증을 호스트에서 수행했습니다.

원본 로컬 로그: `var/mongodb-run/T01-final-{typecheck,test,legacy-infra,mongo}.log`.
실행 환경·작업자·검토 원본 이벤트와 소스 해시도 같은 디렉터리에 있습니다.
작업자 종료로 implementer의 최종 토큰 집계는 없으며, 조정자 사용량도 제공되지 않습니다. 검토자 사용량만 실측했으므로 전체 토큰 절감이나 병렬 속도 향상을 주장하지 않습니다.

운영 전환, SQL 런타임 제거, 도메인 저장소 이전은 아직 수행하지 않았습니다.
