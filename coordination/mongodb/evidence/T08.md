# T08 · 사용자 분석·재료·Brew 작업

코디네이터 직접 구현·검토. 기존 공개 계약을 유지하는 MongoJobAnalysisService,
MongoMaterialsService, MongoCompanyResearchService, MongoBrewJobService를 추가했다.

- 분석의 시작·완료·실패를 targetVersion과 attempts로 fencing하고, 늦은 이전 작업이
  최신 결과를 덮지 못하게 했다. 직전 결과 한 세대, 요구사항·coverage·match를 같은
  결과 버전으로 저장한다.
- 공고 공통 요구사항은 한 번만 추출하며 동시 분석 시 실제 승자 결과로 사용자별
  coverage와 match를 계산한다. 원문 인용은 Unicode code point 범위로 검증한다.
- 재료 0개 Brew, 자동 선택 10개, 사용자 선택 0개와 최대 10개를 보존했다.
  선택 갱신은 Brew referenceVersion과 활성 기록 guard를 사용한다.
- Brew 작업과 outbox를 한 트랜잭션으로 저장하고, 멱등키의 작업 유형 재사용과
  타 사용자 접근을 거절한다. 회사 조사 사실·신호의 근거 ID와 소유권도 검증한다.
- HTTP 제출 → MongoDB outbox → Redis Worker → 분석 결과·근거·coverage·match 저장
  E2E를 추가했다. 전체 brewing-flow의 Mongo 연결은 T09·T10 서비스 연결과 함께
  다시 실행한다.

검증:
- `pnpm typecheck` 통과.
- MongoDB/Redis 대상: 4개 파일, 11 통과·8 MySQL 사례 스킵.
- 격리 MySQL/Redis 전체 회귀 통과.
- 전체 suite: contracts 51, database 11, web 124, backend 354 통과.
  기존 Windows Codex 가짜 실행 파일 문제 4건만 동일하게 실패했으며 T18에서 수정한다.
- `git diff --check` 통과.

운영 연결·데이터 변경 없음. `test/e2e/brewing-flow.test.ts` Mongo 전체 연결 검증은
의존 서비스 구현이 끝나는 T10 확인 지점에서 완료한다.
