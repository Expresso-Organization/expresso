# T03 · 트랜잭션·Outbox·공개 경계

직접 구현·코드 검토·통합 검증을 수행했다. 별도 에이전트 검토는 실행하지 않았다.

- `inTransaction`은 snapshot 읽기와 majority+journal 쓰기를 사용한다.
- Outbox는 입력 충돌을 거부하고, leaseToken 조건으로 발행 성공·실패를 갱신한다.
  큐 성공 후 DB 오류는 같은 jobId로 재전달하며, 오래된 발행기는 새 결과를 덮지 못한다.
- 25개 서비스의 공개 메서드 타입을 24개 모듈 진입점으로 노출했다.
  라우트·인증·Worker와 다른 서비스의 생성자 타입을 해당 API 타입으로 바꿨다.
- 공개 오류·순수 함수를 저장소 구현과 분리했다. 기존 SQL 구현과 생성자 export는
  비교 실행을 위해 T17까지 유지하며, 새 구현은 같은 공개 API 타입을 충족해야 한다.

검증: `pnpm typecheck` 통과. 실제 MongoDB Outbox 6개 및 Redis DLQ 1개 통과.
격리한 MySQL/Redis의 기존 통합 테스트 155개 통과. 전체 테스트는 기존 Windows
Codex fixture 4개 실패가 동일하게 남아 있으며 백엔드 222개가 통과했다.

로그: `var/mongodb-run/T03-{outbox,typecheck,legacy-infra,full-test}.log`.
운영 데이터 변경과 런타임 MongoDB 전환은 하지 않았다.
