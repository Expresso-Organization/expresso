# T11 생성 결과와 사용량 확정

## 구현

- `MongoGenerationService`가 제출, 상태 조회, worker 실행, 자유 HTML 준비·완료·실패를 MongoDB에서 처리한다.
- 문장 writer와 layout designer 호출은 트랜잭션 밖에서 실행한다.
- 완료 트랜잭션은 활성 계정·recipe version·활성 career record·template을 다시 확인한 뒤 portfolio, section, block, 문장 근거, record usage, layout, usage ledger, snapshot, job 완료를 함께 확정한다.
- worker 실행 토큰과 attempts 조건으로 중복 worker 중 하나만 materialization을 소유한다.
- `(userId, generationJobId, reason)` ledger와 조건부 counter 증가로 같은 성공을 한 번만 차감한다.
- 0002 MongoDB 마이그레이션이 `generation_usage_ledger.amount`를 SQL과 같은 정수 `-1 | 1` 제약으로 바로잡는다. 0001은 수정하지 않았다.

## 검증

- `pnpm typecheck`: 통과.
- Mongo generation 통합 테스트: 4 통과, 6 MySQL 전용 건너뜀.
  - 동시 제출 20회와 worker 5개가 portfolio·snapshot·ledger·counter 1회로 수렴.
  - 근거 없는 수치와 provider 실패는 차감하지 않고 실패 분류 유지.
  - ready 자유 HTML 동시 완료 2회가 1회 차감으로 수렴, 실패 페이지는 무차감.
  - materialization 뒤 quota 거부 시 section·block·snapshot·ledger가 전부 롤백되고 실패 draft만 남음.
- database migration/schema 테스트: 12 통과, MySQL 전용 15 건너뜀. 0002 체크섬 안정성, 재실행, 정수 `-1 | 1` 허용과 그 외 값 거부 확인.
- 기존 MySQL 인프라 회귀: 34 파일 통과, 157 테스트 통과, 2 파일/149 테스트 건너뜀. 격리 데이터베이스만 생성·삭제함 (`var/mongodb-run/T11-final-legacy-infra.log`).
- 전체 `pnpm test`: contracts 51, web 124, database 12, backend 368 통과. 기존 Windows 가짜 Codex 실행 파일 문제 4건만 실패했으며 T11 변경과 무관한 기존 T18 수정 대상이다.
- `git diff --check`: 통과.
