# T04 · 계정·권한·동의

직접 구현하고 실제 MongoDB에서 검증했다. 외부 작업자는 사용하지 않았다.

- 가입과 첫 세션, Google 계정·연결·첫 세션을 같은 트랜잭션으로 저장한다.
  비밀번호 해시와 세션 토큰 생성은 기존 구현을 재사용한다.
- 이메일의 대소문자·악센트 비교, OAuth 식별자·사용자별 연결, tokenHash 고유성을 유지한다.
- 세션 만료·폐기·계정 삭제를 직접 검사한다. TTL 삭제를 기다리지 않는다.
- `requireActiveUser`의 lifecycleVersion 쓰기로 계정 삭제와 변경 작업을 충돌시킨다.
- 권한은 기존 플랜 정책과 KST 월 경계를 재사용한다. 전달된 트랜잭션의 세션도 유지한다.
- 동의 확인은 같은 세션에서 실제 문서를 갱신한다. 철회가 먼저 커밋되면 작업 시작이
  재검사에서 거절되며 Outbox가 남지 않는다.

기존 auth·identity·Google·entitlements·consent 테스트 본문을 MySQL/MongoDB 양쪽에서
재사용했다. 동시 가입, 첫 세션 실패 롤백, 계정 삭제 및 동의 철회 경합, 중복 OAuth
연결 방지도 추가했다. MongoDB 커리어 카테고리 HTTP 주입은 승인된 계획대로 T06에서
검증하며, 이 단계에서는 가입 직후 시스템 카테고리 7개가 유지되는지 DB에서 확인했다.

검증 결과:

- `pnpm typecheck`: 통과.
- 계정·권한·동의 대상 실행: 기존/신규 테스트 53개 통과. 이후 추가한 OAuth 중복 연결
  사례도 아래 전체 실행에서 통과했다.
- 실제 MongoDB·Redis를 제공한 `pnpm test`: 백엔드 268개 통과, 기존 Windows Codex
  fixture 4개 실패 동일. DB 패키지의 MongoDB 테스트 11개 통과.
- 격리 MySQL·Redis 기존 통합 테스트: 155개 통과.

로그는 `var/mongodb-run/T04-{all,typecheck,full-test,legacy-infra}.log`다.
운영 연결은 변경하지 않았다. 전체 도메인 구현과 T17 연결 전환이 남아 있다.
