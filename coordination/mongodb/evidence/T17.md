# T17 검증 증적

## 구현

- API와 Worker를 `createMongoResource` 및 MongoDB 서비스·outbox로 전면 연결했다.
- 모든 정식 `service.ts`/`board-service.ts`의 클래스는 저장소 중립 이름을 사용하고 `Mongo*`는 테스트 호환 alias로만 유지한다.
- runtime과 migration URI를 분리하고 readiness가 primary·인증·최신 migration을 검사하도록 했다. 큐 기본 prefix는 `expresso-mongo-v1`이다.
- SQL 구현·마이그레이션·운영 도구는 `legacy-mysql` 경로로 격리했다. 현재 database CLI/export는 MongoDB migration만 사용한다.

## 검증

- runtime scan: legacy/test 파일 제외 `mysql2|SqlTag|createMysqlResource` 0건.
- API/Worker/config/Mongo platform의 `DATABASE_URL|TEST_DATABASE_URL` 참조 0건.
- `pnpm typecheck`: contracts/database/web/backend 모두 통과.
- `pnpm test`: contracts 51, database 15, web 124, backend 398 통과.
- `node scripts/test-infra.mjs`: 31 files / 170 tests 통과.
- MySQL 비교 suite와 opt-in live AI/restart suite의 skip은 별도 기록했으며 MongoDB suite는 실제 인프라에서 실행했다.
- 직접 검토에서 공개 계약 유지, MongoDB-only 조립, SQL runtime 의존 0건, 정식 클래스명 전환을 확인하고 승인했다.
