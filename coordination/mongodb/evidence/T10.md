# T10 · Recipe와 템플릿

코디네이터 직접 구현·검토. 기존 planner와 template renderer를 그대로 재사용하고
MongoRecipeService, MongoTemplateService, 별도 recipe revision 저장 경계를 추가했다.

- 선택 기록·공고 요건·인터뷰 답변의 원래 ID를 planner source와 evidence path에
  유지한다. 빈 source 배열과 범위를 벗어난 advisory 번호는 항목을 버리지 않고
  빈 evidence로 저장한다. targetLength 0도 보존한다.
- AI/규칙 planner는 트랜잭션 밖에서 실행한다. 완료 시 Brew referenceVersion과
  활성 기록을 다시 확인하고 recipe·section·item·path·unused source를 한 번에 저장한다.
- 사용자 편집은 Recipe editVersion으로 직렬화한다. 섹션·항목 이동/추가/삭제,
  명시적 instruction, 잠금, diff, snapshot 복원을 MongoDB에서 검증했다.
- revision은 별도 컬렉션에 보관하며 최신 50개를 제외한 오래된 문서를 정리한다.
- 활성 디자인 카탈로그 30종의 코드·style을 seed에서 읽어 모두 렌더링한다.
  비활성 또는 과거 행은 삭제하지 않고 새 미리보기 목록에서만 제외할 수 있다.

검증:
- Recipe·planner·template·interview와 MongoDB/Redis brewing E2E 5개 파일,
  18 통과·7 MySQL 사례 스킵.
- 전체 brewing E2E에서 HTTP → Mongo outbox → Redis Worker로 공고 분석, 재료,
  인터뷰, 답변, record.cleanup, Recipe 생성과 사용자 잠금까지 확인했다.
- 전체 typecheck, `git diff --check` 통과.
- 격리 MySQL/Redis 전체 회귀 통과.

운영 연결·데이터 변경 없음.
