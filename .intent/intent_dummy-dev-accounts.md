# 관리자 화면과 더미 개발자 계정 5종

## 개발 목표와 의도

포트폴리오 생성이 사람마다 얼마나 다른 결과를 내는지 시험할 계정이 지금은 하나뿐입니다. 그 계정(dev01, 가상 인물 윤하린)은 프론트엔드 개발자 한 사람의 기록 19건만 가지고 있습니다. 그래서 기록이 거의 없는 신입이나 기록이 100건 넘는 시니어에게 생성이 어떻게 동작하는지 볼 방법이 없습니다.

> "다양한 컨셉의 더미 개발자 계정 5개 추가. … 커리어 기록은 적음 -> 매우 많음까지 다양하게. … 관리자가 손쉽게 관리하고 해당 계정으로 로그인할 수 있는 방안이 필요함."

이 작업은 운영 서버에서도 동작해야 합니다. 그래서 제품에 관리자 권한을 새로 만듭니다. 관리자는 관리 화면에서 더미 계정을 만들고 지우고, 비밀번호 없이 그 계정으로 들어가 생성을 시작합니다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 관리자 권한 | 서버에서 명령 한 줄(`admin grant <이메일>`)로 기존 계정을 관리자로 지정하고 해제합니다. 웹 화면에서는 관리자를 지정할 수 없습니다. | 운영에서 더미 계정을 다룰 사람을 정해야 합니다. 웹에서 지정할 수 있으면 관리자 계정 하나가 뚫렸을 때 관리자가 늘어납니다. |
| 관리 화면(`/admin`) | 관리자에게만 사이드바에 「관리」 항목이 보입니다. 화면에는 더미 계정 5종이 한 줄씩 있고, 줄마다 직군 · 경력 · 기록 수 · 마지막 대신 로그인 시각과 관리자 이름이 보입니다. 관리자가 아닌 사람이 주소를 열면 「페이지 없음」이 뜹니다. | 계정 다섯을 한곳에서 보고 다뤄야 "손쉽게 관리"가 됩니다. 일반 사용자에게 관리 화면이 있다는 것도 드러내지 않습니다. |
| 더미 계정 만들기 · 다시 채우기 · 지우기 | 줄마다 버튼이 있습니다. 「만들기」는 저장소에 있는 원본 데이터로 계정과 기록을 만듭니다. 「다시 채우기」는 그 계정의 모든 데이터(생성한 포트폴리오 포함)를 지우고 원본으로 다시 만듭니다. 「지우기」는 계정을 통째로 없앱니다. 다시 채우기와 지우기는 확인 창을 거칩니다. | 시험하다 기록이 바뀌면 같은 조건에서 다시 시험할 수 없습니다. 운영 DB에 손으로 넣으면 서버마다 내용이 달라집니다. |
| 더미 계정 5종 | 아래 표의 가상 인물 다섯입니다. 이메일은 `dummy-<이름>@expresso.test`입니다. 모두 이메일 인증 · 약관 동의 · AI 처리 동의 두 항목 · team 요금제를 갖춘 상태로 만들어집니다. | 직군과 기록 양이 다른 사람이 있어야 생성 결과가 얼마나 달라지는지 비교할 수 있습니다. 동의와 요금제가 없으면 생성이 403으로 막힙니다. |
| 대신 로그인 | 관리 화면에서 「이 계정으로 보기」를 누르면 홈 화면이 그 더미 계정으로 열립니다. 더미 계정에만 허용합니다. 실제 사용자 계정으로는 들어갈 수 없습니다. | 더미 계정에는 비밀번호가 없어서 이 방법 외에는 들어갈 길이 없습니다. 실제 사용자의 데이터를 관리자가 보는 길은 만들지 않습니다. |
| 대신 로그인 표시와 되돌아오기 | 대신 로그인한 동안 모든 화면 맨 위에 더미 계정 이름과 「관리자로 돌아가기」 버튼이 있는 띠가 보입니다. 버튼을 누르면 관리 화면으로 돌아옵니다. | 지금 누구로 보고 있는지 모르면 관리자 본인 계정에서 한 일로 착각합니다. |
| 관리 기록 | 대신 로그인 시작 · 끝, 더미 계정 만들기 · 다시 채우기 · 지우기, 관리자 지정 · 해제를 누가 언제 했는지 DB에 남깁니다. | 운영에서 다른 계정으로 들어가는 기능이므로 나중에 누가 무엇을 했는지 확인할 수 있어야 합니다. |

| 가상 인물 | 직군 · 경력 | 기록 양 |
|---|---|---|
| 한서윤 | 컴퓨터공학 졸업 예정 · 백엔드 지망 신입 | 아주 적음 · 3건 |
| 오태민 | UI 디자이너 5년 뒤 프론트엔드로 전직한 1년차 | 적음 · 10건 |
| 문가령 | 커머스 데이터 분석가 4년차 | 보통 · 25건 |
| 배준호 | 추천 시스템 ML 엔지니어 · 석사 · 논문 다수 | 많음 · 50건 |
| 정우진 | 15년차 플랫폼 · 인프라 스태프 엔지니어 · 발표와 오픈소스 다수 | 매우 많음 · 100건 |

## 개발 목표

- 관리자 지정: 서버에서 `admin grant`를 실행한 계정에만 사이드바 「관리」가 보이고, 다른 계정으로 `/admin`을 열면 「페이지 없음」이 뜬다.
- 계정 만들기: 관리 화면에서 다섯 계정을 만들면 각 줄의 기록 수가 3 · 10 · 25 · 50 · 100으로 보인다.
- 대신 로그인: 「이 계정으로 보기」를 누르면 홈이 그 가상 인물의 이름으로 열리고, 화면 위 띠에 이름과 「관리자로 돌아가기」가 보인다.
- 생성: 대신 로그인한 상태에서 채용 공고로 포트폴리오 생성을 시작하면 동의 · 요금제 오류 없이 생성 작업이 만들어진다.
- 되돌아오기와 기록: 「관리자로 돌아가기」를 누르면 관리 화면으로 돌아오고, 그 줄의 마지막 대신 로그인 시각과 관리자 이름이 바뀌어 있다.

## 범위 밖과 제약

- 실제 사용자 계정으로 대신 로그인하는 기능은 만들지 않습니다.
- 관리 화면에는 더미 계정 관리만 둡니다. 사용자 목록 · 통계 같은 다른 관리 기능은 이번에 만들지 않습니다.
- 열린 PR #122(로그인 화면 「개발 계정으로 접속」 버튼)가 고치는 파일(`api/dev/session/route.ts`, `proxy.ts`, `LoginForm.tsx`, `lib/auth/dev-login.ts`)은 건드리지 않습니다. #122는 개발자 한 명이 환경 변수의 계정으로 들어가는 문이고, 이번 작업은 관리자가 운영에서 더미 계정으로 들어가는 문입니다. 둘은 따로 동작합니다. `docs/operations/DEPLOYMENT.md`는 두 PR이 다른 절을 추가하므로 병합할 때 한 번 맞춥니다.
- 더미 계정이 운영 사용자 수 · 통계에 함께 잡히는 문제는 이번에 다루지 않습니다.

## 열린 질문

- 관리자 지정을 서버 명령으로 할지, 환경 변수(`ADMIN_EMAILS`)로 할지 — 서버 명령으로 쓴다. 명령은 DB에 기록이 남고 재시작이 필요 없다. 환경 변수로 바꾸면 관리 기록에 지정 · 해제가 남지 않는다.
- 더미 계정에 비밀번호를 줄지 — 주지 않는다. 비밀번호가 있으면 관리자가 아닌 사람도 그 비밀번호로 들어올 수 있다.
