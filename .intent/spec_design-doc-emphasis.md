# 설계서 핵심 내용 굵게 · 하이라이트 표시 — 명세

## 요구사항

- [ ] R1 `mark` 스타일: bean-50 바탕 + crema 2px 밑줄, 글자색은 본문과 같음. 화면 · PDF 모두(`print-color-adjust: exact`).
- [ ] R2 하이라이트는 소절(■ h4, 소절이 없으면 h3) 하나에 0–1문장. 문장 하나를 통째로 감싼다(시작부터 마침표까지).
- [ ] R3 굵게는 문단 · 목록 항목 하나에 0–3곳. 핵심 용어의 첫 등장 · 결정값 · 수치. `mark` 안에는 굵게를 두지 않는다.
- [ ] R4 「<strong>이름</strong> — 설명」 형식의 목록 이름표는 구조이므로 유지한다.
- [ ] R5 표(`td` · `th` · `caption`) · 그림 · 코드 · 제목 · 8.2 자동 생성 구간은 바뀌지 않는다.
- [ ] R6 태그를 걷어 낸 본문 글이 작업 전과 같다.

## 설계

- 문서를 장(01 – 10) 단위 조각으로 나눠 하위 에이전트 넷이 고친다(A 01–04 · B 05 · C 06 · D 07–10).
- 조각마다 검사 스크립트가 R5 · R6과 밀도(R2 · R3)를 센다. 호스트가 다시 합치고 같은 검사를 한 번 더 한다.

## 버린 대안

- 굵게만 쓰기 — 굵게가 이미 많은 장(5 · 7)에서는 결론 문장이 드러나지 않는다.
- 소절 끝 요약 상자 — 글을 새로 써야 해서 「글은 그대로」 제약을 어긴다.

## 완료 기준

- 검사 스크립트 통과, PDF에서 하이라이트가 보이고 쪽 수 변화가 1쪽 안쪽.
