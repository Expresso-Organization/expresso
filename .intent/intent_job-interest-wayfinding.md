# 관심 공고 다시 찾아가기 — 사이드바 링크와 목록 필터

## 문제

PR #88로 공고를 관심 공고에 담을 수 있게 됐지만, 담은 공고를 다시 여는 길이 없다.

- 사이드바 "관심 공고" 줄(`components/shell/Sidebar.tsx`)이 `div`라 눌러도 아무 데도
  가지 않는다. 묶음 머리의 "+"(`aria-label="관심 공고 추가"`)도 동작이 없다.
- 공고 탐색(`app/(app)/jobs/page.tsx`) 머리의 "관심 공고 N"은 `type="button"`뿐인
  버튼이다. 백엔드는 `interested=true`를 받지만(`ListJobPostingsQuerySchema`) 웹 목록
  주소(`jobs/list-query.ts`)에 `interested`가 없어, 관심 공고만 보는 목록을 만들 수 없다.

## 원하는 결과

1. 사이드바 관심 공고 줄을 누르면 `/jobs/{id}`(공고 상세)로 간다. 그 공고 상세를 보고
   있는 동안 해당 줄은 카테고리 줄과 같은 방식(`aria-current="page"`, 활성 배경)으로
   표시된다. 사이드바는 목록이 아니므로 `from`을 달지 않는다.
2. 공고 탐색 머리 "관심 공고 N"을 누르면 주소가 `/jobs?interested=true`가 되고 내 관심
   공고만 나온다. 이 상태에서 다시 누르면 필터가 풀린다(토글). 켜져 있는 동안 버튼은
   켜진 상태로 보이고 보조기기에도 켜짐이 전달된다(`aria-current`).
3. 관심 공고 목록에는 나라 기본값(한국)을 걸지 않는다. 머리 숫자 N은 나라 조건 없이
   센 건수(`watchedJobs`)라서, 기본값이 걸리면 해외 공고를 담은 사람에게 N보다 적은
   목록이 나온다. 검증: 다른 조건이 없을 때 머리 숫자 = 목록 `summary.total`.
4. 관심 공고 목록 안에서 카테고리 칩 · 필터(근무지 · 경력 · 근무 형태 · 회사) · 쪽 이동 ·
   검색 · 검색 결과 정렬을 눌러도 `interested=true`가 유지된다. 칩 건수는 이미 관심 집합
   안에서 센 값이다(백엔드 `filter("category")`가 `interested`를 유지).
5. 관심 공고 목록에서 상세로 갔다가 "목록으로"를 누르면 관심 공고 목록으로 돌아온다
   (`backToListHref`가 `interested`를 보존).
6. `interested` 값은 `"true"`일 때만 켠다. 그 밖의 값은 주소 조립 · 돌아가기 주소에서
   버린다. `list-query` 테스트가 왕복과 폐기를 확인한다.
7. 목록 머리 문구는 관심 모드에서 "관심 공고 · N건"이고, 0건이면 "조건에 맞는 관심
   공고가 없습니다"처럼 무엇이 없는지 말한다.

## 영향 범위

- 사용자: 앱 셸 사이드바와 공고 탐색 · 검색을 보는 로그인 사용자.
- 모듈: `services/web`만. `components/shell/Sidebar.tsx`(관심 줄을 클라이언트 조각으로
  분리), `app/(app)/jobs/page.tsx` · `page.module.css` · `list-query.ts` · 테스트.
- 백엔드 · 계약 · 데이터 변경 없음.

## 제약

- 색 · 크기는 `tokens.css`의 `--ex-*`만 쓴다. 기존 사이드바 줄 모양을 바꾸지 않는다.
- `list-query`의 원칙(주소창 값은 믿지 않고 아는 조건만 다시 조립)을 지킨다.
- #88이 아직 머지 전이라 브랜치를 `feat/job-interest-toggle` 위에 쌓는다. PR base는
  #88 머지 전까지 그 브랜치다.

## 범위 밖

- `interested=false`(관심 아닌 것만) — 화면에 그런 개념이 없다.
- 단계(`stage`) 필터 UI. 백엔드는 받지만 화면 정의서에 단계 칩이 없다.
- 관심 모드의 기본 정렬을 "마감 순"으로 바꾸는 일. 정렬 기본값은 지금처럼 일치도 순이다.
- 목록 행 북마크를 담기/해제 버튼으로 만드는 일, 레일 "마감 순" 버튼 동작, "알림 설정".
- 사이드바 "내 포트폴리오" "+" 등 다른 묶음의 버튼.

## 열린 질문

- 사이드바 "+"는 무엇을 하는가 — 화면 정의서는 `ph-plus` 아이콘(`cursor: pointer`)만
  그리고 목적지를 적지 않았다. 구현 명세서 · 기능 명세서(T2.4.6)도 정하지 않았고
  `API_GAPS.md`는 이 버튼을 공백으로 적어 두었다. 관심 공고를 담는 곳은 공고 상세뿐이고
  상세에 닿는 목록이 공고 탐색이므로, **"+"는 `/jobs`(공고 탐색)로 가는 링크**로 제안한다.
  → 답: 제안대로 `/jobs` 링크로 한다.
- 정의서 06 우측 레일 "관심 공고" 머리에는 `전체` 링크(`href="#saved"`)가 있는데 웹
  레일에는 없다. 목적지가 이번에 만드는 `/jobs?interested=true`와 같으므로 **이번에 함께
  넣는 것**으로 제안한다.
  → 답: 이번에 함께 넣는다.
