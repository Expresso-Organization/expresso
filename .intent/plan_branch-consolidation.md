# 로컬 브랜치 정리와 승인 기능 통합 — 계획

1. 지정 브랜치와 워크트리의 상태를 확인하고 복구 bundle·패치·원본 파일·실험 데이터 백업을 검증한 뒤 정리한다.
2. 최신 main의 격리 워크트리에서 참고 링크 브랜치의 계약·인용 검증·서비스·도구·테스트를 옮긴다. 공개 URL 검사와 HTML 변환의 중복은 제거하고 최신 제작 도구를 유지한다.
3. runtime-config, AI 생성기, API·Worker에 요건 추출 전용 설정을 추가하고 독립 설정·계측·기본 off 테스트를 추가한다. 환경 파일은 열지 않고 README에 설정을 기록한다.
4. 개발 전용 비교 페이지에 기존 제품 UI와 토큰을 재사용한다. 현재·선별안 전환과 상태 조작을 구현하고 변경점을 짧게 표시한다. 데이터는 검토용 예시로 명시한다.
5. 승인한 검색 진행·빈 결과 피드백, 제목 안 행 작업·하단 필터와 합계·452px 패널, 근거 기반 추이 차트 생성과 렌더링을 현재 구조에 연결한다. 기존 선택·편집·정렬·드래그·제작 도구를 보존한다.
6. pnpm install --frozen-lockfile, pnpm typecheck, pnpm test, pnpm test:infra, 웹 빌드로 검증한다. 브라우저에서 데스크톱·모바일·키보드·Reduce Motion과 반대 방향 전환을 확인한다.
7. 작업 기록과 검증 결과를 커밋하고 승인된 다섯 기능을 PR로 전달한다. 비교 페이지를 열어 둔다.

가장 위험한 부분은 최신 대화 서비스와 링크 출처 계약의 통합이다. 기존 제작 회귀 테스트를 함께 확인하고 실패하면 해당 구현 커밋을 되돌린다. 추천 모델 브랜치는 변경하지 않는다.
