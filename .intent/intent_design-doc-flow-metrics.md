# 설계서 전체 사용자 플로우 그림과 순위 지표 설명 추가

## 문제

설계서 피드백 두 가지.

1. 사용자가 서비스를 처음부터 끝까지 어떻게 지나가는지 한눈에 보이는 그림이 없다. 2.1 「이용 절차」는
   10단계 표뿐이고, 무엇이 한 번만 하는 일이고 무엇이 공고마다 반복되는지, 배포 뒤 어디로 돌아가는지가
   글로만 있다.
2. 9.2의 주요 지표 NDCG@10과 Recall@K가 「무엇을 평가하는가」 한 줄로만 적혀 있어 처음 보는 사람이
   값의 뜻과 계산을 알 수 없다.

## 원하는 결과

- 2.1 「■ 이용 절차」 표 앞에 **전체 사용자 플로우 그림**: 가입 · 온보딩(최초 1회) → 커리어 기록 →
  공고마다 반복되는 흐름(공고 탐색 → 공고 분석 → 재료 고르기 → AI 대화 → 레시피 → 디자인 선택 → 다듬기 →
  배포) → 방문 분석 → 다듬기 · 재배포 또는 다음 공고로 되돌아가는 고리. 단계마다 화면 번호(5.3)와 학습 모델이
  쓰이는 자리(공고 추천 · 기록 추천)를 표시한다. 제안서 그림 양식을 따른다.
- 9.2 지표 표 뒤에 **「■ 순위 지표의 이해」**: NDCG@k와 Recall@k 각각의 뜻, 계산식, 공고 몇 건으로 직접 계산해
  보는 예시, 값을 읽는 법, 두 지표를 함께 보는 이유(스크리닝은 Recall, 재정렬은 NDCG). 이해를 돕는 그림 한 장.

## 영향 범위

`docs/졸업작품-설계서.html` 2.1 · 9.2와 뒤따르는 그림 번호, PDF, md 초안 02 · 09. 결정 권한은 사용자(팀장).

## 제약

- 계산 방식은 설계서에 이미 적힌 것을 따른다 — NDCG의 gain은 선형(교사 적합도 점수 그대로), 순위 할인은 log2.
- 예시 숫자는 예시라고 밝히고, 실제 결과(9.2 파일럿 수치)와 섞지 않는다.
- 그림이 들어가면 2장 · 9장의 뒤 그림 번호와 본문 참조를 함께 고친다.

## 범위 밖

MAE · 순서 일치율 · ROC 설명 확장, 실제 Recall@K 측정.

## 열린 질문

1. 플로우 그림 위치 — 답: 기본안(2026-10-06 사용자 결정): 2.1 「이용 절차」(그림 2.1이 되고 기존 2.1 – 2.3은 2.2 – 2.4로 밀림).
   다른 안: 5.1 사용자 메뉴구성 옆.
2. Recall@k의 「관련 공고」 기준 — 답: 기본안(2026-10-06 사용자 결정): 교사 적합도 60점 이상. ROC 양성 · MAP@10 · MRR@10과 같은 기준이다.
