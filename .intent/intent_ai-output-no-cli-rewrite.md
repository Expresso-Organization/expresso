# AI 출력 거절 · 재작성 경로 전면 제거

## 개발 목표와 의도

구성 플래너 측정에서 Claude Code CLI가 첫 출력을 "JSON이 아니다"라고 거절했다. 모델은 150초 동안 쓴 출력을 처음부터 다시 썼다. 출력 토큰은 두 배가 되었다. 요청: "그 어떤 경우에서도 모델의 출력을 거부해서 다시 쓰는 일이 발생해서는 안 돼." 전수 조사에서 출력을 버리는 경로 다섯 개를 찾았다. 구현 뒤 실측에서 여섯 번째 경로(설계가 먼저 오는 생성이 실패하면 옛 경로로 지면 전체를 다시 만듦)를 더 찾았다. 이 변경은 여섯 경로를 모두 없앤다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| CLI 검증 없애기 | 모델이 JSON을 글로 쓰고 서버가 읽는다 | CLI 검증은 끌 수 없다. CLI가 거절하면 모델이 처음부터 다시 쓴다 |
| JSON 문법 수정 | 깨진 자리만 같은 세션에서 고쳐 받는다. 끊긴 출력은 이어 쓰게 한다 | 쉼표 하나로 출력 전체를 버리지 않는다 |
| 쓰는 동안 끊지 않기 | 시간 상한을 출력이 멈춘 시간으로 잰다 | 지금은 전체 시간을 넘기면 쓰던 출력을 버린다 |
| 서비스 시간 상한 제거 | AI 호출을 감싼 420초 · 900초 상한을 걷어낸다 | 상한이 지나면 결과를 버린다 |
| 고치기 횟수 | 걸린 칸이 줄거나 모델이 값을 바꾸는 동안 계속 고쳐 받는다. 값만 바뀔 때는 첫 호출 시간 안에서만 계속한다 | 지금은 두 번에서 멈춘다. 그 뒤 출력을 버린다 |
| 옛 경로 대체 제거 | 설계가 먼저 오는 생성이 실패해도 옛 경로로 다시 만들지 않는다 | 대체하면 쓴 지면을 버리고 처음부터 다시 만든다 |
| 자유 HTML 지면 | 마크업 없음 검사를 고치기 요청으로 바꾼다 | 같은 방식으로 출력을 버린다 |

## 개발 목표

- 어느 호출도 `--json-schema`를 쓰지 않는다.
- 워커 로그에 `structured_output_rejected`가 없다.
- 문법이 깨진 가짜 출력이 같은 세션의 고치기 한 번으로 통과한다.
- 구성 생성 실측의 출력 토큰이 한 번 쓴 분량에 머문다.
- 출력이 흐르는 호출은 `AI_TIMEOUT_MS`를 넘겨도 끊기지 않는다.

## 범위 밖과 제약

- Codex 어댑터는 다루지 않는다(Claude Code만 쓴다).
- 오류로 출력이 없이 끝난 호출을 큐가 다시 돌리는 동작은 그대로 둔다.
- 디자인 토큰 품질 검사는 모델 출력을 보지 않으므로 그대로 둔다.
