# 지면에 canvas · three.js 그림 싣기

## 개발 목표와 의도

포트폴리오 첫 화면의 그림을, 사람의 화면을 SVG로 따라 그린 그림 대신 이 사람의 커리어 기록 · 고른 스타일 · 강조할 점에서
나온 추상적인 그래픽으로 만들려 한다. 그런데 지금은 모델이 쓴 스크립트를 소독기 · 배포 문서의 CSP · 미리보기의 `sandbox=""`가
모두 막아, 지면에 canvas 그림이나 three.js 장면을 실을 길이 없다. 사용자: "이건 표현력 문제를 야기해. 이 제약을 풀자".
첫 화면 견본에서 상품 상세 화면을 상자와 막대로 옮긴 SVG가 주인공으로 섰고, 모든 지면이 비슷한 설명도가 되었다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 지면 스크립트 칸 | 모델이 HTML · CSS 옆에 `script`를 따로 쓴다. 지면에 `<canvas>`를 둘 수 있고, 스크립트가 그 위에 2D · WebGL · three.js로 그린다 | 스크립트 없이는 움직이는 추상 그래픽 · 3D 장면을 만들 수 없다 |
| 가둔 실행 | 스크립트는 익명 출처의 틀 안에서만 돈다. 문서가 그 스크립트(해시)와 고정한 three.js 한 판 말고는 실행하지 않고, 바깥으로 요청 · 그림 비콘 · 양식을 보내지 못한다 | 지면 재료에 바깥에서 긁어 온 공고문이 섞인다. 모델이 그 안의 지시를 옮겨 적어도 방문자와 앱에 닿지 못해야 한다 |
| 스크립트 없는 첫 모습 | 스크립트가 돌지 않는 자리(생성 중 실시간 지면 · 축소 미리보기 · 동작 줄이기 설정)에서는 CSS로 그린 첫 모습이 보인다 | 생성 중 3분 남짓 보는 지면과 썸네일의 첫 화면이 비면 안 된다 |
| 보는 자리마다 실행 | 배포 지면 · 디자인 대화의 첫 화면 · 다듬기 미리보기에서 스크립트가 돈다 | 사용자가 고르고 다듬는 화면에서 그림이 보여야 고를 수 있다 |
| 추상 그래픽 지침 | 디자인 지침이 첫 화면 그림을 기록 · 스타일 · 강조점에서 나온 추상 그래픽(svg · canvas · three.js)으로 잡게 한다 | 사용자의 디자인 방향. 화면을 따라 그린 설명도가 모든 지면을 같게 만든다 |

## 개발 목표

- 디자인 대화에서 첫 화면을 그리면 canvas · three.js 그림이 움직이는 견본이 나온다: 공고 화면 대화에서 확인
- 배포한 지면에서 같은 그림이 돈다: 공개 주소에서 확인
- 적대 스크립트(바깥 요청 · 그림 비콘 · 부모 창 접근 · 쿠키 읽기 · 추적 메시지 위조)를 넣은 지면을 각 자리에서 열면 모두 막힌다: headless Chrome 점검 결과
- 생성 중 실시간 지면에는 스크립트가 돌지 않고 첫 모습이 보인다

## 범위 밖과 제약

- 생성 중 실시간 지면(`LivePreview`, `allow-same-origin`)에는 스크립트를 돌리지 않는다. 둘을 함께 주면 모델 코드가 앱 출처를 얻는다.
- 미리보기 경로(`/preview` · 편집 미리보기 경로)는 `script-src 'none'`을 그대로 둔다.
- 틀이 자기 자신을 다른 주소로 옮기는 것(`location = …`)은 CSP로 막을 수 없다. 남는 위험으로 적는다.
- 스크립트의 문법 검사는 이번에 하지 않는다. 깨진 스크립트는 첫 모습만 남긴다.

## 열린 질문

- three.js를 어디서 받는가 → jsDelivr의 정확한 판 한 주소만 CSP에 연다(호스트 전체를 열지 않는다). 스스로 내보내려면 정적 파일에 CORS 머리가 필요해 다음으로 미룬다.
