# 세션 유지와 로그인 진입 정비

## 문제

세션이 발급 시점부터 고정 30일이라 매일 쓰는 사용자도 30일째에 갑자기 로그아웃된다.
연장이 없고, 사용자가 "이 기기에서 로그인 상태를 유지할지"를 고를 자리도 없어서
공용 PC에서도 30일 쿠키가 남는다.

진입 동선도 어긋난다. 보호 구간에 들어가려다 로그인으로 밀려나면 로그인 뒤 항상
`/home`으로 가고 보려던 자리를 잃는다. 만료된 세션 쿠키는 401을 받고도 지워지지
않아 `/` → `/home` → `/login`을 매번 돈다. 이미 로그인한 사람이 `/login`·`/signup`을
열면 그대로 폼이 보인다. 로그인 폼의 서버 검증 오류는 어느 칸이 틀렸든 이메일 칸
아래에 붙는다.

## 원하는 결과

- 활동 중인 사용자는 다시 로그인하지 않는다. 세션 만료가 **마지막 활동 기준**으로
  연장되고, 쿠키 만료도 함께 늘어난다. 연장에는 절대 상한이 있다.
- 로그인 화면에 "로그인 상태 유지" 선택이 있다. 끄면 브라우저를 닫을 때 끝나는
  세션 쿠키가 발급되고 서버 세션도 그에 맞게 짧다. 회원가입·Google 경로도 같은
  규칙을 따른다.
- 보호 구간에서 로그인으로 밀려난 사용자는 로그인 뒤 **원래 가려던 주소**로
  돌아온다. 같은 출처의 경로만 허용한다.
- 백엔드가 401을 답한 세션 쿠키는 그 자리에서 지워진다. 그 뒤 `/`는 로그인으로
  바로 간다.
- 로그인 상태에서 `/login`·`/signup`을 열면 `/home`으로 간다.
- 로그인 폼의 검증 오류는 틀린 칸 아래에 붙는다.
- 백엔드 통합 테스트가 연장·짧은 세션·상한을 검증한다.

## 영향 범위

- `packages/contracts/src/identity.ts` — 로그인·가입·Google 요청에 세션 유지 옵션
- `services/backend/src/modules/identity` — 세션 발급 TTL, 활동 시 연장
- `services/web` — `proxy.ts`, `lib/session.ts`, `lib/require-session.ts`,
  `auth-actions.ts`, 로그인·가입 화면, Google 콜백
- 데이터: `identity_sessions` 문서에 연장 규칙을 표현할 필드가 필요할 수 있다
- 결정 권한: minjaepark

## 제약

- 세션 토큰은 `httpOnly` 쿠키 `ex_session` 하나에만 둔다. 클라이언트 JS가 읽는
  자리에 토큰을 두지 않는다.
- 프록시(`proxy.ts`)는 백엔드를 부르지 않는다. 쿠키 유무만 본다.
- 스키마 변경은 `packages/database` 마이그레이션으로만 한다.
- 화면은 기존 로그인·가입 레이아웃과 `tokens.css` 값을 재사용한다.
- 발급된 기존 세션은 배포 뒤에도 그대로 유효해야 한다.

## 범위 밖

- 비밀번호 재설정·이메일 인증·메일 발송 (다음 intent: `auth-email`)
- 인증 엔드포인트 속도 제한 (`auth-rate-limit`)
- 패스키 (`passkey-login`)
- 비밀번호 변경·세션 목록·다른 기기 로그아웃 (`account-security`)
- GitHub 로그인
- 랜딩 페이지 제작 (`/`는 지금처럼 로그인 여부로만 분기)

## 열린 질문

- 연장 규칙의 값 — **답: 제안값으로 확정.** 유지 켬 = 마지막 활동 후 30일, 절대
  상한 90일 / 유지 끔 = 마지막 활동 후 12시간, 브라우저 세션 쿠키.
- "로그인 상태 유지"의 기본값 — **답: 켬.** 현재 동작과 같다.
