# 로그인 화면 개발 계정 접속 버튼

## 개발 목표와 의도

배포된 https://expresso.ai.kr 에서 화면을 확인하려면 매번 이메일과 비밀번호를
손으로 넣어 로그인해야 한다. "현재 배포된 https://expresso.ai.kr/home 주소에서
개발 계정으로 접속하는 버튼을 로그인 화면 하단에 넣어줘"가 요청이다.

로그인하지 않은 상태로 `/home`을 열면 프록시가 `/login?next=/home`으로 돌린다.
그 화면 오른쪽 아래에는 지금도 작은 칸이 하나 있는데, 거기 들어 있는 "데모 계정
보기"는 개발 서버(`NODE_ENV=development`)에서만 나타나고 계정과 비밀번호를
글자로 보여 줄 뿐이어서, 배포된 주소에서는 아무것도 없고 개발 서버에서도 값을
복사해 두 칸에 옮겨 적어야 한다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 개발 계정 접속 버튼 | 로그인 화면 오른쪽 아래 버튼을 누르면 설정해 둔 개발 계정으로 로그인되고, `/login?next=/home`으로 왔다면 `/home`으로 돌아간다 | 배포된 주소에서 화면을 확인할 때마다 이메일·비밀번호를 손으로 넣는 일이 없어진다 |
| 배포 환경에서도 동작 | 지금은 프로덕션 빌드에서 버튼도 로그인 경로(`/api/dev/session`)도 꺼져 있다. 서버에 계정 정보를 적어 둔 경우에만 둘 다 열리도록 조건을 바꾼다 | 요청의 대상이 배포된 expresso.ai.kr 이다. 조건을 바꾸지 않으면 버튼을 넣어도 배포본에는 나타나지 않는다 |
| 계정·비밀번호를 글자로 보여 주던 칸 제거 | 지금 그 자리에 있는 "데모 계정 보기" 팝오버를 버튼으로 바꾼다 | 버튼이 대신 로그인하므로 값을 옮겨 적을 일이 없고, 배포된 화면에 비밀번호를 글자로 띄우는 일도 없어야 한다 |

## 개발 목표

- 배포 확인: expresso.ai.kr 서버에 계정 정보를 넣고 재시작한 뒤 `/home`을 열면,
  로그인 화면 오른쪽 아래에 "개발 계정으로 접속" 버튼이 있고 누르면 `/home`이 열린다.
- 꺼 둔 상태 확인: 서버에 계정 정보가 없으면 버튼이 화면에 아예 없고
  `/api/dev/session`은 404다.
- 로컬 확인: 프로덕션 빌드(`next build && next start`)로 띄운 웹에서도 버튼이
  보이고 눌러서 로그인된다 — 지금은 개발 서버에서만 보인다.
- 기존 로그인 영향 없음: 이메일·비밀번호 로그인과 Google 버튼은 그대로다.

## 범위 밖과 제약

- 서버의 `services/web/.env`는 저장소 밖(600 권한)이다. 이 변경으로 값이 자동으로
  들어가지는 않는다. 배포 후 그 파일에 세 줄을 넣고 `expresso-web`을 재시작해야
  버튼이 나타난다. 비밀번호는 저장소에 커밋하지 않는다.
- 백엔드와 계약은 건드리지 않는다. `/api/dev/session`은 지금처럼 제품의 실제
  로그인 API를 호출한다 — 인증을 우회하는 경로를 새로 만들지 않는다.

## 열린 질문

1. **누구나 누를 수 있는 버튼이 된다.** 배포된 로그인 화면에 나타나므로 주소를 아는
   사람은 모두 그 계정으로 들어온다. 그 계정에는 공개돼도 괜찮은 기록만 둔다는
   전제로 진행한다. 이 전제가 아니라면 이번 변경을 하지 않는 것이 맞다.
2. **배포 DB에는 `dev01@expresso.test`가 없을 수 있다.** 그 계정은 체험 DB
   (`expresso_portfolio_trial`)에 있다. 배포 DB에 없으면 첫 클릭에서 그 이름으로
   새로 가입되고, 기록이 비어 있으며 온보딩을 건너뛰어 AI 처리 동의가 없는 상태다
   (AI 기능이 403). 비어 있는 계정으로 시작하고 필요하면 그때 온보딩을 한 번 거치는
   쪽으로 진행한다 — 시드 데이터를 넣는 일은 이번 범위 밖이다.
