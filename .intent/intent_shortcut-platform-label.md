# 단축키 표시를 사용 중인 운영체제에 맞추기

## 개발 목표와 의도

좌측 사이드바의 검색 줄에는 어느 기기에서 열어도 `⌘K`가 보입니다. 윈도우와 리눅스에는 ⌘ 키가 없어서, 이 표시를 본 사용자는 어떤 키를 눌러야 하는지 알 수 없습니다. 실제 동작은 Ctrl+K도 이미 받으므로 표시만 맥에 고정된 상태입니다.

요청: "좌측 사이드바 단축키가 맥 기준으로만 표시되는 문제가 있다"

같은 문제가 편집 화면의 지시 입력 칸(`⌘↵`)에도 있습니다. 이 입력 칸은 Ctrl+Enter도 받지만 표시는 ⌘만 보입니다. 두 곳을 같은 방식으로 고칩니다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 사이드바 검색 단축키 표시 | 맥·아이패드에서는 `⌘K`, 그 밖의 기기에서는 `Ctrl+K`로 보인다. | 윈도우·리눅스 사용자는 `⌘K`를 보고 누를 키를 알 수 없다. |
| 편집 지시 입력 칸 단축키 표시 | 문서 편집 화면의 두 입력 칸(페이지 편집, 요소 편집)에서 맥은 `⌘↵`, 그 밖의 기기는 `Ctrl+↵`로 보인다. | 사이드바만 고치면 같은 단축키가 화면마다 다르게 보여 혼란스럽다. |

## 개발 목표

- 맥에서 사이드바 검색 줄 오른쪽에 `⌘K`가 보인다.
- 윈도우 기기(또는 사용자 에이전트를 윈도우로 바꾼 브라우저)에서 같은 자리에 `Ctrl+K`가 보인다.
- 편집 화면의 두 지시 입력 칸에서도 위와 같이 플랫폼별 표시가 보인다.
- 새로고침 때 맥에서는 표시가 바뀌지 않는다.

## 범위 밖과 제약

- 단축키 동작(Ctrl+K, Ctrl+Enter 입력 처리)은 이미 두 플랫폼에서 동작하므로 바꾸지 않는다.
- 코드 주석 속 ⌘ 표기는 손대지 않는다.
- 모바일 앱·데스크톱 클라이언트(`services/mobile`, `services/desktop`)는 다루지 않는다.

## 열린 질문

없음. 맥이 아닌 기기의 표기는 `Ctrl+K` 형식으로 정한다.
