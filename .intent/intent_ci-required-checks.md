# 경로 밖 PR도 필수 검사를 받는 CI

## 개발 목표와 의도

`main`에 브랜치 보호(필수 검사 `verify`)를 걸어 auto-merge가 CI 통과를 기다리게 했다. 그런데 웹 · 백엔드 CI는 PR 경로 필터가 있어서
`docs/` · `.intent/` · `services/mobile`만 바꾼 PR에서는 검사가 돌지 않는다. 그런 PR은 필수 검사를 영영 못 받아 머지도 auto-merge도 막힌다.
두 CI의 잡 이름이 둘 다 `verify`라 필수 검사가 어느 CI를 가리키는지도 모호하다. 사용자: "그것도 지금 고치자."

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 모든 PR에서 CI 실행 · 경로 밖이면 검사 건너뛰기 | 두 CI가 모든 PR에서 돌고, 먼저 「변경 감지」 잡이 바뀐 파일을 본다. 그 CI가 보는 경로를 안 건드렸으면 검사 잡을 건너뛴다 | 건너뛴 잡은 필수 검사에서 통과로 친다. 없으면 문서 PR이 「대기 중」으로 막힌다 |
| 감지 실패 시 검사 | 바뀐 파일 목록을 못 읽으면 건너뛰지 않고 전체 검사를 돈다 | 감지 실패가 검사 생략(=통과)으로 바뀌면 깨진 코드가 머지된다 |
| 검사 이름 분리 | 필수 검사 이름을 `웹 검사` · `백엔드 검사`로 나누고 브랜치 보호를 이 둘로 바꾼다 | 같은 이름 둘이면 어느 CI가 실패했는지 보호 규칙이 가르지 못한다 |

## 개발 목표

- 이 PR(워크플로만 바꿈)에서 `웹 검사` · `백엔드 검사`가 결과를 내고 auto-merge로 머지된다.
- 문서만 바꾼 PR에서 두 검사가 「건너뜀」으로 끝나고 머지 가능 상태가 된다.
- 웹 코드를 바꾼 PR에서는 `웹 검사` · `백엔드 검사`가 실제로 돈다.

## 범위 밖과 제약

- `main` 푸시 실행의 경로 필터와 배포 워크플로는 그대로 둔다.
- 브랜치 보호를 바꾸면 옛 이름(`verify`)으로만 검사를 받은 열린 PR은 CI를 다시 돌려야 머지된다.
