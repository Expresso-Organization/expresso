# 생성 화면 지면 스트림 재연결 · 완료 뒤 전환 보장

## 개발 목표와 의도

생성 화면은 지면 스트림 연결 하나로 다음 단계(청사진 · 완성 · 다듬기 이동)를 안다. 그 연결이 한 번 끊기면 다시 붙지 않는다.
그래서 생성이 끝나도 화면은 입력 묶음 지면에 멈춰 있고, 사람이 「새로고침」을 눌러야 넘어간다.
사용자: "내가 새로고침 버튼 누르기 전까지 다음 단계로 안 넘어가는 버그가 있네."

운영 기록(2026-11-10 브루 `8f7d79bc`, 생성 잡 `4de06ed4`): 02:10:36에 연 스트림이 02:13:07에 끊겼고, 그 뒤 브라우저(Safari)는 다시 연결하지 않았다.
지면은 02:13:15에 시작해 02:13:44에 청사진, 02:14:44에 완성됐다. 사용자는 02:16:14에 새로고침을 누르고 나서야 다듬기로 넘어갔다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 끊긴 스트림 다시 연결 | 브라우저가 스트림을 닫아 버리면 1.5초 뒤 같은 잡의 스트림을 다시 연다. 처음부터 다시 받아 청사진과 채우기를 그대로 다시 그린다 | 없으면 연결이 한 번 끊긴 뒤 생성이 끝나도 화면이 멈춘다 |
| 화면으로 돌아오면 바로 다시 연결 | 다른 앱이나 탭에 갔다가 돌아왔을 때 연결이 닫혀 있으면 기다리지 않고 바로 다시 연다 | 백그라운드에서 끊긴 연결을 돌아온 순간 복구해야 사람이 멈춘 화면을 보지 않는다 |
| 완료 신호 뒤 다듬기로 넘어갈 때까지 다시 읽기 | 스트림이 완성(`done`)이나 실패(`failed`)를 알리면 화면을 다시 읽고, 서버가 아직 「생성 중」으로 그리면 1.5초마다 다시 읽는다 | 워커가 스트림에 완성을 먼저 쓰고 잡 상태를 20–60ms 뒤에 바꾼다. 그 사이에 다시 읽으면 생성 화면이 다시 그려지고 멈춘다 |

## 개발 목표

- 스트림이 끊겨도 넘어간다: 생성 중 연결을 끊으면 1.5초 뒤 새 연결이 생기고, 생성이 끝나면 새로고침 없이 다듬기 화면으로 간다.
- 완료 경합이 없다: 완성 신호를 받은 순간 서버가 아직 생성 중이어도 1.5초 안에 다시 읽어 다듬기로 간다.
- 기존 테스트와 새 테스트(`LivePreview.test.tsx`)가 통과한다.
- 운영에 배포된 뒤 생성 한 번이 새로고침 없이 다듬기까지 간다.

## 범위 밖과 제약

- 구성 대기 중 10초 뒤 지면을 먼저 띄우는 변경은 다른 세션이 맡는다(`GenerationWait.tsx`). 이 변경은 `LivePreview.tsx`만 고친다.
- 워커가 스트림 완성과 잡 상태를 쓰는 순서는 바꾸지 않는다. 화면이 서버 상태를 기다리는 쪽으로 푼다.
- 운영 Worker의 `outbox change stream failed` 경고는 따로 본다.
