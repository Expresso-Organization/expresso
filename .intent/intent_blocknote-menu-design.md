# 커리어 문서 본문 편집 메뉴 디자인 정합

## 개발 목표와 의도

> "이것들도 디자인을 익스프레소에 맞게 고쳐보렴. 이건 다른 오픈소스에서 가져와서 이식한건데 디자인이 너무 튄다."

커리어 문서 본문은 오픈소스 편집기 BlockNote(ariakit 테마)를 그대로 씁니다. 본문 옆 블록 단추, 블록 메뉴(삭제 · 색깔), 색 고르기 메뉴, `/` 명령 메뉴, 선택 영역 서식 툴바는 ariakit 기본 모양으로 그려집니다.
어두운 테마의 패널에서 보면 고른 항목이 파란 띠(`#007acc`)로 칠해지고, 블록 단추는 크고 흰 아이콘으로 떠 있습니다. 단축키 표시는 입체 버튼처럼 그려지고 안내 문구는 기울임꼴입니다. 디자인 시스템 RULE 01(시스템은 무채색, 채도는 Espresso만)을 깨고, 같은 화면의 표 셀 팝업 · 속성 메뉴와 모양이 다릅니다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 메뉴 표면 통일 | 블록 메뉴 · 색 메뉴 · `/` 명령 메뉴 · 서식 툴바가 표 셀 팝업과 같은 흰(어두운 테마에선 진회색) 표면, 테두리, 둥근 모서리, 그림자로 뜬다 | 지금은 ariakit 회색 표면과 다른 그림자로 떠서 같은 화면의 다른 팝업과 따로 논다 |
| 고른 항목을 무채색으로 | 마우스를 올리거나 방향키로 고른 항목을 파랑 대신 옅은 잉크색 배경으로 칠한다 | 파란 띠가 화면에서 가장 튀고, 채도는 Espresso만 쓴다는 규칙을 깬다 |
| 블록 단추 정돈 | 본문 옆 `+` · 끌기 단추를 작고 옅은 아이콘으로 두고, 올렸을 때만 진해진다 | 지금은 큰 흰 아이콘이 본문 글자보다 먼저 눈에 들어온다 |
| `/` 명령 메뉴 항목 정돈 | 아이콘은 테두리 있는 작은 상자, 제목 · 설명은 시스템 글자 단계, 단축키는 얇은 테두리의 고정폭 글자로 보인다. 묶음 이름은 옅은 작은 제목이다 | 입체 버튼 모양의 단축키와 큰 아이콘이 메뉴를 무겁게 만든다 |
| 빈 줄 안내 문구 | 「텍스트를 입력하거나 /를…」 안내를 기울이지 않고 옅은 글자로 둔다 | 한글 기울임꼴은 어색하고 시스템 글자 규칙에 없다 |

## 개발 목표

- 밝은 · 어두운 테마에서 블록 메뉴 · 색 메뉴 · `/` 메뉴 · 서식 툴바의 고른 항목에 파란색이 없다.
- 네 메뉴의 표면이 표 셀 팝업(시기 · 역량 팝업)과 같은 배경 · 테두리 · 모서리 · 그림자다.
- 블록 단추가 본문 글자보다 옅고 작게(18px) 보이고, 올리면 진해진다.
- `tokens.test.ts`가 통과한다(새 색 · 크기 값 없음).

## 범위 밖과 제약

- 메뉴의 항목 · 순서 · 동작, 색 메뉴의 글자 · 배경색 값(BlockNote 강조색)은 바꾸지 않는다. 기록 내용에 쓰는 색이라 시스템 색이 아니다.
- BlockNote를 다른 테마(mantine 등)로 바꾸거나 메뉴를 직접 다시 만들지 않는다. 스타일만 덮어쓴다.
- 새 색 · 크기 값을 만들지 않는다. `tokens.css`의 토큰만 쓴다.
