# 디자인 시스템 토큰 기반 포트폴리오 섹션 키트

## 문제

생성된 포트폴리오의 디자인이 엉망입니다. 2026-10-16 체험 서버에서 Linear Midnight로 만든 결과를 #56·#57 렌더러로 다시 그려 확인했습니다.

- **한 페이지에 시각 언어가 네 가지입니다.** 섹션마다 출처가 다른 수집 원본 컴포넌트(Watermelon 히어로·카드·피처, Componentry 주석 텍스트, 그라데이션 제목)가 쓰입니다. 원본은 자기 Tailwind 색과 크기를 써서, 어두운 Linear 페이지 위에 밝은 히어로 카드가 떠 있습니다.
- **배치가 깨집니다.** dossier 배치의 좁은 열에 원본 히어로가 들어가, 상단 메뉴가 한 글자씩 세로로 꺾입니다. 첫 화면은 높이 대부분이 비어 있고, 소개 문장은 흰 바탕 위 연회색이라 거의 보이지 않습니다.
- **고른 디자인이 거의 반영되지 않습니다.** 38종 디자인 시스템은 서체(라틴·한글), 글자 크기 단계, 간격, 모서리, 그림자, 컴포넌트 규칙(테두리·표식·강조·구분선)을 정의합니다. 렌더러가 받는 값은 색 3개뿐입니다. 서체는 고정값(Pretendard·JetBrains Mono·Outfit)이고, 본문은 14px 회색입니다.
- **품질 검사가 이 결과를 통과시켰습니다.** 생성 경로의 검사는 마크업이 있는지와 수치 출처 두 가지뿐이라, 결과가 `ready`로 나왔습니다.

## 원하는 결과

- 구조화 생성은 Expresso가 소유한 섹션 컴포넌트 한 벌로 지면을 그립니다. 첫 화면, 프로젝트 목록, 사례 유형들, 소개·역량, 경력, 근거, 연락처, 묶음 컨테이너입니다. 새로 만드는 생성에는 수집 원본(`sourceId`)이 선택지로 나오지 않습니다.
- 섹션 컴포넌트는 고른 디자인 시스템의 토큰 전체를 씁니다.
  - 색 9개
  - 서체 3종과 한글 대체 서체(웹폰트로 실제 로드)
  - 글자 크기 단계·굵기·자간·행 길이
  - 간격 5종
  - 모서리·테두리·그림자
  - 컴포넌트 규칙 4종(테두리·표식·강조·구분선)
  - 배치·밀도
  - 모션 시간·곡선
  
  같은 내용을 서로 다른 디자인 시스템으로 그리면 색뿐 아니라 서체·크기·간격·모양이 눈에 띄게 다릅니다.
- 템플릿으로 만든 기존 포트폴리오도 그 템플릿에 대응하는 디자인 시스템의 토큰으로 그립니다. 저장된 지면 Spec(`sourceId` 포함)은 깨지지 않고 열립니다.
- 그리기 전에 토큰으로 판정할 수 있는 품질 조건을 검사합니다. 본문·작은 글자의 대비(WCAG AA), 본문 최소 크기, 웹폰트 존재가 대상이고, 조건을 어기면 `qaReport`가 실패로 나옵니다.
- 가상 프로필 3종 × 디자인 시스템 3종(밝은 내장, 어두운 Refero, 프리셋 하나)을 1440·926·390px에서 그립니다. 브라우저 검사(가로 넘침, 한 글자 줄바꿈, 열 이탈, 대비, 서체 적용)를 통과하고, 전후 화면을 실행 기록으로 남깁니다. 결과 화면을 사용자에게 보여 주고 확인을 받습니다.

## 영향 범위

- 포트폴리오를 생성하거나 편집 화면에서 다시 그리는 모든 사용자.
- `packages/portfolio-renderer`(카탈로그·컴포넌트·CSS), `packages/contracts`(구조화 Spec 모델 스키마), `services/backend/src/modules/page`(생성 문맥·렌더링 호출), `services/backend/src/modules/design-systems`(판 조회·글꼴), 검증 스크립트와 실행 기록.
- 결정 권한: 박민재.

## 제약

- json-render 구조(카탈로그·레지스트리·Spec, `$state` 데이터 바인딩)와 모델이 구성만 정하는 방식은 유지합니다.
- 모든 섹션은 JavaScript 없이 표시되고, 모션 감소 설정과 인쇄에서 모션이 꺼집니다.
- 저장 계약(`StructuredPortfolioSnapshot`)과 편집 API는 하위 호환을 지킵니다. 데이터 마이그레이션 없이 진행하는 것을 우선합니다.
- 수집 원본 라이브러리(#55–#57)는 지우지 않습니다. 생성 선택지에서만 빠지고, 저장된 Spec의 렌더링과 참고 자료로 남습니다.
- 글꼴은 지면이 보이는 모든 곳(문서 경로, 공개 사이트, 편집기 미리보기, 생성 중 미리보기)의 CSP에서 허용되는 방식으로 싣습니다.

## 범위 밖

- 내용 정리 품질(intent A2): 스킬 기록을 사례로 두는 문제, 채우지 못한 요건이나 하지 않는 일을 지면에 쓰는 문제, 요약·본문·항목 반복.
- 생성된 지면을 화면으로 보고 고치는 에이전트(intent B)와 운영 서버의 헤드리스 브라우저.
- 수집 원본을 토큰에 맞춰 다시 쓰는 일.
- 이미지 생성·편집, 새 디자인 시스템 추가.

## 열린 질문

1. 섹션 컴포넌트의 시각 기준을 어디서 가져올지 정해야 합니다. 후보는 화면 정의서(`docs/Expresso Screens.dc.html`)의 포트폴리오 예시, 각 디자인 시스템의 `DESIGN.html` 예시, 수집 라이브러리의 구도 참고 자료입니다. spec에서 후보별 장단을 정리해 묻겠습니다.
