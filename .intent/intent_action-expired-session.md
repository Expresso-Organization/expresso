# 세션 없는 서버 액션의 로그인 이동

## 개발 목표와 의도

로그인 쿠키가 사라진 상태에서 화면의 버튼(서버 액션)을 누르면, 로그인 화면으로 가는 대신 「편집기를 불러오지 못했습니다」 같은 오류 화면이 뜬다. 예: 편집 화면에서 AI 제안의 「그대로 두기」를 눌렀을 때. 프록시가 이 요청에도 페이지 이동용 리다이렉트를 돌려주는데, 서버 액션은 리다이렉트를 따라간 로그인 화면 HTML을 받아 해석하지 못하기 때문이다. 요청: "세션 만료 중 서버 액션이 오류 화면으로 빠지는 문제를 여기서 진행해 주세요."

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 서버 액션의 로그인 이동 | 쿠키 없이 버튼을 누르면 오류 화면 없이 로그인 화면(개발 로그인이 켜져 있으면 개발 로그인)으로 가고, 로그인 뒤 보던 화면으로 돌아온다 | 지금은 오류 화면에 갇혀 「다시 시도」를 눌러도 같은 오류가 반복된다 |
| 자바스크립트 없는 폼 제출 | 스크립트 없이 폼을 보내도 같은 로그인 화면으로 간다(GET으로 이동) | 지금은 POST가 GET 전용 로그인 경로로 넘어가 405가 난다 |

## 개발 목표

- 편집 화면에서 로그인 쿠키를 지운 뒤 AI 제안 「그대로 두기」를 누르면, 오류 화면 없이 로그인 화면이 열리고 주소의 `next`가 그 편집 화면이다.
- 쿠키 없이 주소를 직접 여는 지금 동작(로그인으로 이동)은 그대로다.

## 범위 밖과 제약

- 쿠키는 있지만 서버 세션이 끝난 경우는 이미 화면의 세션 확인이 로그인으로 보낸다. 손대지 않는다.
- 로컬 개발 서버끼리 쿠키가 덮이는 문제는 제품 문제가 아니라 다루지 않는다.

## 열린 질문
