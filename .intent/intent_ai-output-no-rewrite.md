# AI 출력 거절 · 재작성 제거

## 변경 의도

AI 호출 19곳 거의 모두가 출력이 글자 수 · 개수 · 형식 기준을 조금만 어겨도 출력 전체를 거절하고 처음부터 다시 쓰게 합니다. 지면 채우기는 본문이 80자 예산을 6자 넘었다고 약 150초를 더 썼고, 다듬기는 쓰지 않는 칸의 키를 빠뜨렸다고 다시 썼습니다. 작업 큐는 그 실패를 다시 최대 5번 돌립니다. 출력은 오는 대로 보여 주고, 검사에 걸린 칸만 쓴 에이전트가 고칩니다.

요청: "쓸데없이 출력 거절해서 처음부터 다시 쓰는 일이 절대로 없도록", "작성이 끝나면 바로 사용자 화면에 띄우고, 검사에서 통과하지 못한 부분을 작성한 에이전트에게 넘겨서 직접 수정하게", "수정된 내용이 오면 사용자 화면에 애니메이션과 함께 반영해"

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 모양만 검사 | 공급자에게 넘기는 출력 형식에는 키와 값의 종류만 남긴다. 글자 수 · 개수 · 형식 기준은 프롬프트에 "본문 80자 이내"처럼 적어 요청한다. 쓰지 않는 칸은 빼도 된다 | 공급자는 기준을 어긴 출력을 통째로 돌려보내고, 그 재작성은 우리 코드가 보지 못한 채 시간만 쓴다 |
| 바로 보여 주기 | 출력이 다 오면 검사보다 먼저 화면에 띄운다. 지면 생성은 채운 글이 칸마다 바로 보인다 | 검사 · 수정을 기다리는 동안 사용자가 빈 화면을 보지 않는다 |
| 쓴 에이전트가 고치기 | 검사(글자 수, 개수, 형식, 내용 규칙)에 걸린 칸만 "어느 칸이 무엇을 어겼는지" 목록으로 같은 대화에 보내고, 고친 칸만 받는다. 출력 전체를 다시 쓰지 않는다 | 같은 대화라 자료를 다시 보내지 않고, 고친 칸만 쓰므로 짧다(실측: 한 문장 고치기 8초) |
| 고친 내용 반영 | 고친 칸이 오면 화면의 그 자리만 바뀐다. 이전 글이 흐려지고 고친 글이 쓰이며 잠깐 강조된다 | 무엇이 고쳐졌는지 사용자가 본다 |
| 고치기 한도 | 고치기는 두 번까지 한다. 그 뒤에도 남은 위반은 그 칸을 쓴 그대로 두고 기록한다 | 고치기가 끝없이 돌지 않는다 |
| 큐 재실행 중지 | 계약 검사 실패로 끝난 작업은 작업 큐가 다시 돌리지 않는다 | 지금은 한 번의 실패가 호출 수를 최대 10배로 늘린다 |
| 모순 정리 | "적게 골라도 된다"는데 3개 미만을 거절하는 질문 생성처럼 프롬프트와 기준이 어긋난 곳을 맞춘다 | 모델이 지시대로 하면 거절된다 |
| 규칙 | 저장소 지침(AGENTS.md)에 이 원칙을 적고, 공급자 출력 형식에 글자 수 · 개수 · 형식 기준이 남아 있으면 실패하는 테스트를 둔다 | 새 호출을 만들 때 같은 실수가 다시 들어오지 않게 한다 |

## 개발 목표

- 체험 서버에서 지면을 만들 때 워커 로그에 "구조화 출력 거절"이 한 줄도 없다.
- 예산을 넘긴 칸이 있으면, 생성 화면 녹화에서 채운 글이 먼저 보이고 그 칸만 고친 글로 바뀌는 장면이 나온다.
- 호출 지점마다 기준을 어긴 출력을 넣는 테스트에서, 그 칸만 고치는 요청 한 번으로 결과가 나온다.
- `pnpm typecheck` · `pnpm test` · `pnpm test:infra` 통과.

## 범위 밖과 제약

- Claude Code 공급자 기준이다. codex는 맞추지 않는다.
- 생성 중 화면이 있는 곳은 지면 생성뿐이다. 다른 호출(질문 · 레시피 · 공고 분석 등)도 같은 방식으로 고치지만, 화면에는 지금처럼 끝난 결과가 보인다.
- 저장 계약(DB에 들어가는 모양)은 바꾸지 않는다.
- `feat/portfolio-design-first` 위의 별도 브랜치 · PR로 한다.
