# 배포 재시작에 끊긴 에이전트 답변의 중단 표시

## 개발 목표와 의도

> 이 채팅에서 "응답을 완료하지 못했습니다. 설정을 확인하고 다시 보내 주세요." 문구가 뜨며 에이전트 채팅 작업이 실패하는 문제 있음

2026-11-10 11:27(KST) 에이전트 화면에서 "내 프로젝트들을 3갈래로 정리해줘"를 보내자 「기록 목록 확인」 도구까지 돈 뒤 답변이 빈 채로 멈추고 위 문구가 떴다. 같은 시각 운영 배포가 API를 다시 시작했다. 설정에는 문제가 없었다. 재시작 때 서버가 답변을 만들던 Claude Code 프로세스까지 함께 꺼서, 서버는 이 실행을 "중단"이 아니라 "실패"로 기록했다. 사용자는 고칠 것이 없는 설정을 찾아 헤매게 된다.

배포가 실행 중인 답변을 끊는 일은 앞으로도 생긴다. 이번 변경은 끊긴 답변을 사실대로 "서버 실행이 중단되었습니다. 다시 보내 주세요."로 알리고, 실제 실패는 원인을 서버 로그에 남기게 한다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 재시작 중단 표시 | 배포로 API가 다시 시작될 때 실행 중이던 답변은 "서버 실행이 중단되었습니다. 다시 보내 주세요."로 끝나고 「다시 보내기」 버튼이 보인다. | 지금은 설정을 확인하라는 문구가 떠서, 다시 보내면 되는 상황을 사용자가 고장으로 오해한다. |
| 실패 원인 로그 | 답변이 실패하면 서버 로그(`api.log`)에 대화 번호와 오류 내용이 한 줄 남는다. | 지금은 오류를 버려서, 이번 원인도 요청 시각과 프로세스 번호를 맞춰 보며 추적해야 했다. |
| 서버 종료 방식 변경 | 서버를 멈출 때 종료 신호를 API 프로세스에만 보낸다. 답변을 만들던 프로세스는 API가 직접 정리한다(`KillMode=mixed`). | 종료 신호가 두 프로세스에 동시에 가면 어느 쪽이 먼저 끝나느냐에 따라 표시가 "중단"과 "실패"로 갈린다. |

## 개발 목표

- 실행 중에 API가 종료되면 대화의 실행 상태가 `interrupted`이고 문구가 "서버 실행이 중단되었습니다. 다시 보내 주세요."이다: 통합 테스트에서 확인한다.
- 종료와 무관한 실패는 지금처럼 `failed`로 남고, 서버 로그에 오류 한 줄이 찍힌다: 통합 테스트에서 확인한다.
- 운영 `systemctl show expresso-api -p KillMode`가 `mixed`를 보여 준다: 유닛 파일을 서버에 반영한 뒤 확인한다.

## 범위 밖과 제약

- 배포 중에도 답변을 끝까지 만들어 주는 것(종료 대기)은 하지 않는다. 답변은 최대 10분이 걸리고 systemd 종료 대기는 90초다.
- 종료와 무관한 실패 문구("설정을 확인하고")는 바꾸지 않는다.
- 유닛 파일은 배포 스크립트가 복사하지 않는다. 서버 반영은 머지 뒤 승인을 받고 손으로 한다.
- Worker 유닛도 같은 종료 방식이지만 작업이 BullMQ로 다시 시도되므로 이번에 바꾸지 않는다.
