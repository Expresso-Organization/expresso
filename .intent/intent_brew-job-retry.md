# 실패한 레시피·질문 작업의 다시 시도

## 변경 의도

레시피 만들기나 인터뷰 질문 만들기가 한 번 실패하면 버튼을 다시 눌러도 아무 일도 일어나지 않는다.
AI 처리 동의 없이 실패시킨 뒤 동의를 켜고 다시 누르면, 요청은 202로 접수되지만 워커는 작업을 받지 않고 화면은 "만들지 못했습니다"에 머문다.
요청: "실패했고 재시도 가능한 작업을 다시 제출하면 새로 큐에 올라가도록 고친다."

## 기능 목록

| 기능 | 끝나면 무엇이 달라지는가 | 왜 필요한가 |
|---|---|---|
| 재시도 가능한 실패의 다시 시도 | 지금은 눌러도 실패 문구 그대로다 → 끝나면 "차례를 기다리는 중"으로 바뀌고 워커가 다시 만든다 | 원인이 사라진 실패(동의 누락, AI 일시 오류)를 복구할 방법이 없다 |
| 레시피 · 질문 모두 적용 | 두 화면이 같은 방식으로 다시 시도된다 | 같은 제출 경로라 한쪽만 고치면 다른 쪽에 증상이 남는다 |

## 개발 목표

- 실패한 작업을 다시 제출하면 같은 작업이 대기(`queued`)로 돌아가고 큐에 새 작업이 한 건 올라간다.
- 다시 올라간 작업이 성공하면 상태가 `succeeded`가 된다.
- 연달아 두 번 눌러도 큐에는 한 건만 더 올라간다.
- 재시도 불가 실패(`BREW_INPUT_REJECTED` 등)와 성공한 작업은 지금처럼 같은 결과를 돌려주고 큐에 올라가지 않는다.
- 위 항목을 통합 테스트로 확인하고 `pnpm test` · `pnpm test:infra`가 통과한다.

## 범위 밖과 제약

- 웹 화면과 웹이 보내는 요청 키는 바꾸지 않는다. 브루 하나에 작업 하나를 유지한다.
- 성공한 레시피의 "구성 다시 만들기"도 같은 키라 지금은 기존 결과만 돌려준다. 이번에는 고치지 않는다.
- 구 MySQL 경로(`legacy-mysql-service.ts`)는 운영 경로가 아니라 고치지 않는다.

## 열린 질문

- 계약 거절(`CONTRACT_REJECTED`)은 주석에 "사용자가 다시 누르는 편이 낫다"고 적혀 있지만 재시도 불가라 다시 눌러도 재생만 한다. 후속으로 정한다.
- 큐 자체 재시도(최대 5회) 사이 몇 초 동안 작업이 "실패"로 보인다. 그때 누르면 작업이 두 번 돌 수 있다. 결과는 하나만 남지만 AI 호출이 한 번 더 쓰인다. 한계로 기록한다.
