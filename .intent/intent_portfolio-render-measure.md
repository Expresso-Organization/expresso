# 생성 중 브라우저 측정과 구성 재요청

## 변경 의도

포트폴리오 생성은 모델이 고른 구성을 그린 뒤 화면을 보지 않고 저장합니다. 포스터형 제목이 "아틀라 / 스"로 끊기거나 패널이 단 밖으로 나가는 결함은 개발용 검사 스크립트를 돌려서야 보였습니다. 이슈 #97의 2단계입니다.

요청: "2단계로 가자, 워커에 Chromium 설치"

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 생성 중 화면 측정 | 생성한 페이지를 실제 브라우저에서 390 · 926 · 1440px 너비로 열어 가로 넘침, 한 글자 줄바꿈, 단 이탈, 그림 설명 겹침, 늘어난 태그, 빠진 이미지를 잰다 | 지금은 이런 결함이 있어도 그대로 저장된다 |
| 구성 다시 요청 | 결함이 나오면 어느 너비의 어느 요소인지 적어 모델에게 구성을 다시 요청한다. 최대 2회이고, 결함이 줄어든 판만 채택한다 | 측정만 하고 고치지 않으면 결함은 그대로 남는다 |
| 측정 기록 | 생성 결과의 품질 기록에 너비별 측정 결과와 재요청 횟수가 남는다. 결함이 남아도 페이지는 저장되고, 남은 결함이 기록된다 | 어떤 결함이 남았는지 알아야 렌더러를 고칠 수 있다 |
| 워커 브라우저 | 배포가 워커 서버에 Chromium과 한국어 폰트를 준비하고, 워커는 브라우저 하나를 띄워 생성마다 재사용한다. 브라우저를 못 띄우면 측정을 건너뛰고 생성은 계속한다 | 측정하려면 실제 레이아웃 엔진이 있어야 한다 |
| 개발 검사와 같은 기준 | 개발용 검사 스크립트(`verify-token-kit.mjs`)가 제품의 측정 코드를 그대로 쓴다 | 두 곳의 기준이 갈리면 개발에서 통과한 결함이 운영에서 남는다 |

## 개발 목표

- 일부러 결함을 낸 구성으로 생성하면 재요청이 일어나고, 품질 기록에 재요청 전후 측정값이 남는다.
- 체험 서버에서 실제 생성 1회의 품질 기록에 너비별 측정 결과가 있다.
- 측정에 걸린 시간과 메모리를 재서 결함 문서(`portfolio-structured-pipeline-gaps.md`)에 적는다.
- `pnpm typecheck` · `pnpm test` · `pnpm test:infra`가 통과한다.

## 범위 밖과 제약

- 화면을 보고 위계 · 균형을 판단해 고치는 수선 에이전트(이슈 #97 7단계)는 하지 않습니다.
- 편집 화면에서 다시 그릴 때는 측정하지 않습니다. 모델을 부르지 않는 경로라 고칠 수단이 없습니다.
- PR #100(유형 선택) 위에서 작업합니다.
