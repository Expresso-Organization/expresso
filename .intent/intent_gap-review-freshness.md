# 보완점 정리 카드의 「다시 대조 필요」 표시와 PR 65 · 70 잔여 흡수

## 개발 목표와 의도

윤규현의 PR #65 · #70(P1~P8) 기능은 2026-10-15 `job-chat-rail` 작업으로 공통 에이전트 채팅에
이미 들어와 있다. 남은 차이를 표로 대조한 뒤 사용자가 "1, 2 흡수 · 3 폐기"로 정했다.

남은 차이 중 실제로 곤란한 것은 하나다. 공고 상세 우측 채팅에서 요건 대조와 보완점 정리를 받은
뒤, 근거로 쓰인 기록 「ETL 파이프라인 개선」의 본문을 고치고 대화를 다시 열면 요건 대조 카드에는
「다시 대조 필요」가 뜬다. 그런데 보완점 정리 카드는 지금 기록에 없는 예전 문장을 근거로 인용한
채 아무 표시가 없어서, 지금도 맞는 결과처럼 보인다. PR #70의 경력 Gap 분석 화면은 이 경우에
"분석 입력이 변경됐습니다"를 보였다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 보완점 카드 「다시 대조 필요」 | 보완점 정리 카드를 열 때, 그 정리 뒤에 공고 원문이나 근거 기록이 바뀌었으면 카드 머리에 요건 대조 카드와 같은 「다시 대조 필요」 표시가 붙는다. 바뀐 것이 없으면 아무것도 붙지 않는다 | 표시가 없으면 사용자는 예전 기록을 근거로 한 보완점을 지금 기록 기준으로 믿고 준비 계획까지 만들려 한다. 계획을 만들 때 서버가 거절하는 동작은 있지만, 카드만 보고는 그 이유를 알 수 없다 |
| 자료 목록 제목 두 줄 자르기 표준 속성 | 채팅 「자료 추가」 목록 결과 제목의 두 줄 자르기에 표준 CSS 속성을 함께 둔다. 화면은 지금과 같다 | 같은 파일의 공고 제목은 이미 표준 속성을 함께 쓰는데 이 자리만 빠져 있어 CSS 검사기가 경고한다 |
| AI 없이 재계획 입력칸 | 만들지 않는다. 남은 작업 재배치는 지금처럼 채팅으로 요청한다 | 2026-10-15 intent에서 316px 레일 폭 때문에 에이전트 도구로만 하기로 정했고, 계획 자체가 에이전트 대화에서만 생기므로 AI 없이 재계획만 하는 경우가 드물다 |

## 개발 목표

- 기록을 고친 뒤의 표시: 공고 상세 채팅에서 요건 대조 → 보완점 정리를 받고, 보완점 근거로 인용된
  기록 본문을 고친 뒤 대화를 다시 열면 보완점 카드에 「다시 대조 필요」가 보인다.
- 공고나 대조 근거가 바뀐 경우: 요건 대조 카드에 「다시 대조 필요」가 뜨는 상황이면 보완점 카드에도
  같이 뜬다.
- 바뀐 것이 없을 때: 아무 기록도 고치지 않았거나, 보완점과 상관없는 다른 기록만 고쳤으면 보완점 카드에
  표시가 없다.
- 다른 사용자는 남의 대화의 보완점 최신성을 조회할 수 없다(404).
- 자료 목록 제목은 지금처럼 두 줄에서 잘린다.

## 범위 밖과 제약

- PR #65 · #70을 닫는 것과 `codex/agent-chat` 브랜치 정리는 사용자가 결정한다. 이 작업에서 손대지 않는다.
- 대조 표에서 버리기로 한 나머지(로컬 Codex 런타임, 테마 스크립트 이동, 마크다운 `defer` 변경,
  발언 선택 체크박스, 일정 이력, 별도 컬렉션 · 마이그레이션)는 가져오지 않는다.
- 표시만 한다. 표시가 떠도 카드를 막거나 자동으로 다시 대조하지 않는다.
- 이번 변경 전에 만든 보완점은 근거 기록의 당시 내용을 저장해 두지 않았다. 그런 카드는 바탕이 된
  요건 대조의 최신성만 따라 표시한다.
- 새 컬렉션과 마이그레이션은 만들지 않는다.

## 열린 질문

1. 보완점 정리 뒤에 요건 대조를 새로 했고 그 대조가 최신이면, 예전 보완점 카드는 어떻게 보여야 하나.
   제안: 이번에는 표시하지 않는다. 그 경우 준비 계획을 만들면 서버가 "보완점을 먼저 다시
   정리하십시오"로 이미 거절하고, 문구도 「다시 대조 필요」가 아니라 「다시 정리 필요」가 맞아서 표시
   종류가 하나 늘어난다. 표시하기로 하면 spec에 문구 하나와 판정 하나가 추가된다.
   답(2026-10-27): 제안대로 표시하지 않는다.
