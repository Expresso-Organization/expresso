# 초안 먼저 전달과 스크린샷으로 지면 다듬기

## 변경 의도

빠른 전달과 시각 품질을 둘 다 잡으려 합니다. json-render로 초안은 빨리 나오지만, 지금은 측정 결함 재요청까지 끝나야 사용자가 지면을 받고, 결함이 없어도 밋밋한 지면은 그대로 나갑니다. 초안을 먼저 보여 주고, 그 뒤에 모델이 완성된 지면의 스크린샷을 보고 구성을 고쳐 새 판으로 바꿉니다. 이슈 #97의 7단계를 2단계 마무리에 당겨 옵니다.

요청: "json-render로 포트폴리오 초안은 빠르게 나오고, AI가 보고 수정해서 퀄리티를 높이는 식으로 해서 빠른 딜리버리와 시각적 퀄리티를 둘 다 잡기 위함이야"

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 초안 먼저 전달 | 생성은 구성을 한 번 고르고 그려 잰 뒤 바로 초안으로 저장하고 끝난다. 측정 결함 재요청은 다듬기 단계로 옮긴다 | 모델을 여러 번 부르는 동안 사용자가 기다리지 않는다 |
| 다듬기 | 초안이 저장되면 워커가 이어서 다듬는다. 측정 결함이 있으면 고치고, 지면을 1440px 첫 화면 · 1440px 전체 · 390px 전체로 찍어 모델에게 보여 위계 · 강조 · 여백 · 리듬 · 디자인과의 어울림을 고친 구성을 받는다 | 측정 수치로는 "보기 좋은가"를 판단할 수 없다 |
| 전후 비교 채택 | 고친 구성을 그려 재고, 결함이 늘지 않았으면 전후 스크린샷을 순서를 섞어 모델에게 보여 더 나은 쪽을 고르게 한다. 고친 쪽이 이기면 새 판으로 저장한다. 그사이 사용자가 지면을 고쳤으면 저장하지 않는다 | 고친 판이 항상 낫지 않고, 사용자 편집을 덮으면 안 된다 |
| 다듬는 중 표시 | 다듬기 화면(편집 화면)이 다듬는 동안 "AI가 화면을 보고 다듬고 있습니다"를 보이고, 끝나면 새 판으로 바뀐다 | 초안 뒤에 더 나은 판이 온다는 것을 사용자가 알아야 한다 |
| 다듬기 기록 | 모델이 지적한 점, 비교 결과와 이유, 채택 여부, 걸린 시간이 기록된다 | 반복되는 지적을 보고 렌더러 · 컴포넌트를 고친다 |
| 이미지 입력 | AI 호출이 이미지를 받는다. Claude Code 공급자에서 동작하고, 못 받는 공급자는 다듬기를 건너뛰고 이유를 남긴다 | 지금 AI 호출은 글만 보낸다 |

## 개발 목표

- 체험 서버 실제 생성 1회: 초안이 먼저 열리고, 다듬는 중 표시 뒤에 새 판(또는 초안 유지)과 다듬기 기록이 남는다.
- 같은 프로필의 초안과 다듬은 판 스크린샷을 나란히 놓은 비교 이미지를 만든다.
- 초안까지 걸린 시간과 다듬기에 걸린 시간 · 비용을 재서 결함 문서에 적는다.
- `pnpm typecheck` · `pnpm test` · `pnpm test:infra` 통과.

## 범위 밖과 제약

- 다듬기는 한 번(결함 수정 최대 2회 + 검토 1회 + 비교 1회)입니다. 시간 · 비용을 본 뒤 늘릴지 정합니다.
- 모델은 구성(Spec)만 고칩니다. 스크린샷은 저장하지 않습니다. 다듬기는 사용량을 따로 세지 않습니다.
- PR #104에 이어서 올립니다.
