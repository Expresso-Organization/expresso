# 설계서 핵심 내용 굵게 · 하이라이트 표시

## 문제

설계서(211쪽)는 문단이 길고, 강조가 장마다 고르지 않다. 5 · 7장은 굵게가 많지만(153 · 193곳) 3 · 4 · 8 · 10장은
문단 수에 비해 거의 없고(3장 문단 17개에 9곳, 8장 8개에 1곳), 하이라이트는 한 곳도 없다. 읽는 사람이 각 절의
결론을 찾으려면 문단을 끝까지 읽어야 한다.

## 원하는 결과

- 강조를 두 단계로 나누어 문서 전체에 같은 규칙으로 적용한다.
  - **하이라이트**(`<mark>`): 그 소절(■)의 결론 · 결정 한 문장. 소절마다 많아야 하나.
  - **굵게**(`<strong>`): 문장 안의 핵심 용어 · 수치 · 결정값. 한 문단에 많아야 두세 곳.
- 하이라이트 모양은 bean-50 바탕에 crema 밑줄(토큰 값만), 화면과 PDF가 같다.
- 글 자체는 한 글자도 바꾸지 않는다 — 표시만 더한다.
- 이미 굵게가 지나친 곳(5 · 7장)은 같은 규칙으로 줄인다.

## 영향 범위

`docs/졸업작품-설계서.html` 본문 문단 · 목록, CSS 한 곳, PDF. 결정 권한은 사용자(팀장).

## 제약

- 표 안 · 코드 · 그림 · 자동 생성 구간(8.2)은 건드리지 않는다.
- 태그를 걷어 낸 본문 글이 작업 전과 같아야 한다(스크립트로 검사).
- 장식용 그러데이션을 쓰지 않는다.

## 범위 밖

문장 고쳐 쓰기, md 초안(강조 표시는 HTML만).

## 열린 질문

1. 강조 밀도 — 답: 기본안(2026-10-06 사용자 결정): 하이라이트는 소절당 0–1문장, 굵게는 문단당 0–3곳. 5 · 7장의 지나친 굵게는 줄인다.
2. 하이라이트 색 — 답: 기본안 1안(2026-10-06 사용자 결정): bean-50 바탕 + crema 밑줄. 다른 안: crema 형광펜(더 진함).
