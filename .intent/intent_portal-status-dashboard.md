# 개발 포털 진행 현황 대시보드

## 변경 의도

제안서와 설계서가 정한 작업 범위 가운데 지금 무엇이 끝났고 무엇이 남았는지를 팀이 함께 볼 자리가 없다. 개발 포털(dev.expresso.ai.kr)에는 문서 · 라이브러리 · 발표 자료 탭만 있다. 진행 상황은 각자 PR과 코드를 열어 봐야 알 수 있다.

> "개발포털에 배포해서 진행 상황을 공유하고 확인할 수 있는 대시보드형 페이지를 만들라는 거야" · "shadcn을 적극적으로 활용해서 만들어"

2026-10-25에 main 코드를 조사한 판정(사용자 기능 150개 중 완료 12)이 지금은 대화 안에만 있다.

## 기능 목록

| 기능 | 끝나면 무엇이 달라지는가 | 왜 필요한가 |
|---|---|---|
| 포털 「진행 현황」 탭 | 지금은 상단에 문서 · 라이브러리 · 발표 탭만 있다 → 끝나면 「진행 현황」 탭을 눌러 대시보드가 열리고, 주소(`#/status`)를 보내면 같은 화면이 열린다 | 진행 상황을 공유할 고정된 주소가 있어야 팀이 같은 화면을 보고 말한다 |
| 요약 지표와 일정 | 첫 화면 위쪽에 완료 · 부분 · API만 · 미구현 개수 카드와 15주 일정 막대가 있고, 오늘 위치에 세로 선이 그어진다 | 지금 몇 주차이고 남은 기간에 무엇을 해야 하는지가 먼저 보여야 한다 |
| 마일스톤 · 도메인 진척 | M1~M4 카드에 항목별 판정이 보인다. 도메인 D1~D12는 판정 비율 막대로 보이고, 막대를 누르면 아래 표가 그 도메인으로 걸러진다 | 어느 마일스톤 · 도메인이 늦는지 한눈에 비교해야 우선순위를 정한다 |
| 담당자 필터와 상세기능 표 | 담당자를 고르면 그 사람의 기능 · 남은 작업 · 막힌 자리만 남는다. 표의 행을 펼치면 빠진 것과 근거 파일이 보인다 | 각자 자기 몫을 찾으려고 150행을 훑지 않게 한다 |
| AI학습서버 · 관리자 · 열린 PR · 남은 작업 | 학습 파일럿 지표, 관리자 기능 판정, 열린 PR 목록, 주차별 남은 작업이 각각 탭 · 표로 보인다 | 서비스 기능 밖의 일(모델 · 운영 · 진행 중인 PR)도 같은 자리에서 확인해야 빠뜨리지 않는다 |
| 데이터 갱신 명령 | 판정은 데이터 파일(`docs/status/status.json`) 하나에 있다. 명령 하나(`node scripts/status/refresh-status.mjs`)로 기준 커밋과 열린 PR 목록을 다시 받는다 | 화면을 고치지 않고 숫자만 갱신할 수 있어야 현황이 낡지 않는다 |
| 앞서 만든 진행 현황 문서 제거 | 지금은 `docs/작업-범위와-진행-현황.html` 문서가 같은 내용을 담고 있다 → 끝나면 지워지고 대시보드 하나만 남는다 | 같은 현황이 두 곳에 있으면 한쪽이 먼저 낡는다 |

## 개발 목표

- 포털 상단의 「진행 현황」 탭을 누르면 대시보드가 열리고, `#/status` 주소로 바로 들어와도 같은 화면이 나온다.
- 포털 테마를 밝게 · 어둡게 바꾸면 대시보드도 같은 테마로 바뀐다.
- 담당자를 「채서현」으로 고르면 D3 · D5 기능과 AI학습서버 작업만 남는다.
- 화면의 카드 · 표 · 탭 · 선택 상자 · 차트는 shadcn 컴포넌트이고, 색은 Expresso 토큰과 같다.
- main에 머지하면 기존 포털 배포 워크플로가 대시보드까지 발행한다.

## 범위 밖과 제약

- 판정을 코드에서 자동으로 다시 매기지 않는다. 판정은 사람이 데이터 파일에서 고친다.
- 제품 웹(services/web)과 루트 의존성 잠금 파일은 건드리지 않는다. 잠금 파일이 바뀌면 운영 웹 배포가 함께 돈다.
- 포털 배포 서버의 발행 스크립트는 바꾸지 않는다.

## 열린 질문

- 포털 발행에는 빌드 단계가 없다. shadcn은 React 빌드가 필요하다. 원본은 `services/dev-portal/status/`에 두고 빌드 결과를 `docs/status/`에 커밋하는 방식으로 진행해도 되는가?
