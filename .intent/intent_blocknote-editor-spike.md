# 커리어 기록 본문 BlockNote 교체 검증

## 개발 목표와 의도

커리어 기록 본문 편집기는 Tiptap 위에 슬래시 메뉴 · 블록 손잡이 · 저장 변환 · 동기화를 직접 만들어 붙였습니다. 2026-10-28 점검(`docs/architecture/career-record-editor-status-2026-10-28.md`)에서 이 직접 만든 부분이 결함의 출처였습니다. 슬래시 메뉴로 표를 넣은 기록은 다시 열면 탭이 멈췄습니다. `Shift+Enter` 줄바꿈은 새로고침하면 사라졌습니다. 새 편집기에 쓴 본문은 공고 매칭과 포트폴리오 생성에 전달되지 않았습니다.

요청: "마크다운 편집기 우리가 다 구현하는 게 아니라 웹용 오픈소스 마크다운 편집기를 가져와 붙이는게 더 나을 것 같네"

노션형 오픈소스 편집기 BlockNote로 본문 편집기를 바꿀 수 있는지 실제 코드로 확인합니다. 이번 작업은 교체 여부를 정하는 검증입니다. 결과는 「교체한다 / 하지 않는다」 판단과 근거를 적은 보고서입니다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 기록 패널의 BlockNote 본문 | 기록을 열면 BlockNote 편집기가 본문 자리에 뜹니다. `/`로 블록 메뉴를 열고, 블록 왼쪽 손잡이로 끌어 옮기고, 글자를 선택하면 서식 툴바가 뜹니다. 표 · 줄바꿈 · 밑줄을 쓰고 새로고침해도 그대로 열립니다. | 지금 결함 대부분이 직접 만든 메뉴 · 손잡이 · 변환에서 나왔습니다. 라이브러리가 이 부분을 대신하는지 화면에서 봐야 판단할 수 있습니다. |
| 본문 이미지 넣기 | 본문에 이미지를 끌어 놓거나 블록 메뉴에서 고르면 업로드되고 바로 보입니다. | 지금 편집기는 본문 이미지를 올릴 수 없습니다. 기존 미디어 업로드에 붙는지 확인해야 합니다. |
| 기존 기록 옮기기 | 이미 있는 기록 본문을 BlockNote 형식으로 바꾸고, 블록 종류별로 무엇이 남고 무엇이 빠졌는지 표로 보고합니다. | 사용자 기록을 잃으면 교체할 수 없습니다. 실제 기록으로 손실을 재야 합니다. |
| 동시 편집 병합 | 같은 기록을 두 탭에서 열고 서로 다른 문단을 동시에 고치면 두 수정이 모두 남습니다. 연결이 끊겼다 돌아오면 그사이 입력이 저장됩니다. | 지금은 한쪽 문서 전체가 덮어써집니다. 기존 저장 통로(WebSocket과 저장 기록)를 그대로 쓰면서 병합되는지 확인해야 합니다. |
| 본문을 매칭 · 생성에 전달 | BlockNote에서 쓴 본문이 기록 목록 미리보기와 공고 매칭 · 포트폴리오 생성이 읽는 본문 텍스트(`bodyMd`)에 들어갑니다. | 지금은 새 본문이 이 기능들에 전달되지 않습니다. 교체 뒤에도 같은 문제가 남는지 확인해야 합니다. |
| 검증 보고서 | 다섯 항목의 결과, 교체 판단, 교체 시 남는 작업(AI 제안 · 디자인 맞춤 등)과 규모를 문서로 남깁니다. | 교체는 큰 작업입니다. 판단 근거가 문서로 남아야 다음 작업 범위를 정할 수 있습니다. |

## 개발 목표

- 검증 서버에서 기록을 열고 표 · 줄바꿈 · 밑줄 · 이미지를 넣은 뒤 새로고침하면 같은 모습으로 열립니다.
- 체험 DB 복사본의 기록 전부를 옮긴 결과표가 보고서에 있고, 사라진 본문 글자 수가 기록별로 적혀 있습니다.
- 두 탭에서 동시에 다른 문단을 고친 뒤 새로고침하면 두 수정이 모두 보입니다.
- BlockNote에서 쓴 문장이 기록 목록 카드 미리보기에 보입니다.
- 보고서에 교체 판단과 남는 작업 목록이 있습니다.

## 범위 밖과 제약

- 이번 결과물은 검증용 브랜치(`spike/blocknote-editor`)와 보고서입니다. 편집기 코드는 `main`에 합치지 않습니다. 교체하기로 하면 새 intent로 다시 시작합니다.
- AI 변경 제안은 BlockNote에서 다시 만들지 않습니다. 옮길 때 드는 작업만 보고서에 추정합니다.
- 속성 · 뷰 · 수식 · 관계는 건드리지 않습니다.
- 운영 · 체험 DB는 쓰지 않습니다. 복사본 DB에서만 검증합니다.
- 유료 · GPL 패키지(`@blocknote/xl-*`)는 쓰지 않습니다.

## 열린 질문

- 결과물 범위: 보고서만 `main`에 합치고 편집기 코드는 브랜치에 둡니다. 2026-10-28 사용자가 확정했습니다.
