# 포트폴리오 제작 흐름의 설계서 6단계 복원

## 문제

포트폴리오 만들기가 설계서(제안서 기준으로 맞춘 판)와 다른 흐름으로 돌아갑니다. 설계서 2.1 이용 절차는 3–8단계를 제작 흐름으로 정의하고, 화면 상단에 여섯 단계로 표시합니다. 순서는 공고 분석(01) → 재료 고르기(01b) → AI 대화(02) → 레시피(02b) → 디자인 선택(03) → 다듬기(04)입니다. 그런데 사이드바·홈의 "새 포트폴리오"는 v2 흐름(디자인 → 레시피 → 생성, 2026-08-30 기획)으로 들어갑니다. 이 흐름에서는 공고 분석·재료 고르기·AI 대화를 거치지 않습니다.

두 흐름이 섞여 있어서 현재 main에서는 다음 문제가 있습니다(2026-10-15 조사).

- **생성을 시작할 수 없습니다.** 생성을 실행하는 화면(`DesignPicker`)은 `?legacy=1`일 때만 열리는데, 그 주소로 가는 링크가 없습니다. 대신 열리는 v2 디자인 카탈로그(38종)는 선택을 저장만 하고 생성하지 않습니다.
- **두 화면을 계속 오갑니다.** 레시피 화면은 디자인 선택이 있으면 v2 "레시피"로 바뀌고, 다음 버튼이 다시 디자인으로 돌아갑니다. 디자인 카탈로그의 다음 버튼은 레시피로 갑니다.
- **디자인 선택이 생성에 반영되지 않습니다.** 브루에 저장한 디자인 시스템(`designSystemRevisionId`)을 생성 경로가 읽지 않습니다.
- **온보딩 링크가 깨져 있습니다.** "첫 포트폴리오"의 공고 고르기 링크(`/brew/toss/analyze`)는 404입니다.

## 원하는 결과

- "새 포트폴리오" 입구(사이드바, 상단 메뉴, 홈 카드, 편집기, 온보딩 첫 포트폴리오, `/portfolio/new`)가 모두 공고 고르기 화면(`/brew/new`)으로 갑니다. "목표 없이" 시작도 같은 여섯 단계의 흐름을 탑니다.
- 제작 흐름의 모든 화면이 같은 여섯 단계(공고 분석 · 재료 고르기 · AI 대화 · 레시피 · 디자인 선택 · 다듬기)를 상단에 표시합니다. 각 화면의 "다음"은 바로 다음 단계로 갑니다. 두 화면을 오가는 경로는 없습니다.
- 디자인 선택(7단계)에서 38종 디자인 시스템 카탈로그 중 하나를 고르고 생성을 실행할 수 있습니다. 생성 화면의 진행 상황이 보이고, 끝나면 다듬기(편집기)로 갑니다.
- 고른 디자인 시스템이 생성 결과에 반영됩니다. 지면의 배경·글자·강조 색, 서체 계열(serif·sans), 전체 배치가 그 디자인 시스템의 토큰에서 나옵니다. 어떤 디자인 시스템으로 생성했는지 생성 기록에 남습니다.
- 흐름 순서와 입구, 디자인 선택에서 생성으로 가는 경로, 디자인 시스템 → 생성 스타일 변환을 테스트로 고정합니다.
- 체험 서버에서 새 포트폴리오 → 공고 분석 → … → 디자인 선택 → 생성 → 다듬기를 실제로 한 번 끝까지 진행해 확인합니다. 화면 기록을 보고에 붙입니다.

## 영향 범위

- 포트폴리오를 만드는 모든 사용자.
- 웹: `services/web`의 제작 위저드(`brew/new`, `brew/[brewId]/*`, `portfolio/new`, 입구 링크, `WizardShell`).
- 백엔드: 생성 요청 계약(`packages/contracts`), 생성 모듈, 지면 생성 스타일 구성(`PageService`), 디자인 시스템 모듈.
- 결정 권한: 박민재.

## 제약

- 설계서 2.1 이용 절차와 화면 목록(01 · 01b · 02 · 02b · 03 · 04)을 기준으로 합니다. 7단계 화면은 38종 디자인 시스템 카탈로그를 씁니다(2026-10-15 결정).
- v2 코드(`DesignCatalog`, 디자인 선택 저장 API, design-systems 모듈)는 지우지 않고 7단계에서 다시 씁니다. 웹 위저드의 `portfolio-v2` 단계 분기만 없앱니다.
- 이미 만든 브루·포트폴리오·배포 스냅샷을 깨지 않습니다. 디자인 선택이 저장된 기존 브루도 여섯 단계 흐름으로 열립니다.
- 데이터 마이그레이션 없이 진행하는 것을 우선합니다. 필요하면 spec에서 이유를 적습니다.
- PR 기준 브랜치는 `main`입니다(#56·#57·#67과 다른 영역).

## 범위 밖

- 디자인 시스템의 나머지 토큰(서체 패밀리 이름, 간격, 모양, 모션, 컴포넌트 규칙)을 렌더러에 반영하는 일. 이번에는 구조화 렌더러가 이미 받는 색 3개·서체 계열·배치까지만 연결합니다.
- 재료 고르기의 모델 B, 공고 추천의 모델 A 연동(AI학습서버 과제).
- 각 단계 화면의 내용과 디자인 개편. 흐름 연결과 7단계의 생성 연결만 합니다.
- v2 기획서(`docs/architecture/portfolio-creation-flow-v2.md`)의 블루프린트 편집, 생성 후 공고 맞춤 기능.
- 레거시 `DesignPicker`(템플릿 미리보기 선택) 코드 삭제. 다른 경로에서 쓰지 않으면 spec에서 처리 방법을 정합니다.

## 열린 질문

1. "목표 없이" 시작한 브루는 공고 분석 단계에서 무엇을 보여 주는가. 설계서 화면 01에 "목표 없이" 입구가 있으므로 같은 화면에서 처리하는 방향으로 spec에서 정합니다.
