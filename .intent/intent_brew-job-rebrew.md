# 거절·성공한 레시피·질문 작업의 다시 만들기

## 변경 의도

재시도 가능한 실패는 앞선 변경(`fix/brew-job-retry`)으로 다시 돌게 됐다. 하지만 버튼이 있는데도 아무 일도 하지 않는 자리가 셋 남아 있다.
재료가 모자라 거절되면 화면은 "기록을 더 고른 뒤 다시 시도해 주세요"라고 안내하지만, 기록을 더 고르고 눌러도 같은 거절이 다시 보인다.
레시피 화면의 "구성 다시 만들기"는 눌러도 기존 레시피를 그대로 돌려준다.
계약 거절(`CONTRACT_REJECTED`)도 주석과 달리 다시 눌러도 같은 결과만 나온다.

## 기능 목록

| 기능 | 끝나면 무엇이 달라지는가 | 왜 필요한가 |
|---|---|---|
| 거절 뒤 다시 누르기 | 지금은 같은 거절이 다시 보인다 → 끝나면 새 작업이 돌아 바뀐 재료로 다시 판단한다 | 화면이 시키는 대로 고쳐도 진행할 수 없다 |
| 구성 다시 만들기 | 지금은 기존 레시피 그대로다 → 끝나면 새 레시피 버전(v2, v3…)이 만들어진다 | 버튼이 약속한 기능이 동작하지 않는다 |
| 재시도 불가 실패의 큐 재시도 중단 | 지금은 거절된 작업도 큐가 다섯 번까지 다시 돌린다 → 끝나면 한 번에 멈춘다 | 같은 답에 AI 호출만 더 쓴다(주석의 의도와 같게) |
| 큐가 다시 돌리는 동안 "기다리는 중" 표시 | 지금은 큐 자체 재시도 사이 몇 초간 "만들지 못했습니다"와 버튼이 보인다 → 끝나면 "차례를 기다리는 중"이 이어진다 | 이 틈에 누르면 같은 작업이 둘 생겨 레시피 버전이 하나 더 만들어진다 |

## 개발 목표

- 거절된 작업이 있는 브루에서 다시 누르면 새 작업이 생기고 큐에 올라간다.
- 성공한 레시피에서 "구성 다시 만들기"를 누르면 새 레시피가 만들어진다.
- 같은 화면에서 버튼을 두 번 눌러도 작업은 하나만 생긴다.
- 재시도 불가로 분류된 실패는 큐가 다시 돌리지 않는다.
- 위 항목을 단위·통합 테스트로 확인하고 `pnpm typecheck` · 백엔드 `test` · `pnpm test:infra`가 통과한다.

## 범위 밖과 제약

- 서버의 같은 키 재생 규칙은 그대로다. 같은 요청을 다시 보내면(네트워크 재전송) 지금처럼 같은 결과를 돌려준다. 새 작업인지는 화면이 마지막으로 본 작업으로 정한다.
- 계약과 화면 문구는 바꾸지 않는다.
- 인터뷰 질문은 브루당 한 세션이라, 질문이 이미 있으면 새 작업도 기존 세션을 돌려준다.
