# 커리어 기록 감사 결함 전체 수정

## 개발 목표와 의도

2026-11-02 커리어 기록 감사(`origin/main` `81988a33`)에서 높음 13건과 중간 · 낮음 결함이 나왔다. 그중 일부는 사용자가 쓴 글을 지우거나 깨뜨린다. 운영(expresso.ai.kr)에서는 본문 저장 연결이 아예 열리지 않는다. 검증 서버에서는 표 · 줄바꿈을 쓴 본문이 새로고침 한 번 뒤 「외부에서 바뀐 본문」 한 줄로 바뀌었다. 다른 문단에 AI 「문장 다듬기」를 적용하자 빨간 글자색이 사라졌다. 이 변경은 감사 결함을 단계별로 모두 고치고, 같은 결함이 다시 생기면 시험이 잡게 한다. #141(저장된 뷰 · 휴지통)이 이미 main에 들어왔으므로 그 위에서 시작하고, #141이 닫은 항목은 다시 확인만 한다.

사용자의 말 — 「전부 고치는 게 목표야. 단계적으로 진행하고, 최종 완료까지 계속 진행해」

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 운영 본문 저장 연결 | 운영에서 기록을 열면 머리말이 「저장됨」이 되고 입력이 새로고침 뒤에도 남는다. 배포 스크립트가 배포 끝에 저장 연결이 열리는지 확인한다. | 지금 운영에서는 본문 입력이 서버에 하나도 가지 않는다. |
| 기록 전체 페이지 스크롤 | 기록을 「넓게 보기」로 열면 휠 · 트랙패드로 속성 아래 본문과 AI 도크까지 내려간다. | 속성이 긴 기록은 전체 페이지에서 본문에 닿을 수 없다. |
| AI 편집 메뉴 표시 | 글을 고르고 「AI 편집」을 누르면 다듬기 · 짧게 같은 항목이 툴바 아래에 보인다. 고르면 제안이 화면에 들어온다. | 지금은 메뉴가 툴바에 잘려 눌러도 아무 일이 없어 보인다. |
| 끊긴 연결 회복 | 편집기를 오래 열어 둔 뒤 서버가 재시작되거나 노트북이 잠들어도 다시 연결되어 밀린 입력이 저장된다. 저장되지 않은 입력이 있으면 탭을 닫을 때 경고가 뜬다. 상태 표시는 실제 저장 상태와 같다. | 연 지 15분이 지나면 다시 연결되지 않아 입력이 사라진다. |
| 본문 원본 하나 | 인터뷰 재답변처럼 편집기 밖에서 본문을 바꾸면 열린 편집기에 바로 들어오고 이력에 복원 지점이 남는다. 다음에 열어도 편집기에서 쓴 글이 지워지지 않는다. | 지금은 다음에 열 때 편집기 본문 전체가 바깥 글로 덮인다. |
| Markdown 읽기 | `R&D`, `**굵게**`, `[링크](…)`, 들여쓴 목록이 든 기록을 처음 열어도 그대로 보이고, 공고 매칭 · 포트폴리오 생성에도 깨지지 않은 글이 간다. | 지금은 `R&amp;D`로 바뀌어 저장되고 서식 기호가 글자로 남는다. |
| AI 적용이 다른 블록을 지키기 | AI 제안을 적용해도 고르지 않은 블록의 색 · 정렬 · 들여쓴 자식 · 토글 내용이 그대로다. 되돌리기 뒤 다시 적용하면 실제로 다시 바뀐다. 그사이 사람이 고친 블록은 덮지 않고 충돌로 알린다. | 지금은 다른 블록의 서식이 사라지고, 사람이 고친 글을 덮는다. |
| 이력 복원 안전장치 | 「복원」을 누르면 확인을 한 번 묻고, 복원 직전 상태가 이력에 「복원 전」으로 남는다. | 지금은 한 번 클릭으로 최근 최대 10분 입력이 되찾을 수 없게 사라진다. |
| 긴 본문 | 5만 자가 넘는 글을 붙여 넣어도 기록이 다시 열리고, 목록이 깨지지 않는다. 한도를 넘으면 붙여 넣는 자리에서 이유가 보인다. | 지금은 그 기록이 열리지 않고 그 카테고리 목록 전체가 500이다. |
| 파일 올리기 | 8MB까지의 그림을 본문에 끌어 놓으면 올라간다. 메뉴에는 실제로 올릴 수 있는 블록만 남는다. | 지금은 1MB가 넘으면 실패하고, 올릴 수 없는 파일 · 동영상 메뉴가 보인다. |
| 많은 기록 · 속성 변경 | 기록이 100건을 넘는 카테고리에서 속성 종류를 바꾸거나 지워도 값이 옮겨지고, 그 뒤 기록을 고칠 수 있다. 50건이 넘는 카테고리는 끝까지 내려 모든 기록을 본다. | 지금은 속성 변경 뒤 모든 기록 저장이 400이고, 51번째 기록부터 안 보인다. |

| 표 · 패널 정합성 | 표 · 보드에 수식 · 롤업 값이 보이고, 숫자 셀을 고친 값이 저장되고, 키보드로 팝업을 닫고 33번째 행까지 이동한다. 기록 복제는 지금 본문을 복사하고, 카테고리 이동 미리보기는 속성 이름을 보여 준다. | 지금은 계산 값이 「—」이고 키보드 · 복제 · 이동 화면이 잘못 동작한다. |
| 서버 정합성 | 뷰 이름이 겹치거나 입력이 틀리면 500 대신 이유가 오고, 시각 정렬 2쪽 · 관계 필터 · 카테고리 이동 뒤 계산 · 휴지통 뒤 롤업이 맞는다. | 지금은 같은 뷰를 두 번 복제하면 500이고, 일부 뷰 쪽이 기록을 빠뜨린다. |
| 화면 문구 · 동작 없는 단추 정리 | 설명문 · 동작 없는 꺾쇠 · 탭을 지우고, 「아래에 새 기록」은 아래에 만든다. 패널은 Escape로 닫히고 포커스를 돌려준다. | 화면 원칙에 어긋나고, 눌러도 아무 일 없는 단추가 있다. |
| 회귀 시험 | 위 장면마다 E2E · 통합 시험이 하나씩 생기고, 잘못된 동작을 기대값으로 둔 시험 두 개를 고친다. | 지금 시험은 모두 통과하면서 위 결함을 하나도 잡지 못했다. |

## 개발 목표

- 운영: 배포 뒤 기록 본문에 쓴 글이 새로고침 뒤 남고, `deploy.sh`가 WebSocket 핸드셰이크 101을 확인한다.
- 검증 서버: 감사 보고서의 재현 절차(H2 · H3 · H4 · H5 · H6 · H7 · H8 · H12)를 다시 따라 하면 결함이 나오지 않는다.
- 많은 데이터: 기록 101건 카테고리에서 속성 종류를 바꾼 뒤 아무 기록 제목을 고쳐도 저장된다.
- 시험: `pnpm typecheck` · `pnpm test` · `pnpm test:infra` · 커리어 E2E가 통과하고, 각 결함의 재현 시험이 포함된다.
- 단계마다 커밋을 나눠 같은 PR에 올린다. 단계가 끝날 때마다 푸시해, 중간에 멈춰도 끝난 단계를 리뷰 · 병합할 수 있다.

## 범위 밖과 제약

- 운영 서버 nginx 파일과 `.env`는 저장소에서 고칠 수 없다. 저장소 설정 · 배포 확인 · 적용 절차를 만들고, 서버 적용은 사용자가 한다(또는 사용자 승인 뒤 ssh로 한다).
- 비공개 기록 본문 그림을 인증 없이 주는 `GET /v1/media/:id`는 공개 포트폴리오가 같은 주소를 쓰므로 이번에 막지 않는다. 열린 질문 2.
- 열린 #153(Spring 전환)과 쓰기 경로가 겹친다. 이 변경은 지금 main의 Fastify 경로를 고친다. #153은 이 변경 뒤에 다시 맞춰야 한다.
- 설계 문서가 범위 밖으로 둔 노션 기능(동기화 블록, 댓글 등)은 하지 않는다.

## 열린 질문

1. 운영 nginx 적용: 저장소 설정을 고친 뒤 서버 적용을 사용자가 할지, 승인 뒤 제가 ssh로 할지. 기본값은 사용자 적용 절차를 문서로 남기는 것이다.
2. 미디어 공개 정책: 기록 본문 그림과 공개 포트폴리오 그림을 나눠 서명 주소로 바꿀지. 기본값은 이번 범위 밖이다.
3. 노출 블록: 글자색 · 정렬 · 토글 · 제목 4–6을 저장 계약에 넣어 살릴지(기본), 메뉴에서 뺄지.
