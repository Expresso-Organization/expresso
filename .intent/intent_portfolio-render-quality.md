# 생성 포트폴리오의 원본 렌더링 결함 수정

## 문제

PR #55로 모델이 수집 원본(히어로 32개, 사례 6개)을 골라 포트폴리오를 만듭니다. 배포된 세 결과(`library-selection-2026-10-07`)를 1440px로 확인하면, 원본을 고른 지면이 그렇지 않은 지면보다 완성도가 낮습니다.

- **사례 항목표가 서식 없이 나온다.** 원본을 고른 사례는 `CaseTechnical`·`CaseProcess`·`CaseEssay` 구분을 버리고 맨 `<dl>`로 역할·기간·문제 정의를 출력합니다. 브라우저 기본 들여쓰기가 그대로 보입니다(`renderer.tsx` 205–251행).
- **원본의 샘플 장식이 남는다.** 샘플 문구는 지우지만 문구를 담던 상자와 샘플 수치로 그린 그림은 남습니다. Feature 1 카드마다 빈 알약 모양 상자가, Feature 4 카드에는 원본 수치 `[40, 60, 35, 80, 55, 90, 70]`로 그린 막대 그래프·도넛·선이 보입니다. 입력에 없는 데이터를 그래프 모양으로 보여 줍니다.
- **히어로의 이름이 이미지 속 글자와 겹친다.** 히어로가 첫 프로젝트 이미지를 `backgroundImage`로 깔고 `brightness(.38)`로 어둡게 합니다. 이미지 안의 제목("계절의 언어", "CITY CLIMATE / OPEN NOTE 01")이 이름·내비게이션과 같은 자리에 겹칩니다.
- **관련 자료 링크가 번호로만 표시된다.** "관련 자료 1 ↗"는 어떤 자료인지 알려 주지 않습니다. 입력의 근거 항목에는 제목이 있습니다.
- **사례 이미지가 지나치게 크다.** 원본 사례의 이미지는 1440px 화면에서 약 1,300px 폭으로 표시되고, 사례 하나가 약 2,000px 높이입니다. 원본이 아닌 사례에는 이미지 높이 상한이 있지만 원본 사례에는 적용되지 않습니다.
- **Feature 슬롯 수가 숫자로 고정돼 있다.** 원본에 연결한 항목 수(Feature 1은 5개, Feature 4는 3개)를 `slice(5 : 3)`로 적어 두어, 원본 변환 결과가 바뀌어도 함께 갱신되지 않습니다.
- 현재 검증(`verify-structured-profiles.mjs`, `check-collected-runtime.mjs`)은 위 결함을 하나도 잡지 못했습니다.

## 원하는 결과

- 원본을 고른 사례도 사례 유형별 항목 표현(기술형=항목표, 과정형=단계, 기사형=설명 묶음)으로 그려지고, 기본 들여쓰기가 남은 `dd`가 없다.
- 실행 원본 38개의 렌더링 결과에 텍스트가 없는 샘플 상자와 샘플 수치로 그린 그래프 요소가 없다.
- 히어로는 배경 이미지를 유지하고, 이름·자기 정의 뒤에 블러 판을 깔아 이미지 속 글자 위에서도 읽힌다.
- 관련 자료 링크가 근거 항목의 제목을 표시한다.
- 원본 사례의 이미지가 원본이 아닌 사례와 같은 크기 상한을 따른다.
- Feature 슬롯 수를 원본 변환 결과에서 읽고, 코드에 숫자로 적지 않는다.
- 검증 스크립트가 위 항목을 측정해 위반 시 실패한다.
- 배포된 세 결과와 같은 저장 Spec을 다시 렌더링한 결과를 새 실행 기록으로 남기고 개발 포털에 배포한다. 렌더러 수정만 비교하기 위해 모델은 다시 호출하지 않는다.

## 영향 범위

- 생성 포트폴리오를 보는 사용자와 채용 담당자. 제품 미리보기, 공개 포트폴리오, 내보내기, 개발 포털 비교 페이지가 모두 같은 서버 렌더러를 씁니다.
- `packages/portfolio-renderer`(renderer·library·source-jsx·styles·collected), `scripts/library/renderer`(빌드·검증), `docs/library/previews/portfolio/runs/`.
- 결정 권한: 박민재.

## 제약

- Spec 계약과 저장된 Spec을 바꾸지 않는다. 기존 포트폴리오가 같은 Spec으로 다시 그려져야 한다.
- 원본 코드를 손으로 고치지 않는다. 보관된 registry JSON과 SHA-256 검증을 유지하고, 변환은 빌드 스크립트와 렌더 시점 바인딩에서 한다.
- 입력에 없는 수치·그림을 만들지 않는다. 샘플 장식은 대체하지 않고 제거한다.
- 저장 HTML은 JavaScript 없이 표시되어야 하고, 모션 감소 설정을 따른다.

## 범위 밖

- 실행 원본 확대(project-grid 25개, experience·evidence 계열 등 본문 섹션 연결). 다음 intent에서 다룹니다.
- 모델 프롬프트·선택 기준 변경과 모델 재생성.
- 래스터 이미지 안 글자를 판독하는 검사. 이미지 내용은 검증하지 못한다는 한계로 기록합니다.
- 편집기 UI 변경. 히어로 배경 이미지를 편집기에서 바꾸는 기능은 후속 작업으로 둡니다.

## 열린 질문

1. 히어로 배경 이미지를 어떻게 처리할까요?
   - 답(2026-10-09): 기본 배경 이미지를 유지하고 이름 뒤에 블러 처리로 가독성을 확보한다. 이미지는 향후 편집기에서 수정할 수 있게 한다.
2. 사례 PNG 좌상단(0, 20)의 작은 검은 사각형이 DOM 요소인지 캡처 잔상인지 확인이 필요합니다. 구현 중 확인하고, 요소이면 같은 작업에서 제거합니다.
