# 화면 문구 어휘 표준화

## 개발 목표와 의도

설정 화면의 「지면 밝기」처럼, 일반 웹사이트에서 쓰지 않는 말이 화면 곳곳에 있다. 요청 원문: "설정에서 지면 밝기 -> 테마로 수정 필요. 이처럼 일반적이지 않고 어색한 문구들을 일반적인 웹사이트에서 제공되는 어휘에 맞게 전수 조사할 것".

웹 앱의 한글 문구 약 2,000개를 전수 조사했다. 사용자가 보는 화면에서 어색한 말은 여섯 묶음이다. 설정 화면의 「지면 밝기」는 첫 번째 묶음에 든다. 이 묶음별로 표준 웹 어휘로 바꾸고, 바꾸지 않는 것과 이유를 함께 남긴다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 설정 테마 문구 | 설정의 「지면 / 지면 밝기」가 「화면 / 테마」로 보인다. 선택지는 밝게 · 어둡게 · 시스템 그대로다 | 요청 원문의 첫 항목이다. 「테마」는 다른 웹사이트 설정과 같은 이름이라 찾기 쉽다 |
| 인쇄 용어 교체 | 「지면」은 「페이지」, 「판」은 「버전」, 「칼럼」은 「열」, 「액자」는 「프레임」, 「서체」는 「글꼴」, 「쪽」은 「페이지」로 보인다 | 신문·출판 용어라 웹 서비스를 쓰는 사람에게 뜻이 바로 오지 않는다. 한 화면에 「지면 전체」와 「웹페이지 전체」가 같이 있어 같은 것을 두 이름으로 부르는 문제도 있다 |
| 커피 비유 교체 | 단계 이름과 버튼의 「재료 고르기」는 「기록 선택」, 「다시 뽑기」는 「다시 생성」, 「포트폴리오 추출」은 「포트폴리오 생성」으로 보인다 | 비유라서 기능이 무엇인지 이름만으로 알 수 없다. 같은 동작을 화면에 따라 추출 · 뽑기 · 생성으로 달리 부르기도 한다 |
| 존대 어미 통일 | 로그인 · 가입 · 온보딩의 「~하십시오」, 「여쭙니다」가 「~해 주세요」, 「다시 동의가 필요합니다」로 보인다 | 같은 앱에서 어미가 둘이면 두 사람이 쓴 것처럼 읽힌다. 대부분의 화면이 「~해 주세요」를 쓴다 |
| 일상어로 풀어 쓴 표현 | 「무릅니다」는 「되돌립니다」, 「줄 세웠습니다」는 「정렬했습니다」, 「닿지 못했습니다」는 「연결하지 못했습니다」처럼 표준 표현으로 보인다 | 오류 문구와 버튼은 읽자마자 뜻이 통해야 한다 |
| 404 · 오류 화면 문구 | 「그 주소에는 아무것도 없습니다」는 「페이지를 찾을 수 없습니다」, 「화면을 그리지 못했습니다」는 「화면을 표시하지 못했습니다」로 보인다 | 다른 사이트에서 보던 오류 문구와 같아야 무슨 일인지 바로 안다 |
| 서버 오류 문구 | 백엔드가 화면에 전달하는 오류(「아직 지면을 만들지 않았습니다」 등)도 같은 어휘로 보인다 | 화면 문구만 바꾸면 오류 알림에 옛 말이 남는다 |

## 개발 목표

- 설정 → 화면: 섹션 이름이 「화면」, 항목 이름이 「테마」로 보인다.
- 앱 전체 화면(편집기 · 배포 · 분석 · 제작 단계 · 로그인)에서 위 용어 묶음의 옛 말이 보이지 않는다. 확인은 문자열 검색으로 한다.
- 문구를 확인하는 기존 테스트가 모두 통과한다.

## 범위 밖과 제약

- AI에게 보내는 지시문(프롬프트)과 코드 주석은 바꾸지 않는다. 지시문을 바꾸면 AI 출력이 달라진다.
- 「Expresso」와 「바리스타」(AI 대화 상대의 이름)는 제품 이름이라 유지한다.
- 화면 구조 · 색 · 크기는 바꾸지 않는다.

## 열린 질문

- 커피 비유 중 이름이 제품 정체성인 것(예: 랜딩의 「에스프레소」 표현)은 이번에 유지했다. 기능을 가리키는 말만 바꿨다. 더 지우려면 알려 달라.
