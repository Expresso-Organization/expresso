# 구조화 생성 내용 정리 단계의 재요청과 연락처 고정

## 문제

포트폴리오 생성이 첫 번째 모델 호출(내용 정리)에서 실패해 제품에서 지면을 만들 수 없습니다. Sonnet 경로로 PR #57에서 2/2, 2026-10-15 체험 서버(PR #81)에서 2/2가 같은 이유로 실패했습니다.

- **연락처 키 누락:** 모델 출력 스키마가 `contact`를 요구합니다. 그런데 생성기는 모델이 연락처를 넣으면 "연락처 입력 경로가 없는 실행"으로 거부합니다(`structured-generator.ts`). 제품 경로에서 값은 항상 `null`인데, 모델이 키를 빠뜨리면 실패합니다.
- **이름 아래 소개 규칙 위반:** `profile.headline`의 "짧은 한 문장" 규칙은 Zod `superRefine`이라 공급자 스키마에 전달되지 않습니다. 모델이 어기면 어댑터가 `AI_INVALID_OUTPUT`을 던지고 출력을 버립니다.
- **재요청이 없습니다.** Spec 단계는 검사 오류를 붙여 한 번 다시 요청하지만, 내용 정리 단계는 첫 위반에서 바로 `PAGE_GENERATION_FAILED`로 끝납니다. 생성 한 번에 걸리는 시간과 비용이 그대로 낭비됩니다.

## 원하는 결과

- 모델에게 연락처를 묻지 않습니다. 연락처는 입력 경로가 생길 때까지 생성기가 `null`로 정합니다.
- 내용 정리 결과가 규칙을 어기면 오류 내용과 직전 출력을 붙여 한 번 다시 요청합니다. 규칙은 이름 · 섹션 ID 보존, 제공되지 않은 근거 · 이미지 금지, 이름 아래 한 문장입니다. 두 번째도 어기면 지금처럼 생성 실패로 끝나고, 실패 메시지에 마지막 오류가 들어갑니다.
- 공급자가 스키마에 맞지 않는 출력을 낸 경우(`AI_INVALID_OUTPUT`)도 같은 재요청 대상입니다.
- 모델 호출은 생성 한 번에 최대 4회입니다(내용 정리 2회 + Spec 2회). 재요청한 호출의 사용량도 생성 기록의 사용량에 합산됩니다.
- 단위 테스트로 고정합니다: 소개 규칙 위반 → 두 번째 호출 성공, 연락처를 묻지 않음, `AI_INVALID_OUTPUT` → 재요청, 두 번 연속 실패 → 생성 실패.
- 체험 서버에서 실제 생성을 끝까지 진행합니다. 생성된 지면의 CSS에 고른 디자인 시스템의 색(`--sp-bg` · `--sp-ink` · `--sp-accent`)이 들어갔는지 확인합니다. PR #81에서 남은 확인 항목을 함께 끝냅니다.

## 영향 범위

- 포트폴리오를 생성하는 모든 사용자(AI 공급자를 켠 환경).
- `services/backend/src/modules/page/structured-generator.ts`, `packages/contracts`(내용 정리 모델 스키마), 해당 테스트.
- 결정 권한: 박민재.

## 제약

- PR #81(`feat/portfolio-six-step-flow`) 위에 쌓습니다. #81 → 이 PR 순서로 머지합니다. #67도 같은 파일을 바꾸므로 머지 순서에 따라 충돌을 정리합니다.
- 저장되는 내용 계약(`StructuredPortfolioContentSchema`)과 렌더링 결과는 바꾸지 않습니다. 소개 문장 규칙은 그대로 강제합니다.
- 모델 티어(`sonnet`)와 Spec 단계의 재요청 방식은 바꾸지 않습니다.

## 범위 밖

- 연락처 입력 경로 만들기(사용자가 연락처를 포트폴리오에 넣는 기능).
- Spec 단계의 `AI_INVALID_OUTPUT` 재요청, 렌더러 예외 분리(PR #67이 다룹니다).
- 소개 문장을 코드로 잘라 규칙에 맞추는 방식. 모델이 쓴 문장을 임의로 자르지 않습니다.
- AI 대화 "질문 만들기"의 재시도 문제(별도 작업으로 분리됨).
