# 커리어 카테고리 사용자 소유화와 레거시 태그 이관

## 변경 의도

기획은 시스템이 기본 레이아웃을 주고 사용자가 노션처럼 속성을 고치는 것입니다. 지금 기본 카테고리 7개는 전체 사용자 공용이라 속성을 못 고치고, 옛 정의(v1)라 "기술"이 v2 패널에서 빈칸입니다.

요청: "레거시 태그 데이터를 마이그레이션하고, 레거시 태그의 흔적을 없애자"

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 가입 시 카테고리 생성 | 가입하면 기본 카테고리 7개가 템플릿에서 복사되어 그 사용자 소유로 만들어진다 | 공용 한 벌이면 한 사람의 편집이 모두에게 보인다. 정의서 10b가 이 동작이다 |
| 기본 카테고리 속성 편집 | 기본 카테고리에서도 속성을 추가하고 이름 · 타입을 바꾸고 지울 수 있다 | 사용자가 속성을 자유롭게 고치는 것이 기획이다 |
| 기존 사용자 이관 | 이미 가입한 사용자도 자기 카테고리 7개를 받고, 기록 · 저장한 보기 · 연결이 새 카테고리로 옮겨진다 | 이관 중 기록이나 보기를 잃으면 안 된다 |
| 태그 이관 | 기술 · 역량 같은 태그 값이 다중 선택 칩으로 옮겨지고, 칩을 새로 추가할 수 있다 | 지금은 v2 문서 패널에서 빈칸으로 보이고 고칠 수 없다 |
| 기본 속성 정리 | 새 사용자의 기본 속성을 정의서 05–05e에 맞춘다. 경험의 수치 · 성과 · 상황 · 맡은 일 · 한 일 · 결과는 기본에서 빠지고, 값이 있던 사용자에게는 남는다 | 기획하지 않은 속성이 기본으로 깔려 있다 |
| 기록 글 읽기 유지 | 공고 매칭 · 자료 추천 · 인터뷰가 태그를 옵션 번호가 아니라 이름으로 읽는다 | 이름을 못 읽으면 이관 뒤 매칭 점수가 떨어진다 |
| AI 기록 정리 조정 | 인터뷰 답변을 AI가 정리할 때 제목과 역량만 고치고, 사용자가 넣은 다른 속성은 건드리지 않는다. 상황 · 맡은 일 · 한 일 · 결과 · 수치는 더 이상 속성에 넣지 않는다 | 지금은 속성 전체를 덮어써 사용자 값을 지우고, 기획에 없는 속성을 만든다 |
| 옛 정의 삭제 | 옛 속성 정의 방식(v1)과 `tags` 타입, 그것을 v2로 바꾸던 코드를 지운다 | 두 방식이 섞여 같은 값을 다르게 읽은 것이 이번 빈칸의 원인이다 |

## 개발 목표

- 새 계정이 프로젝트에 속성을 추가하고, 다른 계정에는 안 보인다.
- dev01 "개인 가계부 PWA"에 기술 칩이 보이고 새 기술이 추가된다.
- 이관 전후 사용자별 기록 · 보기 · 연결 수와 공고 매칭 점수가 같다.
- typecheck · test · test:infra · 웹 E2E 통과.

## 범위 밖과 제약

- 템플릿을 나중에 바꿔도 이미 만든 사용자 카테고리는 바뀌지 않습니다.

## 열린 질문

없음. AI 기록 정리는 2026-10-25에 "역량만 속성에 넣고, STAR를 본문 단락으로 정리하는 일은 후속 작업으로 뗀다"로 정했습니다.
