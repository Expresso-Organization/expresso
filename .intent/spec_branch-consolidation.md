# 로컬 브랜치 정리와 승인 기능 통합 — 명세

## 요구사항
- 백업 검증 후 지정된 여섯 로컬 브랜치와 연결된 네 워크트리를 삭제한다. main과 나머지 브랜치는 보존한다.
- read_link는 사용자 메시지에 적힌 공개 HTTP(S) 주소만 실행당 세 번까지 읽는다. 일반 HTML·텍스트만 받고 인용은 같은 실행의 읽은 본문과 대조한다. 사용자 역할은 링크 내용으로 추정하지 않는다.
- 기존 대화와 메시지 출처 계약을 유지하면서 링크 출처를 허용한다. 현재 제작·작업물 도구와 공개 URL 검사·HTML 변환을 재사용한다.
- AI_PROVIDER_POSTING_FACTS는 기본 off이며 API와 Worker가 같은 별도 클라이언트를 쓴다. 전체 AI 설정과 독립적이고 기존 사용량 계측은 유지한다.
- /dev/branch-review는 개발 환경에서만 열리는 비교 페이지다. 제품 토큰과 기존 UI를 재사용하고 검토용 예시임을 표시한다. DB 쓰기와 AI 호출은 없다.
- 페이지에서 검색의 정상·지연·빈 결과, 표의 선택·필터·집계, 차트의 유효·단위 불일치 상태를 확인한다. 사용자 승인에 따라 세 변경을 운영 화면에 적용한다. 검색은 실제 탐색 진행·5초 지연·빈 결과를 안내하고, 취소 기능은 추가하지 않는다. 경력 표는 제목 안에 행 작업을 모으고 하단 필터·숫자 합계와 기본 452px 패널을 제공한다. 추이는 같은 단위의 근거 값이 세 개 이상일 때 생성·렌더링하고 편집에서도 유지한다.

## 설계
계약 → 대화 서비스 → 도구 런타임에 링크 근거를 연결한다. 기존 URL·HTML 공용 코드를 재사용한다. 요건 추출 클라이언트는 프로바이더와 사용량 기록을 명시적으로 받는다. 비교용 컴포넌트는 개발 라우트 아래에 격리한다.

## 완료 기준
루트 타입 검사·테스트와 Mongo/Redis 통합 검증 통과, Next 빌드 통과, 비교 페이지 1440·390px과 Reduce Motion 점검. 실제 AI 실행을 생략하면 보고한다.
