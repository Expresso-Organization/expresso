# 커리어 기록 본문 BlockNote 편집기 전환

## 개발 목표와 의도

커리어 기록 본문 편집기를 노션형 오픈소스 편집기 BlockNote로 바꿉니다. 검증 보고서(`docs/architecture/career-editor-blocknote-spike.md`)에서 검증한 항목이 모두 통과했습니다. 블록 메뉴 · 손잡이 · 머리글 표 · 이미지 · 두 탭 동시 편집 병합 · 연결 끊김 뒤 저장 · 본문의 매칭 · 생성 전달입니다. 남은 것은 AI 변경 제안을 BlockNote에서 다시 쓸 수 있게 하는 일과 운영에 맞는 저장 처리입니다.

요청: "최종 완료까지 진행해" (2026-10-28, 구현 순서 1단계 승인)

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| BlockNote 본문 | 기록 패널과 전체 페이지 본문이 BlockNote로 열립니다. `/` 메뉴, 블록 손잡이 끌기, 선택 서식 툴바, 표 머리글, 콜아웃, 이미지 업로드가 됩니다. | 지금 편집기는 메뉴가 빈약하고 저장 변환 결함이 반복됐습니다. |
| 동시 편집 병합 | 같은 기록을 두 곳에서 고쳐도 두 수정이 글자 단위로 합쳐집니다. | 지금은 한쪽 문서 전체가 덮어써집니다. |
| 기존 기록 자동 옮기기 | 기존 기록을 처음 열면 내용 그대로 새 편집기로 옮겨집니다. | 사용자 기록을 잃으면 안 됩니다. |
| 본문을 매칭 · 생성에 전달 | 본문을 고치면 몇 초 안에 목록 미리보기 · 공고 매칭 · 포트폴리오 생성이 읽는 본문 텍스트가 바뀝니다. | 지금은 새 편집기 본문이 이 기능들에 전달되지 않습니다. |
| AI 변경 제안 | 글을 고르고 「AI 편집」에서 다듬기를 고르면 바뀔 내용이 비교로 보이고, 적용하면 열린 편집기에 바로 반영되고, 되돌리기가 됩니다. 에이전트 채팅의 기록 수정 제안도 같습니다. | AI 제안은 기존 기능입니다. 전환 뒤에도 같아야 합니다. 지금은 적용 결과가 열린 편집기에 반영되지 않는 결함도 있습니다. |
| 인터뷰 답변 반영 | 인터뷰 답변을 다시 하면 그 답변으로 만든 기록 본문이 새 답변으로 바뀌어 편집기에도 보입니다. | 인터뷰는 본문 텍스트를 직접 고칩니다. 편집기 문서가 따라가지 않으면 다음 저장 때 답변이 지워집니다. |

## 개발 목표

- 기존 기록을 열면 내용이 그대로 BlockNote로 보이고, 고친 뒤 새로고침해도 남아 있습니다.
- 두 탭에서 같은 문단의 다른 자리를 고치면 두 수정이 모두 남습니다.
- 본문을 고치고 몇 초 뒤 목록 카드 미리보기에 새 문장이 보입니다.
- 문장을 고르고 AI 편집을 적용하면 열린 편집기에 바로 바뀐 문장이 보이고, 「변경 되돌리기」로 원래 문장이 돌아옵니다.
- 인터뷰 답변을 다시 한 기록을 열면 새 답변 내용이 보입니다.

## 범위 밖과 제약

- 저장 통로(WebSocket · 저장 기록 컬렉션)는 그대로 씁니다. Spring 전환 PR 묶음(#71–#76)은 2026-10-14 이후 멈춰 있어 이번 작업은 지금 `main`의 Fastify 백엔드 기준으로 합니다. 그 묶음을 살리면 이 변경 위로 다시 맞춰야 합니다.
- 근거 참조 블록, 메뉴를 화면 정의서에 맞추기, 옛 편집기 코드 제거는 다음 작업입니다.
- 목록 · 뷰 화면은 다른 세션(2단계)이 맡습니다.
