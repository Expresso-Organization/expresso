# 커리어 보기의 선택 속성 이름 표시

## 개발 목표와 의도

커리어 기록 화면의 모든 보기에서 단일 선택 · 다중 선택 속성 값을 선택지 이름으로 보여 줍니다.
요청: 랜딩 화면을 찍다가 발견한 결함을 "이 작업을 여기에서 진행해 주세요"로 맡겼습니다.
2026-11-02 로컬 서버의 프로젝트 갤러리에서 카드마다 `d133a337-91cb-5fc1-…` 같은 문자열 칩이 서너 개씩 붙어 있었습니다. 이 칩은 「기술」 속성의 값입니다. 처음에는 관계 속성으로 보였지만, 실제로는 다중 선택 속성입니다. 다중 선택 값은 선택지 이름이 아니라 선택지 ID로 저장됩니다. 표 보기는 ID를 이름으로 바꿔 보여 주지만, 갤러리 · 목록 · 보드는 ID를 그대로 보여 줍니다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 프로젝트 갤러리 칩 | 카드의 기술 칩이 "React · Next.js"처럼 선택지 이름으로 보인다. | 지금은 UUID가 보여 카드가 무엇을 다룬 프로젝트인지 알 수 없고, 카드 높이도 늘어난다. |
| 목록 · 일반 갤러리의 속성 미리보기 | 보기에 표시하기로 고른 단일 선택 · 다중 선택 속성이 이름으로 보인다. | 같은 결함이다. 경험 · 자격증 등 다른 카테고리의 목록 · 갤러리 보기에서 나타난다. |
| 보드 열 이름 | 스킬 · 도구의 「분류」처럼 선택 속성으로 묶은 보드의 열 제목이 선택지 이름으로 보인다. | 스킬 · 도구 카테고리의 기본 보기가 이 보드라 열 제목이 UUID면 화면 전체를 읽을 수 없다. |
| 지운 선택지 | 기록에 남은 값이 이미 지운 선택지를 가리키면 아무것도 보이지 않는다. | ID를 보여 주면 같은 결함이 다시 나타난다. 표 보기도 같은 규칙으로 바꾼다. |

## 개발 목표

- 로컬 서버(체험 DB 복사본, 예시 인물 계정)의 프로젝트 갤러리 카드에 UUID 칩이 없고 기술 이름 칩이 보인다.
- 스킬 · 도구 보드의 열 제목이 선택지 이름이다.
- 목록 보기에서 다중 선택 속성을 표시하면 이름이 보인다.
- 값을 이름으로 바꾸는 코드가 한 곳에 있고, 표 · 갤러리 · 목록 · 보드가 모두 그것을 쓴다.

## 범위 밖과 제약

- 파일 · 미디어 속성 값(파일 ID 배열)의 표시는 바꾸지 않는다. 이 데이터에는 그 속성이 없어 확인할 수 없다.
- 저장된 필터의 "포함" 비교는 지금처럼 ID로 비교한다. 화면 표시만 바꾼다.
- 열린 PR 141(저장된 뷰 · 보드 · 타임라인 완성)이 같은 파일들을 크게 고친다. 그 PR이 프로젝트 갤러리 칩과 보드 열 이름은 이미 고친다. 목록 · 일반 갤러리는 그대로 남는다.
