# 배포 재시작 시 진행 중 AI 잡 고착 해소

## 개발 목표와 의도

「포트폴리오 생성 파이프라인이 제대로 진행이 안돼. 로딩 창에서 계속 멈추는 느낌인데」.
2026-11-10 12:03 운영에서 AI 대화 단계의 「질문 만드는 중」 화면이 끝나지 않았다. 질문을 만드는 동안 PR 머지 배포가 Worker를 재시작했고, 진행 중이던 AI 호출이 죽었다. Worker가 그 실패를 저장하기 전에 DB 연결을 먼저 닫아서 잡이 「만드는 중」으로 영원히 남았다. 같은 배포에서 API는 열린 실시간 상태 연결 때문에 90초 동안 내려가지 않다가 강제 종료됐다.
머지마다 배포가 돌기 때문에 하루에도 여러 번 생길 수 있다. 배포가 진행 중인 작업을 끊더라도, 그 작업은 재시작 뒤 이어서 끝나야 한다. (이슈 #203)

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 끊긴 작업 이어 하기 | 배포로 Worker가 내려갈 때 진행 중이던 질문 · 구성 · 포트폴리오 생성은 실패로 끝나지 않는다. 새 Worker가 뜨면 같은 작업을 다시 돌려 끝낸다. 그동안 화면은 「차례를 기다리는 중」을 보인다. | 지금은 배포 한 번에 사용자의 작업이 영원히 멈추거나 실패로 끝나고, 사용자가 다시 시작해야 한다. |
| 종료 순서 정리 | Worker는 진행 중 작업이 결과를 저장한 뒤에 DB 연결을 닫는다. | DB를 먼저 닫으면 실패도 저장되지 않아 화면이 끝없이 기다린다. 이번 고착의 직접 원인이다. |
| API 즉시 종료 | 배포 때 API가 열린 실시간 상태 연결(SSE)을 끊고 바로 내려간다. 화면은 다시 연결하거나 새로 읽는 방식으로 돌아간다. | 지금은 배포마다 API가 최대 90초 동안 응답하지 않는다. |

## 개발 목표

- 질문 생성 중에 Worker를 재시작해도 그 질문 생성이 새 Worker에서 끝나고, `brew_jobs`에 `running` 행이 남지 않는다.
- 포트폴리오 생성 중에 Worker를 재시작해도 생성이 실패로 기록되지 않고 다시 돌아 끝난다.
- Worker 로그에 `failed to persist dead-letter job`이 찍히지 않는다.
- SSE 연결을 연 채 API를 재시작하면 몇 초 안에 내려가고 다시 뜬다.

## 범위 밖과 제약

- 오래 `running`으로 남은 잡을 주기적으로 회수하는 기능은 넣지 않는다. 이번 변경으로 고착 경로가 닫힌다.
- systemd 유닛(`KillMode`, `TimeoutStopSec`)은 바꾸지 않는다. 서버 유닛은 손으로 반영하므로 코드만으로 고친다.
- 공고 분석 · 지면 다듬기의 실패 기록 방식은 그대로 둔다.
