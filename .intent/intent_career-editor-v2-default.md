# 커리어 편집기 v2 기본 활성화와 이전 기록 화면 삭제

## 변경 의도

기록 화면은 설정값(`CAREER_EDITOR_V2_ENABLED`)이 `true`일 때만 새 편집기(v2)를 띄우고, 운영 배포는 값이 없으면 `false`를 적습니다. 체험 서버에서 기록을 누르니 이전 화면의 "기존 Markdown 문서" 패널이 열렸고, 속성 이름이 `role`, 기술 목록이 `["Vite","React"]` 원문으로 나왔습니다.

요청: "LegacyCareerBrowser 삭제하고, 편집기 v2를 기본으로 활성화하자"

## 기능 목록

| 기능 | 끝나면 무엇이 달라지는가 | 왜 필요한가 |
|---|---|---|
| 카테고리 화면 v2 통일 | 지금은 이전 목록과 "기존 Markdown 문서" 패널이 뜬다 → 끝나면 늘 v2 보기와 문서 패널이 뜬다 | 이전 화면은 값을 원문으로 보여 주고 보기 탭이 동작하지 않는다 |
| 기록 상세 v2 통일 | 지금은 기록 상세가 읽기 전용이다 → 끝나면 편집기로 열린다 | 목록만 v2면 같은 기록을 두 방식으로 다룬다 |
| 이전 화면 삭제 | 지금은 이전 화면 코드가 남아 있다 → 끝나면 코드와 전용 스타일이 없다 | 쓰이지 않는 화면이 남는다 |
| v2 설정값 삭제 | 지금은 웹과 API가 이 값을 읽는다 → 끝나면 읽지 않고 v2 API가 늘 열린다 | 기본값만 바꾸면 운영 `.env`의 `false`가 API를 꺼 화면이 오류를 낸다 |

## 개발 목표

- 설정값 없이 띄운 서버에서 `/career/project`에 v2 갤러리가 보이고, 기록을 누르면 v2 문서 패널이 열린다.
- API에 `CAREER_EDITOR_V2_ENABLED=false`를 넣고 다시 띄워도 같은 화면이 나온다.
- 기록 상세(`/career/records/:id`)에서 본문을 고칠 수 있다.
- `pnpm typecheck` · `pnpm test` · `pnpm test:infra` · 웹 E2E가 통과한다.

## 범위 밖과 제약

- 기록 API(목록 · 본문 저장)는 v2 화면도 쓰므로 남깁니다.
- 운영에서 v2를 끄는 스위치가 없어집니다. 되돌리려면 이 변경을 되돌려 배포합니다.
