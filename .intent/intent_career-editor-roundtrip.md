# 커리어 본문 표 머리글 · 줄바꿈 · 밑줄 저장 수정

## 개발 목표와 의도

지금 커리어 기록 본문에서 세 가지 입력이 저장 단계에서 깨집니다. 2026-10-28 점검(`docs/architecture/career-record-editor-status-2026-10-28.md`)에서 재현했습니다. 슬래시 메뉴로 표를 넣은 기록은 다시 열면 브라우저 탭이 멈췄습니다. `Shift+Enter`로 나눈 줄은 새로고침하면 한 줄로 붙었습니다. `Cmd+U`(밑줄)는 예외를 내고 적용되지 않았습니다.

본문 편집기는 BlockNote로 바꾸기로 했지만 여러 PR이 걸립니다. 그 사이 사용자 기록이 계속 깨지지 않게 지금 편집기에서 먼저 고칩니다.

요청: "최종 완료까지 진행해" (2026-10-28, 구현 순서 0단계 승인)

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 표 머리글 저장 | 슬래시 메뉴로 넣은 표(첫 행이 머리글)를 저장하고 다시 열면 머리글 행이 그대로 보입니다. 이미 머리글 표가 저장된 기록도 다시 열립니다. | 지금은 이런 기록을 열면 탭이 멈춰 기록 전체를 쓸 수 없습니다. |
| 줄바꿈 저장 | `Shift+Enter`로 나눈 줄이 새로고침 뒤에도 나뉜 채 보입니다. | 지금은 알림 없이 두 줄이 붙어 저장됩니다. |
| 밑줄 | 글자를 고르고 `Cmd+U`를 누르면 밑줄이 들어가고 저장됩니다. | 지금은 단축키가 예외를 내고 아무 일도 하지 않습니다. |

## 개발 목표

- 슬래시 메뉴로 표를 넣고 머리글 칸에 글을 쓴 뒤 새로고침하면 같은 표가 열리고 탭이 멈추지 않습니다.
- 「첫 줄 ⏎ 둘째 줄」(Shift+Enter)을 쓰고 새로고침하면 두 줄로 보입니다.
- 밑줄을 넣고 새로고침하면 밑줄이 남아 있습니다.
- 편집기가 아는 모든 블록 · 서식이 저장했다 다시 열어도 같은지 확인하는 자동 시험이 있습니다.

## 범위 밖과 제약

- BlockNote 전환은 다음 작업입니다. 이번에는 지금 편집기의 저장 변환만 고칩니다.
- 이미 줄이 붙어 저장된 기록의 줄바꿈 위치는 저장된 데이터에 남아 있지 않아 되살릴 수 없습니다.
