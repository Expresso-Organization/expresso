# 적합도 모델 학습 파이프라인 main 반영

## 개발 목표와 의도

9월 파일럿 코드는 `codex/p5-data-collection`에만, 10/25 본 학습 계획은 `docs/match-model-training-plan`에만 있다. 진행 현황은 main만 판정해서 「AI학습서버」 35개 중 33개를 「scripts/ml-data 자체가 부재」로 보여 준다. 이번 주가 학습 마지막 주(10주차)라 본 학습을 시작할 자리를 main에 만든다.

> "적합도 모델 학습 브랜치 main 반영"

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 학습 파이프라인 | main에 `scripts/ml-data`(합성 프로필 · 교사 라벨 · 학습 · 평가)가 생기고 `pnpm ml:data:test`로 검증한다 | 본 학습은 이 코드를 고쳐 쓰는 계획이라, main에 없으면 시작할 곳이 없다 |
| 파일럿 문서 | 설계 문서와 학습 결과 리포트가 개발 포털에서 열린다 | 설계서 9.2와 완료 보고서가 인용할 수치의 출처다 |
| 본 학습 계획 | `match-model-training-v1.md`가 들어온다. 주차는 진행 현황 기준으로 고친다(10/26–11/1을 9주차로 적었다). 담당은 박민재로 고친다 | 이번 주부터의 작업 목록인데, 주차가 하나 어긋나면 남은 기간을 잘못 읽는다 |

## 개발 목표

- 루트에서 `pnpm ml:data:test`가 모델 테스트까지 통과하고, 백엔드 · 웹 CI도 통과한다.
- 개발 포털에서 학습 결과 리포트와 그림 6개가 열린다.
- 다음 스캔에서 「AI학습서버」 미구현이 33개보다 줄어든다.
- `git log`에 9월 커밋 66개가 그대로 남는다.

## 범위 밖과 제약

본 학습 실행, 추론 서비스, 백엔드 연결, 설계서 수정은 하지 않는다. 데이터 · 가중치는 올리지 않는다.
