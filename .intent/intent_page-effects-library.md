# 지면 3D · 입자 효과 라이브러리

## 개발 목표와 의도

첫 화면의 3D를 모델이 처음부터 짜면 결과가 들쭉날쭉하다. 공중에 오브젝트 하나가 떠 있거나, 입자 · 프리즘이 어색하게
나왔다. 사용자: "웹용 3D 인터랙티브 오브젝트랑 파티클 효과는 인터넷에 찾아보면 많을 거야. 그걸 라이브러리로 흡수하도록
하고, 모델이 라이브러리를 참고하도록 하자". 공개 라이선스(MIT)로 검증된 웹 효과를 제품 코드로 들여와 효과 목록을 만들고,
모델은 거기서 골라 팔레트와 기록의 값만 넘긴다. 시안 중 블루프린트 선화는 사용자가 괜찮다고 해서 효과로 넣는다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 효과 라이브러리 | 입자 그물 · 점 격자 물결 · 안개 · 블루프린트 선화를 `ExpressoEffects.mount("이름", 옵션)`으로 부른다. 효과는 고른 스타일의 색을 쓰고 커서에 반응한다 | 검증된 효과를 쓰면 모델이 짤 때보다 결과가 고르다 |
| 쓰는 효과만 싣기 | 지면 스크립트가 부르는 효과의 코드만 문서에 싣고 정책에 해시를 넣는다 | 효과 전부를 실으면 지면이 무거워진다 |
| 효과 목록 지침 | 그리는 호출이 효과마다 모습 · 어울리는 쓰임 · 바탕 · 넘길 값을 읽고 고른다. 3D · 입자는 직접 짜지 않는다 | 모델이 무엇을 고를 수 있는지 알아야 한다 |
| 출처 기록 | 효과마다 출처 · 판 · 라이선스를 남기고 고지를 문서에 싣는다 | MIT 조건 |

## 개발 목표

- 같은 짝을 3D로 다시 그리면 모델이 라이브러리의 효과를 고르고, 효과가 우리 틀 · 정책 안에서 움직인다
- 효과 목록의 각 효과를 밝은 바탕 · 어두운 바탕에서 그린 갤러리를 보드에 올린다
- 효과를 쓰지 않는 지면의 문서는 그대로다

## 범위 밖과 제약

- 바깥 이미지 · 파일을 받는 효과(구름 노이즈 이미지 등)는 들이지 않는다 — 정책이 막는다.
- three r170과 맞지 않는 효과(Vanta BIRDS)는 이번에 들이지 않는다.
- 효과 코드는 생성 스크립트로 묶는다. 묶음을 손으로 고치지 않는다.

## 고친 범위 (2026-11-21)

실제 견본을 본 사용자: "이미지로 보는데 너무 끔찍하네. 의미없는 3D 오브젝트는 그냥 안쓰는게 더 낫겠다". 오브젝트를 띄우는 효과(액체 방울 · 선화 지구본)를 뺐다.
3D는 배경 장(입자 그물 · 점 격자)과 일의 구조를 보이는 블루프린트 선화로만 쓰고, 맞는 효과가 없으면 canvas 2D로 짓는다. 모델이 three.js로 형체를 직접 짓지 않는다.
