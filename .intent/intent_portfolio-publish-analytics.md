# 포트폴리오 배포 · 방문 수집 · 분석 화면 연결

## 개발 목표와 의도

배포 화면, 방문 기록 API, 분석 대시보드는 각각 만들어져 있습니다. 하지만 실제 사용자가 처음부터 끝까지 따라가면 중간에 끊깁니다.

> "익스프레소 서비스의 포트폴리오 배포/방문자 데이터 수집/분석 결과 시각화 기능 구현에 들어가자"
> "포트폴리오 사이트 배포에는 expresso.ai.kr 도메인을 써야 해."

지금 사용자가 겪는 장면은 다음과 같습니다.
- 포트폴리오를 고친 뒤 같은 주소로 v2를 배포하면 "이미 쓰이고 있는 주소입니다"가 뜹니다.
- 공개 사이트는 방문을 하나도 기록하지 않습니다. 그래서 분석 화면에는 늘 "집계된 날이 아직 없습니다"가 보입니다.
- 화면에 보이는 공개 주소 `jiwon.xpresso.me`는 열리지 않는 임시 주소입니다.

이번 변경은 이 흐름을 끝까지 잇습니다. 배포한 사이트를 방문자가 열면 기록이 쌓이고, 그 기록이 분석 화면에 실제 값으로 그려집니다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 공개 주소 `{주소}.expresso.ai.kr` | 배포하면 `jiwon.expresso.ai.kr`처럼 제품 도메인 아래 주소가 생기고, 그 주소를 열면 포트폴리오가 보입니다. 배포 · 홈 · 편집 · 분석 화면의 주소 표기도 이 주소로 바뀝니다. `expresso.ai.kr/site/jiwon`도 계속 열립니다. | 지금 화면에 보이는 주소는 열리지 않습니다. 사용자가 채용 담당자에게 건넬 주소가 없습니다. |
| 같은 주소로 다시 배포 | 주소는 포트폴리오가 계속 가지고, 배포는 그 주소에 새 버전을 올립니다. v2 · v3를 같은 주소로 배포할 수 있습니다. 이전 버전으로 되돌려도 주소는 그대로입니다. | 지금은 두 번째 배포부터 주소를 매번 바꿔야 해서 이미 건넨 링크가 쓸모없어집니다. |
| 공개 사이트 방문 기록 | 방문자가 사이트를 열면 방문이 기록됩니다. 읽는 동안 섹션별 머문 시간, 끝까지 읽었는지, 메일 · 전화 · 외부 링크 · 파일 클릭이 기록됩니다. 로그인한 주인이 앱에서 자기 사이트를 보는 경우는 세지 않습니다. 방문자를 식별하는 정보는 남기지 않습니다. | 기록이 없으면 분석 화면에 그릴 것이 없습니다. |
| 버전을 넘어 이어지는 분석 | 새 버전을 배포해도 그 전의 방문 기록이 분석 화면에 그대로 합쳐져 보입니다. 공개를 중단한 포트폴리오도 분석 목록에서 고를 수 있습니다. | 지금은 배포할 때마다 분석이 0으로 돌아가고, 공개를 중단하면 지난 기록을 볼 수 없습니다. |
| 분석 화면이 실제 값만 그림 | 섹션별 체류에 사이트의 실제 섹션 제목이 보입니다. 연락처 클릭 같은 숫자 카드의 작은 막대가 그 지표의 날짜별 값을 그립니다. 방문 추이에 완독 선이 함께 보입니다. 섹션별 체류를 목록으로 고르면 목록으로 그립니다. 기업 도메인 방문은 수집할 수 없다는 이유와 함께 지표 목록에서 "없음"으로 보입니다. | 지금은 섹션이 "1번 섹션"처럼 보이고, 연락처 클릭 카드에 방문 막대가 그려집니다. 기업 도메인은 PRO 사용자에게 항상 "아직 없습니다"로 보입니다. 이 화면들은 사실과 다른 내용을 보여 줍니다. |

## 개발 목표

- 같은 포트폴리오를 같은 주소로 두 번 배포하면 두 번 모두 성공하고, 배포 화면 버전 목록에 v1 · v2가 보입니다.
- 로그인하지 않은 브라우저로 `jiwon.site.localhost:<포트>`(운영에서는 `jiwon.expresso.ai.kr`)를 열고 끝까지 스크롤한 뒤 메일 링크를 누릅니다. 그다음 "지금 집계"를 누르면 분석 화면의 방문 · 끝까지 읽은 비율 · 연락처 클릭이 1씩 늘어 있습니다.
- 같은 화면의 섹션별 체류에 그 사이트 섹션의 제목이 보입니다.
- v2를 배포한 뒤에도 분석 화면의 방문 수가 v1 때 쌓인 수를 포함합니다.
- 앱에서 로그인한 채 `expresso.ai.kr/site/jiwon`을 열어도 방문 수가 늘지 않습니다.

## 범위 밖과 제약

- 운영 도메인 준비는 코드 밖의 일이라 사용자가 해야 합니다. hosting.co.kr에 `*.expresso.ai.kr` A 레코드를 추가하고 와일드카드 인증서를 발급해야 합니다. 이 두 가지가 끝나기 전까지 운영에서는 `expresso.ai.kr/site/{주소}`로만 열립니다. 이번 변경에는 nginx 설정 파일과 절차 문서까지 넣습니다.
- 주인이 로그인한 앱 밖에서 `jiwon.expresso.ai.kr`을 직접 열면 방문으로 셉니다. 로그인 쿠키는 앱 주소에만 있고 서브도메인으로 보내지 않습니다.
- 넣지 않는 것: 커스텀 도메인, 이탈 지점, 문의 메일, 순 방문자 · 재방문율, 대시보드 뷰 탭 · 주석, 원시 방문 기록 보관 기한, 해설 기간이 날마다 밀리는 문제, "편집본이 공개본보다 앞서 있습니다" 표시, 연락처 공개 범위 · 검색 엔진 노출 설정의 반영.
- 이미 배포된 버전은 섹션 체류를 기록하지 않습니다. 섹션 목록은 배포 시점에 만들어 두므로, 다시 배포하면 그때부터 기록합니다.

## 열린 질문

- 공개 주소를 서브도메인(`jiwon.expresso.ai.kr`)으로 할지 경로(`expresso.ai.kr/site/jiwon`)로 할지 정해야 합니다. 이 문서는 화면 정의서 08b를 따라 서브도메인으로 썼습니다. 경로로 정하면 DNS · 인증서 작업과 서브도메인 라우팅이 빠지고, 주소 표기만 경로 형태로 바뀝니다.
