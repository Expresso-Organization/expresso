# 개발 포털 첫 화면 패치노트와 서버 자동 갱신

## 개발 목표와 의도

지금 패치노트는 `docs/`의 HTML 문서 한 장이라, 개발 포털에서 찾아 들어가야 하고 PR이 머지될 때마다 사람이 다시 써야 합니다.
요청은 "이 패치노트를 개발 포털의 첫 화면으로 하고, 웹에 맞는 디자인으로 이식하자. 그리고 패치노트가 지속적으로 업데이트될 수 있도록 서버에 셋업하자. 기간은 12/01까지"입니다.
2026-11-10 고친 요청: "진행 현황을 계속 첫 화면으로 하고, 좌측 사이드바에 패치노트 탭을 두고, 그걸 기본으로 활성화되어 있도록 하자."
끝나면 dev.expresso.ai.kr을 열자마자 패치노트가 보이고, 12월 1일까지 머지되는 PR은 서버가 사용자 관점 문구로 정리해 저절로 추가합니다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 진행 현황 사이드바 「패치노트」 | 포털 첫 화면은 그대로 「진행 현황」이고, 그 왼쪽 사이드바 맨 위에 「패치노트」 · 「대시보드」가 있습니다. 진행 현황을 열면 「패치노트」가 선택되어 있습니다. 예전 주소 `#/patch-notes`도 여기로 엽니다. | 팀원과 심사자가 포털에 들어오자마자 최근 변경을 봐야 하고, 진행 현황과 한자리에서 오가야 합니다. |
| 웹 디자인 패치노트 화면 | 날짜별 최신순으로, 변경마다 굵은 이름과 PR 번호, 그 아래 세부 내용을 보여 줍니다. 개발 · 운영 변경은 날짜마다 아래에 따로 묶습니다. 제품과 같은 색 · 글꼴을 쓰고, 포털의 밝은 · 어두운 테마를 따릅니다. | 지금 정리본은 인쇄용 문서 양식이라 포털 안에서 다른 화면과 모양이 다릅니다. |
| 서버 자동 갱신 | 서버가 15분마다 새로 머지된 PR을 찾아, Claude Code가 PR 본문을 읽고 같은 형식(굵은 이름 · 세부 내용 · 사용자/개발 · 운영 구분)으로 한 항목씩 씁니다. | PR이 머지될 때마다 사람이 패치노트를 다시 쓰지 않아도 됩니다. |
| 기간 11/02–12/01 | 12월 1일(KST)까지 머지된 PR만 추가하고, 그 뒤에는 더 추가하지 않습니다. 화면 머리에 기간을 보여 줍니다. | 요청한 기간입니다. |
| 11/02–11/10 정리본 유지 | 지금까지 손으로 다듬은 51개 변경을 그대로 첫 데이터로 씁니다. | 이미 검토한 문구를 AI가 다시 쓰면 품질이 흔들립니다. |
| 정적 패치노트 문서 제거 | `docs/patch-notes-2026-11-10.html`을 지우고 문서 목록의 줄은 진행 현황으로 연결합니다. | 같은 내용이 두 곳에 있으면 한쪽이 낡습니다. |

## 개발 목표

- 첫 화면: dev.expresso.ai.kr을 열면 「진행 현황」이 열리고, 사이드바의 「패치노트」가 선택된 채 가장 최근 변경이 맨 위에 보입니다.
- 형식: 각 변경이 굵은 이름 · PR 링크 · 세부 bullet로 보이고, 날짜마다 「개발 · 운영」 묶음이 아래에 있습니다.
- 자동 갱신: 서버에서 `systemctl list-timers expresso-patch-notes.timer`에 다음 실행이 보이고, 정리본에 없는 PR(예: #222 이후 머지분)이 실행 뒤 화면에 나타납니다.
- 테마: 포털 설정에서 어두운 테마를 고르면 패치노트도 어둡게 바뀝니다.

## 범위 밖과 제약

- 자동으로 쓴 항목을 사람이 검토하는 화면은 만들지 않습니다. 고칠 문구는 데이터 파일을 직접 고칩니다.
- 여러 PR을 하나의 변경으로 묶는 것은 정리본에만 있고, 자동 갱신은 PR 하나에 변경 하나를 씁니다.
- 서버는 남의 서비스가 함께 도는 공용 기계입니다. nginx 설정은 바꾸지 않고 기존 `/status/data/` 경로를 씁니다.
- 서버 설치는 PR이 `main`에 머지된 뒤에 합니다. 서버 클론이 `origin/main`을 따르기 때문입니다.

## 열린 질문

없음. 기간(12/01까지 자동 갱신)과 문구 작성 방식(서버 Claude Code)은 2026-11-10에 답을 받았습니다.
