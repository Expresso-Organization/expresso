# 자유 생성의 정리본 · 디자인 지침 · 배치 자유 방식 연결

## 개발 목표와 의도

자유 생성 실험(`docs/architecture/portfolio-free-generation-lab.md`)에서 정리본과 디자인 지침을 쓰고 스타일은 색 · 서체 · 밀도만 넘긴 조건이 눈가림 품질 1 · 3 · 1위, 다양성 4점으로 가장 높았습니다. 지금 제품의 자유 생성은 미리 만든 키트 부품으로 조판해 7 · 7 · 8위였습니다. 요청자는 결과를 보고 "연결 진행"을 골랐습니다.

이 작업은 디자인 선택 화면에서 「자유 생성」을 고른 포트폴리오가 실험의 그 방식으로 만들어지게 합니다. 구조화 생성은 바꾸지 않습니다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 자유 생성 방식 교체 | 디자인 선택 화면에서 「자유 생성」을 고르고 만들면, 지면을 쓰기 전에 기록에서 자료 정리본을 뽑고, 디자인 지침을 받은 모델이 배치를 정해 HTML · CSS 전체를 씁니다. 색 · 서체 계열 · 밀도는 고른 디자인을 따릅니다. | 실험에서 가장 좋았던 방식이 제품에서는 아직 돌지 않습니다. |
| 디자인 지침 내장 | 실험이 이 장비의 스킬 파일에서 읽던 디자인 지침 본문을 저장소에 넣습니다. 출처와 라이선스(Apache-2.0)를 함께 둡니다. | 서버에는 그 스킬 파일이 없어, 저장소에 없으면 운영에서 지침 없이 돕니다. |
| 키트 없는 지면의 문서 조립 | 새 방식으로 만든 지면은 편집 화면 · 새 탭 미리보기 · 배포 페이지에서 키트 CSS 없이 모델이 쓴 CSS만으로 그려집니다. 예전에 키트로 만든 자유 지면은 지금처럼 키트와 함께 그려집니다. | 키트 CSS는 제목 크기 · 간격 · 색 변수를 정합니다. 모델이 CSS 전체를 쓴 지면에 함께 실으면 두 규칙이 부딪혀 실험에서 본 것과 다른 화면이 나옵니다. |
| 생성 중 미리보기 | 만드는 동안의 미리보기가 새 출력(계획 → CSS → HTML 순서)을 읽어, CSS가 먼저 깔린 뒤 지면이 위에서부터 쓰이는 모습을 보여 줍니다. | 지금 미리보기는 글자 칸만 있는 출력을 전제로 해서, 계획 칸이 앞에 오면 아무것도 그리지 못합니다. HTML이 CSS보다 먼저 오면 1분가량 꾸밈 없는 글만 보입니다. |

## 개발 목표

- 자유 생성으로 만든 포트폴리오가 실험의 지면처럼 나온다: 체험 계정으로 「자유 생성」을 골라 만들면 편집 화면에 키트 부품(`k-page`)이 아닌 지면이 뜨고, 이름 · 모든 섹션 · 근거 목록이 있다.
- 만드는 동안 지면이 쓰이는 모습이 보인다: 생성 화면에서 스타일이 입혀진 지면이 위에서부터 채워진다.
- 같은 지면이 세 자리에서 같게 보인다: 편집 화면, 새 탭 미리보기(`/edit/<id>/preview`)의 첫 화면이 같다.
- 예전 지면이 깨지지 않는다: 키트로 만든 기존 자유 지면과 구조화 지면을 열면 이 작업 전과 같게 보인다.
- `pnpm typecheck` · `pnpm test` · `pnpm test:infra`가 통과한다.

## 범위 밖과 제약

- 구조화 생성의 코드와 동작은 바꾸지 않습니다.
- 자유 지면의 요소 단위 편집은 만들지 않습니다. 지금처럼 지시를 붙여 지면 전체를 다시 만듭니다.
- 정제 호출의 사용량은 기존 `page_fill` 계약으로 잡힙니다. 계약 이름을 새로 두면 동의 · 사용량 · DB 제약 표가 함께 바뀌어 이번에는 하지 않습니다.
- 자유 생성 한 번의 값과 시간이 지금의 약 3배(약 $0.3 · 2분)가 됩니다. 크레딧도 그만큼 듭니다.
- 고른 디자인의 골격(단일 칼럼 · 격자 · 넓은 여백)은 자유 생성에서 규칙이 아니게 됩니다.

## 열린 질문

- CSS를 HTML보다 먼저 쓰게 하면 실험과 출력 순서가 달라집니다. 같은 세 인물로 다시 만들어 눈으로 확인하고, 눈에 띄게 나빠지면 HTML 먼저로 되돌리고 미리보기는 CSS가 온 뒤에 한 번에 보이게 합니다.
