# 일치도 · 추천의 기록 3건 조건 제거

## 개발 목표와 의도

커리어 기록이 1건이라도 있으면 공고 일치도를 계산하고 홈 추천에 올립니다.
요청자의 말: "사용자를 자동으로 커리어 기록 추가 쪽으로 유도하는건 좋은데, '3건'이라는 기준을 굳이 적용할 필요가 있나 싶다."
지금은 기록이 2건인 사용자가 공고를 분석하면 요건 대조 표는 채워집니다. 그런데 일치도 점수 자리는 비고, 그 공고는 홈의 「지금 나에게 맞는 공고」에도 뜨지 않습니다.
3이라는 값은 코드 두 곳에 적혀 있을 뿐이고 문서 어디에도 근거가 없습니다. 근거를 댈 수 없는 상수는 조정하지 않고 지웁니다.
기록이 0건이면 비교할 재료가 없으므로 그때만 계산하지 않습니다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 공고 분석의 일치도 저장 | 기록이 1건 이상이면 공고 분석이 끝날 때 일치도 점수를 저장한다. 공고 상세에 점수가 보이고 홈 추천 목록에 그 공고가 오른다. | 지금은 기록 1~2건 사용자가 분석을 끝내도 점수와 추천이 비어 있다. 분석은 했는데 결과의 절반이 사라진다. |
| 일치도 다시 계산 API | `POST /v1/jobs/postings/{id}/match`는 기록이 0건일 때만 거절한다. | 같은 점수를 내는 두 경로가 서로 다른 기준을 쓰면 안 된다. |
| 홈 첫 실행 문구 | 기록 0건 홈의 제목 "기록 3건만 있으면 추천이 시작됩니다"를 "첫 기록을 남기면 공고와 맞춰 볼 수 있습니다"로 바꾼다. 제목과 같은 말을 되풀이하는 본문 첫 줄은 지운다. | 기준이 없어지면 이 문장은 사실이 아니다. |
| 구현 명세서 문구 | `docs/Expresso 구현 명세서.dc.html`의 "기록 3건만 있으면" 두 곳을 새 문구로 바꾼다. | 명세서에 옛 문구가 남으면 다음 작업자가 이 기준을 다시 들여온다. |

## 개발 목표

- 기록 1건인 계정으로 공고를 분석하면 공고 상세에 일치도 점수가 보이고 홈 「지금 나에게 맞는 공고」에 그 공고가 있다.
- 기록 0건인 계정은 분석해도 점수가 저장되지 않는다. 다시 계산 API는 409를 낸다.
- 홈 첫 실행 화면에 "3건"이라는 말이 없다.
- 백엔드 통합 테스트가 기록 1건 계산과 0건 거절을 확인한다.

## 범위 밖과 제약

- 이미 분석해 둔 공고의 점수를 소급해서 만들지 않는다. 기록 1~2건 상태에서 분석한 공고는 다시 분석하면 점수가 생긴다.
- 졸업작품 설계서의 "기록 3건 미만이면 모델을 쓰지 않고 최신순으로 답한다"는 추천 모델 설계(미머지 브랜치)의 문장이라 이 작업에서 손대지 않는다.
- 일치도 계산식(요건 충족률)은 바꾸지 않는다.
