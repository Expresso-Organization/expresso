# 사용자 눈에 보이는 결함 넷 정리

## 개발 목표와 의도

2026-11-02 운영 사이트(expresso.ai.kr)를 돌아본 뒤 요청자가 고른 네 가지를 고칩니다.
"이거 삭제", "이거 해결하자", "편집기에서 생성 비용 보여줄 필요 없을 것 같아", "제거하던지 아니면 실제로 구현하던지".
로그인 화면 왼쪽에는 출처 없는 숫자 셋(12,400 · 4.2일 · 31%)이 서 있었고, 공개 포트폴리오 주소를 메신저에 붙이면 제목이 "Expresso"로만 떴습니다.
홈의 추천 공고 「만들기」와 「이어서 답하기」는 눌러도 아무 일이 없었습니다.
이 변경은 모두 화면 쪽이고, 저장 구조와 API 계약은 건드리지 않습니다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 로그인 지면 수치 제거 | 로그인 · 회원가입 왼쪽 패널에서 숫자 세 칸이 사라지고 문구와 로고만 남는다. | 세 숫자는 출처가 없다. 실제 수치처럼 보이는 가짜 데이터는 제품 원칙에 어긋난다. |
| 공개 포트폴리오 공유 메타 | 공개 주소를 카카오톡 · 링크드인 · 슬랙에 붙이면 포트폴리오 제목과 설명이 미리보기에 뜬다. 검색 노출을 끈 사이트는 검색엔진에 색인 금지 표시가 붙는다. | 지금은 모든 사이트가 "Expresso"로만 떠서 받는 사람이 누구의 포트폴리오인지 알 수 없다. 배포 설정의 제목 · 설명 · 색인 여부는 이미 저장하고 있는데 화면이 쓰지 않는다. |
| robots.txt | 앱 주소와 공개 주소 모두 `/robots.txt`가 응답한다. 앱 화면 경로는 수집 금지, 공개 포트폴리오는 허용이다. | 지금은 404 안내 화면이 응답한다. 검색엔진이 로그인 뒤 화면을 긁으려다 실패 기록을 남긴다. |
| 홈 추천 공고 「만들기」 연결 | 누르면 그 공고로 분석을 시작하고 새 포트폴리오 화면으로 간다. 공고 이름을 누르면 공고 상세로 간다. | 지금은 눌러도 아무 일이 없다. 홈에서 포트폴리오 제작으로 들어가는 가장 짧은 길이 끊겨 있다. |
| 홈 「이어서 답하기」 연결 | 누르면 멈춘 제작의 그 단계(재료 · 대화 · 디자인)로 바로 간다. 새 포트폴리오 화면의 「이어서 만들기」와 같은 규칙이다. | 지금은 눌러도 아무 일이 없다. 진행 중 작업을 보여 주면서 들어갈 문이 없다. |
| 공고 상세 기술 스택 중복 제거 | 공고 상세에서 기술 스택 칩 묶음이 한 번만 보인다. 요건을 뽑은 공고는 대조 상태가 붙은 묶음을, 아직 안 뽑은 공고는 본문에서 읽은 묶음을 보여 준다. | 같은 칩 스무 개가 화면에 두 번 서서 내용이 두 배로 길어 보인다. |
| 모바일 공고 탐색 머리 정리 | 375px 폭에서 수집처 안내 문구는 숨기고, 「관심 공고」 · 「알림 설정」은 한 줄로 서며, 카테고리 탭은 가로로 밀어 본다. | 지금은 글자가 한 자씩 세로로 떨어져 머리 영역이 화면 절반을 차지한다. |
| 편집기 생성 비용 표시 제거 | 편집기 머리의 "웹 QA 통과" 배지 옆에서 "$0.4835" 같은 달러 금액이 사라진다. | 생성 원가는 운영 지표이지 사용자가 볼 정보가 아니다. |
| `/career` 주소 연결 | `/career`를 열면 첫 번째 카테고리 화면으로 넘어간다. | 지금은 "그 주소에는 아무것도 없습니다"가 뜬다. 홈과 사이드바는 카테고리 주소로만 가서 사용자가 `/career`를 직접 치면 막힌다. |

## 개발 목표

- 로그인 화면: `/login`과 `/signup` 왼쪽 패널에 숫자 칸이 없다.
- 공유 메타: 배포된 사이트 주소를 `curl`로 받으면 `<title>`이 포트폴리오 제목이고 `og:title` · `og:url`이 있다. 색인을 끈 사이트는 `<meta name="robots" content="noindex">`가 있다.
- robots: `https://expresso.ai.kr/robots.txt`와 `https://{slug}.expresso.ai.kr/robots.txt`가 텍스트로 응답한다.
- 홈: 추천 공고 「만들기」를 누르면 `/brew/new/{분석 id}`로 간다. 「이어서 답하기」를 누르면 `/brew/{제작 id}/{단계}`로 간다.
- 공고 상세: 기술 스택 칩 묶음이 하나다.
- 모바일 공고 탐색: 375px에서 머리 영역 글자가 세로로 떨어지지 않는다.
- 편집기: 머리 배지에 달러 금액이 없다.
- `/career`: 첫 카테고리 화면으로 넘어간다.

## 범위 밖과 제약

- 랜딩 페이지는 이 작업에서 만들지 않는다. 화면 정의서(`docs/Expresso Landing.dc.html`)가 따로 있는 설계 작업이라 별도 세션으로 뗀다. `/`는 지금처럼 로그인으로 보낸다.
- sitemap은 만들지 않는다. 공개 사이트가 각각 다른 호스트(`{slug}.expresso.ai.kr`)이고 공개 slug 목록을 주는 API가 없다. 사이트별 색인은 메타 태그가 맡는다.
- OG 이미지는 붙이지 않는다. 포트폴리오마다 그릴 이미지가 없고, 브랜드 로고를 모든 사이트에 붙이면 주인의 포트폴리오가 아니라 Expresso 광고처럼 보인다.
- 홈 버튼 두 개는 열린 PR 118이 같은 방식으로 연결한다. 그 PR이 main과 충돌 중이라 기다리지 않고 같은 코드로 여기서 연결한다. PR 118을 머지할 때 이 부분은 한쪽을 고르면 된다.
- 기록 3건 조건과 홈 첫 실행 문구("기록 3건만 있으면")는 이 작업에서 손대지 않는다. 앞선 대화에서 기준 자체를 없애기로 했으므로 별도 변경으로 다룬다.

## 열린 질문

- 랜딩 페이지를 별도 세션으로 떼는 데 동의하는가. 동의하면 수락 뒤 세션 카드를 만든다.
