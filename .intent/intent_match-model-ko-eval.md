# 한국어 공고 적합도 평가 세트

## 개발 목표와 의도

파일럿 `fit-v1`의 공고는 JTH 영어 구조화 필드다. 서비스 공고는 수집한 한국어 원문이다. 그래서 `fit-v1`로 잰 성능은 서비스 성능을 말하지 못한다.

> "아니 성능은 무조건 한국어 공고로 재야해"
> "Sonnet 교사만으로 진행"

이번 변경은 파일럿 검증 · 평가 프로필(90명 · 70명)에 수집 한국어 공고를 10건씩 붙인 평가 세트를 만든다. 정답은 Claude Sonnet 5.5 교사가 같은 루브릭으로 매긴다. 인코더 비교 · Bi-Encoder+MLP · Cross-Encoder · Decisions API · Jev · 규칙 baseline의 성능은 모두 이 세트로 판정한다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 한국어 공고 내보내기 | 로컬 DB에서 본문이 한국어 위주인 공고를 직군 · 제목 · 원문과 함께 파일로 내보낸다 | 평가에 쓸 서비스 공고가 DB에만 있다 |
| 공고 요건 분해 | 내보낸 공고마다 서비스 요건 추출기를 한 번 돌려 요건을 붙인다 | 규칙 baseline(일치도 계산)이 요건 없이는 점수를 내지 못한다. 지금 공고의 요건 칸은 모두 비어 있다 |
| 후보 구성 | 프로필의 희망 직무와 공고 직군을 대응시켜 같은 직군 5 · 인접 3 · 무작위 2건을 고른다. 공고는 검증 · 평가로 반씩 나눈다 | 파일럿과 같은 규칙이어야 두 세트 수치를 나란히 읽는다 |
| Sonnet 교사 라벨 | 1,600쌍을 `claude-sonnet-5-5`가 루브릭 `job-profile-fit-v1`로 판정한다. 걸린 칸은 같은 대화에서 그 칸만 고쳐 받는다 | 한국어 공고에는 정답이 없다. 출력 전체를 다시 쓰게 하는 방식은 금지다 |
| 한국어 세트로 평가 | 실험 명령이 `fit-v1`로 학습하고 한국어 세트로 평가한다. Cross-Encoder는 한국어 쌍을 직접 채점한다 | 학습 데이터는 아직 영어뿐이다. 학습과 평가의 공고 원천이 달라도 돌아야 한다 |

## 개발 목표

- 맥에서 한국어 공고 내보내기가 공고 수 · 직군별 수 · 요건 분해 결과를 출력한다.
- 가짜 프로필로 후보 구성 → 가짜 교사 라벨 → `train-bi --eval-data` → `eval-cross`가 끝까지 돌고, 한국어 세트 지표가 나온다.
- 라벨링 러너가 문법 오류와 규칙 위반을 같은 세션(`--resume`)에서 고쳐 받는 것을 시험으로 확인한다.
- `pnpm ml:data:test`가 통과한다.

## 범위 밖과 제약

- 사람 판정 세트는 만들지 않는다(사용자 결정).
- 한국어 공고로 학습하는 `fit-v2`는 하지 않는다. 이번에는 평가만 한국어로 옮긴다.
- 프로필은 학습 PC에만 있으므로 후보 구성과 라벨링은 PC에서 한다.

## 열린 질문

- 학습 PC의 합성 프로필 원본 폴더(`<run-root>/profiles/<분할>/*.json`) 위치. 실행 절차에서 찾는 명령을 둔다.
