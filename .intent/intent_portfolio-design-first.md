# 디자인 먼저 생성과 단계별 화면 전달

## 변경 의도

지금 생성은 글을 먼저 다 쓰고(사례마다 본문 200자 안팎과 항목), 디자인은 그 글을 담을 칸을 고르는 일이라 어떤 디자인을 골라도 글의 나열로 나옵니다. 사용자는 그동안 5분 넘게 빈 화면을 봅니다. 포트폴리오를 디자인하는 것이 핵심이므로 지면을 먼저 설계하고, 글은 설계가 정한 자리만큼 채웁니다. 단계가 끝날 때마다 화면을 바로 보여 줍니다.

요청: "포트폴리오를 '디자인'하는게 핵심이야", "지면 설계가 끝나면 화면 구성이 바로 나타나고, 사용자가 보고 있는 상태에서 내용과 세부 디자인이 순차적으로 채워지게끔 하자"

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 지면 설계 | 모델이 자료 · 디자인 · 유형을 보고 먼저 지면을 설계한다. 첫 화면에 세울 문장이나 숫자, 크게 보여 줄 대표 작업, 작업마다의 시각 형태(수치 강조 · 전후 비교 · 과정 흐름 · 이미지 전시 · 인용), 섹션 순서와 비중, 싣지 않을 자료, 칸마다 글자 수를 정한다 | 글이 먼저면 디자인이 글을 담는 칸 고르기로 끝난다 |
| 시각 부품 | 수치 강조 줄, 전후 비교 막대, 과정 흐름, 이미지 격자, 큰 인용을 디자인 토큰으로 그리는 부품을 더한다 | 지금 부품은 대부분 제목 · 본문 · 항목표를 담는 칸이다 |
| 글 채우기 | 설계도의 칸을 기록 원문에서 정해진 글자 수 안으로 채운다. 숫자는 원문에서 찾은 것만 쓴다 | 글이 디자인을 따라가야 문서가 아니라 지면이 된다 |
| 청사진 전달 | 설계가 끝나면 생성 화면에 지면 구성이 바로 나타난다. 아직 그리지 않은 부분은 청사진처럼 선과 자리 표시로, 글 자리는 글이 올 때까지 스켈레톤 애니메이션으로 보인다 | 사용자가 5분 동안 빈 화면을 보지 않는다 |
| 순차 채움 | 사용자가 보는 화면에서 글이 칸마다 채워지고, 이어서 세부 디자인이 입혀진다. 화면은 깜빡이거나 맨 위로 튀지 않는다 | 결과가 만들어지는 과정이 곧 전달이다 |
| 지면 스크립트 | 구조화 지면에 우리 키트의 고정 스크립트를 싣는다. 해시로 고정한 스크립트만 돌고, 모델 · 사용자 내용에서 온 스크립트는 지금처럼 지운다. 공개 · 미리보기 지면은 앱과 출처를 나눈 격리 안에서 돌고 바깥으로 요청하지 못한다. 스크립트가 꺼져도 내용은 모두 보인다 | 차트 · 수치 · 스크롤 모션 · 탭 같은 표현이 스크립트 없이는 막힌다. 스크립트를 막은 근거(모델이 HTML을 직접 쓰던 자유 생성)는 구조화 지면에 해당하지 않는다 |
| 다듬기 확장 | 스크린샷 다듬기가 배치뿐 아니라 설계(무엇을 크게, 무엇을 뺄지)와 글자 수까지 고친다 | 지금 다듬기는 글을 못 건드려 재배치에서 끝난다 |

## 개발 목표

- 같은 가상 프로필 3종에서 새 구조의 지면이 수치 강조 · 전후 비교 · 과정 흐름 같은 시각 부품을 쓰고, 지금 구조와 나란히 놓은 비교 이미지에서 "글의 나열"이 아니다.
- 체험 서버 실제 생성에서 디자인 선택 뒤 청사진이 뜨기까지, 글이 다 차기까지, 다듬은 판까지의 시간을 각각 잰다. 청사진은 지금 초안(311초)보다 먼저 뜬다.
- 생성 화면을 녹화한 영상에서 청사진 → 스켈레톤 → 글 → 세부 디자인 순서로 깜빡임 없이 바뀐다.
- 공개 지면에서 키트 스크립트는 돌고, 내용에 넣은 스크립트와 바깥 요청은 막히며, 지면이 앱 쿠키 · API에 닿지 못함을 브라우저 테스트로 확인한다.
- `pnpm typecheck` · `pnpm test` · `pnpm test:infra` 통과.

## 범위 밖과 제약

- 사진 생성은 하지 않습니다. 차트는 라이브러리를 실제로 그려 보고(디자인 변수 색 · 390px 가독성 · 용량) 고릅니다.
- 모델이 HTML을 직접 쓰는 자유 HTML 지면은 지금처럼 스크립트 없이 둡니다.
- 편집(다듬기) 화면의 직접 편집은 새 부품을 깨지 않게만 합니다.
- PR #104 위에서 PR 하나로 작업하고, 단계는 커밋으로 나눕니다.
