# 설계서 그림의 제안서 양식 반영

## 문제

설계서의 구조 그림은 흰 상자 · 회색 선 · 작은 글자 위주라서 같은 내용을 다룬 제안서 그림보다 읽기 어렵다.
제안서 그림은 단계 머리표, 역할별 색(입력 · 동결 · 학습 · 출력), 굵은 상자 제목, 범례를 쓴다.

## 원하는 결과

- 교체(7): 그림 1.1 ← 제안서 12, 1.2 ← 38(막대 색과 칸 구분), 3.1 ← 26 · 27, 3.2 ← 32, 4.2 ← 29, 4.3 ← 30,
  6.1 ← 13.
- 추가(2): 4장 「두 모델의 단계적 활용」 ← 31, 3장 라벨 생성 방법 ← 33(루브릭 기반 교사 지식 증류).
- 그림은 A4 세로 본문 폭에서 읽히도록 다시 배치한다(제안서 1920px 지면을 그대로 줄이지 않는다).

## 영향 범위

`docs/졸업작품-설계서.html`의 그림 9개와 그림 CSS, PDF, md 초안의 그림 자리 설명. 결정 권한은 사용자(팀장).

## 제약

- 그림 안의 이름 · 수치는 설계서 본문과 같아야 한다. 다르면 본문(코드 근거)을 따른다.
- 3장은 「서비스가 수집한 공고 → 학습」 기준. 파일럿 방식(JTH jobs.csv)은 그림에 넣지 않는다.
- 쪽 수는 210쪽 안팎을 유지한다.

## 범위 밖

화면 슬라이드, 표지 · 목차, 비즈니스 모델 · 벤치마킹 · 팀 · 기술 스택, 제안서 14 · 28 · 39.
