# 설계서의 제안서 기준 정합

## 문제

졸업작품 설계서(v0.2, 2026-09-28)의 AI 학습 모델 설계는 2026-08-14 결정(LightGBM
lambdarank, 직접 설계한 특징 22·34차원, 동의 이력서 60명, Claude 교사 3구간 라벨)에
머물러 있다. 9월에 발표한 프로젝트 제안서는 사전학습 임베딩 기반의 Bi-Encoder+MLP 선별과
Cross-Encoder 재정렬, 합성 프로필 1,000개, 루브릭 교사 라벨로 바뀌었다. 설계서는 교차
인코더와 딥러닝을 근거를 들어 **제외**한다고 적고 있어 제안서와 결론이 반대다.
팀 구성 · 일정도 설계서에는 비어 있고 제안서에는 확정되어 있다.

같은 과제의 두 제출 문서가 서로 다른 모델을 말하면 심사에서 어느 쪽도 믿을 수 없다.

## 원하는 결과

- 설계서의 3 · 4 · 9장과 2.2 · 2.3 · 6.3 · 6.4 · 7.4 · 10.1이 제안서의 모델 구성을 말한다.
  - 채용 공고 추천 모델: 동결 `multilingual-e5-base` Bi-Encoder+MLP 선별 → `bge-reranker-v2-m3`
    Cross-Encoder 재정렬(마지막 4개 층 + 예측 헤드 학습)
  - 커리어 기록 추천 모델: 위 Cross-Encoder를 재사용해 (공고, 기록) 쌍을 채점하고, 관련성 ·
    요건 범위 · 경험 중복 기준으로 선택 조합을 정한다
  - 데이터: 청년패널조사 YP2021 · AI Hub 채용면접 인터뷰(71592) 근거 합성 프로필 1,000개,
    프로필 × 공고 10,000쌍, 학습 8,400 · 검증 900 · 평가 700
  - 라벨: 루브릭 교사(Luna · Sonnet), 필수 45 · 업무 40 · 우대 15%, 근거 점수 100/75/50/25/0
  - 인코더 비교: e5-base · KURE-v1 · BGE-M3 · Qwen3-Embedding-0.6B
  - 지표: NDCG@10 · Recall@K · MAE · 공고쌍 순서 일치율 · p95 지연 · 처리량
- 1.2에 15주 일정과 M1–M4 마일스톤(`codex/proposal-milestones`)이 들어간다.
- 1.3에 5명과 역할이 들어가고, 2.3 · 2.5 · 2.6의 개발담당 210행이 아래 대응표로 채워진다.
- md 초안 · HTML · PDF 세 벌이 같은 내용이다. 「LightGBM」 · 「lambdarank」 · 「22차원」 ·
  「feature_spec」이 본문에 남지 않는다.

## 제약

- 제안서에 없는 수치를 새로 만들지 않는다. 설계서에 있던 근거 없는 값(NDCG ≥ 0.80 같은
  목표치, κ ≥ 0.6 게이트, $45–90 비용, LightGBM 파라미터)은 걷어내고 「확정 전」으로 적는다.
- 코드에서 센 값(어댑터 7종, 경로 163개 등)은 제안서보다 최신이므로 유지한다.
- 그림은 `docs/AGENTS.md`의 출처 규칙을 따른다. 문체는 기존 평서체를 유지한다.

## 범위 밖

- 제안서 수정. 제안서가 더 오래된 곳(수집 출처, 클라이언트 범위)은 보고만 한다.
- 5.5 관리자 화면 21개, 7.3 API 설계 확장, 8.2 추출 스크립트.
- 학습 모델 구현과 9.2 ROC 실측.

## 열린 질문

1. 모델 B가 Cross-Encoder를 재사용할 때 별도 (공고, 기록) 라벨로 다시 학습하는가?
   — 기본안: 하지 않는다. 같은 가중치로 채점하고, 프로필 단위로 학습한 모델을 기록 1건에
   쓰는 분포 차이를 한계로 적는다.
2. 양식이 요구하는 9.2 ROC의 양성 기준을 무엇으로 두는가? — 기본안: 루브릭 「직접 근거」
   (75점) 이상을 양성으로 둔다. 루브릭에 있는 값이므로 새로 만든 수치가 아니다.
3. 1.3의 학번은 제안서에 없다. — 기본안: 빈칸으로 둔다.
