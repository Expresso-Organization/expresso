# 공고 상세 우측 사이드바의 공고 전용 에이전트 채팅과 P1~P8 기능 흡수

## 문제

1. 공고 상세(`/jobs/[jobId]`) 우측 사이드바는 범용 에이전트 채팅(`AgentChat`)을
   그대로 끼워 넣은 상태라 공고를 보며 대화하는 쓰임에 맞지 않는다.
   - 환영 화면이 범용 문구이고 표제가 316px 폭의 절반을 차지한다. 공고 이름 · 회사가
     없다.
   - 시작 제안 "기록 다듬기"는 기록이 연결되어야 동작하는데, 공고 페이지의 새 대화에는
     공고만 연결된다.
   - 대화 복원이 주소의 `?chat=`과 브라우저 전역 `sessionStorage`를 따라서 다른 공고의
     대화가 열린다.
   - 채팅은 고정 높이 카드이고 아래로 일치율 · 빠진 재료 · 회사 톤 · "이 공고로
     포트폴리오 만들기" 카드가 이어진다.
2. 공고 기반 대화 기능(P1~P8)이 공통 채팅과 별개로 개발되었다. PR 59(P1~P5)는
   `codex/agent-chat` 브랜치에 별도 `/agentic-chat` 화면과 `job-chat` ·
   `job-career-match` 백엔드로 들어갔고, PR 65 · PR 70(P6~P8)은 그 위에서 패널을
   `AgentChat` 아래에 덧붙였다. 대화 저장 · 공고 연결이 공통 채팅과 중복되고, 운영
   경로(Claude 런타임)에서는 모델이 맞춤 분석 결과와 인터뷰 규칙을 받지 못한다 — 둘 다
   로컬 Codex 런타임에만 들어 있다. 기반은 공통 `AgentChat`(PR 22)이고, 그 PR들에서는
   기능만 가져온다.

## 원하는 결과

공고 상세 우측 사이드바에는 에이전트 채팅만 있고, 아래 기능이 그 대화 안에서 동작한다.

| | 기능 | 출처 |
|---|---|---|
| A1 | 채팅이 사이드바 위아래 전체 높이를 쓰고, 대화는 채팅 안에서만 스크롤된다. 1023px 이하에서 사이드바가 본문 아래로 내려가면 정해진 높이 안에서 동작한다 | 요청 |
| A2 | "이 공고로 포트폴리오 만들기" · 일치율 · 빠진 재료 카드가 없다. 회사 톤은 왼쪽 본문 맨 아래 절로 옮긴다 | 요청 |
| A3 | 공고 페이지는 이 공고가 연결된 가장 최근 대화를 연다. 없으면 이 공고가 연결된 새 대화. 목록에서 고른 대화와 "크게 열기"(`/agent`)는 그대로 이어진다 | 요청 |
| A4 | 새 대화 첫 화면에 회사 · 직무명이 보이고, 시작 제안은 공고 하나만 연결된 상태에서 동작하는 것만 둔다 | 요청 |
| A5 | 실패한 질문을 같은 질문으로 다시 보낼 수 있다 | P2 |
| B1 | 요건 대조: 요건마다 강함 · 일부 · 미확인 판정, 공고 인용, 내 기록 인용, 보완 제안이 카드로 나온다. 기록이나 공고가 바뀌면 카드에 "다시 대조 필요"가 표시된다 | P3 |
| B2 | 보완 인터뷰: 미확인 · 일부 요건부터 한 번에 한 질문씩 묻고, 역할 · 행동 · 결과 중 빠진 것을 이어 묻고, 충분하거나 사용자가 멈추면 멈춘다 | P4 |
| C1 | 대화에서 말한 경험으로 새 경력 기록 초안이 카드로 나온다. 출처 발언 인용, 제목 · 본문 수정, 카테고리 선택 후 승인하면 새 기록으로 저장, 거절하면 저장하지 않는다 | P5 |
| D1 | 보완점 정리: 확인 필요 · 보완 필요, 우선순위, 근거, 다음 행동이 카드로 나온다 | P6 |
| D2 | 준비 계획: 고른 보완점과 주당 시간 · 기간 · 시작일로 주차별 작업이 나오고, 수정 · 승인 · 거절할 수 있다 | P7 |
| D3 | 진행 기록: 승인한 계획의 작업마다 상태 · 메모 · 결과 · 링크 · 사용 시간을 남기고, 남은 작업을 다시 배치할 수 있다 | P8 |

- 기존 기록 변경 제안 · 승인 · 되돌리기, 대화 목록, 자료 추가는 지금처럼 동작한다.
  `/agent`와 커리어 기록 편집기의 채팅은 겉모습이 바뀌지 않는다.
- 화면 정의서 06b(공고 상세)의 우측 레일이 바뀐 화면과 일치한다.

## 흡수 방식 (제안)

- **에이전트 도구 + 대화 안 카드.** 공통 채팅의 기존 방식(`propose_record_edit` →
  카드 → 승인)을 모든 기능에 쓴다. 에이전트가 도구를 부르고, 서버가 검증 · 저장하고,
  결과가 대화 안 카드로 나오고, 승인은 카드에서 한다. 도구 결과가 에이전트에게
  돌아가므로 B2 인터뷰가 B1 결과를 근거로 질문한다.
- **분석은 에이전트가 쓰고 서버가 검증한다.** B1 · D1은 별도 AI 호출 없이 에이전트가
  도구 입력으로 구조화된 결과를 낸다. 서버는 P3 · P6의 인용 검증(공고 · 기록 원문 안에
  그대로 있는지)과 입력 지문 · 최신성 판정을 가져와 적용한다.
- **기록 읽기 도구.** 에이전트가 연결되지 않은 내 기록도 볼 수 있도록 기록 목록 · 기록
  읽기 도구를 둔다. 기록 사용은 지금 채팅이 이미 받는 동의(`career_records`)로 다룬다.
  P3 · P6이 새로 요구한 `job_chat` · `job_career_match` · `job_career_gap` 동의 범위는
  만들지 않는다.
- **규칙 기반 계산은 로직을 옮긴다.** P7 계획 배치(`planner.ts`), P8 재배치
  (`scheduleRemaining`), P5 승인 트랜잭션(기록 생성 + 계산 이벤트). 계획 승인 · 진행
  기록처럼 AI가 필요 없는 동작은 에이전트가 꺼져 있어도 카드에서 된다.
- **좁은 폭 배치.** 계획 카드는 주차 · 작업 요약만 보이고, 수정은 기존 자료 미리보기
  대화상자 형식으로 연다. 승인된 계획 카드가 그대로 진행 체크리스트가 된다. 재배치는
  폼이 아니라 에이전트 도구로 요청한다.

## 영향 범위

- 화면: 공고 상세. `/agent` · 커리어 기록 편집기는 새 도구 카드가 나올 수 있다.
- 웹: `jobs/[jobId]/page.tsx` · `page.module.css`, `features/agent-chat/*`(공고 모드,
  도구별 카드), `docs/Expresso Screens.dc.html` 06b.
- 백엔드: `modules/agent-chat`, `platform/agent/runtime.ts`(도구 · 시스템 프롬프트),
  새 모듈(요건 대조, 새 기록 제안, 보완점, 준비 계획, 진행 기록), 계정 삭제 연결.
- 계약 · 데이터: `packages/contracts`의 도구 결과 타입, `packages/database`의 새
  컬렉션과 마이그레이션 0011부터.
- 결정 권한: Nedian0Brien.

## 제약

- 기반은 main의 공통 에이전트 채팅이다. `codex/agent-chat` 브랜치(PR 59 병합분)와
  PR 65 · 70의 구조 · 경로 · 저장 방식은 따르지 않는다.
- 색 · 크기는 `tokens.css`의 `--ex-*`. 내부 단계명(P3, P6 등)은 화면 문구와 저장
  데이터에 쓰지 않는다. 고정 문자열 메시지로 기능을 분기하지 않는다.
- 단계마다 테스트를 둔다: 인용 검증 · 배치 로직 단위 테스트, 승인 트랜잭션 통합 테스트,
  공고별 대화 선택 테스트.
- 로컬 확인은 이 워크트리 전용 DB · 큐 접두사로 한다(공유 DB에 다른 브랜치의 0011~0013이
  적용되어 있을 수 있다). 에이전트 실행 확인에는 `AGENT_CHAT_ENABLED=1`과 로컬 Claude
  로그인이 필요하다.

## 전달 방식 (제안)

이 intent를 묶음 기준으로 두고, 의존 순서대로 PR을 쌓는다. 각 단계는 spec · plan을
따로 둔다(`job-chat-rail-a` 등).

| PR | 내용 | 의존 |
|---|---|---|
| A | A1~A5, 정의서 06b | main |
| B | B1 · B2, 기록 읽기 도구, 도구별 카드 분기 구조 | A |
| C | C1 | B |
| D | D1 → D2 → D3 (각각 앞 단계 결과를 읽으므로 나누지 않는다) | B |

A는 단독으로 먼저 머지할 수 있다.

- 가져오지 않는 것: `job_chat_sessions` · `job_chat_messages`와 그 마이그레이션,
  `POST /job-chat/messages`, `/agentic-chat` · `/career-test` 화면,
  `AiClientAgentRuntime`과 `AGENT_CHAT_PROVIDER=codex`(로컬 개발용, 필요하면 별도),
  PR 65의 `layout.tsx` 테마 스크립트 이동(테마 깜빡임 회귀), PR 59의 커리어 기록 삭제
  버튼(무관한 기능).
- PR 59 · 65 · 70을 닫는 것과 `codex/agent-chat` 브랜치 정리 — 사용자가 결정한다.

- `/agent` · 기록 편집기 채팅의 디자인 변경.

## 열린 질문

1. 요건 대조(B1)와 보완점 정리(D1)는 개념이 겹친다. 제안: 따로 둔다 — 대조는 요건별
   판정, 보완점은 그 결과와 대화 답변을 바탕으로 한 할 일 목록이다.
2. 에이전트가 한 번의 도구 입력으로 요건 12개 × 인용을 내는 크기가 Claude Agent SDK에서
   문제없는지 B의 spec에서 확인한다. 문제가 있으면 요건을 나눠 여러 번 기록하는 도구로
   바꾼다.
