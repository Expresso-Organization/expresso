# 수치 출처 검사의 HTML 엔티티 오탐 수정

## 개발 목표와 의도

요청: "수치 출처 검사의 HTML 엔티티 오탐 수정."

생성된 지면에 따옴표가 든 글("사내 디자인 시스템 '모아 UI'")이 있으면, 편집 화면 QA에 "수치 출처를 검토해 주세요" 경고가 뜹니다. 2026-10-28 체험 생성 판에서 출처 없는 수치로 잡힌 값은 "27"이었습니다. 지면에 27이라는 숫자는 없습니다. React가 작은따옴표를 `&#x27;`로 써서 내보내는데, 보이는 글을 뽑는 함수가 이 표기를 풀지 않고 숫자로 읽었습니다. 사용자는 고칠 것이 없는 경고를 보게 됩니다.

이번 변경은 보이는 글을 뽑을 때 HTML 문자 표기를 글자로 풀어, 지면에 실제로 보이는 숫자만 검사하게 합니다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 문자 표기를 푼 뒤 수치 검사 | 편집 화면 QA의 수치 출처 검사가 `&#x27;` · `&#39;` · `&quot;` 같은 표기를 글자로 바꾼 뒤 숫자를 셉니다. 따옴표가 든 지면에서 "27" · "39" 경고가 사라집니다. | 지금은 따옴표 하나로 경고가 떠, 진짜 출처 없는 수치 경고와 구별되지 않습니다. |
| 표기 풀기 한 곳으로 | 공고 수집기 두 곳이 따로 쓰던 표기 풀기를 같은 함수로 바꿉니다. | 같은 일을 세 군데에서 조금씩 다르게 하고 있고, 그중 어느 것도 `&#x..;` 꼴을 풀지 않습니다. |

## 개발 목표

- `'모아 UI'`가 든 지면 HTML로 수치 출처 검사를 돌리면 출처 없는 수치가 0개입니다.
- 지면에 실제로 출처 없는 숫자가 있으면 지금처럼 잡힙니다.
- 공고 수집기 테스트(`jobs/ingest`)가 지금 결과 그대로 통과합니다.
- `pnpm test`가 통과합니다.

## 범위 밖과 제약

- 이미 저장된 판의 QA 결과는 다시 계산하지 않습니다. 새로 생성하거나 다듬은 판부터 맞게 나옵니다.
- 공고 수집기의 "세 번까지만 푼다" 규칙은 그대로 둡니다. 한 번 푸는 함수만 공용으로 씁니다.
