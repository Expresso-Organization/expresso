# 검색 칸 · 검색 버튼 pill 곡률 통일

## 개발 목표와 의도

검색 칸과 검색 버튼의 모서리 곡률이 화면마다 다르다. 요청자의 말: "사이트의 검색바, 검색 버튼 등의 곡률이 다른 문제가 있어. 검색바와 검색 버튼을 pill 형태로 통일하고 곡률을 통일하자."

실제 장면: 공고 탐색(`/jobs`)의 검색바는 양 끝이 완전히 둥근 pill인데, 그 안의 「찾기」 버튼은 모서리만 살짝 둥근 사각형이다. 검색어를 넣으면 같은 검색바가 모서리 16px의 카드로 바뀐다. 공고로 시작하기(`/brew/new`)의 검색바는 11px 사각형이고 「찾기」 버튼은 8px이다. 홈(`/home`)만 검색바와 버튼이 모두 pill이다.

앱의 모든 검색 칸을 홈과 같은 pill로 맞추고, 그 곡률 값을 한 곳에서 가져오게 한다. 다른 컴포넌트의 곡률 불일치는 이번에 고치지 않고 스크린샷 보고서로 따로 낸다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 큰 검색바와 검색 버튼 pill 통일 | `/jobs` 빈 검색바의 「찾기」 버튼, `/brew/new` · `/portfolio/new`의 검색바와 「찾기」 버튼, `/brew/new` 공고 목록의 검색 칸이 홈처럼 양 끝이 둥근 모양이 된다. | 같은 일을 하는 칸이 화면마다 다른 모양이면 같은 기능으로 읽히지 않고, 한 바 안에서 바와 버튼의 곡률이 다르면 어긋나 보인다. |
| `/jobs` 확정 검색바를 pill로 분리 | 검색어를 넣은 뒤에도 검색 줄은 검색 전과 같은 pill 바로 남는다. 「이렇게 이해했습니다」와 조건 칩 줄은 그 바 아래 별도 줄로 선다. | 검색 버튼을 누르는 순간 바가 카드로 모양을 바꾸면 같은 검색바로 보이지 않는다. 요청자가 이 방식을 골랐다. |
| 작은 검색 칸 pill 통일 | 커리어 표 툴바의 「기록 검색」, 에이전트 채팅의 대화 · 자료 검색, 지표 라이브러리의 지표 찾기, 디자인 카탈로그 검색, 편집기 기록 찾기 칸이 pill이 된다. | 「검색 칸은 pill」이라는 규칙 하나로 앱 전체를 읽을 수 있게 한다. 요청자가 작은 칸까지 포함하기로 골랐다. |
| pill 곡률 토큰 | 디자인 토큰 파일(`tokens.css`)에 pill 곡률 값이 생기고 위 칸과 버튼이 모두 그 값을 쓴다. | 지금은 같은 pill 값(999px)이 89곳에 숫자로 흩어져 있어, 곡률을 다시 맞출 때 찾을 자리가 없다. |
| 검색 칸 곡률 검사 | 검색 칸 스타일에 pill이 아닌 곡률을 적으면 웹 테스트가 실패한다. | 새 검색 칸이 다시 다른 곡률로 들어오는 것을 사람이 화면마다 찾아낼 수 없다. |

## 개발 목표

- `/home`, `/jobs`, `/brew/new`, `/portfolio/new`에서 검색바와 그 안 버튼이 모두 양 끝이 둥글다.
- `/jobs?q=프론트엔드`에서 검색 줄이 검색 전과 같은 pill이고, 조건 칩과 칩 팝오버가 그대로 동작한다.
- 커리어 표 툴바, 에이전트 채팅, 지표 라이브러리, 디자인 카탈로그, 편집기 기록 찾기의 검색 칸이 pill이다.
- 검색 칸 하나의 곡률을 사각형으로 바꾸면 `pnpm --filter @expresso/web test`가 실패한다.
- 전수 조사 보고서에 고친 곳의 전후 스크린샷과 남은 불일치의 스크린샷이 있다.

## 범위 밖과 제약

- 버튼 · 입력 칸 · 칩 · 카드 · 팝오버의 곡률 불일치는 보고서에만 싣고 고치지 않는다. 곡률 단계를 정할 근거가 화면 정의서에도 없어 요청자의 결정이 필요하다.
- 통합 검색(⌘K) 창은 대화상자 머리에 붙은 입력 줄이라 바꾸지 않는다.
- 검색 칸을 눌렀을 때 생기는 테두리는 PR #179가 다루므로 건드리지 않는다.

## 열린 질문

없음. `/jobs` 확정 상태와 작은 검색 칸 범위는 요청자가 답했다.
