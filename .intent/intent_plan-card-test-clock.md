# 준비 계획 카드 테스트의 오늘 날짜 고정

## 개발 목표와 의도

`PlanCards.test.tsx`의 "불러온 계획에 진행을 저장하고, 완료에 결과가 없으면 이유를 보인다"가 2026-10-26부터 실패합니다. 요청: "테스트가 오늘 날짜에 기대지 않도록 시계를 고정하거나 기준 날짜를 주입한다."

원인은 상태 표기가 아니라 펼쳐 두는 주입니다. 준비 계획 카드는 처음 열릴 때 오늘이 든 주 하나만 펼칩니다(`PlanCard.tsx`의 `currentWeek`, 오늘은 `new Date()`). 테스트 자료의 두 작업은 2026-10-19 주와 2026-10-26 주에 있습니다. 10-26부터는 둘째 주가 펼쳐지고 첫째 주가 접혀서 `작업 1 · 시작 전` 버튼이 화면에 없습니다. 11-02부터는 오늘이 든 주가 없어 끝나지 않은 첫 주가 펼쳐지므로 다시 통과합니다. 실패하는 기간은 10-26부터 11-01까지입니다.

오늘이 든 주를 펼치는 것은 의도한 제품 동작이고 맞게 동작합니다. 그래서 제품 코드는 그대로 두고 테스트가 쓰는 오늘을 고정합니다. 테스트 하나를 위해 카드에 기준 날짜 속성을 새로 만들지 않습니다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 테스트의 오늘 고정 | 이 테스트 파일이 도는 동안 오늘을 2026-10-21(첫째 주 수요일)로 둡니다. 날짜만 바꾸고 타이머는 실제 시간으로 돕니다. | 고정하지 않으면 테스트 결과가 실행한 날짜에 따라 달라지고, 같은 자료로 매주 다른 주가 펼쳐집니다. |

## 개발 목표

- 2026-10-26 오늘 `PlanCards.test.tsx`의 네 테스트가 모두 통과합니다. 고치기 전에는 1개 실패, 3개 통과입니다.
- 같은 파일을 시스템 날짜를 바꿔(10-26, 11-02 등) 돌려도 결과가 같습니다.
- 다른 테스트 파일에 날짜 고정이 남지 않습니다(각 테스트가 끝나면 실제 시계로 돌아갑니다).
- `pnpm typecheck`와 웹 패키지 `pnpm test`가 통과합니다.

## 범위 밖과 제약

- 제품 코드(`PlanCard.tsx`)는 바꾸지 않습니다.
- `currentWeek`가 오늘은 기기 시간대 날짜로, 주의 끝은 UTC로 계산하는 불일치는 이 실패의 원인이 아니므로 이번에 다루지 않습니다.
