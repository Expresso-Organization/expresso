# 큐 통합 시험 Mongo 도달 불가 지연 확인의 간헐 실패 수정

## 개발 목표와 의도

"그럼 이슈 발행하고 문제 찾아서 해결해봐" (이슈 #189)

웹 파일만 바꾼 PR #185의 백엔드 CI가 `queue.integration.test.ts`의 「Mongo 도달 불가(서버 선택 실패)는 시도 횟수를 쓰지 않고 미룬다」에서 `expected +0 to be 1`로 실패했고, 다시 돌리니 통과했다. 코드와 관계없이 CI가 깨지면 PR마다 다시 돌리는 일이 생기고, 진짜 실패를 흔들림으로 넘길 위험이 커진다.

원인은 시험이 잡을 먼저 읽고 상태를 나중에 읽는 순서다. 그 사이에 워커가 잡을 끝내면 끝나기 전 값(`attemptsMade: 0`)을 들고 completed로 판정한다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 완료 확인 순서 수정 | 시험이 상태가 completed인 것을 먼저 확인한 뒤 잡을 새로 읽어 `attemptsMade`를 본다. | 지금 순서는 끝나기 전 값을 읽을 수 있어 CI가 코드와 관계없이 깨진다. |

## 개발 목표

- 이 시험을 로컬에서 반복 실행했을 때 수정 전에는 실패가 나고, 수정 후에는 같은 횟수에서 실패가 없다.
- 운영 코드(`createQueueWorker`)는 바뀌지 않는다.

## 범위 밖과 제약

- 다른 통합 시험의 대기 방식은 바꾸지 않는다. 상태만 보는 대기(`getState()`만 비교)는 같은 경합이 없다.
