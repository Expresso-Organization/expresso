# 구현 순서
1. packages/contracts/agent-chat 및 packages/database 마이그레이션: 대화/실행 계약과 인덱스.
2. backend/platform/agent 및 modules/agent-chat: Claude SDK, 도메인 도구, 소유권, 스트리밍, 취소, 변경 승인.
3. web/features/agent-chat: 프레임워크 기반 공유 UI, 대화 목록, 문맥 표시와 페이지 간 이동.
4. 공고/커리어 화면과 셸에 연결하고 별도 채팅 탭 제공.
5. 타입·단위·실제 MongoDB/Redis 검사, 브라우저에서 이어가기/복원/승인/취소 확인.
6. 변경 파일만 커밋·푸시. 기존 main 작업과 프레임워크 원본은 보존.
실행 복구는 메시지와 실행 상태의 서버 저장을 기준으로 한다. 종료된 모델 프로세스의 자동 재실행은 하지 않고 중단 상태로 복원한다.
검증: pnpm typecheck, pnpm test, pnpm test:infra 및 공통 채팅 브라우저 검증.

## 구현 중 확정
- 서버가 저장한 전체 상태를 SSE로 전달한다. 초기 구현에서는 MongoDB 상태 조회를 재사용해 재연결 시 중복 델타를 방지한다. Redis는 기존 인프라 검증 대상이며 채팅 이벤트의 별도 저장소로 추가하지 않았다.
- 대화당 100개 메시지, 입력 8,000자, 출력 64,000자, 턴당 8단계/600초/$1 한도를 둔다.
- 프레임워크 thread.aui 구성을 제품 토큰으로 옮기고 ExternalStoreRuntime에 연결했다. core 0.3.18의 assistant-cloud 불일치로 프레임워크와 같은 core 0.3.17을 고정했다.
- 기록 변경 도구는 SDK가 구조화 명령을 만들어 기존 CareerDocumentService의 검증/제안/적용 경로를 사용한다.
- test/support/agent-chat-preview.ts는 별도 DB와 검증 계정만 사용한다. AGENT_CHAT_LIVE=1이면 실제 Claude 실행 어댑터로 검증한다.

- 사용자 검토 후 자체 구성한 채팅 메시지·입력창을 제거했다. 프레임워크 원본 Thread 및 의존 컴포넌트 21개를 직접 이식하고, 원본 파일별 출처를 framework-manifest.json에 기록한다. UI 문구·제품 테마 변수·도메인 승인 슬롯만 연결한다.

## 검증 결과
- 전체 타입 검사 및 웹/백엔드 빌드 통과.
- 공통 채팅 집중 테스트: 백엔드 8개, 프론트엔드/BFF 5개 통과.
- 백엔드 전체 테스트 308개 통과, 인프라 테스트 205개 통과(환경 조건에 따른 skip 별도).
- 웹 전체 205개 통과. PropertyValueEditor의 기존 숫자 오류 문구 테스트 1개 실패: 변경 전 main에서도 같은 오류를 재현했다.
- 실제 Claude 로그인으로 일반 응답, 공고 문맥, 커리어 기록 변경 제안/적용/되돌리기, 실행 중지와 새로고침 복원을 브라우저에서 확인했다.
- 프레임워크 원본 /chat과 실제 화면을 비교했다. 이식한 21개 중 19개는 원본과 동일하고 2개는 문구/기능 가드만 수정했다.
- 검증 미리보기: http://127.0.0.1:3110/agent (별도 expresso_agent_chat_preview DB). 운영 활성화는 마이그레이션 후 AGENT_CHAT_ENABLED=1과 Claude 인증 설정이 필요하다.

## 익스프레소 디자인 적용
- 사용자 요청에 따라 원본 Thread/Composer를 유지하고 Welcome/AssistantHeader/도구 슬롯 및 CSS Modules로 제품 디자인을 적용한다.
- 기존 LogoMark, Phosphor 아이콘, --ex-* 역할 토큰, 서체/글줄 스케일을 사용한다. 새로운 브랜드 이미지는 만들지 않는다.
- 독립 화면의 대화 목록, 현재 문맥 표시, 실제 입력으로 연결되는 시작 질문, 변경 승인 강조를 디자인한다. 패널과 작은 화면에서는 목록을 접는다.
- 표시 이름은 사용자 최종 선택인 `Expresso AI`로 통일했다.
- 1440×900 독립 화면/공고 패널, 390×844 모바일에서 확인했다. 가로 넘침이 없고 모바일 입력창이 화면 안에 유지된다.
- 시작 작업 버튼의 입력창 연결을 확인했다. 기존 대화와 변경 제안은 보존했다.
- 타입 검사·웹 빌드·토큰/대화 집중 검사 11개 통과. 전체 테스트에는 기존 PropertyValueEditor 숫자 문구 실패 1건이 동일하게 남는다.

## 대화 목록 사이드바 정리
- 사용자 검토에 따라 독립 채팅의 두 번째 사이드바를 제거하고 현재 대화 제목에 검색·전환 팝업을 연결했다. 새 대화 버튼과 자료 행은 헤더에 유지한다.
- 독립 화면·공고·커리어 기록에서 공통 ConversationSwitcher를 사용한다. 프레임워크의 원본 shadcn Popover를 추가하고 출처/해시를 기록했다.
- 제목 검색, 검색 결과 없음, Enter 전환, Escape 닫기와 제목으로 초점 복원을 실제 브라우저에서 확인했다. 한글 조합 중 Enter는 전환하지 않는다.
- 1440×900 독립 화면/공고 패널과 390×844 모바일 메뉴를 확인했다. 모바일 가로 넘침이 없다.
- 전체 타입 검사와 웹 빌드 통과. 웹 테스트 205개 통과, 기존 PropertyValueEditor 숫자 오류 문구 테스트 1개 실패 유지.

## 우측 채팅 목록 배치
- 사용자가 제목 메뉴 방식 대신 우측 사이드바를 요청했다. 독립 화면의 오른쪽에 검색·최근 대화 목록을 고정하고 제목을 일반 텍스트로 복원했다.
- 모바일과 공고/커리어 패널에서는 우측 상단의 명시적인 채팅 목록 버튼으로 목록을 연다. 기존 프레임워크 Thread와 대화 데이터는 유지한다.
- 1440px 화면의 우측 목록 검색·Enter 전환 및 390px 모바일 목록 열기를 브라우저에서 확인했다. 모바일 가로 넘침 없음.
- 타입 검사와 웹 빌드 통과. 웹 테스트 205개 통과, 기존 숫자 입력 문구 테스트 실패 1건 유지.

## 대화와 자료 목록 탭
- 사용자 요청으로 우측 목록 상단을 채팅 / 커리어 기록 / 채용 공고 / 내 포트폴리오 탭으로 확장했다. 프레임워크 원본 shadcn Tabs를 재사용하고 출처 해시를 등록했다.
- 기록·공고·포트폴리오는 기존 계약 및 API 클라이언트로 조회한다. 인증 쿠키를 서버에서만 읽는 GET BFF를 추가하고 종류·쿼리·응답 계약을 검증한다.
- 기록/공고 검색, 페이지 추가 조회, 로딩·빈 목록·오류/재시도를 제공한다. 기록·공고 상세 이동은 현재 대화 ID를 유지한다. 내 포트폴리오는 편집 화면으로 이동한다.
- 실제 브라우저에서 1440px 우측 탭, 기록/공고 데이터, 기록 상세 이동과 대화 ID 유지, 검증 계정의 포트폴리오 빈 목록을 확인했다. 390px 모바일에서도 네 탭과 공고 검색 빈 결과를 확인했고 가로 넘침이 없다.
- 전체 타입 검사·웹 빌드 통과. 새 BFF 검사 5개 통과(인증, 종류/쿼리 제한, 커서 전달, 응답 계약 오류, 연결 실패). 웹 전체 210개 통과, 기존 PropertyValueEditor 숫자 오류 문구 실패 1개 유지.

## 좌측 사이드바 로직 공통화
- 사용자 요청에 따라 우측 자료 목록도 좌측의 SidebarFrame, SidebarCollapseProvider, GlideMenu, 행/선택 CSS를 직접 재사용한다.
- SidebarFrame에 선택적 제목·접근성 이름·접힌 내용 슬롯을 추가했다. 기존 좌측 호출은 기본값을 유지한다. 접힘 저장 키를 분리해 좌우 상태가 간섭하지 않는다.
- 양쪽 폭 250px, 접힌 폭 56px, 크롬 배경·테두리·그룹 제목·목록 행·하이라이트를 공유한다. 우측 네 탭과 API 연결은 유지하고 접힌 레일의 아이콘에서 해당 탭을 펼칠 수 있다.
- 브라우저에서 우측 접기→새로고침 복원(좌측250/우측56), 기록 아이콘→기록 탭 펼침, 모바일 네 목록을 확인했다. 저장 키 독립성과 재마운트 복원 테스트 통과.
- 웹 빌드 통과. 전체 웹 검사의 기존 숫자 문구 실패는 유지된다. 추가 저장 상태 테스트의 환경 초기화를 수정하고 집중 재검사에서 통과했다.

## shadcn line 탭 적용
- 사용자 지정 shadcn Tabs line 문서에 맞춰 기존 TabsList의 variant="line"을 사용한다. 아이콘 시안을 텍스트 탭으로 되돌리고 탭의 색·글자 크기·밑줄을 덮던 CSS를 제거했다.
- 기존 원본 Tabs 컴포넌트의 기본 선택 밑줄과 텍스트 스타일을 적용하고 가로 폭만 패널에 맞춘다.
- 실제 화면에서 텍스트/선택 밑줄과 방향키 전환 확인. 전체 타입 검사 통과, 웹 테스트 211개 통과 및 기존 숫자 입력 문구 실패 1건 유지.
