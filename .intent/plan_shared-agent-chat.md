# 구현 순서
1. packages/contracts/agent-chat 및 packages/database 마이그레이션: 대화/실행 계약과 인덱스.
2. backend/platform/agent 및 modules/agent-chat: Claude SDK, 도메인 도구, 소유권, 스트리밍, 취소, 변경 승인.
3. web/features/agent-chat: 프레임워크 기반 공유 UI, 대화 목록, 문맥 표시와 페이지 간 이동.
4. 공고/커리어 화면과 셸에 연결하고 별도 채팅 탭 제공.
5. 타입·단위·실제 MongoDB/Redis 검사, 브라우저에서 이어가기/복원/승인/취소 확인.
6. 변경 파일만 커밋·푸시. 기존 main 작업과 프레임워크 원본은 보존.
실행 복구는 메시지와 실행 상태의 서버 저장을 기준으로 한다. 종료된 모델 프로세스의 자동 재실행은 하지 않고 중단 상태로 복원한다.
검증: pnpm typecheck, pnpm test, pnpm test:infra 및 공통 채팅 브라우저 검증.

## 구현 중 확정
- 서버가 저장한 전체 상태를 SSE로 전달한다. 초기 구현에서는 MongoDB 상태 조회를 재사용해 재연결 시 중복 델타를 방지한다. Redis는 기존 인프라 검증 대상이며 채팅 이벤트의 별도 저장소로 추가하지 않았다.
- 대화당 100개 메시지, 입력 8,000자, 출력 64,000자, 턴당 8단계/600초/$1 한도를 둔다.
- 프레임워크 thread.aui 구성을 제품 토큰으로 옮기고 ExternalStoreRuntime에 연결했다. core 0.3.18의 assistant-cloud 불일치로 프레임워크와 같은 core 0.3.17을 고정했다.
- 기록 변경 도구는 SDK가 구조화 명령을 만들어 기존 CareerDocumentService의 검증/제안/적용 경로를 사용한다.
- test/support/agent-chat-preview.ts는 별도 DB와 검증 계정만 사용한다. AGENT_CHAT_LIVE=1이면 실제 Claude 실행 어댑터로 검증한다.

- 사용자 검토 후 자체 구성한 채팅 메시지·입력창을 제거했다. 프레임워크 원본 Thread 및 의존 컴포넌트 21개를 직접 이식하고, 원본 파일별 출처를 framework-manifest.json에 기록한다. UI 문구·제품 테마 변수·도메인 승인 슬롯만 연결한다.

## 운영 배포와 인증 분리
- 사용자 요청으로 모델을 Sonnet으로 고정하고, 서버 인증 사용자는 기존 계정 ID의 운영 허용 목록으로 제한한다. 일반 사용자는 본인 Anthropic API 키를 입력해야 실행할 수 있다.
- 개인 키는 브라우저 메모리/실행 요청에만 두고 DB·프롬프트에 저장하지 않는다. 키 실행은 별도 임시 HOME/Claude 설정 디렉터리와 최소 환경 변수로 서버 OAuth 인증을 분리하며 종료 후 정리한다. 로그 마스킹 경로도 추가했다.
- 서버의 ubuntu Claude 로그인 파일은 존재하나 실제 Sonnet 검증에서 OAuth 세션 만료로 실패했다. 사용자 재로그인과 개발 멤버 계정 목록을 요청했다.
- 타입 검사, 전체 단위 테스트(웹212/백엔드311), 웹 빌드 및 인증 분리 집중 테스트5개 통과. 브라우저에서 일반 사용자의 키 요청과 입력창 차단을 확인했다.

## 운영 채팅 동의 안내 수정
- 개발 멤버 계정에 AI 사용 동의가 없어 메시지 전송이403으로 차단되는데, 채팅 화면에 동의 경로가 없어 Access denied만 표시되는 문제를 확인했다.
- 접근 상태 응답에 동의 필요 여부를 포함하고, 미동의 시 입력을 잠그며 기존 계정 설정의 동의 화면으로 안내한다. 실행 중 동의 철회도 식별 가능한 오류 상세와 한국어 안내로 처리한다.
- 동의를 대신 부여하거나 검사를 우회하지 않는다. 동의 유무 조회와 미동의 상태의 메시지/실행 미발생을 통합 테스트로 검증한다.

## AI 채팅 진입 동의 모달
- 사용자 요청에 따라 독립 AI 채팅 탭 진입 시, 활성화된 채팅의 미동의 사용자에게 shadcn Dialog를 자동 표시한다. 이미 동의한 사용자는 반복 표시하지 않는다.
- 대화/커리어 기록의 Claude 전달, 선택 동의, 철회 경로, 변경 승인 절차를 안내한다. ‘동의하고 시작’에서만 기존 career_records 동의를 현재 정책 버전으로 저장하고 성공 응답 확인 후 입력 잠금을 해제한다.
- ‘나중에’/닫기는 동의를 기록하지 않는다. 화면 안내 버튼에서 다시 열 수 있다. 공고/기록 패널은 자동 표시 없이 버튼으로 연다.
- 타입 검사·웹 빌드·전체 단위 테스트 통과. 동의 BFF 범위/인증 검사와 모달의 나중에·저장 실패 검사 통과.

## 동의 모달 디자인 개선
- Expresso 브랜드 헤더, 제목/설명 위계, 전달 정보·사용처·기록 반영 조건의 세 행, 선택/철회 안내, 구분된 하단 액션으로 재구성했다. 기존 동의 범위와 저장 로직은 유지한다.
- design-ops web-compact 프로필 및 patterns/modal.md Implementation defaults를 참고해 폭512px/여백24px/버튼40px을 적용했다. 모바일 버튼48px, 서체와 색은 기존 Expresso 토큰을 사용한다.
- 실제 브라우저에서 데스크톱과390×844 모바일을 확인했다. 설명과 버튼이 표시되고 가로 넘침이 없다. 본문/흰 배경 대비9.69:1, 동의 버튼 대비6.67:1. 별도 QA 계정 동의는 시각 검증 후 원래 상태로 복원했다.
- 타입 검사·전체 단위 테스트·웹 빌드 통과.

## API 키 초기 등록과 설정 관리
- 사용자 요청으로 API 키 입력을 첫 진입 모달의 동의 다음 단계와 계정 설정의 AI 채팅 영역으로 이동했다. 채팅 화면의 상시 키 입력란을 제거했다. 개발 멤버는 서버 인증을 계속 사용한다.
- 키를 계속 사용할 수 있도록 agent_credentials 컬렉션과0010 마이그레이션을 추가했다. AES-256-GCM으로 암호화하고 계정 ID를 AAD에 결합한다. 암호화 키는 서버 환경에서 DB와 분리해 보관한다. 조회 API는 등록 여부만 반환하며 원문은 노출하지 않는다.
- 등록/교체/삭제는 인증된 본인 계정에만 적용한다. 계정 삭제 시 키도 정리한다. 채팅 요청에서 키를 받지 않고 저장된 키를 실행 시 복호화해 기존 격리된 SDK 환경으로 전달한다.
- 타입 검사·전체 단위 테스트·웹/백엔드 빌드, 실제MongoDB 마이그레이션17개 및 암호화/재시작복원/타계정복사차단/교체삭제 검사 통과.
- 별도 QA 계정에서 모달 테스트키등록→새로고침유지→설정 등록상태확인→삭제를 브라우저로 검증했다. 실제 유효 API 키나 모델 호출은 사용하지 않았다.
