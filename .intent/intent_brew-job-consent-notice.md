# 질문·레시피 작업의 동의 실패 안내

## 개발 목표와 의도

10/15 체험에서 "질문 만들기"가 "커리어 기록 사용" 동의가 꺼져 실패했다. 큐는 같은 이유로 다섯 번 돌았고, 화면은 "만들지 못했습니다. 다시 시도해 주세요."만 보였다. 무엇을 고쳐야 하는지 알 수 없었다.
실패 뒤 다시 누르면 새 작업이 도는 부분과 재시도 불가 실패를 한 번에 끝내는 부분은 PR #102(`fix/brew-job-rebrew`)가 맡는다. 이 변경은 그 위에서 동의 실패를 따로 분류하고 화면에 이유를 적는다.
요청: "when the failure is a consent error, the counter screen tells the user which consent is required and links to /account."

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 동의 실패 안내 | 질문·레시피 실패 카드에 "커리어 기록 사용 동의가 꺼져 있어 만들지 못했습니다"와 설정의 AI 사용 동의 자리로 가는 링크가 보인다 | 지금 문구로는 원인을 몰라 동의를 켜러 갈 수 없다 |
| 동의 실패는 한 번만 | 동의가 꺼져 실패하면 큐가 다시 돌리지 않고 바로 실패로 끝난다 | 지금은 일시 오류로 분류되어 다섯 번 반복되고 그동안 실패 표시가 늦다 |

## 개발 목표

- 동의를 끈 계정으로 "질문 만들기"를 누르면 큐 시도는 한 번이고, 카드에 동의 이름과 `/account` 링크가 보인다.
- 링크를 누르면 설정 화면의 "AI 사용 동의" 자리로 간다.
- 동의를 켜고 돌아와 다시 누르면 같은 제작에서 질문이 만들어진다. 레시피 화면도 같다.
- `pnpm typecheck` · `pnpm test` · `pnpm test:infra`가 통과한다.

## 범위 밖과 제약

- PR #102 위에 쌓는다. #102가 바뀌면 이 브랜치를 그 위로 다시 맞춘다.
- 구 MySQL 경로는 계약에 맞출 만큼만 고친다.
