# 개발 현황 스캔 에이전트와 진행 현황 대시보드

## 변경 의도

지금 포털의 「진행 현황」은 2026-10-25에 한 번 조사한 판정을 사람이 파일로 옮겨 둔 것이다. 코드가 바뀌어도 숫자는 그대로이고, 「막힌 자리」 같은 칸은 손으로 쓴 문장이다.

> "오라클 서버에서 도는 에이전트를 활용해서 현재 개발 상황을 스캔하고, 기능별로 구현 현황과 도메인별 개발 진척도를 모니터링하고, 각 팀원들이 지금 해야할 할일을 알아낼 수 있어야 해."

이 기능이 대체하는 것은 이번 대화의 수작업이다. 서브에이전트 셋이 main 코드를 읽고 설계서 기능 150개를 판정했다. 이번에는 같은 일을 서버가 스스로 반복한다.

## 기능 목록

| 기능 | 끝나면 무엇이 달라지는가 | 왜 필요한가 |
|---|---|---|
| 기능 스캔 에이전트 | 지금은 판정이 사람 손으로만 바뀐다 → main에 새 커밋이 들어오면 서버의 Claude Code가 바뀐 도메인의 코드를 읽고 기능마다 완료 · 부분 · API만 · 미구현과 근거 파일을 다시 매긴다 | 현황이 코드와 같은 속도로 움직여야 믿고 쓴다 |
| 대상 기능 목록 | 설계서 2.5(사용자 150개) · 2.3(AI학습서버 35개) · 2.6(관리자 24개) 표에서 기능과 담당을 읽는다 | 기준이 설계서 하나여야 설계서를 고치면 스캔 대상도 따라 바뀐다 |
| 진척 이력 | 스캔할 때마다 도메인별 판정 수를 쌓아 「D7 완료가 지난주 0 → 이번 주 2」처럼 추이 선으로 보인다 | 진척은 한 시점이 아니라 변화로 읽어야 늦는 도메인이 보인다 |
| 팀원별 할 일 | 팀원을 고르면 지금 할 일이 우선순위대로 나온다 — 담당 기능의 빠진 부분, 이번 주 일정, 손봐야 할 내 PR(CI 실패 · 충돌 · 멈춤). 항목마다 근거 링크가 붙는다 | 각자 무엇부터 할지 대시보드에서 바로 정해야 한다 |
| PR · CI 상태 | 열린 PR의 CI · 충돌 · 리뷰 · 멈춘 기간과 main의 CI · 배포 결과가 15분 간격으로 갱신된다 | 할 일 판단에 쓰는 사실이 최신이어야 한다 |
| 스캔 기록 | 마지막 스캔 시각 · 대상 커밋 · 다시 본 도메인 · 실패 여부가 화면 위쪽에 보인다 | 값이 언제 것인지 모르면 판정을 믿을 수 없다 |
| 손으로 쓴 칸 제거 | 「막힌 자리」 · 파일럿 차트 · 손으로 옮긴 판정 파일이 사라진다 | 사람이 갱신해야 하는 칸은 금방 낡는다 |

## 개발 목표

- main에 기능 코드를 머지하면 1시간 안에 해당 도메인의 판정과 「마지막 스캔」 시각이 바뀐다.
- 대시보드에서 「채서현」을 고르면 할 일 목록이 나오고, 항목을 누르면 근거(파일 · PR · 설계서 번호)로 간다.
- 도메인 진척 차트에 스캔 이력이 날짜별 선으로 그려진다.
- 판정의 근거 파일 경로는 스캔 때 실제로 있는지 검사되고, 없는 경로는 버려진다.
- 스캔 에이전트는 코드를 읽기만 한다(도구는 Read · Grep · Glob만).

## 범위 밖과 제약

- 서버의 제품 서비스(`~/expresso`)와 그 AI 설정은 건드리지 않는다. 스캔은 별도 클론에서 돈다.
- Claude 사용량은 제품의 AI 기능과 같은 계정을 쓴다. 그래서 바뀐 도메인만 다시 보고, 전체 재스캔은 주 1회로 제한한다.
- 열린 PR의 브랜치 코드는 판정하지 않는다. 판정은 main 기준이다.
