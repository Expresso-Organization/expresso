# 포트폴리오 지면 서버 운영 계정 정보 노출 차단

## 개발 목표와 의도

다른 사용자의 포트폴리오에 서버 운영자의 이름과 이메일이 찍히는 문제를 막는다.
Discord #issue(2026-11-10): "포트폴리오 생성시 사용자정보와 실제 포트폴리오의 정보가 일치하지 않는 상황".
오시건 님 계정으로 만든 포트폴리오의 맨 아래 연락처 줄에 「이름 Minjae Park · Email libera3920@gmail.com」이 들어갔다.
다른 사용자의 데이터가 섞인 것은 아니다. 서버에서 생성을 맡는 Claude Code CLI가 로그인 계정의 이메일과 git 사용자 이름을 모델 컨텍스트에 자동으로 넣는다. 그런데 자유 지면 프롬프트는 작성자 이름도 연락처도 주지 않으면서 키트 안내로 연락처 줄(이름 · 값)을 두라고 한다. 그래서 모델이 그 빈칸을 서버 계정 정보로 채웠다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 작성자 이름과 연락처 여부 알림 | 자유 지면을 만들 때 모델에게 작성자 이름(설정의 표시 이름)을 주고, 연락처는 받지 않았으니 이메일 · 전화 줄을 두지 말라고 알린다 | 이름과 연락처를 주지 않으면 모델이 컨텍스트의 다른 값으로 채운다 |
| 근거에 없는 이메일 고쳐 받기 | 만든 지면에 기록 · 답변에 없는 이메일 주소가 있으면, 같은 대화에서 "그 줄을 지운다"고 고쳐 받는다 | 프롬프트만으로는 빈도가 낮은 노출을 막았는지 확인할 수 없다. 서버가 결과를 보고 걸러야 한다 |
| 서버 git 사용자 이름 제거 | 생성과 에이전트 채팅의 CLI 호출이 git 사용자 이름(「Git user: Minjae Park」)을 컨텍스트에 싣지 않게 한다 | 지면에 운영자 이름이 들어간 출처다 |
| 에이전트 채팅의 운영 계정 안내 | 에이전트 채팅에, 컨텍스트에 보이는 이메일은 서버 운영 계정이지 사용자 정보가 아니라고 알린다 | 이메일 줄은 CLI 옵션으로 끌 수 없다. 사용자가 "내 이메일"을 물으면 운영자 주소를 답할 수 있다 |

## 개발 목표

- 서버 CLI에 같은 플래그로 물었을 때 「Git user」 줄이 나오지 않는다.
- 남의 이메일이 든 지면을 받은 단위 테스트에서 고치기 요청이 그 주소와 "그 줄을 지운다"를 담아 나간다.
- 자유 지면 프롬프트에 작성자 이름과 「연락처 없음」 문장이 들어간다(프롬프트 단위 테스트).
- 오시건 님 포트폴리오의 판 7개를 사용자 승인 뒤 정리한다.

## 범위 밖과 제약

- 이메일 줄은 구독 OAuth로 로그인한 CLI가 항상 넣는다. `--system-prompt`, `CLAUDE_CODE_DISABLE_CLAUDE_MDS`, `IS_DEMO`로도 빠지지 않는다(2026-11-14 서버 2.1.272 실측). 원천 제거(API 키 경로 전환)는 이번에 하지 않는다.
- 운영 DB의 지면 7개 정리는 운영 쓰기라 코드와 분리해 승인을 받고 한다. 이 판들은 배포되지 않았다.
