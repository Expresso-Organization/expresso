# 홈에서 대화로 넘어가는 전환

## 개발 목표와 의도

홈에서 말을 보내면 대화 화면이 홈과 이어진 한 장면으로 열리게 한다. 지금은 화면이 한 번에 바뀌고, 그 사이에 보낸 말과 상관없는 화면이 잠깐 지나간다.

지금 홈 입력창에서 Enter를 누르면 이렇게 보인다(검증 서버 측정).

1. 0.6초 동안 아무 변화가 없다. 서버 응답을 기다리는 시간이다.
2. 화면이 한 번에 대화 화면으로 바뀐다. 가운데의 입력창이 사라지고 아래에 다른 입력창이 생긴다.
3. 0.12초 동안 빈 대화의 시작 화면(큰 로고 · 「내 경험을, 다음 기회로.」 · 시작 버튼 셋)과 「채팅 사용 권한 확인 중…」이 보인다.
4. 0.03초 동안 빈 화면이 보인다.
5. 보낸 말이 나타난다.

3과 4는 사용자가 한 일과 맞지 않는 화면이다. 말을 보냈는데 「무엇을 할까요」를 묻는 화면이 지나간다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 누르자마자 반응 | Enter를 누르면 입력창만 남고 로고 · 추천 프롬프트 · 위젯 · 제안이 바로 옅어진다. 다시 눌러도 두 번 보내지지 않는다. | 서버를 기다리는 동안 화면이 그대로면 눌렸는지 알 수 없다. |
| 입력창이 자리를 옮김 | 가운데의 홈 입력창이 그대로 대화 화면 아래의 입력창 자리로 내려가며 크기를 맞춘다. | 같은 입력창이 이어진다는 것이 보여야 다른 화면으로 튕긴 것이 아니라 대화가 시작된 것으로 읽힌다. |
| 보낸 말이 첫 장면에 있음 | 대화 화면의 첫 장면에 보낸 말이 이미 말풍선으로 있고, 입력창 쪽에서 위로 떠오르며 나타난다. 시작 화면 · 권한 확인 문구 · 빈 화면은 지나가지 않는다. | 보낸 말이 어디로 갔는지가 눈으로 이어져야 한다. |
| 보낼 수 없을 때는 말풍선 없음 | AI 사용 동의가 없거나 크레딧을 다 쓴 계정, 대화를 만들지 못한 경우에는 말풍선을 띄우지 않고 지금처럼 입력창에 글을 남긴다. | 보내지 않은 말이 보낸 것처럼 보이면 안 된다. |
| 제안 카드에서 시작해도 같음 | 제안 카드의 「대화로 시작」 동작도 같은 전환으로 열린다. | 같은 결과(대화 시작)가 진입점마다 다르게 보이면 안 된다. |
| 다른 이동은 그대로 | 사이드바에서 지난 대화를 고를 때, 뒤로 가기, 「새 대화」로 홈에 돌아갈 때는 지금처럼 바로 바뀐다. 다른 화면의 대화 레일도 그대로다. | 이번 전환은 「말을 보내 대화를 시작함」 한 가지 뜻만 나타낸다. |
| 움직임 줄이기 설정 | 기기에서 움직임 줄이기를 켠 사용자에게는 움직이지 않고 바로 바뀐다. 보낸 말이 첫 장면에 있는 것은 같다. | 화면 전체가 움직이는 전환은 멀미를 일으킬 수 있다. |

## 개발 목표

- 홈 입력창에서 보내면, 녹화 프레임에서 입력창이 가운데에서 아래 자리로 옮겨 가는 중간 프레임이 보인다.
- 대화 화면이 처음 보이는 프레임부터 보낸 말이 있고, 시작 화면 · 「채팅 사용 권한 확인 중…」이 한 프레임도 보이지 않는다.
- Enter 직후(서버 응답 전) 프레임에서 로고 · 추천 프롬프트 · 위젯이 옅어져 있다.
- 동의가 필요한 계정으로 보내면 말풍선 없이 입력창에 글이 남는다.
- 사이드바에서 지난 대화를 열 때는 전환이 돌지 않는다.
- 움직임 줄이기를 켜면 전환이 돌지 않고, 보낸 말은 첫 장면에 있다.

## 범위 밖과 제약

- 대화에서 홈으로 돌아가는 반대 방향 전환은 만들지 않는다.
- 전환은 브라우저의 View Transitions 기능을 쓴다. 지원하지 않는 브라우저에서는 지금처럼 바로 바뀌고, 보낸 말이 첫 장면에 있는 것만 같다.
- 서버 응답을 기다리는 시간(개발 서버 0.6초) 자체는 줄이지 않는다.
