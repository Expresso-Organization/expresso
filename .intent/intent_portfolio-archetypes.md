# 포트폴리오 유형 선택과 포스터형 · 글 · 목록형

## 문제

디자인 시스템 38종 가운데 무엇을 골라도 포트폴리오의 짜임새는 같습니다. 이름과 소개 문단 → 목차 → 사례(문단과 "역할 / 기간 / 문제 정의 / 담당 작업 / 결과와 한계" 항목표) → 경력 → 근거 자료 → 연락 순서입니다. 바뀌는 것은 색 · 글꼴 · 간격뿐입니다. 지난 가상 프로필 생성(Clarity · Linear Midnight · Monochrome)을 나란히 놓으면 색만 다른 같은 문서로 보입니다. 사용자는 "포트폴리오 웹사이트가 아니라 문서에 가깝다"고 평가했습니다.

레퍼런스 포트폴리오 81곳을 조사해 보니 차이는 색이 아니라 짜임새에서 나옵니다(`docs/architecture/portfolio-archetype-research.md`). 그중 사용자 자료만으로 만들 수 있는 두 유형이 이번 대상입니다.

- **포스터형**: 첫 화면에 이름이나 역할을 화면 폭에 가깝게 크게 쓰고, 색면이나 무늬를 깝니다. 글은 한두 줄입니다(예: [Wodniack](https://wodniack.dev), [Colin Moy](https://colin-moy.webflow.io)).
- **글 · 목록형**: 큰 소개 문장 하나와 연도별 목록(프로젝트 · 경력)으로 짭니다. 장식이 거의 없습니다(예: [Dan Eden](https://daneden.me), [Hanson Wu](https://www.hansonwu.com)).

사용자마다 취향이 다르므로, 짜임새 하나를 정답으로 정하는 대신 고를 수 있어야 합니다.

## 원하는 결과

- 지금은 디자인 선택 화면에서 디자인 시스템(색 · 글꼴 · 간격)만 고른다 → 끝나면 같은 화면에서 **유형**(포스터형 · 글 · 목록형 · 지금의 사례 상세형)을 따로 고르고, 유형 하나와 디자인 하나를 조합해 생성한다. 확인: 디자인 선택 화면에서 유형을 바꾸고 "이 디자인으로 만들기"를 눌러 생성된 결과.
- 지금은 첫 화면이 역할 · 이름 · 문장 · 소개 문단 · 태그를 쌓은 표제부다 → 끝나면 포스터형의 첫 화면은 이름이나 역할이 화면 폭에 가깝게 크고, 그 아래 글은 한두 줄이다. 확인: 가상 프로필 3종의 포스터형 1440px 첫 화면.
- 지금은 프로젝트가 문단과 항목표로 나온다 → 끝나면 글 · 목록형에서 프로젝트와 경력은 "연도 · 이름 · 한 줄 설명" 목록으로 나오고, 항목표는 나오지 않는다. 확인: 가상 프로필 3종의 글 · 목록형 화면.
- 같은 사람 · 같은 디자인이라도 유형을 바꾸면 한눈에 다른 사이트로 보인다. 확인: 같은 가상 프로필 × 같은 디자인 × 유형 3개를 나란히 놓은 비교 화면을 사용자에게 보여 확인받는다.
- 유형 두 개는 디자인 38종 모두에서 깨지지 않는다(가로 넘침 · 한 글자 줄바꿈 · 대비 · 서체 적용 검사 통과). 확인: 38종 × 유형 2개 브라우저 검사 기록.
- 이미 만든 포트폴리오는 다시 열어도 지금과 같은 모양이다. 유형을 고르지 않고 만들면 지금의 사례 상세형으로 만들어진다. 확인: 기존 저장본 렌더 테스트.

## 영향 범위

- 사용자: 포트폴리오를 새로 생성하는 모든 사용자.
- 화면: 생성 흐름의 디자인 선택 단계(유형 고르기 추가).
- 바뀌는 곳: 생성 요청 계약(유형 값), 모델에게 주는 지시와 고를 수 있는 구성, 렌더러의 컴포넌트(포스터 첫 화면, 목록 섹션 등).
- 결정 권한: Nedian0Brien.

## 제약

- 내용은 사용자 자료에서만 가져옵니다. 포스터형의 짧은 글도 기록에 있는 직무 · 이름 · 한 줄에서 만들고, 지어내지 않습니다.
- 공개 지면은 JavaScript 없이 보여야 합니다(`script`를 실을 수 없음). 움직임은 CSS로만 냅니다.
- 색 · 글꼴은 고른 디자인 시스템의 토큰에서만 옵니다. 유형은 짜임새만 정합니다.
- 다듬기(편집) 화면은 이번 범위 밖입니다. 다만 깨지지 않게 합니다.
- PR #99(디자인 배치) 위에서 작업합니다.

## 범위 밖

- 제품 랜딩형(수치 · 버튼): 수치 추출(#97 3단계)과 함께 다음에 합니다.
- 인물 사진 중심형: 프로필 사진 업로드가 필요해 다음에 합니다.
- 작업물 격자형: 작업 이미지 확보 경로(링크 캡처 · 타이포그래피 커버)가 먼저 필요합니다.
- 3D · 인터랙티브형: 공개 지면에 JavaScript를 실을 수 없어 이번에는 다루지 않습니다.
- 유형을 고를 때 사용자 본인 자료로 그린 미리보기: 이번에는 유형별 설명과 견본 화면까지만 둡니다.
- 사용자 자료에 맞지 않는 유형을 미리 거르는 기능: 이번 두 유형은 자료 조건이 없어 필요하지 않습니다.

## 열린 질문

- 유형을 고르는 자리. 디자인 선택 화면의 카탈로그 위에 유형 선택을 두는 안을 기본으로 생각합니다. spec 단계에서 지금 화면 구조를 보고 정하고, 화면을 보여 드립니다.
- 유형이 정하는 범위. 유형이 섹션 순서와 쓸 수 있는 컴포넌트를 정하고, 모델은 그 안에서 변형만 고르는 안을 기본으로 생각합니다. spec 단계에서 확정합니다.
