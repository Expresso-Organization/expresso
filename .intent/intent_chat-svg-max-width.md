# 채팅 영역 svg 전역 max-width 해제

## 문제

앱 전역 `services/web/src/styles/global.css:76-80`의 `img, svg { display: block; max-width: 100% }`가
에이전트 채팅(`.acf-scope`)에도 적용된다. 채팅 전용 preflight(`agent-chat-preflight.css`)는
Tailwind v4 preflight처럼 `img, video`에만 `max-width`를 주고 svg에는 주지 않는다. 그런데 전역
규칙은 레이어 밖에 있어 채팅의 `@layer utilities`보다 우선하고, 좁은 버튼 안의 아이콘이 버튼
콘텐츠 폭에 맞춰 줄어든다.

`TooltipIconButton`(`size-6 p-1`, 테두리 1px)의 콘텐츠 폭은 14px이다. 그 안의 16px 아이콘이
14×16으로 줄어든다. 화면 정의서에는 채팅 액션바 아이콘 크기가 정해져 있지 않다. 그래서 기준은
`thread.aui.tsx` NOTE의 "원본 스타일 유지"다. 원본 assistant-ui에서는 이 아이콘이 16px로 그려진다.

headless Chrome으로 측정했다. 위 네 줄은 실제 화면, 아래 줄은 같은 클래스 조합으로 만든 요소다.

| 자리 | 지금 보이는가 | 현재 | 규칙 해제 시 |
| --- | --- | --- | --- |
| 어시스턴트 메시지 "복사" · "더 보기" | 보임 (`/agent?chat=`, 3폭) | 14×16 | 16×16 |
| 코드 블록 "Copy" (`markdown-text.tsx:74`) | 코드 블록이 있을 때 | 14×16 (클래스 동일) | 16×16 |
| "다시 생성" · 사용자 "Edit" · 분기 이전/다음 | 숨김 (capabilities 꺼짐) | 14×16 (클래스 동일) | 16×16 |
| 첨부 삭제 (`size-5` + 아이콘 `size-3`) | 숨김 (첨부 어댑터 없음) | 10×12 | 12×12 |

이 규칙을 채팅 범위에서 풀었을 때 크기가 바뀐 svg는 위 아이콘들뿐이다. 측정 범위는 `/agent`, 대화
3개, 공고 상세 2개, 기록 편집기, 대화 목록 팝오버 4개 탭, `/agent` 자료 사이드바 4개 탭이고,
각각 1400 · 768 · 375 폭에서 쟀다.

## 원하는 결과

- 어시스턴트 액션바 아이콘이 16×16으로 그려진다. 숨겨진 액션 아이콘도 클래스가 같으므로 같은 크기가 된다.
- 위 측정 범위에서 그 밖의 svg는 크기가 바뀌지 않는다.
- 개발 서버와 프로덕션 빌드에서 결과가 같다.
- e2e 회귀 테스트가 액션바 아이콘 16×16을 확인한다.

## 영향 범위

에이전트 채팅을 쓰는 세 화면과 채팅 팝오버·다이얼로그(`.acf-scope`). 코드는 채팅 전용 CSS 한 곳이다.

## 제약

- 전역 `global.css` 규칙은 바꾸지 않는다. 채팅 밖 화면 15개를 3폭에서 쟀을 때는 규칙을 풀어도
  바뀐 svg가 없었다. 하지만 데이터가 없어 열지 못한 분석 대시보드(`width="132"` 고정 svg), 공개
  포트폴리오, 디자인 카탈로그에는 인라인 svg가 있다. 이 화면들이 이 규칙에 기대는지 확인하지 못했다.
- 선택자는 `.acf-scope svg`(0,1,1)로 한다. `:where(.acf-scope) svg`는 전역 `svg`와 명시도가 같아서,
  CSS가 불러오는 순서에 따라 결과가 달라진다. 채팅 유틸리티는 `@layer` 안에 있어 원래 레이어 밖
  규칙에 진다. 그래서 이 선택자 때문에 새로 막히는 유틸리티는 없다.

## 범위 밖

- 전역 `global.css`에서 svg를 빼는 변경. 위의 확인하지 못한 화면을 데이터로 열 수 있을 때 따로 다룬다.
- `TooltipIconButton`의 크기·패딩 변경.
