# 생성 기다림 진행 막대 · 지면 순환 멈춤

## 개발 목표와 의도

디자인을 고르고 생성을 누르면 잔 그림과 "고른 기록 읽는 중..." 한 줄만 있는 화면이 선다. 구성(레시피)이 아직 도는 중이면 이 화면이 길게 머문다. 2026-11-10 운영 기록에서 생성을 누른 뒤 구성을 기다린 시간은 6건 모두 107~248초였다. 그동안 화면에는 움직이는 것이 잔뿐이라 사용자는 멈춘 것으로 읽었다(포트폴리오 `72e105b0…`, 108초 대기).

섹션 정보가 뜬 뒤에는 입력 묶음이 1.5초마다 한 구역씩 쌓이고, 다 쌓이면 지면을 비우고 처음부터 다시 쌓는다. 읽는 도중에 지면이 비워져 끝까지 읽을 수 없다.

> "섹션 정보가 뜰 때까지, 가짜 로딩 프로그레스 바를 적절하게 불규칙적으로 움직이도록 해서 로고 애니메이션 아래에 추가"
> "마지막 섹션까지 뜨면 더이상 순환하지 않도록 하고, 스크롤이 가능하게 하자."

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 브루잉 진행 막대 | 섹션 정보가 뜨기 전까지 잔 바로 아래에 가는 막대가 선다. 막대는 잠깐 멈췄다가 몇 칸씩 차오르기를 불규칙하게 되풀이하고, 끝까지 차지는 않는다. 섹션 정보가 뜨는 순간 끝까지 찬 뒤 사라진다 | 2~4분 동안 화면이 같은 모습이면 멈춘 것과 구별되지 않는다 |
| 다시 열어도 이어지는 막대 | 새로고침하거나 다시 열면 막대가 처음이 아니라 생성을 누른 뒤 지난 시간만큼 찬 자리에서 시작한다 | 다시 열 때마다 0에서 시작하면 오래 기다린 사람에게 처음부터 다시 하는 것처럼 보인다 |
| 지면 순환 멈춤 | 입력 묶음이 마지막 구역(기록)까지 올라오면 그 자리에 멈춘다. 지면을 비우고 다시 쌓지 않는다 | 읽는 도중에 지면이 비워지면 섹션 구성을 끝까지 읽을 수 없다 |
| 지면 스크롤 | 다 쌓인 지면에는 스크롤 막대가 보이고 위아래로 자유롭게 움직인다. 쌓는 도중에 사용자가 스크롤하면 남은 구역을 모두 보이고 그때부터 자동으로 움직이지 않는다 | 사용자가 읽는 자리를 화면이 다시 옮기면 읽기를 방해한다 |

## 개발 목표

- 구성이 끝나기 전에 생성을 누르면 잔 아래 막대가 불규칙하게 차오르고, 2분이 지나도 끝까지 차지 않는다.
- 구성이 끝나 섹션 정보가 뜨면 막대가 끝까지 찬 뒤 사라진다.
- 기다림 화면을 새로고침하면 막대가 지난 시간만큼 찬 자리에서 다시 시작한다.
- 입력 묶음이 기록 구역까지 올라온 뒤 10초를 더 기다려도 지면이 비워지지 않는다.
- 다 쌓인 지면에 스크롤 막대가 보이고 마우스 휠로 처음 구역까지 올라간다.

## 범위 밖과 제약

- 막대의 값은 실제 진행률이 아니다. 구성 잡은 진행 신호를 보내지 않는다. 그래서 화면 읽기 프로그램에는 수치를 읽어 주지 않고 "진행 중"으로만 알린다.
- 구성 시간 자체를 줄이는 일, 글자를 다 채운 뒤 편집기로 넘어가기 전 약 16초 멈춤(값 고치기 3회 · 저장)은 이번 변경에 넣지 않는다.
