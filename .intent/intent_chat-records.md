# 대화로 기록 — 인터뷰와 자동 저장

## 개발 목표와 의도

> "사용자는 에이전트와 편하게 대화하고, 기록에 넣을 부분은 에이전트가 인터뷰 질문으로 적극적으로 끌어내고, 도출된 결과를 기반으로 문서로 정리하는 것은 자동으로 수행되어야 해. 사용자는 그냥 대화만 하면 자연스럽게 커리어 기록을 얻게 되는 형태야."

Expresso AI 기획(`docs/expresso-ai/product-plan.md`, PR #252)의 셋째 마일스톤이다. 지금은 대화에서 경험을 말해도 "기록으로 남겨 줘"라고 따로 요청해야 초안 카드가 뜨고, 카드에서 제목 · 카테고리 · 본문을 확인해 「저장」을 눌러야 기록이 된다. 그렇게 저장한 기록은 상태가 「초안」이라 포트폴리오 재료로도 쓰이지 않는다.

이 변경 뒤에는 사용자가 한 일을 말하면 컨설턴트가 빠진 내용을 물어 끌어내고, 내용이 모이면 기록으로 정리해 바로 저장한다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 인터뷰 | 사용자가 한 일을 말하면 컨설턴트가 상황 · 역할 · 행동 · 결과 가운데 빠진 것을 묻는다. 고를 답이 있는 질문은 선택지로, 수치 · 기간처럼 짧게 적을 것은 입력 칸 묶음으로 낸다. | 사용자가 스스로 쓴 말에는 역할과 결과가 빠지기 쉽다. 빠진 채 저장하면 포트폴리오에 쓸 수 없는 기록이 된다. |
| 입력 칸 묶음 | 답변 글 아래에 짧은 입력 칸이 한 개에서 네 개까지 뜬다. 채워서 「보내기」를 누르면 「칸 이름: 값」으로 내 메시지가 올라간다. | 기간 · 인원 · 수치를 하나씩 물으면 질문마다 대화 실행이 한 번씩 든다. 한 번에 물으면 실행도 크레딧도 줄어든다. |
| 기록 자동 저장 | 내용이 모이면 컨설턴트가 기록으로 정리해 바로 저장한다. 상태는 「정리됨」이고 포트폴리오 재료로 쓸 수 있다. 저장한 것은 답변에서 알린다. | 저장을 사용자의 확인에 맡기면 대화만으로 기록이 쌓이지 않는다. |
| 저장된 기록 카드 | 답변 글 아래에 저장한 기록의 제목 · 서랍 · 본문 앞부분이 카드로 뜬다. 「기록 열기」로 그 기록을 열고, 「되돌리기」로 저장을 되돌린다(기록은 휴지통으로 간다). | 사용자가 무엇이 저장됐는지 그 자리에서 보고, 잘못된 저장을 바로 거둘 수 있어야 한다. |
| 기존 기록에 더하기 | 대화에 연결된 기록에 내용을 더하는 제안(새 블록만 넣는 제안)은 승인 없이 바로 적용한다. 카드에서 되돌릴 수 있다. 있는 문장을 고치거나 지우는 제안은 지금처럼 승인을 받는다. | 같은 경험의 새 사실을 새 기록으로 따로 만들면 기록이 조각난다. 사용자가 쓴 문장을 바꾸는 일은 사용자가 봐야 한다. |
| 「새 기록 초안」 도구 제거 | 에이전트의 `propose_new_record` 도구를 지운다. 앞선 대화에 남은 초안 카드는 그대로 보이고 승인도 된다. | 저장이 자동이 되면 초안을 따로 제안할 일이 없다. 도구가 둘이면 모델이 어느 쪽을 쓸지 갈린다. |

## 개발 목표

- 대화만으로 기록이 생긴다: "인턴 때 EKS 위에 Airflow를 올려 운영했어요"라고 말하고 컨설턴트의 질문에 답하면, 따로 요청하지 않아도 기록이 저장되고 카드가 뜬다.
- 재료가 된다: 저장된 기록의 상태가 「정리됨」이고 라이브러리의 커리어 기록에 보인다.
- 되돌린다: 카드의 「되돌리기」를 누르면 그 기록이 휴지통으로 가고 카드가 되돌렸다고 알린다.
- 말한 것만 쓴다: 사용자가 말하지 않은 수치나 기술이 든 저장은 서버가 돌려보낸다(출처 인용 검사).
- 입력 칸 묶음으로 답한다: 기간과 인원을 묻는 칸에 적어 보내면 그 값이 내 메시지로 올라가고 컨설턴트가 이어 간다.

## 범위 밖과 제약

- 사용자가 쓴 기존 문장을 고치거나 지우는 일은 지금처럼 승인을 받는다.
- 준비 계획의 작업을 마쳤을 때 먼저 묻는 일은 「챙기기」 마일스톤에서 한다. 대화에서 작업을 마쳤다고 말하면 인터뷰는 시작한다.
- 저장된 기록을 「확인됨」으로 바꾸는 일은 지금처럼 기록 화면의 상태 칸에서 한다.
- 한 대화는 메시지 98개에서 멈춘다. 인터뷰는 질문 네 번 안에 저장하도록 지침에 적는다.
- 카드와 입력 칸의 모양은 구현 뒤 화면 캡처로 확인받는다. 이 PR은 병합하지 않고 열어 둔다.
