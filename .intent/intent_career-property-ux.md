# 커리어 기록 속성 편집 UX 결함 수정

## 개발 목표와 의도

커리어 기록 편집기의 속성 · 계산 영역을 완성 계획 4단계 수준으로 끝낸다. 2026-10-28 점검
(`docs/architecture/career-record-editor-status-2026-10-28.md` 「속성 · 계산」)에서 네 가지 결함이
나왔다. 문서 패널에서 수식 속성을 만들면 편집 칸에 `prop("3f1c…-…")` 같은 UUID가 그대로 보인다.
저장한 직후 값 칸은 「비어 있음」이고 새로고침해야 계산값이 나온다. 생성 · 수정 시각 속성은 계약에
있지만 메뉴에 없다. 속성 추가 목록은 화면 아래로 넘쳐 관계 · 수식 · 롤업 항목이 채팅 입력란 뒤에
가린다.

> 사용자: 「최종 완료까지 진행해」 (2026-10-28 완성 계획 전체 승인. 이 intent의 수락으로 기록한다.)

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 수식 속성 이름 토큰 | 수식 칸에 `prop("성과 수치")`처럼 속성 이름이 보이고, 그 부분이 배경색으로 묶여 하나의 토큰으로 보인다. 속성 단추를 누르면 이름 토큰이 들어간다. 저장된 수식은 지금처럼 속성 UUID를 쓴다. | UUID로는 수식이 어떤 속성을 읽는지 알 수 없다. 이름으로 저장하면 속성 이름을 바꿀 때 수식이 깨진다. |
| 없는 이름 · 겹치는 이름 진단 | 수식 칸에 없는 속성 이름이나 두 속성이 함께 쓰는 이름을 적으면 미리 보기 · 저장 때 그 위치를 진단 목록에 보인다. | 서버는 UUID만 알아서 「prop은 UUID 문자열 하나를 받아야 합니다」라는, 사용자가 고칠 수 없는 오류를 낸다. |
| 계산값 즉시 표시 | 수식 · 롤업 속성을 만들거나 그 수식이 읽는 값을 고치면, 계산하는 동안 값 칸이 깜빡이다가 계산이 끝나면 새 값으로 바뀐다. 새로고침이 필요 없다. | 지금은 저장이 실패한 것처럼 보인다. 계산이 끝나도 패널이 옛 버전을 들고 있어 다음 제목 저장이 충돌로 실패한다. |
| 생성 일시 · 최종 편집 일시 속성 | 속성 추가 목록에 「생성 일시」 · 「최종 편집 일시」가 생긴다. 고르면 바로 추가되고, 값 칸에 기록의 생성 · 수정 시각이 `2026-10-28 14:30` 형식으로 읽기 전용으로 보인다. 이름 바꾸기 · 삭제는 다른 속성과 같다. | 계약과 표 · 정렬 · 필터가 이미 이 유형을 지원하지만 사용자가 만들 방법이 없다. |
| 속성 추가 목록 화면 안 배치 | 속성 추가 목록이 문서 본문이 스크롤되는 영역 안에서 열린다. 아래 공간이 모자라면 위로 열리고, 그래도 모자라면 목록 안에서 스크롤된다. | 관계 · 수식 · 롤업 항목이 채팅 입력란 뒤에 가려 고를 수 없다. |

## 개발 목표

- 수식 토큰: 문서 패널 → 속성 추가 → 수식에서 「숫자」 단추를 누르면 칸에 `prop("숫자")`가 토큰으로 보인다. 저장 뒤 DB의 `config.source`에는 UUID가 있다.
- 이름 변경 내성: 표 머리글에서 「숫자」를 「성과」로 바꾼 뒤에도 계산값이 그대로 나온다.
- 계산값: 수식을 저장하거나 수식이 읽는 숫자를 고친 뒤 새로고침 없이 몇 초 안에 새 계산값이 보인다.
- 시각 속성: 「생성 일시」를 추가하면 값 칸에 기록 생성 시각이 보이고 입력할 수 없다.
- 목록 배치: 문서 패널 맨 아래의 「속성 추가」를 눌러도 「롤업」까지 채팅 입력란에 가리지 않고 누를 수 있다.

## 범위 밖과 제약

- 본문 편집기(`editor/**` · `session/**`), 뷰(`views/**`), `modules/career-editor/**`는 다른 세션이 작업 중이라 건드리지 않는다.
- `PropertyList.tsx` · `PropertyCreatePopover.tsx`는 저장된 뷰 세션도 고치므로 그 세션이 바꾼 줄을 피해 최소한으로 바꾼다.
- 이미 만든 수식을 다시 편집하는 화면은 이번에 만들지 않는다. 수식 편집기는 지금처럼 새 수식 속성을 만들 때만 쓴다.
- 서버가 계산 완료를 밀어 주는 경로(소켓 이벤트)는 만들지 않는다. 커리어 소켓은 본문 프레임만 다룬다.
