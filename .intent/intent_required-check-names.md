# main 필수 검사와 CI 검사 이름 맞춤

## 개발 목표와 의도

"규칙 고치고 머지"

`main` 보호 규칙은 필수 검사로 「웹 검사」 · 「백엔드 검사」를 요구하는데, 웹 CI와 백엔드 CI의 작업 이름은 둘 다 `verify`라 그 이름으로 보고하는 검사가 없다. 그래서 CI가 통과한 PR #191도 `BLOCKED`로 머지되지 않았다. 또 두 CI는 PR에서 경로 필터로 아예 시작하지 않을 수 있어서, 이름을 맞춰도 백엔드만 바꾼 PR에는 「웹 검사」가 오지 않는다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 검사 이름 맞춤 | 웹 CI의 검사 작업이 「웹 검사」, 백엔드 CI의 검사 작업이 「백엔드 검사」로 보고된다. | 보호 규칙이 요구하는 이름과 같아야 머지가 열린다. |
| 늘 보고하는 필수 검사 | PR이면 두 CI가 항상 시작하고, 먼저 바뀐 파일을 본 뒤 관계없는 PR이면 검사 작업을 건너뛴다. 건너뛴 작업도 필수 검사로 통과 처리된다. | 경로 필터로 CI가 시작하지 않으면 필수 검사가 오지 않아 PR이 영원히 막힌다. |

## 개발 목표

- 이 PR과 PR #191에서 「웹 검사」 · 「백엔드 검사」가 보고되고 `mergeStateStatus`가 `BLOCKED`가 아니다.
- 웹 파일을 건드리지 않은 PR에서는 「웹 검사」가 건너뜀(skipped)으로 끝나 시간을 쓰지 않는다.

## 범위 밖과 제약

- 보호 규칙(저장소 설정)은 바꾸지 않는다. 규칙의 이름이 뜻을 드러내므로 워크플로를 규칙에 맞춘다.
- `main` 푸시의 경로 필터는 그대로 둔다(보호 규칙은 PR에만 걸린다).
