# 제작 흐름의 레시피 단계 제거

## 개발 목표와 의도

지금은 AI 대화를 마치면 "레시피" 화면으로 가서 "레시피 만들기"를 누르고 약 1~1.5분을 기다린 뒤 섹션 구성을 보고, 다시 디자인 선택으로 넘어간다. 요청: "'레시피' 단계가 굳이 필요하지 않을 것 같다. 레시피 단계를 제거하자", 이어서 구성 전에도 만들기를 누를 수 있고 "이 경우에 맞는 로딩 스크린을 제공하도록 하자". 화면 단계는 없애고, 생성에 필요한 섹션 구성(레시피)은 뒤에서 자동으로 만든다. 구성 내용은 생성 기다림 화면의 지면에서 보인다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 단계 줄에서 레시피 제거 | 위쪽 단계 줄이 공고 분석 · 재료 고르기 · AI 대화 · 디자인 선택 · 다듬기 다섯 칸이 된다 | 사용자가 검토하지 않아도 되는 단계를 거치지 않는다 |
| 레시피 화면 삭제 | `/brew/{id}/outline` 화면을 지운다 | 단계가 없으면 들어갈 길도 없어야 한다 |
| AI 대화에서 바로 디자인으로 | AI 대화 화면의 "건너뛰고 진행" · 마지막 버튼을 누르면 구성 만들기를 맡기고 곧바로 디자인 선택 화면으로 간다 | 구성을 만드는 1~1.5분 동안 디자인을 고를 수 있다 |
| 구성 전에도 만들기 | 구성이 아직이어도 "이 디자인으로 만들기"를 누를 수 있고, 구성이 끝나는 대로 생성이 이어서 시작된다. 구성이 실패하면 그 생성도 실패로 끝나고 디자인 화면에 이유가 보인다 | 디자인을 빨리 고른 사람이 구성이 끝나기를 기다렸다가 다시 누르지 않아도 된다 |
| 구성을 기다리는 로딩 화면 | 구성 전에 눌렀으면 브루잉이 화면 가운데에 머물고, 잔 아래에서 "담을 섹션 고르는 중..." 같은 구성 문장이 돈다. 구성이 끝나면 지금처럼 빈 지면이 올라오고 섹션이 쌓인다 | 구성 중에는 지면에 올릴 섹션이 아직 없다 |
| 이어하기 · 문구 정리 | 레시피 단계에서 멈춘 제작은 디자인 선택으로 이어지고, 화면 문구의 "레시피"를 "구성"으로 바꾼다 | 없는 단계를 가리키는 말이 남으면 안 된다 |

## 개발 목표

- 단계 줄에 다섯 칸이 보이고, "레시피" 칸이 없다.
- AI 대화에서 "건너뛰고 진행"을 누르면 디자인 선택 화면이 열리고, 곧바로 "이 디자인으로 만들기"를 누를 수 있다.
- 구성 전에 누르면 브루잉과 구성 문장이 이어지다가, 구성이 끝나면 빈 지면이 올라오고, 그 뒤 생성이 끝나 편집 화면으로 넘어간다.
- `/brew/{id}/outline`을 열면 찾을 수 없는 화면이다.
- 홈에서 레시피 단계에 멈춘 제작을 이어 열면 디자인 선택 화면이 열린다.

## 범위 밖과 제약

- 백엔드의 레시피(구성) 데이터와 생성 파이프라인은 그대로 쓴다. 생성은 계속 레시피를 읽고, 구성이 끝나면 기다리던 생성에 구성을 붙여 시작한다.
- 레거시 MySQL 저장소는 구성 없는 생성 요청을 받지 않는다.
- 섹션 구성을 사용자가 직접 고치는 기능은 이번에 없어진다. 구성은 생성 뒤 06 다듬기에서 고친다.
- 화면 정의서(`docs/Expresso Screens.dc.html`)의 02b 레시피 화면은 이번에 고치지 않고 후속으로 남긴다.

## 열린 질문

- 구성 전에 누를 수 있게 할지 → 누를 수 있게 하고, 구성이 끝나는 대로 생성을 잇는다(2026-10-27 사용자 결정).
