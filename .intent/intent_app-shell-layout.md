# 앱 셸 공용 레이아웃

## 개발 목표와 의도

사이드바는 앱 화면 사이를 옮겨 다니는 동안 그대로 있어야 합니다. 지금은 홈에서 탐색, 탐색에서 분석으로 옮길 때마다 사이드바 전체가 회색 스켈레톤으로 바뀌었다가 다시 채워집니다.
PR #261은 스켈레톤을 150ms 늦게 보이게 해서 짧은 응답에서는 깜빡임을 가렸습니다. 응답이 150ms를 넘으면 여전히 이동마다 사이드바가 사라졌다 돌아옵니다.
원인은 화면 구간마다 `layout.tsx`가 사이드바 셸(`AppChrome`)을 따로 그리는 구조입니다. 구간을 옮기면 Next가 셸을 새로 그리고, 사이드바도 처음부터 다시 불러옵니다.
요청: "사이드바가 이동 사이에 남도록 레이아웃 구조를 고친다. 셸을 쓰지 않는 화면은 지금 모양을 유지한다."

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 앱 화면 공용 셸 | 홈 · 라이브러리 · 탐색 · 분석 · 커리어 기록 · 에이전트 · 목표 · 설정 · 관리 · 제작 · 배포 화면이 하나의 셸을 같이 씁니다. 화면을 옮기면 본문만 바뀌고 사이드바는 그 자리에 남습니다. 접어 둔 묶음과 스크롤 위치도 유지됩니다. | 이동마다 사이드바가 스켈레톤으로 바뀌어 화면 전체가 다시 뜨는 것처럼 보입니다. |
| 편집기는 셸 밖 | 편집기(`/edit/…`)는 지금처럼 사이드바 없이 화면 전체를 씁니다. 같은 주소 아래의 배포 화면(`/edit/…/deploy`)은 지금처럼 사이드바가 있습니다. | 공용 셸 아래 두면 편집기에 사이드바가 생깁니다. |
| AI 대화 뒤 크레딧 갱신 | 에이전트 대화 한 번이 끝나면 사이드바의 남은 크레딧이 새 값으로 바뀝니다. | 지금은 다른 화면으로 옮길 때 사이드바를 새로 불러와 크레딧이 맞춰졌습니다. 셸이 남으면 그 갱신이 없어집니다. |

## 개발 목표

- 사이드바가 남는다: 운영 빌드에서 홈 → 라이브러리 → 탐색 → 분석 → 커리어 기록을 사이드바 링크로 옮기는 동안 사이드바 요소가 같은 요소로 남습니다.
- 스켈레톤이 서지 않는다: 같은 이동에서 사이드바 스켈레톤(`aria-busy`)이 한 번도 나타나지 않습니다.
- 편집기 모양 유지: `/edit/…`에는 사이드바가 없고, 편집기에서 홈으로 돌아오면 사이드바가 정상으로 섭니다.
- 주소 유지: 운영 빌드의 경로 목록이 바뀌기 전과 같습니다.

## 범위 밖과 제약

- 과제 문구는 제작(`brew`)과 관리를 셸 없는 화면으로 적었지만, 지금 코드에서는 둘 다 사이드바가 있습니다. "지금 모양 유지"를 기준으로 사이드바를 그대로 둡니다.
- 워커가 바꾸는 값(제작 단계 · 크레딧)은 지금처럼 화면의 주기적 새로고침으로 갱신합니다. 새 갱신 경로를 만들지 않습니다.
