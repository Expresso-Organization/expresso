# 모델이 구성하는 포트폴리오 지면 레이아웃

## 문제

생성되는 포트폴리오의 레이아웃이 서로 비슷합니다. 9월 29일부터 지적된 문제이고, 전체 수집 라이브러리를 연결한 뒤(PR #55)에도 세 가상 프로필의 소개 원본은 2종, 전체 원본 조합은 3종에 그쳤습니다.

원인은 모델이 지면을 구성할 수 없는 Spec 구조에 있습니다. 저장된 Spec은 요소 9개가 모두 `page` 바로 아래에 놓인 평평한 목록입니다. 모델이 정하는 것은 배치·팔레트·글꼴 값, 가운데 섹션 순서, 섹션별 사례 유형과 원본 ID, 목차 방식뿐입니다. 사례를 나란히 놓거나, 경력을 측면 열에 두거나, 근거를 사례 옆에 묶는 구성은 선택지에 없습니다. 계약 검증(`validateStructuredPortfolio`)도 `elements` 수가 `page.children + 1`과 같아야 통과하므로 중첩을 막습니다.

json-render는 중첩 트리와 이름 있는 slot(`slots`)을 지원하지만 지금은 쓰지 않습니다. 이 상태로는 json-render를 쓰는 이유가 약합니다.

## 원하는 결과

- 카탈로그에 레이아웃 컨테이너가 있고, 모델이 기존 섹션 요소를 컨테이너의 children·slot에 넣어 지면을 구성할 수 있다.
- 모델은 여전히 데이터 참조(`$state`)와 등록된 컴포넌트·원본 ID만 쓴다. 모든 입력 섹션·경력·근거를 정확히 한 번씩 표시하고, 이름 소개가 처음, 연락처가 마지막이라는 규칙을 동적 Zod 계약과 저장 검증이 그대로 강제한다. 중첩 깊이와 컨테이너 개수에 상한이 있다.
- 기존에 저장된 평평한 Spec은 지금과 같은 결과로 렌더링된다. `library-selection-rerender-2026-10-09`의 Spec 세 개를 다시 그린 HTML이 PR #56 결과와 같다.
- 편집기의 기존 구성·문장 편집이 컨테이너 안의 섹션에서도 동작하고, 편집 후에도 컨테이너 구성이 보존된다.
- 컨테이너는 390px에서 한 열로 바뀌고 가로 넘침이 없으며, JavaScript 없이 표시된다.
- 세 가상 프로필을 모델로 다시 생성해 새 실행 기록으로 남긴다. `compare-runs.mjs` 비교 페이지와 검증 기록에 프로필별 컨테이너 트리 모양, 서로 다른 구성의 수, 토큰·시간 변화를 적는다. 모델이 컨테이너를 쓰지 않거나 세 결과가 같은 구성으로 수렴하면 그대로 보고한다.

## 영향 범위

- 생성 포트폴리오를 보는 사용자와 채용 담당자, 구성 편집을 쓰는 사용자.
- `packages/contracts`(Spec 계약·검증), `packages/portfolio-renderer`(카탈로그·컨테이너 컴포넌트·CSS), `services/backend/src/modules/page`(Spec 프롬프트·구성 편집), `services/web`의 구성 편집 화면, 검증·비교 스크립트, 실행 기록.
- 결정 권한: 박민재.

## 제약

- 모델이 HTML·CSS·문장을 쓰지 않는다. 입력에 없는 내용·수치·이미지를 만들지 않는다.
- 기존 저장 Spec과 공개 페이지를 깨지 않는다. 데이터 마이그레이션 없이 읽는다.
- 저장 크기 제한(`PAGE_MAX_BYTES`)과 JavaScript 없는 표시, 모션 감소 설정을 지킨다.
- PR #56(렌더러 결함 수정) 위에서 진행한다. 이 브랜치의 PR은 #56 머지 후 `main` 기준으로 맞춘다.

## 범위 밖

- SpecStream 점진 렌더링, patch·merge 편집 모드, decision-model composition 도입.
- 실행 원본 확대(project-grid 25개, experience·evidence 계열 연결).
- 편집기에서 컨테이너 자체를 만들거나 옮기는 UI. 이번에는 모델이 만든 구성을 보존하는 것까지 한다.
- 운영용 `anthropic` 공급자 구현, 히어로 배경 이미지 편집 기능.
