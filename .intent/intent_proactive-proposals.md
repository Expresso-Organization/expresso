# 에이전트 능동 제안

## 개발 목표와 의도

홈의 「제안」을 익스프레소가 먼저 행동을 권하는 공간으로 만듭니다. 지금 제안은 규칙으로 센 상태 문장입니다. 검증 계정으로 홈을 열면 「공개 중인 포트폴리오가 없습니다」와 「관심 공고 1건이 7일 안에 마감됩니다」 두 줄이 보이고, 새로 올라온 공고나 공모전이 내 기록과 어떻게 이어지는지는 말하지 않습니다.
요청자의 말: "이건 익스프레소가 사용자의 상황과 맥락, 그리고 새로 올라온 채용 공고와 공모전 등의 활동을 기반으로 적극적으로 행동을 제안하는 공간이어야 해."
그래서 에이전트가 내 기록과 새 공고 · 공모전을 읽고, 근거를 대며 할 일을 제안하게 합니다. 사용자가 누르지 않아도 AI가 실행되므로 켠 사람에게만 돌리고 크레딧을 차감합니다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 제안 켜기 | 홈의 제안 자리에 「제안 켜기」가 보입니다. 누르면 무엇을 읽는지, 언제 실행되는지, 크레딧이 차감된다는 것을 적은 창이 뜨고, 「켜기」를 눌러야 시작됩니다. 켠 뒤에는 같은 자리에서 끌 수 있습니다. | 누르지 않아도 AI가 실행되고 크레딧이 줄기 때문에 본인이 직접 켠 사람에게만 적용해야 합니다. |
| 에이전트가 쓴 제안 | 제안 한 건은 할 일 한 문장, 그렇게 권하는 이유, 근거로 든 내 기록과 대상(공고나 공모전, 마감까지 남은 날)으로 이뤄집니다. 예: 새 공모전과 주제가 겹치는 내 프로젝트 기록을 짚고 참가 계획을 권합니다. | 규칙으로 센 문장은 "정형화"돼 보이고, 내 상황과 새 소식을 잇지 못합니다. |
| 제안에서 대화 시작 | 제안의 단추를 누르면 그 공고나 기록이 연결되고 요청문이 홈 입력창에 채워집니다. 보내기를 누르면 대화가 시작됩니다. | 제안을 읽고 바로 행동으로 옮기게 합니다. |
| 관심 없음 | 제안마다 「관심 없음」을 누르면 그 제안이 사라지고, 같은 대상을 다시 제안하지 않습니다. | 맞지 않는 제안이 계속 남으면 제안 자리를 보지 않게 됩니다. |
| 매일 한 번 실행 | 켠 사용자마다 하루에 한 번 제안을 새로 만듭니다. 홈을 열면 이미 만들어져 있습니다. | 홈을 열 때마다 기다리지 않게 합니다. |
| 새 소식이 들어올 때 실행 | 새 채용 공고나 공모전을 수집한 직후, 그 소식이 기록과 맞는 사용자에게만 하루 한 번까지 제안을 새로 만듭니다. | 마감이 가까운 새 소식을 다음 날까지 미루지 않으려는 것입니다. 관련 없는 사용자의 크레딧은 쓰지 않습니다. |
| 다시 받기 | 「다시 받기」를 누르면 그 자리에서 새로 만들고, 만드는 동안 「자료 고르는 중」 · 「제안 쓰는 중」이 보입니다. | 기록을 고친 직후처럼 지금 다시 보고 싶을 때가 있습니다. |
| 크레딧 차감과 한도 | 실행마다 사용한 만큼 이번 달 크레딧에서 빠집니다. 크레딧이 남지 않았으면 실행하지 않고 그 사실을 제안 자리에 적습니다. 이때는 규칙으로 센 제안을 대신 보여 줍니다. | 요청자가 정한 과금 방식입니다. 한도를 넘겨 실행하지 않아야 합니다. |
| 공모전 수집과 저장 | 위비티의 IT 분야 공모전을 하루에 한 번 받아 저장하고 처음 본 때를 적어 둡니다. 탐색의 공모전 · 해커톤 목록과 홈의 공모전 위젯이 이 저장분을 읽습니다. | 지금은 화면을 열 때마다 읽어서 "새로 올라온 것"을 알 수 없고, 서버의 에이전트가 읽을 수도 없습니다. |

## 개발 목표

- 켜기: 검증 계정으로 홈에서 「제안 켜기」를 누르면 안내 창이 뜨고, 「켜기」를 누르면 제안을 만들기 시작합니다.
- 제안 내용: 만들어진 제안이 실제 내 기록의 제목과 실제 공고나 공모전을 짚습니다. 없는 기록이나 없는 공고를 짚는 제안은 저장되지 않습니다.
- 대화 시작: 제안의 단추를 누르면 입력창에 자료와 요청문이 채워지고, 보내면 에이전트가 답합니다.
- 과금: 한 번 실행한 뒤 사이드바의 이번 달 크레딧이 늘고, 설정의 사용량에 「능동 제안」 줄이 생깁니다.
- 꺼 둔 계정: 켜지 않은 계정은 매일 실행과 새 소식 실행의 대상이 되지 않습니다.

## 범위 밖과 제약

- 가장 저렴한 모델 단계(지금의 haiku 단계)를 씁니다. 모델 이름을 코드에 새로 적지 않습니다.
- 제안이 권하는 행동은 정해진 네 가지입니다: 공고 요건 대조, 공고로 포트폴리오 만들기, 공모전 참가 계획, 기록 보강. 에이전트가 요청문을 직접 쓰지 않고 서버가 씁니다. 공고와 공모전의 글은 바깥에서 온 글이라 그대로 요청문에 넣지 않습니다.
- 방문 통계와 준비 계획 진행을 근거로 한 제안, 부트캠프 · 인턴 전용 출처, 이메일 · 알림 전달은 이번에 하지 않습니다.
- 에이전트를 모든 사용자에게 여는 일(서버 인증 + 크레딧)은 별도 변경입니다. 제안으로 시작한 대화는 지금의 에이전트 접근 조건을 따릅니다.
- 운영 서버 설정(AI 공급자, 예약 작업)은 바꾸지 않습니다. 검증은 검증 서버에서 합니다.

## 열린 질문

- 켜는 창에 실행 한 번의 크레딧을 적을지 정해야 합니다. 검증 서버에서 실제로 잰 값만 적을 수 있으므로, 구현 뒤 잰 값을 보고 정합니다. 그 전까지는 "실행마다 크레딧이 차감됩니다"만 적습니다.
