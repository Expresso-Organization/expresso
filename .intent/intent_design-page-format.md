# 디자인 선택 단계 생성 방식 선택

## 개발 목표와 의도

"디자인 선택 단계에서 포트폴리오 자유 생성 경로(새로 추가)하고 현재 경로(이름 정해야함) 중에서 고를 수 있게 하자. 이건 비교 테스트를 위함이야"

지금 포트폴리오 지면을 만드는 방식은 서버 설정(`PAGE_GENERATION_FORMAT`) 하나로 정해진다.
기본값은 모델이 구성 문서(Spec)를 쓰고 우리 렌더러가 디자인 시스템으로 그리는 방식이고, 모델이 HTML과 CSS 전체를 직접 쓰는 방식은 설정을 바꿔 서버를 다시 띄워야만 쓸 수 있다.
두 방식을 같은 공고 · 같은 재료 · 같은 디자인으로 나란히 만들어 비교하려면, 생성할 때마다 방식을 고를 수 있어야 한다.

이름은 이렇게 정한다.
- **구조화 생성** — 지금 기본 경로. 모델이 구성을 쓰고 렌더러가 그린다. 코드와 커밋이 이미 「구조화 포트폴리오 생성」이라 부른다.
- **자유 생성** — 모델이 지면의 HTML · CSS를 직접 쓴다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 생성 방식 선택 | 디자인 선택 화면의 「페이지 짜임새」 위에 「생성 방식」 두 칸(구조화 생성 · 자유 생성)이 서고, 고른 방식으로 「이 디자인으로 만들기」가 생성한다. 처음에는 구조화 생성이 골라져 있다. | 지금은 방식을 바꾸려면 서버 설정을 고치고 다시 띄워야 해서, 같은 입력으로 두 결과를 비교할 수 없다. |
| 짜임새 칸 비활성 | 자유 생성을 고르면 「페이지 짜임새」 칸이 흐려지고 고를 수 없다. | 짜임새는 구조화 생성의 렌더러만 읽는다. 자유 생성에서 고르게 두면 결과에 반영되지 않는 선택을 하게 된다. |
| 생성 방식 기록 | 생성 작업과 만들어진 포트폴리오에 어느 방식으로 만들었는지 남는다. | 비교하려면 결과물이 어느 방식에서 나왔는지 알아야 한다. |
| 다시 뽑기 방식 유지 | 편집 화면에서 지시를 붙여 다시 뽑으면, 그 포트폴리오를 만든 방식으로 다시 만든다. | 서버 기본값으로 다시 뽑으면 자유 생성 지면이 구조화 지면으로 바뀌어 비교가 깨진다. |

## 개발 목표

- 디자인 선택 화면에서 생성 방식 두 칸이 보이고, 자유 생성을 고르면 짜임새 칸이 비활성으로 바뀐다.
- 자유 생성으로 만들면 생성 작업 문서(`generation_jobs`)와 포트폴리오 문서에 `pageFormat: "html"`이 남는다.
- 방식을 보내지 않는 요청(이전 화면 · 다른 클라이언트)은 지금처럼 서버 설정 값으로 만든다.
- 워커가 작업마다 그 작업의 방식으로 생성기를 고른다는 것을 단위 시험이 확인한다.

## 범위 밖과 제약

- 두 결과를 한 화면에 나란히 놓는 비교 화면은 만들지 않는다. 같은 브루에서 「다시 뽑기」로 다른 방식을 고르면 두 포트폴리오가 생긴다.
- 생성기(`AiPageGenerator` · `StructuredPageGenerator`)의 프롬프트와 출력은 바꾸지 않는다.
- 선택 칸은 모든 사용자에게 보인다(열린 질문 1의 답).

## 열린 질문

1. 생성 방식 칸을 누구에게 보일까. 지금은 모든 사용자에게 보이고 기본값은 구조화 생성이다. 관리자(`role: admin`)에게만 보이게 하면 화면 조건 하나가 늘어난다.
   - 답(2026-11-09): 모든 사용자에게 보인다.
2. 「자유 생성」은 제작 입구의 공고 없이 만드는 갈래(`createFreeBrew`, 화면 문구 「자유 생성」)와 이름이 겹친다. 요청한 이름을 그대로 쓰고, 다른 이름이 필요하면 화면 문구만 바꾼다.
