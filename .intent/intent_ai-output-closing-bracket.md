# AI 출력 끝 닫는 괄호 누락 시 생성 실패 수정

## 개발 목표와 의도

요청: "AI 출력 끝 괄호 누락 시 생성 실패 수정."

2026-10-28 체험 서버에서 포트폴리오를 생성했을 때 다섯 번 가운데 한 번이 이렇게 멈췄습니다. 채우기 모델이 고친 칸을 보낸 답(`{"fixes":[...]}`)이 마지막 `}` 하나만 빠진 채 왔습니다. 서버는 "끝부분을 고쳐 달라"고 같은 대화에 다시 물었습니다. 모델이 보낸 고침은 원문에 적용되지 않았고(`applied: 0`), 생성 전체가 "출력이 JSON이 아님"으로 실패했습니다. 사용자 화면에는 "지난 생성이 실패했습니다"만 남고, 다시 만들려면 생성 1회를 더 씁니다.

이번 변경은 닫는 괄호만 빠진 답을 서버가 바로 닫아 읽게 합니다. 모델에게 다시 묻지 않으므로 이 경우의 실패와 추가 호출이 함께 없어집니다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 빠진 닫는 괄호 채우기 | 다 쓴 답의 끝에서 `}` · `]`만 빠졌으면 서버가 빠진 괄호를 붙여 읽습니다. 로그에 무엇을 붙였는지 남습니다. | 지금은 이 경우 모델에게 고침을 물어도 적용되지 않아 생성 전체가 실패합니다. 괄호 한두 개는 내용이 아니라 문법이라 서버가 정할 수 있습니다. |
| 고침이 적용되지 않았을 때 답 기록 | 문법 고침이 원문에 하나도 적용되지 않으면 모델이 보낸 고침 답을 로그에 남깁니다. | 이번 실패도 모델이 무엇을 보냈는지 로그에 없어 원인을 추측해야 했습니다. |

## 개발 목표

- 끝의 `}`가 빠진 답을 받는 가짜 CLI 테스트에서, 생성이 모델 추가 호출 없이 끝나고 값이 맞게 읽힙니다.
- 출력 한도로 끊긴 답(`max_tokens`)은 지금처럼 이어 쓰기를 받습니다.
- 문자열 중간에서 끊겼거나 괄호가 많이 빠진 답은 지금처럼 끝부분 조각을 모델에게 고쳐 받습니다.
- `pnpm test`와 `fixes.test.ts`의 규칙 검사(공급자 형식 · 다시 쓰기 금지)가 통과합니다.

## 범위 밖과 제약

- AGENTS.md 「지키는 선」을 그대로 지킵니다. 출력을 거절해 처음부터 다시 쓰게 하지 않고, `--json-schema`를 쓰지 않습니다.
- 서버가 채우는 것은 닫는 괄호뿐입니다. 값 · 키 · 쉼표는 채우지 않습니다. 닫은 뒤의 값은 지금처럼 계약(Zod)과 `check`를 지납니다.
- 다른 문법 오류(따옴표 · 쉼표)의 고치기 방식은 바꾸지 않습니다.
