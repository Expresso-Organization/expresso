# 타입 검사의 경로 타입 생성

## 개발 목표와 의도

`pnpm typecheck`가 지금 코드의 화면 경로로 링크를 검사하게 한다. 지금은 `services/web/.next/types`에 남아 있는 파일로 검사한다. 그 폴더는 마지막으로 웹을 빌드했을 때의 것이다.

그래서 같은 코드의 결과가 그 폴더의 상태에 따라 갈린다.

- 폴더가 없으면(CI의 타입 검사 단계, 새로 받은 저장소) 링크 경로를 검사하지 않는다. 없는 경로로 링크를 걸어도 통과하고, 뒤의 빌드 단계에서야 걸린다. #246이 겪은 「타입 검사 통과 · 빌드 실패」가 이것이다.
- 폴더가 옛 것이면 맞는 링크가 「없는 경로」로 걸린다. #247이 `/goal` 링크의 `as Route`를 뗀 뒤로, `/goal`이 생기기 전에 빌드해 둔 작업 폴더에서는 `pnpm typecheck`가 실패한다. 이 오류를 본 사람이 `as Route`를 다시 붙이면 그 링크의 검사가 꺼진다.

#247은 운영 빌드의 같은 문제를 고쳤고, 이 일은 범위 밖으로 남겼다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 검사 전에 경로 타입 새로 만들기 | `pnpm typecheck`를 치면 웹의 화면 경로 목록을 먼저 새로 만들고(1초) 그 목록으로 링크를 검사한다. 빌드를 해 둔 적이 없어도, 예전에 해 둔 빌드가 남아 있어도 결과가 같다. | 결과가 작업 폴더에 남은 파일에 따라 갈리면, 맞는 코드가 실패하고 틀린 코드가 통과한다. |
| CI의 타입 검사 단계도 링크 검사 | PR의 「웹 검사」에서 타입 검사 단계가 없는 경로의 링크를 잡는다. 지금은 빌드 단계까지 가야 잡힌다. | 타입 검사만 돌려 보고 올린 변경이 CI의 뒤 단계에서 실패한다. |
| `next-env.d.ts`를 저장소에서 빼기 | Next가 개발 서버 · 빌드 · 타입 생성 때마다 다시 쓰는 `services/web/next-env.d.ts`를 저장소가 추적하지 않는다. `pnpm typecheck`를 쳐도 `git status`에 바뀐 파일이 생기지 않는다. | 타입 검사가 매번 이 파일을 다시 쓰게 된다. 추적하는 채로 두면 검사할 때마다 변경이 생기고 커밋에 섞인다. Next 문서도 이 파일을 추적하지 말라고 적는다. |
| 배포 스크립트의 되돌리기 줄 제거 | `deploy.sh`가 배포 전에 `next-env.d.ts`를 되돌리던 줄을 지운다. | 추적하지 않는 파일을 되돌리려 하면 git이 오류를 내고 배포가 그 줄에서 멈춘다. 지우지 않으면 이 변경이 배포된 뒤의 모든 배포가 멈춘다. |

## 개발 목표

- `.next`가 없는 상태에서 없는 경로로 링크를 걸고 `pnpm --filter @expresso/web typecheck`를 치면 실패한다. 고치기 전에는 통과한다.
- `/goal`이 생기기 전의 `.next/types`가 남은 상태에서 지금 코드로 같은 명령을 치면 통과한다. 고치기 전에는 `/goal` 링크에서 실패한다.
- 화면을 지우고 그 화면으로 가는 링크를 남기면 실패한다.
- `next-env.d.ts`가 없는 상태에서 쳐도 통과한다(CSS · 이미지 import의 타입 포함).
- 타입 검사 뒤 `git status`에 `next-env.d.ts`가 나오지 않는다.
- 배포 스크립트의 git 구간이 네 경로에서 멈추지 않는다: 이 변경으로 넘어가는 첫 배포, 그 뒤의 보통 배포, 옛 커밋으로 되돌리기, 되돌린 뒤 다시 앞으로.

## 범위 밖과 제약

- 이 변경이 `main`에 들어가면, `next-env.d.ts`를 고친 채로 둔 작업 폴더는 `main`을 받을 때 git이 거절한다. `git checkout -- services/web/next-env.d.ts`를 먼저 친다. 받은 뒤 파일은 개발 서버나 타입 검사가 다시 만든다.
- 이 변경의 배포가 「이 변경으로 넘어가는 첫 배포」 경로의 첫 실제 실행이다. 그 전의 근거는 실제 커밋으로 돌린 로컬 실험이다.
- 편집기(IDE)가 개발 서버를 띄운 동안 읽는 경로 타입은 다루지 않는다. 편집기는 마지막 타입 검사나 빌드 때의 `.next/types`를 읽는다.
- 저장소 곳곳의 기존 `as Route`는 건드리지 않는다.
