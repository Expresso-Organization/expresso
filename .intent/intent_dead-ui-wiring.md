# 동작하지 않는 화면 요소 정리

## 개발 목표와 의도

화면에는 있는데 눌러도 아무 일이 없거나 예시 데이터를 그리는 요소가 웹 곳곳에 있다. 요청: "화면에 보이지만 동작하지 않는 요소를 전부 실제로 동작하게 만든다." 예: 편집 화면의 모바일 버튼과 확대 버튼은 눌러도 그대로이고 배율은 늘 「72%」다. 설정 화면의 사용량 「2 / 3」과 결제 내역은 아무 계정에서나 같다. 동작시킬 수 있는 것은 실제 API와 데이터에 연결하고, 근거가 없는 것은 결정을 받아 화면에서 뺀다. 요소별 판정은 [분류표](inventory_dead-ui-wiring.md)에 있다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 통합 검색 · 사이드바 | ⌘K 검색창이 내 기록 · 포트폴리오 · 공고를 실제로 찾아 누르면 연다. 사이드바의 포트폴리오 추가 ＋와 포트폴리오 행을 누르면 해당 화면으로 간다 | 지금은 「정산」 예시 결과만 보인다 |
| 알림 | 생성 완료 · 마감 임박이 생기면 알림 패널에 쌓이고 안 읽은 수가 맞게 보인다. 「모두 읽음」이 동작한다 | 알림을 만드는 코드가 없어 패널을 API에 붙여도 늘 비어 있다 |
| 공고 탐색 | 「조건 추가」 「이 검색 저장」 최근 검색 「지우기」 정렬 「포트폴리오 만들기」가 동작한다 | 검색을 고치거나 남길 방법이 없다 |
| 홈 · 온보딩 진입 | 홈의 「만들기」와 「이어서 답하기」가 제작 단계로 간다. 온보딩 첫 포트폴리오 화면이 내 추천 공고와 기록 수를 보여 준다 | 첫 화면의 주요 버튼이 동작하지 않는다 |
| 편집 화면 | 데스크톱 · 모바일 전환, 확대 · 축소, 되돌리기, HTML 보기, 미리보기, 「내 커리어에서 가져오기」, 이력 필터가 동작한다 | 편집 중 결과를 확인하거나 되돌릴 수 없다. 이력의 「AI 편집」은 기록이 전부 사용자 편집으로 남아 늘 비어 있다 |
| 설정 | 사용량이 내 생성 횟수와 초기화 날짜를 보여 준다. 데이터 내보내기는 파일로 받는다. 계정 삭제를 요청하면 로그아웃되고, 한 번만 보이는 취소 코드를 안내한다. 알림 탭에서 알림 종류를 켜고 끈다 | 지금 값은 아무 계정에서나 같은 예시다 |
| 근거 없는 요소 제거 | 고정 문구 · 장식 버튼(「⌘↵」, 「팀 요금제」, 「예상 3분」 등)과 쓰지 않는 예시 데이터를 지운다 | 동작하는 것처럼 보이지만 아무 일도 하지 않는다 |

## 개발 목표

- dev01로 로그인해 분류표의 「연결」 요소를 하나씩 누르면 실제 데이터가 바뀌거나 해당 화면으로 간다.
- 편집 화면에서 모바일을 누르면 캔버스 폭과 배율 표시가 함께 바뀐다.
- 포트폴리오를 생성하면 알림 패널에 그 알림이 생긴다.
- `services/web/src/lib/sample`에 예시 데이터가 남지 않는다. 정의서 문구(공고 검색창 예시)는 그 화면 옆으로 옮긴다.
- 판정 스캔을 다시 돌리면 이 목록의 항목에서 「핸들러 없음 · 샘플」 사유가 사라진다.

## 범위 밖과 제약

- 도메인별로 PR을 나눈다: 셸 · 검색 · 알림 / 공고 / 홈 · 온보딩 / 편집 · 배포 / 설정. 각 PR은 시작 전에 main을 받는다.
- 열린 PR이 고치는 화면(이전 커리어 목록 #101, 커리어 보드 · 타임라인 #76, 공고 상세 #65 · #70, 디자인 선택 #100)은 머지 뒤 다시 판정한다. 사이드바 카테고리 추가 · 트리 ＋(T1.1.2 · T1.1.4)는 #105 · #76 머지 뒤 오시건과 정한다. 오시건 · 윤규현 PR과 겹치는 파일은 손대기 전에 묻는다.

## 열린 질문

- 만들지 걷어낼지 → 모두 걷어낸다: 요금제 변경 · 결제 내역, 커스텀 도메인, GitHub 로그인, PDF · 덱 내보내기(지금은 가짜 경로를 저장), 이력서 가져오기(온보딩), 순서 개선 제안, 섹션 추가, 다시 실행.
- 알림 → 알림을 만드는 코드부터 짓는다.
- 분류표의 나머지 「결정」 행(장식 포함) → 모두 걷어낸다.
