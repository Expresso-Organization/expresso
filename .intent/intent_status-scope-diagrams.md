# 진행 현황 작업 범위 · 분량 다이어그램

## 변경 의도

지금 「진행 현황」은 범위와 남은 양을 숫자 카드와 도메인별 막대로만 보여 준다. 전체 209개 기능이 어떻게 나뉘는지, 남은 기능이 학기 끝까지 줄어들 수 있는지, 누구에게 얼마나 몰려 있는지는 숫자를 직접 비교해야 알 수 있다.

> "다양한 다이어그램을 통해서 작업 범위와 분량, 남은 작업 양 등을 좀 시각적으로 보고 싶은데"

이번 변경은 서버 스캔이 이미 만드는 판정 결과와 이력만 사용한다. 스캐너는 바꾸지 않는다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 작업 범위 지도 | 209개 기능을 도메인 → 주요기능 → 기능 순으로 나눈 사각형 지도(트리맵). 칸 하나가 기능 하나이고 색이 완료 · 부분 · API만 · 미구현을 뜻한다. 칸을 누르면 그 기능의 판정 상세가 열린다 | 전체 범위와 남은 자리를 한 화면에서 보려면 기능을 하나하나 그려야 한다 |
| 남은 작업 번다운 | 가로축 학기 2–15주, 세로축 완료가 아닌 기능 수. 스캔 이력으로 실제 선을 그리고, 지금부터 15주까지 0이 되려면 주당 몇 개를 끝내야 하는지 선과 숫자로 보여 준다 | 남은 양이 일정 안에 끝나는 속도로 줄고 있는지 판단해야 한다 |
| 팀원별 작업량 | 팀원마다 담당 기능 수를 상태별로 쌓은 가로 막대. 막대를 누르면 그 팀원 화면으로 바뀐다 | 남은 작업이 한 사람에게 몰려 있으면 일을 다시 나눠야 한다 |
| 제안서 일정표 | 제안서 일정 항목을 주차 위의 막대(간트)로 그리고 이번 주차에 세로선을 긋는다. 막대에 담당자를 적는다 | 남은 작업량을 남은 일정과 같은 화면에서 비교해야 한다 |

팀원을 고르면 네 그림 모두 그 팀원 담당 기능만으로 다시 그린다.

## 개발 목표

- 「진행 현황」을 열면 작업 범위 지도에 209개 칸이 보이고, 칸 색별 개수가 위쪽 카드의 상태별 개수와 같다.
- 지도에서 칸을 누르면 그 기능의 판정 상세(빠진 것 · 근거 파일)가 열린다.
- 번다운에 "15주까지 주당 N개" 숫자가 나오고, N은 남은 기능 수 ÷ 남은 주 수와 같다.
- 팀원별 작업량 막대에서 「채서현」을 누르면 화면 전체가 채서현 담당으로 바뀐다.
- 일정표의 이번 주차 선이 화면 위쪽의 「10주차」와 같은 자리에 있다.
- 라이트 · 다크 테마와 휴대폰 폭에서 그림이 잘리지 않는다.

## 범위 밖과 제약

- 작업량을 시간이나 포인트로 추정하지 않는다. 설계서에 기능별 크기 값이 없어서 분량은 기능 개수로만 센다.
- 스캐너와 결과 파일 형식은 바꾸지 않는다.
- 번다운의 실제 선은 스캔 이력이 쌓인 만큼만 그려진다. 지금은 2026-10-25 한 점뿐이다.
