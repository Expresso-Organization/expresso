# 커리어 카테고리 보관 · 삭제

## 개발 목표와 의도

「내 커리어」에 카테고리를 추가할 수는 있지만 없앨 방법이 없다. 사용자 말로 "내 커리어 카테고리 삭제할 수 있는 방법이 없네." 사이드바에서 「카테고리 추가」로 잘못 만든 카테고리는 영원히 목록에 남고, 카테고리 머리말의 「…」 메뉴에는 「휴지통」 하나뿐이다.
이번 변경으로 모든 카테고리를 보관해 목록에서 치울 수 있게 하고, 직접 만든 카테고리는 삭제까지 할 수 있게 한다. 기본 7종은 인터뷰 답변 저장과 경력 기간 계산이 기대고 있어 보관만 허용한다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 카테고리 보관 | 카테고리 머리말 「…」 메뉴의 「보관」을 누르면 그 카테고리가 사이드바 「내 커리어」 목록에서 빠진다. 기록과 포트폴리오 인용은 그대로 남는다. | 기본 카테고리처럼 지울 수 없는 것도 쓰지 않으면 목록에서 치울 수 있어야 한다. |
| 보관함과 보관 해제 | 사이드바 목록 끝 「보관됨」을 펼치면 보관한 카테고리가 보이고, 열어서 「…」 메뉴의 「보관 해제」로 되돌린다. 보관된 카테고리 머리말에는 「보관됨」이 표시된다. | 보관한 카테고리를 다시 찾고 되돌릴 자리가 없으면 보관이 사실상 삭제가 된다. |
| 직접 만든 카테고리 삭제 | 직접 만든 카테고리의 「…」 메뉴에 「카테고리 삭제」가 생긴다. 기록이 없으면 확인 한 번으로 지워지고 다른 카테고리 화면으로 이동한다. | 잘못 만들었거나 다 쓴 카테고리를 없애는 요청 그 자체다. |
| 기록을 함께 지울지 묻기 | 기록이 남은 카테고리를 지우려 하면 확인 창이 「기록 N개(휴지통 M개 포함)도 영구 삭제됩니다」라고 알리고 「기록까지 삭제」 · 「대신 보관」 · 「취소」 중에서 고르게 한다. | 사용자가 기록을 같이 지울지 직접 정하게 해 달라고 했다. 영구 삭제라 되돌릴 수 없으므로 고르기 전에 수를 보여야 한다. |
| 삭제를 막는 경우 안내 | 포트폴리오가 인용 중인 기록이 있거나, 다른 카테고리의 관계 속성이 이 카테고리를 가리키면 확인 창이 그 이유(포트폴리오 인용 기록 수, 「프로젝트」의 「관련 경력」 같은 속성 이름)를 보여 주고 「대신 보관」만 남긴다. | 그대로 지우면 배포한 포트폴리오의 인용이 끊기거나 다른 카테고리의 관계 칸이 없는 곳을 가리킨다. |

## 개발 목표

- 직접 만든 빈 카테고리: 「…」 → 「카테고리 삭제」 → 확인하면 사이드바에서 사라지고 첫 카테고리 화면으로 간다.
- 기록 3개가 있는 직접 만든 카테고리: 확인 창에 「기록 3개」가 보이고, 「기록까지 삭제」를 누르면 카테고리와 기록이 함께 사라진다. 「대신 보관」을 누르면 보관으로 끝난다.
- 기본 카테고리 「학력」: 「…」 메뉴에 「보관」만 있고 「카테고리 삭제」가 없다. 보관하면 사이드바 「보관됨」 아래로 옮겨 가고, 「보관 해제」로 원래 자리에 돌아온다.
- 포트폴리오가 인용 중인 기록이 있는 카테고리: 확인 창에 「기록까지 삭제」 대신 막힌 이유와 「대신 보관」이 보인다.

## 범위 밖과 제약

- 카테고리 이름 · 아이콘 · 순서 바꾸기는 하지 않는다.
- 보관한 카테고리의 기록은 포트폴리오 재료 추천 · 검색 · 에이전트 대화에서 그대로 쓰인다. 보관은 사이드바 목록과 「카테고리 이동」 · 관계 대상 선택지에서만 숨긴다.
- 삭제한 카테고리와 기록은 되살리지 않는다(휴지통을 거치지 않는다).
- 열린 PR #206(기록 삭제 동작)과 겹치는 파일(`CareerViewShell.tsx`, `packages/contracts/src/career.ts`의 기록 삭제 스키마 부분)은 따로 손대지 않는다.
