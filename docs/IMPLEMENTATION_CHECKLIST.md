# Expresso 백엔드 구현 체크리스트

체크박스는 워커의 완료 보고가 아니라 통합 브랜치에서 완료 기준과 증거가 모두 검증된 뒤에만 닫는다.

## M0. 기반과 계약

- [x] **M0-01. 재현 가능한 기준선을 고정한다.**
  - 완료 기준: 기준 커밋, 변경 파일, 런타임 버전, 로컬 인프라 상태와 `pnpm test`, `pnpm typecheck`, `pnpm build` 결과가 기록되고 동일 명령을 다시 실행할 수 있다.
  - 증거: `coordination/evidence/BASELINE.md`, Git 리비전, 세 명령의 통과 로그 요약.
  - 의존성: 없음.

- [x] **M0-02. 제품 결정과 백엔드 범위를 동결한다.**
  - 완료 기준: B1–B4와 Q1/Q2/Q5의 구현 기본값, 비목표, D1–D12 백엔드 책임이 승인된 결정 문서에 기록된다.
  - 증거: `docs/IMPLEMENTATION_PLAN.md` 결정 게이트, 승인 리비전 또는 사용자 승인 기록.
  - 의존성: M0-01.

- [x] **M0-03. 버전이 있는 API·이벤트 계약을 제공한다.**
  - 완료 기준: `/v1` DTO, 오류 봉투, 페이지네이션, 리소스 버전, 멱등 키, 작업 payload 스키마가 `packages/contracts`에서 빌드되고 유효/무효 fixture 계약 테스트가 통과한다.
  - 증거: 계약 소스, 생성된 스키마/OpenAPI, `pnpm --filter @expresso/contracts test` 결과.
  - 의존성: M0-02.

- [x] **M0-04. 로컬·CI 인프라와 작업 전달 기반을 완성한다.**
  - 완료 기준: PostgreSQL과 Redis를 격리 실행하는 한 명령 구성이 있고 API/Worker readiness, transactional outbox 또는 동등한 전달 보장, 재시도와 DLQ 스모크가 통과한다.
  - 증거: 로컬 인프라 구성, readiness 통합 테스트, outbox/queue 재시도 테스트와 DLQ 로그.
  - 의존성: M0-03.

- [x] **M0-05. 인증과 사용자 데이터 격리를 강제한다.**
  - 완료 기준: 세션 또는 토큰 검증, request user context, 보호 route가 구현되고 사용자 A가 사용자 B의 리소스를 UUID로 직접 요청하는 전체 테스트가 404 또는 403으로 종료된다.
  - 증거: identity 모듈 테스트, 인증 계약 테스트, 교차 사용자 접근 회귀 테스트.
  - 의존성: M0-03.

- [x] **M0-06. CI·관측·비밀 보호 게이트를 구축한다.**
  - 완료 기준: CI가 typecheck/test/build/migration/contract 검사를 실행하고 구조화 로그·request/trace ID·오류 계측이 동작하며 로그에서 토큰, DB URL, 원문 개인정보가 검출되지 않는다.
  - 증거: CI workflow, 관측 스모크 테스트, 비밀 문자열 부정 테스트 결과.
  - 의존성: M0-04, M0-05.

## M1. 커리어 기록 종단 슬라이스

- [x] **M1-01. 가입 시 기본 카테고리 7종을 멱등 생성한다.**
  - 완료 기준: 신규 사용자 생성 시 고정 순서의 시스템 카테고리 7종이 보이고 재시도해도 중복 행이 생기지 않으며 시스템 정의를 삭제·이름 변경할 수 없다.
  - 증거: category 서비스/DB 통합 테스트와 7종 fixture.
  - 의존성: M0-05.

- [x] **M1-02. 기록 CRUD와 자동 저장 동시성 계약을 제공한다.**
  - 완료 기준: 기록 생성·조회·수정 API가 user scope를 강제하고 버전이 오래된 저장을 `412`로 거부하며 같은 멱등 키 재전송 시 기록이 한 개만 존재한다.
  - 증거: HTTP 통합 테스트, 동시 수정 테스트, 멱등 재전송 테스트.
  - 의존성: M1-01.

- [x] **M1-03. 속성·뷰·기록 연결 불변식을 구현한다.**
  - 완료 기준: 카테고리 속성 스키마 검증, 저장된 필터/정렬/뷰, 양방향 기록 연결이 동작하고 값이 있는 속성 삭제와 교차 사용자 연결이 거부된다.
  - 증거: repository/route 테스트, 속성 삭제 영향 응답 fixture, 소유권 제약 테스트.
  - 의존성: M1-02.

- [x] **M1-04. 삭제 영향·휴지통·복원을 보장한다.**
  - 완료 기준: 삭제 전 사용처 수를 반환하고 삭제 기록은 30일 보존되며 복원할 수 있고 배포 snapshot과 기존 포트폴리오 블록은 자동 변경되지 않는다.
  - 증거: 시계 고정 통합 테스트, 복원 테스트, 배포본 불변성 fixture.
  - 의존성: M1-02.

- [x] **M1-05. 스킬을 원문 근거에서 계산한다.**
  - 완료 기준: 스킬 정규화·숙련도·최근 사용 시점이 기록 근거로만 계산되고 모든 skill evidence가 실제 record span과 일치하며 근거 한 건 이하는 약함으로 판정된다.
  - 증거: 정규화/집계 단위 테스트, span 일치 통합 테스트, 근거 없는 스킬 부정 테스트.
  - 의존성: M1-02.

- [x] **M1-06. 첫 인증→기록 종단 흐름을 검증한다.**
  - 완료 기준: 빈 DB에서 사용자 생성, 기본 카테고리 조회, 기록 생성, 자동 저장 충돌, 근거 조회, 다른 사용자 접근 차단이 실제 PostgreSQL HTTP E2E 한 묶음으로 통과한다.
  - 증거: `services/backend/test/e2e/career-vertical-slice.test.ts` 실행 결과와 CI artifact.
  - 의존성: M1-03, M1-04, M1-05, M0-06.

## M2. 채용 공고와 분석

- [x] **M2-01. 사용자 공고 입력과 원문 불변성을 구현한다.**
  - 완료 기준: URL/본문 입력을 정규화 대기열에 넣고 200자 미만 본문을 거부하며 원문·출처·dedupe hash를 보존하고 중복 요청이 한 공고로 합쳐진다.
  - 증거: 입력 API 테스트, 원문 변경 거부 DB 테스트, 중복 fixture 테스트.
  - 의존성: M1-06.

- [x] **M2-02. 검색 조건·저장 검색·관심 공고를 제공한다.**
  - 완료 기준: 자연어에서 얻은 수정 가능한 조건과 원문 질의를 함께 저장하고 사용자별 최대 10개 검색, 최근 검색 삭제, 관심 상태/마감을 user scope로 관리한다.
  - 증거: 검색 parser 계약 fixture, 제한/삭제/관심 통합 테스트.
  - 의존성: M2-01.

- [x] **M2-03. 설명 가능한 일치도와 결과 집계를 계산한다.**
  - 완료 기준: 기록 3건 이상에서 네 축 합계가 0–100 정수이고 축 합·한 문장 사유·다음 행동을 저장하며 5개 미만 표본에서는 수요 비율을 반환하지 않는다.
  - 증거: 점수 golden fixture, 경계값 테스트, 표본 부족 부정 테스트.
  - 의존성: M2-02, M1-05.

- [x] **M2-04. 공고 분석을 재시도 가능한 백그라운드 작업으로 실행한다.**
  - 완료 기준: 분석 API가 job ID와 실제 단계 상태를 반환하고 Worker 재시작/중복 전달에도 분석 결과가 한 번만 완료되며 실패 상태와 재시도 가능성이 보존된다.
  - 증거: API→queue→worker 통합 테스트, 중복 job 테스트, 강제 재시작 로그.
  - 의존성: M2-01, M0-04.

- [x] **M2-05. 요구 역량과 원문 인용을 검증한다.**
  - 완료 기준: 3–6개 요구 역량의 모든 source span이 보존된 공고 원문과 문자열 일치하고 불일치 인용은 저장되지 않는다.
  - 증거: source span validator 테스트, 정상/변조 공고 fixture, requirement DB 통합 테스트.
  - 의존성: M2-04.

- [x] **M2-06. 기록 커버리지와 재분석 이력을 보존한다.**
  - 완료 기준: 요구 역량별 covered/partial/missing 판정과 record ID가 저장되고 재분석 시 직전 결과 1회분을 조회할 수 있으며 기존 레시피 영향 범위를 응답한다.
  - 증거: coverage golden test, 재분석 버전 테스트, 영향 범위 응답 fixture.
  - 의존성: M2-05, M1-05.

- [x] **M2-07. 공고 등록→분석→일치도 종단 흐름을 검증한다.**
  - 완료 기준: 실제 PostgreSQL/Redis에서 공고 입력 후 분석 작업 완료, 원문 인용, 기록 커버리지와 설명 가능한 점수 조회가 한 E2E로 통과한다.
  - 증거: job-analysis E2E 결과, Worker 상태 전이 로그, DB assertion.
  - 의존성: M2-03, M2-06.

## M3. 재료 선정·인터뷰·레시피

- [x] **M3-01. 포트폴리오 재료 추천과 선택을 구현한다.**
  - 완료 기준: 정리된 기록만 최대 10개 자동 선택되고 선택 변경이 brew source에 순위·주체·제외 사유와 함께 저장되며 0개 선택으로 진행할 수 없다.
  - 증거: 추천/선택 단위 테스트, brew source DB 테스트, 0개 경계 테스트.
  - 의존성: M2-07.

- [x] **M3-02. 근거가 있는 인터뷰 질문을 생성·교체한다.**
  - 완료 기준: 질문마다 requirement 또는 기록 gap 근거가 있고 예고한 배정과 실제 질문이 일치하며 교체·건너뛰기·순서를 user scope로 보존한다.
  - 증거: 질문 생성 golden fixture, 근거 없는 질문 부정 테스트, 교체/순서 통합 테스트.
  - 의존성: M3-01.

- [x] **M3-03. 답변을 자동 저장하고 기록으로 승격한다.**
  - 완료 기준: 텍스트/음성 transcript를 중단 후 재개할 수 있고 같은 답변 재전송이 중복 기록을 만들지 않으며 새 수치·사실 없이 생성/보강 변경 목록을 남긴다.
  - 증거: autosave/재개 테스트, 멱등 answer 테스트, fabricated-number 부정 fixture.
  - 의존성: M3-02.

- [x] **M3-04. 섹션·항목·근거가 있는 레시피를 생성한다.**
  - 완료 기준: 선택 기록과 분석 결과에서 레시피 섹션/항목을 만들고 최소 3개 출처→대상 경로를 저장하며 선택했지만 쓰지 않은 소스에 사유가 있다.
  - 증거: recipe golden fixture, evidence path 검증 테스트, 미사용 소스 테스트.
  - 의존성: M3-03.

- [x] **M3-05. 레시피 편집·잠금·변경 이력을 보장한다.**
  - 완료 기준: 섹션/항목 순서·추가·삭제·문장 지시 변경을 diff로 반환하고 사용자 수정 항목을 잠그며 최근 50개 이력에서 항목 복원이 가능하다.
  - 증거: recipe revision 통합 테스트, 잠금 회귀 테스트, 50개 보존 경계 테스트.
  - 의존성: M3-04.

- [x] **M3-06. 분석→인터뷰→레시피 종단 흐름을 검증한다.**
  - 완료 기준: 분석된 공고에서 재료를 고르고 질문에 답해 새 기록과 근거 있는 레시피를 만들며 중단/재개와 잠금이 실제 API/Worker E2E로 통과한다.
  - 증거: brewing-flow E2E 결과, 근거 연결 DB assertion, 재개 상태 로그.
  - 의존성: M3-05.

## M4. 생성과 편집

- [x] **M4-01. 템플릿 렌더링 계약과 추천을 제공한다.**
  - 완료 기준: 모든 템플릿이 모든 레시피 섹션 유형을 실제 사용자 내용으로 렌더할 수 있고 기업 톤 색 적용 시 본문 대비 4.5:1 미만 값을 자동 보정한다.
  - 증거: 템플릿 conformance fixture, 빈 내용/전체 섹션 테스트, 대비 계산 테스트.
  - 의존성: M3-06.

- [x] **M4-02. 생성 작업과 사용량 원장을 원자적으로 처리한다.**
  - 완료 기준: 생성 성공 시에만 quota가 1회 차감되고 같은 멱등 키 100회 재전송과 Worker 재시도에도 한 번만 차감되며 실패 결과는 초안으로 보존된다.
  - 증거: 동시성 통합 테스트, 100회 재전송 결과, 실패/재시도 quota DB assertion.
  - 의존성: M4-01, M0-04, M6-03.

- [x] **M4-03. 생성 전 근거·사실·잠금 검증을 강제한다.**
  - 완료 기준: 모든 생성 문장이 recipe item 또는 record/question 근거로 추적되고 출처 없는 숫자·주장, 제외 항목 위반, 잠긴 블록 변경이 최종 저장 전에 거부된다.
  - 증거: evidence validator 적대적 fixture, 제외/잠금 부정 테스트, trace 조회 테스트.
  - 의존성: M4-02.

- [x] **M4-04. 포트폴리오와 생성 직후 복원점을 저장한다.**
  - 완료 기준: 레시피에서 portfolio/section/block이 생성되고 원본 record usage가 연결되며 생성 직후 snapshot을 포함해 최소 5개 복원점 보존 정책이 동작한다.
  - 증거: portfolio materialization 통합 테스트, record usage 검사, snapshot 보존 테스트.
  - 의존성: M4-03.

- [x] **M4-05. 대상 지정 편집과 변경 미리보기를 제공한다.**
  - 완료 기준: 섹션/블록/요소 경로에 대한 편집 명령이 이전→이후 diff를 먼저 반환하고 승인 전 영속화되지 않으며 record 삽입의 출처 연결이 유지된다.
  - 증거: preview/apply API 계약 테스트, 승인 전 DB 무변경 assertion, source link 테스트.
  - 의존성: M3-06.
