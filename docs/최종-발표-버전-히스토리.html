    Expresso 버전 히스토리 0.1 ~ 2.0

    2026-08-06부터 2026-11-22까지의 개발 과정을 열아홉 버전으로 나눈 문서입니다. 1.0까지는 제안서와 설계서의 범위이고, 1.1부터 2.0은 제품의 기능이 에이전트 채팅 안으로 한 단계씩 옮겨진 순서입니다.

    SUMMARY

    Expresso는 109일 동안 설계서 범위의 제품(1.0)을 만든 뒤, 에이전트 채팅을 제품의 첫 화면으로 올린 에이전틱 플랫폼(2.0)으로 바뀌었습니다.

    • 0.1 ~ 0.8은 제안서와 설계서의 범위를 구현한 기간입니다. 설계서 v1.0의 변경 이력 날짜인 10-28에 사용자 흐름의 마지막 구간인 배포 · 방문 분석과 관리자 화면이 머지됐습니다.
    • 1.0은 11-14 기준입니다. 운영에서 시연 흐름을 실행해 찾은 결함과 운영 장애를 고친 뒤의 상태입니다.
    • 1.1 ~ 1.3에서 홈이 대화 입력창이 됐고(1.1), 에이전트가 구직 목표를 기준으로 권하게 됐고(1.2), 채팅이 모든 계정에 열렸습니다(1.3).
    • 1.4 ~ 1.7에서 에이전트가 대화에 선택지 단추를 넣고(1.4), 지난 대화의 요지를 다음 대화로 넘기고(1.5), 기록을 바로 저장하고 약속한 날 먼저 묻고(1.6), 구직 목표 기준으로 진단해 다음 행동을 권하게 됐습니다(1.7).
    • 1.8 ~ 2.0에서 포트폴리오 제작이 디자인 선택(1.8), 나머지 단계(1.9) 순서로 대화에 들어왔고, 옛 단계 화면을 지워 대화가 제작의 유일한 시작점이 됐습니다(2.0).
    • 1.0 범위 중 추천 모델의 서비스 추론 연결은 main에 없습니다. 학습 · 평가 스크립트는 main에 있고, 연결 코드는 codex/match-model-product 브랜치에 있습니다.

    0.x — 설계 범위 구현

    0.1 ~ 1.0

    0.1부터 1.0까지는 제안서와 설계서가 정한 사용자 흐름을 운영 환경에서 처음부터 끝까지 동작하게 만든 기간입니다. 흐름은 커리어 기록 → 공고 탐색 → 공고 분석 → 재료 고르기 → AI 대화 → 레시피 → 디자인 선택 → 다듬기 → 배포 → 방문 분석입니다. 0.1 ~ 0.3에서 개발 기반과 저장소를 정했고, 0.4 ~ 0.5에서 제안서와 설계서를 쓰며 생성 방식을 바꿨고, 0.6 ~ 0.8에서 화면을 실데이터에 연결하고 운영 결함을 고쳤습니다.

    0.1 ~ 0.3 개발 기반과 저장소

    0.1 명세와 첫 운영 배포 · 08-06 ~ 08-13

    개발은 명세에서 시작했습니다. 08-06에 개발 포털과 명세 문서 13종을 저장소에 넣었습니다(2bc8087f).

    08-12에 첫 구현이 들어왔습니다. 백엔드 모듈 24개와 웹 화면 24개이고, 스택은 Fastify 5 · BullMQ · PostgreSQL입니다(8acfae16). 08-13에 expresso.ai.kr에 운영 배포했고 Google 로그인을 붙였습니다(713ca2c5 · 0d5013f4). 설계서 v0.1은 08-14에 이 저장소 형상을 근거로 작성됐습니다. 08-06 ~ 08-12의 구현은 체크포인트 커밋 한 건으로 들어와 날짜별 순서가 커밋에 남아 있지 않습니다.

    0.2 개발 기반과 자유 HTML 생성 · 08-20 ~ 08-28

    첫 배포 뒤 개발 기반을 갖췄습니다. 08-20에 백엔드 CI를 구성하고 개발 포털을 dev.expresso.ai.kr로 배포했습니다(b197f94a · eb0e164c). 08-21에는 데이터베이스를 PostgreSQL 18에서 MySQL 8.4로 옮겼습니다(a61e4442 외).

    포트폴리오 생성 경로를 이 버전에서 하나로 합쳤습니다. 그전에는 블록과 레이아웃을 따로 저장하는 경로가 함께 있었습니다. #3부터 생성 결과는 자유 HTML 지면 한 판으로 저장되고, 배포는 그 판의 문서를 고정해 공개 화면에 내보냅니다. 같은 주에 반응형 · 다크 모드(#4)와 디자인 30종(#5)이 들어갔습니다.

    0.3 MongoDB 전환과 도메인 확장 · 08-30 ~ 09-02

    08-28에 저장소를 MongoDB로 옮기기로 설계했고 08-30에 운영을 전환했습니다(#7). 이유는 다음 작업인 커리어 기록 편집기입니다. 편집기는 제목 · 속성 · 블록 본문을 가진 기록을 카테고리별 뷰로 다루므로, 문서 중심 저장 구조를 먼저 준비했습니다(docs/architecture/mongodb-migration-design.md).

    전환 직후 디자인, 공고 수집, 커리어 기록이 넓어졌습니다. 디자인 카탈로그가 38종이 됐고 생성 v2의 디자인 단계가 「새 포트폴리오」에 연결됐습니다(#11). 공고 공급원은 Greenhouse 보드 다섯 곳에서 그리팅 · Lever · Workable · 고용24를 더한 스물여덟 곳이 됐습니다(#12). 09-02에는 커리어 기록 편집기가 문서 드로워, 속성 편집, 저장 뷰와 함께 들어갔습니다(#16).

    0.4 ~ 0.5 제안서 · 설계서와 생성 방식

    0.4 제안서와 추천 모델 파일럿 · 09-06 ~ 10-05

    이 기간에 프로젝트의 AI 개발 과제가 정해졌습니다. 09-04에 합성 프로필 1,000명과 LLM 라벨 10,000건으로 공고 적합도 모델 두 개(E5+MLP, Cross-Encoder)를 학습했고, 두 모델 모두 문자 TF-IDF 기준선보다 LLM 라벨을 잘 재현했습니다(학습 결과 리포트, 09-06). 목적은 LLM의 평가 기준을 작은 모델로 옮겨 반복 추론 비용을 낮추는 것입니다.

    09-08에 제안서를 저장소에 반영했고(#19), 09-28부터 설계서를 제안서 기준으로 다시 맞췄습니다(#29 ~ #31). 10-05에 공식 명칭이 「채용 공고·커리어 기록 추천 모델 기반 맞춤형 포트폴리오 생성 및 배포 플랫폼 개발」로 정해졌습니다. 제품에서는 공고 자연어 검색의 조건 칩을 눌러 값을 바꾸거나 끄게 됐습니다(#26, 심민규).

    0.5 구조화 생성과 에이전트 채팅 도입 · 10-06 ~ 10-19

    생성 방식이 한 번 더 바뀌었습니다. #51부터 모델은 내용과 json-render Spec을 쓰고, 등록된 지면 부품이 그 Spec을 렌더링합니다. 0.2의 자유 HTML 생성은 선택 설정으로 남았습니다. #57에서 모델이 컨테이너로 배치를 바꾸게 됐고, #81에서 제작 흐름을 설계서 이용 절차의 여섯 단계(공고 분석 → 재료 고르기 → AI 대화 → 레시피 → 디자인 선택 → 다듬기)로 되돌렸습니다. 설계서 v0.7 발표가 10-10 ~ 10-13에 있었습니다.

    에이전트 채팅이 이 버전에서 처음 들어왔습니다. #22는 채용 공고, 커리어 기록, 독립 채팅 화면에서 같은 대화를 이어 가는 공통 채팅을 Claude Agent SDK로 만들었습니다. 10-17에는 공고 상세의 우측 사이드바가 공고 전용 채팅이 됐고(#77), 요건 대조와 보완 인터뷰(#78), 대화로 새 기록 만들기(#79), 보완점 정리와 준비 계획(#80)이 대화 안의 카드로 들어갔습니다. 윤규현의 Agentic Chat PR(#59 · #70)의 기능이 이 공통 채팅의 도구와 카드로 옮겨졌습니다. 이 시기의 채팅은 화면 옆 사이드바였고, 개발 멤버만 서버 인증으로 썼습니다.

    0.6 ~ 0.8 실데이터 연결과 운영 안정화

    0.6 화면의 실데이터 연결 · 10-26 ~ 10-28 새벽

    화면에는 눌러도 동작하지 않는 요소와 예시 데이터가 남아 있었습니다. 「동작하지 않는 화면 요소 정리」 작업이 공고 탐색(#114), 통합 검색과 알림(#115), 편집과 배포(#120), 설정(#121)을 실제 API에 연결하고 근거 없는 요소를 지웠습니다. 파일을 만들지 않고 가짜 경로만 저장하던 PDF · 덱 내보내기도 이때 걷어냈습니다(#120).

    AI 사용량 계측이 같은 시기에 들어갔습니다. 그전에는 생성 말고는 사용량이 남지 않았습니다. #130부터 AI 호출의 사용량이 사용자별로 기록되고, 생성 한도가 월 생성 횟수에서 월 크레딧(1크레딧 = 10,000토큰)으로 바뀌었습니다. 1.3이 에이전트 채팅을 모든 계정에 열 때 이 크레딧으로 한도를 검사합니다. 개발 포털에는 설계서의 상세기능 209개를 코드와 대조하는 진행 현황 대시보드가 생겼습니다(#103).

    0.7 배포 · 방문 분석 · 관리자 · 10-28 ~ 10-29

    설계서 이용 절차의 마지막 두 단계가 이 버전에서 동작했습니다. 그전에는 같은 주소로 두 번째 배포가 409로 막혔고, 공개 사이트가 방문을 보내지 않아 분석 화면이 비어 있었습니다. #133부터 배포한 포트폴리오가 {주소}.expresso.ai.kr로 열리고, 방문 기록이 분석 화면에 실제 값으로 그려집니다.

    관리자 화면(/admin)이 같은 날 들어갔습니다(#136). 기록 양이 다른 가상 개발자 계정 다섯 개를 만들고 그 계정으로 대신 로그인하는 화면입니다. 포트폴리오 생성이 사람마다 얼마나 다르게 나오는지 시험하려는 목적이었고, 이후의 시연과 운영 검증을 이 더미 계정으로 했습니다. 설계서 v1.0은 변경 이력에 10-28로 적혀 있습니다(09daf82d, main 반영은 11-06 #147).

    0.8 시연 리허설과 운영 안정화 · 11-02 ~ 11-07

    운영에서 전체 흐름을 실행하며 결함을 찾은 주입니다. 11-04에 운영 Worker가 멈췄습니다. MongoDB 재시작 중에 Worker가 시작되면 닫힌 연결이 남아 모든 작업이 실패했고, 프로세스는 살아 있어 자동 재시작이 걸리지 않았습니다. #170이 이 경우 Worker를 종료시켜 재시작되게 했습니다. 생성 하나(3 ~ 5분)가 끝나야 다음 작업이 시작되던 큐는 생성 전용 큐를 나눠 동시에 실행하게 바꿨습니다(#177).

    더미 계정으로 운영에서 시연 흐름을 실행해 찾은 공고 검색, 제작 진입, 수치 왜곡, 편집 오류도 이때 고쳤습니다(#173 · #174). 화면에서는 비로그인 랜딩이 생겼고(#157), 홈이 화면 정의서의 목적인 「지금 무엇을 해야 하는지 알려주는 화면」에 맞게 재구성됐습니다(#160). 이 구간의 PR 30건 중 16건이 fix입니다.

    1.0 설계 범위 버전 · 11-09 ~ 11-14
