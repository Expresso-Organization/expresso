# Expresso 소프트웨어 요구사항 명세서

- 문서 버전: v0.1
- 문서 상태: Draft
- 기준일: 2026-08-21

> 본 문서는 Expresso 요구사항의 초안이다.
> 개별 요구사항 중 팀 합의가 문서화된 `CONFIRMED` 상태의 요구사항만
> 확정 요구사항으로 간주한다.
>
> 문서 상태와 개별 요구사항 상태는 서로 독립적이며,
> Draft 상태의 문서에도 `CONFIRMED` 요구사항이 포함될 수 있다.

## 1. 문서 개요

### 1.1 목적

본 문서는 Expresso 서비스가 충족해야 하는 기능 요구사항,
비즈니스 규칙 및 주요 제약사항을 정의한다.

요구사항 명세서는 Expresso의 MVP 범위 결정과
이후 도메인 모델, 데이터베이스, API, 구현 및 테스트를 위한
상위 기준으로 사용한다.

실제 MVP의 설계와 구현은 `CONFIRMED` 요구사항 중
해당 MVP 범위에 포함된 요구사항을 기준으로 수행한다.

### 1.2 문서 범위

본 문서는 Expresso 전체 서비스 요구사항의 범위와 상태를 관리한다.

초기 버전(v0.1)에서는 전체 서비스의 주요 기능 영역을 식별하되,
Career 영역의 요구사항을 우선적으로 상세화한다.

Career 외 기능 영역은 v0.1에서 최소한 다음 정보를 관리한다.

- 도메인 식별자
- 도메인명
- 도메인의 목적
- 요구사항 상세화 여부

Career 외 영역의 세부 기능은 요구사항 후보로 관리하며,
팀에서 별도로 확정하지 않는 한 상세 설계 및 구현의 기준으로 사용하지 않는다.

### 1.3 요구사항 작성 기준

기존 Expresso 설계서, 개발 포털, 구현 코드,
API 계약 및 데이터 구조는 요구사항을 도출하고 검증하기 위한
참고자료로 사용한다.

기존 자료에 기능이나 정책이 존재한다는 사실만으로
해당 내용을 확정 요구사항으로 간주하지 않는다.

기존 자료를 근거로 도출하거나 검토한 요구사항은
해당 문서, 기능 ID, API, 코드 또는 데이터 구조와의 관계를
추적할 수 있어야 한다.

기존 개발명세의 D/F/T 식별자와
새 SRS의 Requirement ID 사이에
필수적인 1:1 대응 관계를 두지 않는다.

확정된 요구사항과 기존 구현 또는 설계가 충돌하는 경우,
확정 요구사항을 기준으로 변경 영향과 이행 필요사항을 검토한다.

### 1.4 요구사항 상태

각 요구사항은 다음 상태 중 하나를 가진다.

| 상태              | 의미                               |
| --------------- | -------------------------------- |
| `PROPOSED`      | 요구사항 후보로 제안되었으나 팀 합의 전인 상태       |
| `CONFIRMED`     | 팀 전체가 동의하고 그 합의 근거가 기록된 요구사항     |
| `NEED_DECISION` | 기능 필요성 또는 세부 정책에 추가 결정이 필요한 요구사항 |
| `DEFERRED`      | 필요 가능성은 있으나 현재 버전에서는 결정을 미룬 요구사항 |
| `REMOVED`       | 검토 결과 현재 요구사항 범위에서 제외된 항목        |

문서 상태와 개별 요구사항 상태는 독립적으로 관리한다.

`CONFIRMED`는 팀 구성원 전원이 해당 요구사항에 동의하고,
그 합의 사실이 회의 기록, Pull Request 또는 기타 팀이 확인할 수 있는 형태로
기록된 경우에만 부여한다.

`CONFIRMED` 전환은 팀 합의의 근거가 문서에 기록된 경우에만 허용하며,
합의 여부를 임의로 추정하지 않는다.

### 1.5 Requirement ID

상세 요구사항은 다음 형식의 고유 식별자를 사용한다.

`REQ-{DOMAIN}-{NNN}`

예:

- `REQ-CAR-001`
- `REQ-CAR-002`

`{DOMAIN}`에는 도메인 목록에서 정의한 고유 코드를 사용한다.

Requirement ID는 도메인별로 순차 발급한다.

한 번 발급한 Requirement ID는 요구사항이 `REMOVED` 상태가 되더라도
다른 요구사항에 재사용하지 않는다.

기존 개발명세의 D/F/T 식별자와 Requirement ID의 번호를
일치시킬 필요는 없다.

## 2. 서비스 개요

### 2.1 서비스 목적

Expresso는 사용자의 경력, 프로젝트, 학력, 자격, 활동 등
커리어 정보를 구조화하여 관리하고,
채용공고의 요구사항과 관련된 커리어 정보를 활용하여
지원 직무에 적합한 근거 기반 포트폴리오를 생성할 수 있도록 지원하는 서비스이다.

### 2.2 주요 사용자

주요 사용자는 신입 취업 준비생과 경력 이직 준비자를 포함한 구직자이다.

### 2.3 주요 기능 영역

Expresso의 주요 기능 영역은 다음과 같다.

- Career 정보 관리
- 채용공고 수집 및 탐색
- 채용공고 분석
- 포트폴리오 재료 선택 및 구성
- AI Interview
- 포트폴리오 생성
- 포트폴리오 편집 및 배포
- 포트폴리오 방문 분석

각 영역의 상세 요구사항은 본 문서의 기능 요구사항에서 정의한다.

## 3. 기능 요구사항

각 상세 요구사항은 상태, 대상, 설명, 핵심 규칙 및 완료 기준을 기본으로 작성한다.
기본 흐름은 기능의 순서가 존재하는 경우 작성하며,
예외 및 제약과 참고자료는 필요한 경우에만 작성한다.

`CONFIRMED` 요구사항은 팀 합의 근거를 반드시 기록한다.

### 3.1 Career 개요

Career Record는 사용자의 취업 관련 정보를
포트폴리오의 근거 자료로 활용하기 위해 저장하는 하나의 커리어 기록이다.

Career v0.1에서는 다음 Category를 우선 상세화한다.

- 프로젝트
- 학력·이력
- 자격증·수상
- 학술·집필

다음 Category는 현재 상세화 대상에서 제외한다.

- 경험: `DEFERRED`
- 스킬·도구: `DEFERRED`
- 활동·리더십: `DEFERRED`

위 목록은 Expresso의 최종 Career Category 구성을 의미하지 않는다.

#### REQ-CAR-001 Career Record 공통 구조

- **상태:** `PROPOSED`
- **대상:** 사용자

##### 설명

사용자는 취업과 관련된 정보를 Career Record로 관리할 수 있다.

##### 핵심 규칙

- 모든 Career Record는 제목을 공통 필수값으로 가진다.
- 제목 외 입력 항목은 Career Category에 따라 달라질 수 있다.
- 각 Category의 입력 항목은 필수 또는 선택으로 구분한다.

##### 완료 기준

- Career Record에 공통 제목이 존재한다.
- Category별로 정의된 구조에 따라 Record 정보를 표현할 수 있다.

#### REQ-CAR-002 Career Category 소속

- **상태:** `PROPOSED`
- **대상:** 사용자

##### 설명

Career Record는 종류와 구조를 구분하기 위해 Career Category에 속한다.

##### 핵심 규칙

- 모든 Career Record는 정확히 하나의 Category에 속한다.
- Category가 없는 미분류 Career Record는 허용하지 않는다.

##### 완료 기준

- 저장된 모든 Career Record에 하나의 Category가 지정되어 있다.
- 미분류 Career Record가 저장되지 않는다.

#### REQ-CAR-003 시스템 Career Category 제공

- **상태:** `PROPOSED`
- **대상:** 사용자

##### 설명

Career Category는 시스템에서 제공하며 사용자는 제공된 Category를 사용한다.

##### 핵심 규칙

- 사용자는 Custom Category를 직접 생성할 수 없다.
- 현재 Category 구성은 향후 요구사항 변경에 따라 추가, 삭제 또는 변경될 수 있다.
- 시스템 Category 구성 변경 정책은 사용자 Record의 Category 변경 정책과 별도로 관리한다.

##### 완료 기준

- 사용자는 시스템이 제공하는 Category만 사용할 수 있다.
- 사용자가 임의의 Category를 생성할 수 없다.

#### REQ-CAR-004 Career Record 필수값 검증

- **상태:** `PROPOSED`
- **대상:** 사용자

##### 설명

Career Record는 공통 및 Category별 필수값을 충족한 경우에만 저장한다.

##### 핵심 규칙

- 필수값은 단순히 필드가 존재하는 것이 아니라 유효한 값을 가져야 한다.
- 공백 등 유효하지 않은 값은 필수값을 충족한 것으로 보지 않는다.
- Career Record는 저장 전에 공통 필수값과 Category별 필수값 검증을 통과해야 한다.
- 직접 입력, AI 생성, 외부 가져오기 등 생성 경로와 관계없이 동일한 검증 기준을 적용한다.
- 필수값을 충족하지 않은 미완성 Draft Career Record는 현재 지원하지 않는다.

##### 완료 기준

- 모든 필수값이 유효한 경우에만 Career Record가 저장된다.
- 필수값을 충족하지 않은 Record는 저장되지 않는다.

#### REQ-CAR-005 Career Record Category 변경 제한

- **상태:** `PROPOSED`
- **대상:** 사용자

##### 설명

사용자는 Career Record 생성 이후 해당 Record를 다른 Category로 재분류할 수 없다.

##### 핵심 규칙

- 생성된 Career Record의 Category는 사용자가 변경할 수 없다.
- Category를 잘못 선택한 경우 기존 Record를 삭제하고 올바른 Category로 다시 생성하는 방향으로 한다.
- 시스템 자체의 Category 추가, 삭제, 변경은 별도 정책으로 관리한다.

##### 완료 기준

- 생성된 Career Record에서 사용자가 Category를 변경할 수 없다.

#### REQ-CAR-006 프로젝트 Record

- **상태:** `PROPOSED`
- **대상:** 사용자

##### 설명

사용자는 프로젝트 정보를 포트폴리오의 근거 자료로 관리할 수 있다.

##### 핵심 규칙

필수 입력 항목은 다음과 같다.

- 제목
- 프로젝트 설명

선택 입력 항목은 다음과 같다.

- 진행 기간
- 역할
- 사용 기술
- 주요 성과
- 프로젝트 링크
- 대표 이미지 1장

대표 이미지는 선택사항이며 최대 1장이다.

##### 완료 기준

- 제목과 프로젝트 설명을 갖춘 프로젝트 Record를 저장할 수 있다.
- 입력한 선택 항목을 프로젝트 Record에 표현할 수 있다.

#### REQ-CAR-007 학력·이력 Record

- **상태:** `PROPOSED`
- **대상:** 사용자

##### 설명

사용자는 학력, 재직 경력, 교육 과정 등을
하나의 학력·이력 Category 안에서 이력 유형으로 구분하여 관리할 수 있다.

##### 핵심 규칙

필수 입력 항목은 다음과 같다.

- 제목
- 이력 유형
- 기관명

이력 유형은 다음과 같다.

- 학력 (`EDUCATION`)
- 재직 경력 (`EMPLOYMENT`)
- 교육 과정 (`TRAINING`)

학력(`EDUCATION`)의 선택 입력 항목은 다음과 같다.

- 전공
- 학위 정보
- 기간
- 상태
- 상세 설명
- 주요 활동 / 성과

재직 경력(`EMPLOYMENT`)의 선택 입력 항목은 다음과 같다.

- 직무 / 직책
- 기간
- 상태
- 상세 설명
- 주요 활동 / 성과

교육 과정(`TRAINING`)의 선택 입력 항목은 다음과 같다.

- 과정명
- 기간
- 상태
- 상세 설명
- 주요 활동 / 성과

유형별 선택 입력 항목은 해당 이력 유형에서 허용되는 필드 범위이며,
유형에 맞지 않는 필드는 사용하지 않는다.

##### 완료 기준

- 제목, 이력 유형 및 기관명을 갖춘 학력·이력 Record를 저장할 수 있다.
- 이력 유형에 따라 학력, 재직 경력 또는 교육 과정을 구분하여 표현할 수 있다.

#### REQ-CAR-008 자격증·수상 Record

- **상태:** `PROPOSED`
- **대상:** 사용자

##### 설명

사용자는 자격증과 수상을 하나의 Category에서 종류로 구분하여 관리할 수 있다.

##### 핵심 규칙

필수 입력 항목은 다음과 같다.

- 제목
- 종류

종류는 다음과 같다.

- 자격증 (`CERTIFICATE`)
- 수상 (`AWARD`)

자격증(`CERTIFICATE`)의 선택 입력 항목은 다음과 같다.

- 발급 기관
- 취득일
- 유효 만료일
- 자격번호 / 인증번호
- 상세 설명
- 관련 링크

수상(`AWARD`)의 선택 입력 항목은 다음과 같다.

- 주관 기관
- 수상일
- 상세 설명
- 관련 링크

종류별 선택 입력 항목은 해당 종류에서 허용되는 필드 범위이며,
종류에 맞지 않는 필드는 사용하지 않는다.

##### 완료 기준

- 제목과 종류를 갖춘 자격증·수상 Record를 저장할 수 있다.
- 자격증과 수상을 종류로 구분하여 표현할 수 있다.

#### REQ-CAR-009 학술·집필 Record

- **상태:** `PROPOSED`
- **대상:** 사용자

##### 설명

사용자는 학술·집필 정보를 포트폴리오의 근거 자료로 관리할 수 있다.

##### 핵심 규칙

필수 입력 항목은 다음과 같다.

- 제목
- 유형

선택 입력 항목은 다음과 같다.

- 게재 / 발표처
- 발행 / 발표 시점
- 요약 / 상세 설명
- 관련 링크

`발행 / 발표 시점`은 `YYYY-MM` 단위로 표현한다.

##### 완료 기준

- 제목과 유형을 갖춘 학술·집필 Record를 저장할 수 있다.
- 입력한 선택 항목을 학술·집필 Record에 표현할 수 있다.

#### REQ-CAR-010 활동·리더십 Record

- **상태:** `DEFERRED`
- **대상:** 사용자

##### 설명

활동·리더십을 독립 Career Category로 상세화하는 작업은 현재 보류한다.

활동·리더십 Category를 영구 제거한 것은 아니며,
향후 경험 및 다른 Career Category의 경계와 함께 다시 검토할 수 있다.

##### 핵심 규칙

- 현재 독립적인 활동·리더십 CRUD 상세 요구사항을 작성하지 않는다.

#### REQ-CAR-011 Career Record 생성

- **상태:** `PROPOSED`
- **대상:** 사용자

##### 설명

사용자는 자신의 커리어 정보를 관리하기 위해
현재 사용할 수 있는 Career Category를 선택하여
Career Record를 생성할 수 있다.

현재 사용할 수 있는 Career Category는
시스템이 제공하며 상세 구조와 필수값이 정의되어
Career Record 생성 대상으로 사용 가능한 Category를 의미한다.

##### 기본 흐름

1. 사용자는 현재 사용할 수 있는 Career Category를 선택한다.
2. 사용자는 제목과 해당 Category에서 요구하는 정보를 입력한다.
3. 시스템은 공통 필수값과 Category별 필수값을 검증한다.
4. 모든 필수값이 유효한 경우 Career Record를 저장한다.
5. 생성된 Career Record는 해당 사용자에게 귀속된다.

##### 핵심 규칙

- Career Record는 반드시 하나의 Category에 속해야 한다.
- 사용자는 현재 사용할 수 있는 시스템 Category만 선택할 수 있다.
- 제목은 모든 Career Record의 공통 필수값이다.

- 미완성 Career Record의 Draft 저장은 지원하지 않는다.
- 생성 이후 사용자가 Record의 Category를 변경하는 기능은 지원하지 않는다.
- 동일하거나 유사한 제목 또는 내용을 가진 Career Record가 이미 존재하더라도
  새로운 Record 생성을 제한하지 않는다.
- 중복 Record 탐지 및 병합은 현재 생성 요구사항 범위에 포함하지 않는다.

##### 예외 및 제약

- 시스템에서 제공하지 않거나 상세 구조와 필수값이 정의되지 않아
  현재 생성 대상으로 사용할 수 없는 Category를 선택한 경우
  Career Record를 생성하지 않는다.
- 필수값 검증에 실패한 경우 Career Record를 생성하지 않는다.

##### 완료 기준

- 현재 사용할 수 있는 Category와 모든 필수값을 유효하게 입력하면
  Career Record가 저장된다.
- 생성된 Record는 Record를 생성한 사용자에게 귀속된다.
- 필수값을 충족하지 않으면 Career Record가 저장되지 않는다.
- 동일하거나 유사한 Record가 존재하더라도 유효한 입력이라면
  새로운 Record를 생성할 수 있다.

#### REQ-CAR-012 프로젝트 Career Record 목록 조회

- **상태:** `PROPOSED`
- **대상:** 사용자

##### 설명

사용자는 프로젝트 화면에서
자신에게 귀속된 프로젝트 Category의 Career Record 목록을 조회할 수 있다.

현재 Career 영역에서는 모든 Career Record를 한 번에 보여주는
통합 목록을 제공하지 않는다.

프로젝트, 학력·이력, 자격증·수상 등은 각각의 별도 화면에서 관리한다.

여러 Category의 Career Record를 종합하여 보여주는 기능은
향후 별도의 "재료 고르기" 요구사항에서 다루며
현재 프로젝트 조회 요구사항의 범위에 포함하지 않는다.

##### 조회 범위

- 현재 사용자에게 귀속된 프로젝트 Record만 조회한다.
- 다른 사용자의 프로젝트 Record는 조회 대상에 포함하지 않는다.
- 다른 Career Category의 Record는 프로젝트 목록에 포함하지 않는다.

##### 프로젝트 목록 표시 정보

프로젝트 목록에서는 Record별로 다음 정보를 표시한다.

- 대표 이미지 썸네일
- 제목
- 프로젝트 설명 일부
- 진행 기간
- 역할
- 사용 기술
- 주요 성과

프로젝트 링크는 현재 목록 표시 정보에 포함하지 않는다.

##### 대표 이미지 조회 정책

- 프로젝트 Record는 대표 이미지를 최대 1장 가질 수 있다.
- 대표 이미지 등록은 선택사항이다.
- 등록된 대표 이미지가 있으면 목록에 썸네일 형태로 표시한다.
- 등록된 대표 이미지가 없으면 시스템 기본 이미지를 표시한다.

대표 이미지의 다음 정책은 이번 Read 요구사항에서 정의하지 않는다.

- 등록
- 교체
- 삭제

위 정책은 프로젝트 Update 요구사항에서 별도로 다룬다.

이미지 파일 형식, 용량, 저장소 등 구현 세부사항도
현재 요구사항에서 정의하지 않는다.

##### 프로젝트 진행 기간

프로젝트 진행 기간은 선택사항이다.

기간을 입력하지 않는 것은 허용한다.

기간을 입력하는 경우:

- 시작 연·월은 YYYY-MM 형식으로 표현한다.
- 시작 연·월은 필수이다.
- 시작 연·월과 함께 다음 중 정확히 하나를 지정해야 한다.
  1. 종료 연·월(YYYY-MM)
  2. 진행 중 상태

다음 상태는 허용하지 않는다.

- 시작 연·월만 입력하고 종료 연·월과 진행 중 상태를 모두 지정하지 않은 경우
- 종료 연·월과 진행 중 상태를 동시에 지정한 경우
- 종료 연·월이 시작 연·월보다 빠른 경우

종료 연·월이 없다는 사실만으로 진행 중으로 판단하지 않는다.
진행 중 여부는 명시적인 상태로 구분한다.

##### 프로젝트 목록 정렬

프로젝트 목록은 다음 순서로 정렬한다.

1. 시작 연·월이 입력된 프로젝트를 먼저 표시한다.
2. 시작 연·월을 기준으로 내림차순 정렬한다.
   최근 시작한 프로젝트가 먼저 표시된다.
3. 시작 연·월이 동일한 경우
   진행 중인 프로젝트를 우선한다.
4. 시작 연·월이 동일하고 둘 다 종료된 프로젝트라면
   종료 연·월이 늦은 프로젝트를 우선한다.
5. 위 조건이 동일한 경우
   제목을 오름차순으로 정렬한다.
6. 제목까지 동일한 경우
   최근 생성된 Career Record를 우선한다.
7. 시작 연·월이 없는 프로젝트는
   시작 연·월이 있는 프로젝트 뒤에 표시한다.
8. 시작 연·월이 없는 프로젝트끼리는
   제목 오름차순으로 정렬하고,
   제목까지 동일하면 최근 생성된 Career Record를 우선한다.

DB Collation이나 구체적인 문자열 비교 알고리즘 등
기술적인 정렬 구현 방식은 현재 정의하지 않는다.

프로젝트 목록의 별도 검색 및 필터 기능은
현재 프로젝트 목록 조회 요구사항의 범위에 포함하지 않는다.

#### REQ-CAR-013 프로젝트 Career Record 수정

- **상태:** `PROPOSED`
- **대상:** 사용자

##### 설명

사용자는 자신에게 귀속된 프로젝트 Career Record의
수정 가능한 정보를 변경할 수 있다.

##### 수정 권한

- 사용자는 자신에게 귀속된 프로젝트 Record만 수정할 수 있다.
- 다른 사용자의 프로젝트 Record는 수정할 수 없다.

##### 수정 가능한 항목

다음 항목은 수정할 수 있다.

- 제목
- 프로젝트 설명
- 진행 기간
- 역할
- 사용 기술
- 주요 성과
- 프로젝트 링크
- 대표 이미지

Career Category는 생성 이후 변경할 수 없다.

##### 부분 수정

- 사용자는 수정 가능한 항목 중 필요한 항목만 변경할 수 있다.
- 변경하지 않은 항목은 기존 값을 유지한다.
- 저장 여부는 변경 후 프로젝트 Record 전체를 기준으로 검증한다.

##### 필수값

- 제목은 수정 후에도 유효한 값이어야 한다.
- 프로젝트 설명은 수정 후에도 유효한 값이어야 한다.
- 공백 등 유효하지 않은 값으로 변경할 수 없다.
- 필수값은 제거할 수 없다.

##### 선택값

다음 선택 항목은 추가, 변경, 제거할 수 있다.

- 진행 기간
- 역할
- 사용 기술
- 주요 성과
- 프로젝트 링크
- 대표 이미지

##### 진행 기간 수정

프로젝트 기간은 다음 상태 사이에서 변경할 수 있다.

- 기간 없음
- 시작 YYYY-MM + 종료 YYYY-MM
- 시작 YYYY-MM + 진행 중

다음 변경을 허용한다.

- 기간 없음 → 종료된 프로젝트
- 기간 없음 → 진행 중 프로젝트
- 종료된 프로젝트 → 진행 중 프로젝트
- 진행 중 프로젝트 → 종료된 프로젝트
- 기간 있음 → 기간 전체 제거
- 시작/종료 연·월 변경

수정 후 최종 상태는 기존 프로젝트 기간 규칙을 만족해야 한다.

허용하지 않는 상태:

- 시작 연·월만 존재
- 종료 연·월과 진행 중 상태가 동시에 존재
- 종료 연·월이 시작 연·월보다 빠름

##### 대표 이미지 수정

- 대표 이미지가 없는 프로젝트에 이미지를 등록할 수 있다.
- 기존 대표 이미지를 다른 이미지로 교체할 수 있다.
- 기존 대표 이미지를 삭제할 수 있다.
- 대표 이미지를 삭제해도 프로젝트 Record는 유지된다.
- 대표 이미지가 없으면 Read 요구사항에 따라 시스템 기본 이미지를 표시한다.
- 대표 이미지는 최대 1장이다.

이미지 파일 형식, 용량, 저장 방식은 현재 정의하지 않는다.

##### 수정 검증

- 수정 결과를 포함한 프로젝트 Record 전체를 검증한다.
- 모든 유효성 검증을 통과한 경우에만 변경사항을 저장한다.
- 하나라도 검증에 실패하면 변경사항 전체를 반영하지 않는다.
- 일부 필드만 저장하는 부분 성공은 지원하지 않는다.

##### 중복

- 수정 결과가 다른 프로젝트 Record와 동일하거나
  유사한 제목 또는 내용을 가지더라도 수정을 제한하지 않는다.
- 중복 탐지 및 병합은 현재 Update 요구사항 범위에 포함하지 않는다.

##### 수정 이력

- 프로젝트 Record 수정 이력 조회는 현재 요구사항 범위에 포함하지 않는다.
- 이전 버전 복원 기능도 현재 요구사항 범위에 포함하지 않는다.
- 수정이 성공하면 새로운 값이 현재 Record의 값이 된다.

##### 기존 생성 결과물에 대한 영향

- 프로젝트 Career Record를 수정하더라도
  해당 Record를 이용해 이미 생성된 포트폴리오의
  기존 내용과 이미지는 자동으로 변경하지 않는다.
- 수정된 프로젝트 정보는 이후 새로운 재료 선택과
  새로운 결과물 생성에 사용할 수 있다.
- 기존 포트폴리오를 최신 Career 정보와 다시 동기화하는 기능은
  현재 요구사항 범위에 포함하지 않는다.

생성된 포트폴리오는 생성 시점 Career 정보를 기반으로 한
독립 결과물이라는 원칙을 따른다.

snapshot, 데이터 복사, 이미지 보존 및 참조 방식 등의
구현 구조는 현재 정의하지 않는다.

#### REQ-CAR-014 프로젝트 Career Record 삭제

사용자는 자신에게 귀속된 프로젝트 Career Record를

  원본 Record 삭제 시 해당 이미지도 삭제 대상으로 본다.
- 시스템 기본 이미지는 공용 리소스이므로 삭제하지 않는다.

##### 기존 생성 결과물

생성된 포트폴리오는 생성 시점 Career 정보를 기반으로 한
독립된 결과물이라는 원칙을 따른다.

따라서:

- 프로젝트 Career Record를 영구 삭제하더라도
  해당 Record를 이용해 이미 생성된 포트폴리오는 삭제하지 않는다.
- 기존 포트폴리오의 내용은 Career Record 삭제로 인해
  변경하거나 제거하지 않는다.
- 기존 포트폴리오에 이미 포함된 이미지 역시
  사라지거나 깨지지 않고 유지되어야 한다.
- 원본 Career Record와 원본 대표 이미지의 삭제가
  기존 생성 결과물에 자동 전파되지 않는다.

##### 삭제 이후 활용

삭제된 Career Record는:

- 이후 Career 조회에 사용할 수 없다.
- 이후 새로운 재료 선택에 사용할 수 없다.
- 이후 새로운 포트폴리오 등 결과물 생성에 사용할 수 없다.

기존 생성 결과물에는 영향을 주지 않지만
삭제 이후의 새로운 활용은 허용하지 않는다.

##### 구현 범위 제외

다음 구현 방식은 현재 요구사항에서 결정하지 않는다.

- snapshot 방식
- Career 데이터 복사 방식
- 원본과 결과물 사이의 참조 구조
- 이미지 복제 또는 보존 방식
- 이미지 저장소 수명주기
- Foreign Key

- DB 테이블 및 컬럼

#### REQ-CAR-015 학력·이력 Career Record 생성

- **상태:** `PROPOSED`
- **대상:** 사용자

##### 설명

사용자는 학력, 재직 경력, 교육 과정과 관련된 정보를
학력·이력 Career Record로 생성할 수 있다.

학력·이력 Record는 하나의 Career Category 안에서
이력 유형을 통해 세부 종류를 구분한다.

##### 이력 유형

학력·이력 Career Record는 생성 시
다음 중 정확히 하나의 이력 유형을 가진다.

- 학력 (`EDUCATION`)
- 재직 경력 (`EMPLOYMENT`)
- 교육 과정 (`TRAINING`)

- 이력 유형은 필수값이다.
- 생성 이후 사용자는 이력 유형을 변경할 수 없다.
- 이력 유형을 잘못 선택한 경우 기존 Record를 삭제하고
  올바른 유형으로 다시 생성한다.

내부 코드의 구체적인 저장 방식은 현재 정의하지 않는다.

##### 유형별 허용 필드

공통 필수 입력 항목은 다음과 같다.

- 제목
- 이력 유형
- 기관명

학력(`EDUCATION`)의 선택 입력 항목은 다음과 같다.

- 전공
- 학위 정보
- 기간
- 상태
- 상세 설명
- 주요 활동 / 성과

재직 경력(`EMPLOYMENT`)의 선택 입력 항목은 다음과 같다.

- 직무 / 직책
- 기간
- 상태
- 상세 설명
- 주요 활동 / 성과

교육 과정(`TRAINING`)의 선택 입력 항목은 다음과 같다.

- 과정명
- 기간
- 상태
- 상세 설명
- 주요 활동 / 성과

유형별 선택 입력 항목은 단순한 입력 안내가 아니라
해당 이력 유형에서 허용되는 필드 범위이다.

유형에 맞지 않는 필드는 사용하지 않는다.

##### 기간

기간 입력은 선택사항이다.

허용되는 기간 상태는 다음과 같다.

1. 기간 없음
2. 시작 연·월 + 실제 종료 연·월
3. 시작 연·월 + 현재 진행 중

기간을 입력하는 경우:

- 시작 연·월은 `YYYY-MM` 단위이며 필수이다.
- 종료 연·월 또는 현재 진행 중 중 정확히 하나를 지정한다.
- 종료 연·월은 시작 연·월보다 빠를 수 없다.

종료 연·월은 실제 종료 시점을 의미한다.

다음 예상 시점은 현재 요구사항 범위에 포함하지 않는다.

- 예상 졸업 시점
- 예상 퇴사 시점
- 예상 수료 시점

종료 연·월이 없다는 사실만으로 현재 진행 중이라고 판단하지 않는다.

##### 유형별 상태

상태 입력은 선택사항이다.

학력(`EDUCATION`)에서 사용할 수 있는 상태는 다음과 같다.

- 재학
- 휴학
- 졸업
- 중퇴

재직 경력(`EMPLOYMENT`)에서 사용할 수 있는 상태는 다음과 같다.

- 재직
- 퇴사

교육 과정(`TRAINING`)에서 사용할 수 있는 상태는 다음과 같다.

- 수강 중
- 수료
- 중도 종료

상태를 입력하는 경우
선택한 이력 유형에 해당하는 상태만 사용할 수 있다.

##### 현재 진행 중의 의미

`현재 진행 중`은 해당 활동을 계속 수행한다는 의미가 아니라
해당 이력의 소속·재적 관계가 현재까지 유지되고 있다는 의미이다.

따라서 다음 조합을 허용한다.

- 현재 진행 중 + 재학
- 현재 진행 중 + 휴학
- 현재 진행 중 + 재직
- 현재 진행 중 + 수강 중

##### 기간과 상태 정합성

기간과 상태를 모두 입력한 경우
두 값은 서로 일관되어야 한다.

현재 진행 중과 함께 허용하는 상태는 다음과 같다.

- 재학
- 휴학
- 재직
- 수강 중

실제 종료 연·월과 함께 허용하는 상태는 다음과 같다.

- 졸업
- 중퇴
- 퇴사
- 수료
- 중도 종료

따라서 다음과 같은 조합은 허용하지 않는다.

- 현재 진행 중 + 졸업
- 현재 진행 중 + 중퇴
- 현재 진행 중 + 퇴사
- 현재 진행 중 + 수료
- 현재 진행 중 + 중도 종료
- 실제 종료 연·월 + 재학
- 실제 종료 연·월 + 휴학
- 실제 종료 연·월 + 재직
- 실제 종료 연·월 + 수강 중

기간 또는 상태 중 하나만 입력한 경우
상호 정합성 검증은 적용하지 않는다.

단, 입력된 값 자체의 유효성 검증은 그대로 적용한다.

##### 생성 검증

저장 전에 다음을 검증한다.

- 제목이 유효한가
- 이력 유형이 존재하는가
- 기관명이 유효한가
- 입력 필드가 해당 이력 유형에서 허용되는가
- 상태가 해당 이력 유형에서 허용되는가
- 기간이 입력된 경우 기간 규칙을 만족하는가
- 기간과 상태를 모두 입력한 경우 서로 일관되는가

공백 등 유효하지 않은 값은 필수값으로 인정하지 않는다.

모든 검증을 통과한 경우에만 Career Record를 저장한다.

미완성 Draft Career Record는 지원하지 않는다.

##### 사용자 귀속 및 중복

- 생성된 학력·이력 Record는 생성한 사용자에게 귀속된다.
- 동일하거나 유사한 학력·이력 Record가 존재하더라도
  새로운 Record 생성을 제한하지 않는다.
- 중복 탐지 및 병합은 현재 요구사항 범위에 포함하지 않는다.

##### 완료 기준

- 유효한 공통 필수값과 선택한 이력 유형에서 허용되는 값을 입력하면
  학력·이력 Career Record가 저장된다.
- 생성된 Record는 생성한 사용자에게 귀속된다.
- 유형별 허용 필드, 상태 또는 기간 규칙을 충족하지 않으면 저장되지 않는다.
- 동일하거나 유사한 Record가 존재하더라도 유효한 입력이라면
  새로운 Record를 생성할 수 있다.

#### REQ-CAR-016 학력·이력 Career Record 목록 조회

- **상태:** `PROPOSED`
- **대상:** 사용자

##### 설명

사용자는 자신에게 귀속된 학력·이력 Career Record를
하나의 시간순 통합 목록으로 조회할 수 있다.

학력, 재직 경력, 교육 과정은
유형별 별도 목록으로 분리하지 않고 하나의 목록에서 함께 표시한다.

##### 조회 범위

- 현재 사용자에게 귀속된 학력·이력 Record만 조회한다.
- 다른 사용자의 Record는 조회 대상에 포함하지 않는다.
- 학력 / 재직 경력 / 교육 과정 유형을 하나의 목록에 함께 표시한다.

##### 목록 표시 정보

공통 표시 정보는 다음과 같다.

- 이력 유형
- 제목
- 기관명
- 기간
- 상태
- 상세 설명 일부

학력(`EDUCATION`)의 추가 표시 정보는 다음과 같다.

- 전공
- 학위 정보

재직 경력(`EMPLOYMENT`)의 추가 표시 정보는 다음과 같다.

- 직무 / 직책

교육 과정(`TRAINING`)의 추가 표시 정보는 다음과 같다.

- 과정명

다음 정보의 구체적인 표현은 현재 확정하지 않는다.

- 상세 설명 전체
- 주요 활동 / 성과의 상세 표현
- 상세 화면의 전체 구성

목록에서는 Record를 식별하고 주요 내용을 파악할 수 있는
요약 정보만 표시한다.

##### 기간 중복

- 서로 다른 학력·이력 Career Record의 기간은 겹칠 수 있다.
- 기간 중복은 오류로 보지 않는다.
- 기간이 겹친다는 이유로 Record의 생성, 수정 또는 조회를 제한하지 않는다.
- 동시에 진행되는 여러 이력도 목록에 각각 표시한다.

##### 목록 정렬

학력·이력 목록은 다음 순서로 정렬한다.

1. 기간이 입력된 Record를 우선 표시한다.
2. 시작 연·월(`YYYY-MM`)을 기준으로 내림차순 정렬한다.
   최근 시작한 이력이 먼저 표시된다.
3. 시작 연·월이 동일한 경우
   현재 진행 중인 Record를 우선한다.
4. 시작 연·월이 동일하고 둘 다 종료된 경우
   실제 종료 연·월이 늦은 Record를 우선한다.
5. 위 조건이 동일한 경우
   제목을 오름차순으로 정렬한다.
6. 제목까지 동일한 경우
   최근 생성된 Career Record를 우선한다.
7. 기간이 없는 Record는
   기간이 있는 Record 뒤에 표시한다.
8. 기간이 없는 Record끼리는
   제목 오름차순으로 정렬하며,
   제목까지 동일하면 최근 생성된 Record를 우선한다.

DB Collation, 문자열 비교 알고리즘 등의
구체적인 구현 방식은 현재 정의하지 않는다.

##### UI 표현 범위

- 시간 흐름을 이해할 수 있는 통합 목록을 제공한다.
- 사용자는 각 Record의 이력 유형을 구분할 수 있어야 한다.

현재 개발 포털과 같은 세로 타임라인,
선, 점, 카드 배치, 아이콘 등의 구체적인 시각 표현은
SRS에서 확정하지 않는다.

이는 별도 UI 설계에서 결정한다.

##### 검색 및 필터

다음 기능은 현재 학력·이력 목록 조회 요구사항 범위에 포함하지 않는다.

- 검색
- 학력 / 재직 경력 / 교육 과정 유형 필터
- 기타 목록 필터

##### 상세 조회

학력·이력 상세 화면의 구체적인 정보 구성 및 표현 방식은
현재 확정하지 않는다.

다음 내용은 추후 상세 조회 요구사항에서 결정한다.

- 상세 설명 전체
- 주요 활동 / 성과 상세
- 상세 화면 전체 구성

#### REQ-CAR-017 학력·이력 Career Record 수정

- **상태:** `PROPOSED`
- **대상:** 사용자

##### 설명

사용자는 자신에게 귀속된 학력·이력 Career Record의
수정 가능한 정보를 변경할 수 있다.

##### 수정 권한

- 사용자는 자신에게 귀속된 학력·이력 Record만 수정할 수 있다.
- 다른 사용자의 Record는 수정할 수 없다.

##### 이력 유형 변경 제한

- 이력 유형은 생성 이후 변경할 수 없다.
- 학력 / 재직 경력 / 교육 과정 사이의 유형 변경은 지원하지 않는다.
- 잘못된 유형으로 생성한 경우 기존 Record를 삭제하고
  올바른 유형으로 다시 생성한다.

##### 수정 가능한 항목

공통으로 수정할 수 있는 항목은 다음과 같다.

- 제목
- 기관명
- 기간
- 상태
- 상세 설명
- 주요 활동 / 성과

- 전공

##### 부분 수정

- 사용자는 수정 가능한 항목 중 필요한 항목만 변경할 수 있다.
- 변경하지 않은 항목은 기존 값을 유지한다.
- 저장 시 변경 후 학력·이력 Record 전체를 검증한다.

##### 필수값

다음 값은 수정 후에도 유효해야 한다.

- 제목
- 이력 유형
- 기관명

- 이력 유형 자체는 변경할 수 없다.
- 제목과 기관명은 제거하거나 공백 등 유효하지 않은 값으로 변경할 수 없다.

##### 선택값

현재 이력 유형에서 허용되는 선택값은
추가, 변경 또는 제거할 수 있다.

공통 선택값은 다음과 같다.

- 기간
- 상태
- 상세 설명
- 주요 활동 / 성과

유형별 선택값은 다음과 같다.

- 학력: 전공, 학위 정보
- 재직 경력: 직무 / 직책
- 교육 과정: 과정명

##### 기간 수정

허용되는 최종 기간 상태는 다음과 같다.

1. 기간 없음
2. 시작 `YYYY-MM` + 실제 종료 `YYYY-MM`
3. 시작 `YYYY-MM` + 현재 진행 중

다음과 같은 전환을 허용한다.

- 기간 없음 → 종료된 이력
- 기간 없음 → 현재 진행 중
- 현재 진행 중 → 종료된 이력
- 종료된 이력 → 현재 진행 중
- 기간 있음 → 기간 전체 제거
- 시작 연·월 변경
- 종료 연·월 변경

수정 후 최종 상태는 기존 기간 규칙을 만족해야 한다.

다음 상태는 허용하지 않는다.

- 시작 연·월만 존재
- 종료 연·월과 현재 진행 중이 동시에 존재
- 종료 연·월이 시작 연·월보다 빠름

종료 연·월은 실제 종료 시점을 의미한다.
예상 종료 시점은 현재 요구사항 범위에 포함하지 않는다.

학력에서 사용할 수 있는 상태는 다음과 같다.

- 재학
- 휴학
- 졸업

재직 경력에서 사용할 수 있는 상태는 다음과 같다.

교육 과정에서 사용할 수 있는 상태는 다음과 같다.

- 기간 규칙
- 기간-상태 정합성

- 학력과 재직 경력의 기간 중복
- 재직 경력과 교육 과정의 기간 중복

#### REQ-CAR-019 자격증·수상 Career Record 생성

- **상태:** `PROPOSED`
- **대상:** 사용자

##### 설명

사용자는 자격증 또는 수상과 관련된 정보를
자격증·수상 Career Record로 생성할 수 있다.

자격증과 수상은 하나의 Career Category 안에서
종류를 통해 세부 유형을 구분한다.

##### 종류

자격증·수상 Career Record는 생성 시
다음 중 정확히 하나의 종류를 가진다.

- 자격증 (`CERTIFICATE`)
- 수상 (`AWARD`)

- 종류는 필수값이다.
- 생성 이후 사용자는 종류를 변경할 수 없다.
- 종류를 잘못 선택한 경우 기존 Record를 삭제하고
  올바른 종류로 다시 생성한다.

내부 코드의 구체적인 저장 방식은 현재 정의하지 않는다.

##### 공통 필수값

- 제목
- 종류

제목은 공백 등 유효하지 않은 값일 수 없다.

##### 자격증 허용 필드

자격증(`CERTIFICATE`)의 선택 필드는 다음과 같다.

- 발급 기관
- 취득일
- 유효 만료일
- 자격번호 / 인증번호
- 상세 설명
- 관련 링크

취득일은 다음 규칙을 따른다.

- `YYYY-MM-DD` 단위
- 선택사항
- 실제 취득한 날짜를 의미한다.
- 오늘 또는 과거 날짜만 허용한다.
- 미래 날짜는 허용하지 않는다.

유효 만료일은 다음 규칙을 따른다.

- `YYYY-MM-DD` 단위
- 선택사항
- 과거, 오늘, 미래 날짜를 모두 허용한다.
- 취득일과 둘 다 입력한 경우
  유효 만료일은 취득일보다 빠를 수 없다.

유효 만료일이 입력되지 않았다고 해서
해당 자격증을 영구 유효로 자동 판단하지 않는다.

영구 유효 여부를 별도 상태로 관리하는 기능은
현재 요구사항 범위에 포함하지 않는다.

##### 수상 허용 필드

수상(`AWARD`)의 선택 필드는 다음과 같다.

- 주관 기관
- 수상일
- 상세 설명
- 관련 링크

수상일은 다음 규칙을 따른다.

- `YYYY-MM-DD` 단위
- 선택사항
- 실제 수상한 날짜를 의미한다.
- 오늘 또는 과거 날짜만 허용한다.
- 미래 날짜는 허용하지 않는다.

예정된 수상 정보를 관리하는 기능은
현재 요구사항 범위에 포함하지 않는다.

##### 종류별 필드 제한

종류별 선택 필드는 단순 입력 안내가 아니라
해당 종류에서 허용되는 필드 범위이다.

자격증에서 허용되는 필드는 다음과 같다.

- 발급 기관
- 취득일
- 유효 만료일
- 자격번호 / 인증번호
- 상세 설명
- 관련 링크

수상에서 허용되는 필드는 다음과 같다.

- 주관 기관
- 수상일
- 상세 설명
- 관련 링크

종류에 맞지 않는 필드는 사용하지 않는다.

다음 조합은 허용하지 않는다.

- 수상 + 자격번호 / 인증번호
- 수상 + 유효 만료일
- 자격증 + 수상일

##### 생성 검증

저장 전에 다음을 검증한다.

- 제목이 유효한가
- 종류가 존재하는가
- 입력 필드가 선택한 종류에서 허용되는가
- 취득일이 입력된 경우 유효한 `YYYY-MM-DD`인가
- 취득일이 미래 날짜가 아닌가
- 유효 만료일이 입력된 경우 유효한 `YYYY-MM-DD`인가
- 취득일과 유효 만료일이 모두 존재하면
  유효 만료일이 취득일보다 빠르지 않은가
- 수상일이 입력된 경우 유효한 `YYYY-MM-DD`인가
- 수상일이 미래 날짜가 아닌가

모든 검증을 통과한 경우에만 Record를 저장한다.

미완성 Draft Career Record는 지원하지 않는다.

##### 사용자 귀속 및 중복

- 생성된 자격증·수상 Record는 생성한 사용자에게 귀속된다.
- 동일하거나 유사한 Record가 존재하더라도
  새로운 Record 생성을 제한하지 않는다.
- 중복 탐지 및 병합은 현재 요구사항 범위에 포함하지 않는다.

##### 미결정 사항 유지

`관련 링크`의 단일 / 복수 여부는
기존 `DECISION-CAR-008`에서 계속 미결정으로 관리한다.

이번 Create 요구사항에서는 이를 임의로 확정하지 않는다.

##### 완료 기준

- 유효한 제목과 종류를 입력하고 선택한 종류의 필드 및 날짜 규칙을 충족하면
  자격증·수상 Career Record가 저장된다.
- 생성된 Record는 생성한 사용자에게 귀속된다.
- 종류별 허용 필드 또는 날짜 규칙을 충족하지 않으면 저장되지 않는다.
- 동일하거나 유사한 Record가 존재하더라도 유효한 입력이라면
  새로운 Record를 생성할 수 있다.

#### REQ-CAR-020 자격증·수상 Career Record 목록 조회

- **상태:** `PROPOSED`
- **대상:** 사용자

##### 설명

사용자는 자신에게 귀속된 자격증·수상 Career Record를
하나의 통합 목록에서 조회할 수 있다.

##### 조회 범위

- 사용자는 자신에게 귀속된 Record만 조회할 수 있다.
- 자격증(`CERTIFICATE`)과 수상(`AWARD`)을 하나의 목록에서 함께 조회한다.
- 종류별로 별도의 목록을 구성하지 않는다.
- 사용자는 각 Record가 자격증인지 수상인지 구분할 수 있어야 한다.

##### 목록 표시 정보

각 Record에서는 최소 다음 정보를 확인할 수 있다.

공통 표시 정보는 다음과 같다.

- 종류
- 제목

자격증의 표시 정보는 다음과 같다.

- 발급 기관
- 취득일

수상의 표시 정보는 다음과 같다.

- 주관 기관
- 수상일

선택값이 존재하지 않더라도
해당 Record를 조회 대상에서 제외하지 않는다.

다음 정보는 현재 목록의 필수 표시 정보로 확정하지 않는다.

- 자격번호 / 인증번호
- 유효 만료일
- 상세 설명 전체
- 관련 링크

상세 조회 화면의 전체 구성은 현재 요구사항에서 확정하지 않는다.

##### 통합 정렬

자격증의 취득일과 수상의 수상일을
각 Record의 기준 날짜로 사용하여 하나의 목록을 정렬한다.

정렬 우선순위는 다음과 같다.

1. 기준 날짜가 존재하는 Record를 먼저 표시한다.
2. 기준 날짜를 기준으로 내림차순 정렬한다.
3. 기준 날짜가 같으면 제목을 오름차순으로 정렬한다.
4. 제목도 같으면 최근 생성된 Record를 먼저 표시한다.
5. 기준 날짜가 없는 Record는 날짜가 있는 Record 뒤에 표시한다.
6. 기준 날짜가 없는 Record끼리는 제목을 오름차순으로 정렬한다.
7. 제목도 같으면 최근 생성된 Record를 먼저 표시한다.

##### 만료된 자격증

  자격증 Record를 조회 목록에서 제외하지 않는다.

- 만료 여부에 따른 자동 숨김, 별도 필터 또는 상태 분류는

##### 검색 및 필터

다음 기능은 현재 자격증·수상 기본 목록 조회 요구사항에서

- 제목 검색
- 종류 필터
- 기관 필터
- 날짜 필터
- 유효 / 만료 필터

필요한 경우 이후 별도 요구사항으로 추가할 수 있다.

##### 상세 조회

자격증·수상 Record의 상세 조회 화면은
현재 요구사항에서 확정하지 않는다.

다음 내용은 이번 Read 요구사항 범위에서 결정하지 않는다.

- 상세 설명 전체 표시 방식
- 관련 링크 표시 방식
- 자격번호 표시 방식
- 상세 화면 UI 구성

현재 요구사항은 기본 목록 조회와 정렬 정책까지만 정의한다.

- 자신에게 귀속된 자격증과 수상 Record를 하나의 목록에서 조회할 수 있다.
- 사용자는 각 Record의 종류를 구분할 수 있다.
- 목록은 기준 날짜 유무와 정렬 우선순위에 따라 표시된다.
- 선택 표시 정보가 없거나 자격증이 만료되었더라도

#### REQ-CAR-021 자격증·수상 Career Record 수정

- **상태:** `PROPOSED`
- **대상:** 사용자

##### 설명

사용자는 자신에게 귀속된 자격증·수상 Career Record의
수정 가능한 정보를 변경할 수 있다.

##### 수정 권한

- 사용자는 자신에게 귀속된 Record만 수정할 수 있다.
- 다른 사용자의 Record는 수정할 수 없다.

##### 종류 변경 제한

- 자격증(`CERTIFICATE`) 또는 수상(`AWARD`) 종류는
  생성 이후 변경할 수 없다.
- 잘못된 종류로 생성한 경우 기존 Record를 삭제하고
  올바른 종류로 다시 생성한다.

##### 수정 가능한 필드

공통 수정 가능 필드는 다음과 같다.

- 제목

자격증의 수정 가능 필드는 다음과 같다.

- 발급 기관
- 취득일
- 유효 만료일
- 자격번호 / 인증번호
- 상세 설명
- 관련 링크

수상의 수정 가능 필드는 다음과 같다.

- 주관 기관
- 수상일
- 상세 설명
- 관련 링크

현재 종류에서 허용되지 않는 필드는 사용할 수 없다.

##### 부분 수정

- 사용자는 필요한 필드만 수정할 수 있다.
- 수정하지 않은 값은 기존 값을 유지한다.
- 저장 전에는 변경 후 Record 전체를 검증한다.
- 검증에 실패하면 수정사항 전체를 반영하지 않는다.
- 일부 변경만 저장하는 부분 성공은 지원하지 않는다.

##### 필수값

- 제목과 종류는 수정 후에도 유효해야 한다.
- 제목은 제거하거나 공백 등 유효하지 않은 값으로 변경할 수 없다.
- 종류는 필수값이며 변경할 수 없다.

##### 선택값

현재 종류에서 허용되는 선택 필드는
추가, 변경 또는 제거할 수 있다.

##### 날짜 수정

자격증 취득일은 다음 규칙을 따른다.

- `YYYY-MM-DD` 단위
- 오늘 또는 과거 날짜만 허용한다.
- 미래 날짜는 허용하지 않는다.
- 추가, 변경 또는 제거할 수 있다.

자격증 유효 만료일은 다음 규칙을 따른다.

- `YYYY-MM-DD` 단위
- 과거, 오늘 또는 미래 날짜를 허용한다.
- 추가, 변경 또는 제거할 수 있다.
- 취득일과 모두 존재하면 유효 만료일은 취득일보다 빠를 수 없다.

수상일은 다음 규칙을 따른다.

- `YYYY-MM-DD` 단위
- 오늘 또는 과거 날짜만 허용한다.
- 미래 날짜는 허용하지 않는다.
- 추가, 변경 또는 제거할 수 있다.

취득일 또는 수상일은 기존 날짜보다 과거 또는 최근 날짜로 변경할 수 있으며,
수정 후 최종 값의 유효성을 검증한다.

##### 만료된 자격증

- 수정 결과 유효 만료일이 현재 날짜보다 과거여도 허용한다.
- 만료된 자격증도 Career 이력으로 유지할 수 있다.

##### 중복

- 수정 결과가 다른 Record와 동일하거나 유사해져도 수정을 허용한다.
- 중복 탐지 및 병합은 현재 요구사항 범위에 포함하지 않는다.

##### 기존 생성 결과물

Career Record와 생성 결과물의 기존 독립성 원칙을 적용한다.

- 자격증·수상 Record를 수정하더라도 이미 생성된 포트폴리오의
  기존 내용은 자동으로 변경하지 않는다.
- 수정된 정보는 이후 새로운 재료 선택 및
  새로운 결과물 생성에 사용할 수 있다.
- 기존 결과물을 다시 동기화하는 기능은 현재 요구사항 범위에 포함하지 않는다.
- snapshot, 복사, 참조 등의 구현 방식은 현재 결정하지 않는다.

##### 수정 이력

- 수정 이력 조회는 현재 요구사항 범위에 포함하지 않는다.
- 이전 버전 복원은 현재 요구사항 범위에 포함하지 않는다.

##### 관련 링크

관련 링크의 단일 / 복수 여부는
기존 `DECISION-CAR-008`에서 계속 미결정으로 관리한다.

이번 Update 요구사항에서는 이를 임의로 확정하지 않는다.

##### 완료 기준

- 사용자는 자신에게 귀속된 자격증·수상 Record의
  현재 종류에서 허용되는 필드를 수정할 수 있다.
- 수정 후 Record 전체가 필수값, 종류별 필드 및 날짜 규칙을 충족한 경우에만
  변경사항을 저장한다.
- 검증에 실패하면 변경사항 전체를 반영하지 않는다.
- Record 수정은 이미 생성된 결과물의 기존 내용에 자동으로 반영되지 않는다.

- 원본과 결과물의 참조 방식
- Foreign Key
- Cascade
- DB / 스토리지 구조

- 제목
- 유형

- 게재 / 발표처
- 발행 / 발표 시점
- 요약 / 상세 설명
- 관련 링크

##### 제목

- 공백 등 유효하지 않은 제목은 허용하지 않는다.

##### 유형

- 하나의 Record는 하나의 유형을 가진다.

- 논문

유형 enum 또는 DB 저장 방식은 현재 정의하지 않는다.

##### 게재 / 발표처

- 게재 / 발표처는 선택값이다.
- 해당 결과물이 게재되거나 발표된 장소, 기관 또는 매체를 표현한다.

구체적인 데이터 구조는 현재 정의하지 않는다.

##### 발행 / 발표 시점

- 발행 / 발표 시점은 선택값이다.
- `YYYY-MM` 단위로 입력한다.

- 현재 월 또는 과거 월을 허용한다.
- 현재 월 이후의 미래 시점은 허용하지 않는다.

예정된 발표, 출판 또는 게재 일정을 관리하는 기능은
현재 Career Record Create 요구사항 범위에 포함하지 않는다.

정확한 일(day)을 입력하도록 요구하지 않는다.

##### 요약 / 상세 설명

- 요약 / 상세 설명은 선택값이다.
- 사용자는 해당 학술·집필 결과의 내용,

관련 링크의 단일 / 복수 여부는

- 유형이 존재하는가
