## 기술 요약

공개 접근이 가능한 Djinni와 JTH 원본 13개 파일을 수집했습니다. 전체 용량은
481,022,656바이트(481.0MB, 458.7MiB)입니다. 이 가운데 모델 입력이 되는 표 형식
파일은 7개이고, 데이터 카드와 README는 6개입니다.

표 형식 데이터에는 후보자 272,034명, 채용 공고 175,369건, 지원 과정 42,288건이
있습니다. 일곱 표를 단순 합산하면 489,691행입니다. 모든 표에서 기본 키의 누락과
중복은 0건이었고, JTH 지원 과정의 후보자·공고 외래 키 누락도 0건이었습니다.

Djinni는 744,262,901자의 채용·이력 텍스트를 제공하지만 후보자와 공고 사이의 실제
지원 또는 채용 연결 정보는 없습니다. JTH는 78,195개의 채용 단계 이벤트를 제공하므로
매칭 학습과 시간 순서 평가에 적합합니다. 첫 모델은 Djinni로 도메인 표현을 만들고,
JTH의 관측된 지원 과정으로 학습·평가하는 구성이 적절합니다.

Djinni 원본은 MIT 라이선스입니다. 네 표의 식별자는 언어 사이에서 겹치지 않았으므로

후보자·공고 텍스트의 평균 길이는 표에 따라 1,493자에서 1,909자입니다.

JTH는 CC BY-NC 4.0이며 비상업 연구만 허용합니다. 후보자 생성 시점은 2018년 3월부터
2025년 4월까지이고, 지원 이벤트는 2018년 3월부터 2025년 5월까지입니다. 지원 이력이
있는 후보자는 26,101명(전체의 69.5%), 공고는 4,116건(전체의 68.5%)입니다.

검토해야 합니다.

## 모델 개발에 미치는 영향

1. Djinni만으로는 실제 매칭 정답을 만들 수 없습니다. 공고·후보자 텍스트 인코더의
   사전 적응, 기술 추출, 약한 양성 쌍 생성에 사용합니다.
2. JTH는 관측된 후보자–공고 쌍과 단계 라벨이 있어 매칭 모델의 주 학습·평가 자료로
   사용합니다. 날짜 기준 분할을 적용해 미래 정보가 과거 학습에 섞이지 않게 합니다.
3. JTH의 `llm_sex`, `llm_nationality`, `llm_age_bucket` 같은 추론 인구통계 특성은
   입력 특성에서 제외합니다. 공정성 점검용 분석 열로만 격리합니다.
4. 두 데이터셋 모두 한국 채용 시장을 직접 대표하지 않습니다. 첫 실험 결과는 모델
   파이프라인의 성립을 검증하는 값으로 해석하고, 한국어 성능 주장을 하지 않습니다.
5. 원본은 소스별로 분리한 채 유지합니다. 번역·정규화·약한 라벨은 별도 파생 디렉터리에
   쓰고, 원본과 섞지 않습니다.

## 재현 방법

다음 명령은 공개 원본을 다시 내려받고 무결성을 검증한 뒤 같은 품질 지표를 생성합니다.
원본과 생성 결과는 `var/` 아래에 있어 Git에는 올라가지 않습니다.

```powershell
pnpm ml:data:test
pnpm ml:data:collect
pnpm ml:data:profile
```

수집기는 완성되지 않은 파일을 `.partial`로 두고, 기대 크기와 SHA-256 또는 MD5가 모두
맞을 때만 최종 파일명으로 바꿉니다. 이미 검증된 파일은 다시 내려받지 않습니다.

## 다음 단계

첫 5080 실험은 원본 전체를 바로 미세조정하기보다 다음 순서가 적절합니다.

1. Djinni 공고·후보자의 텍스트 필드와 JTH 구조화 필드를 공통 스키마로 정규화합니다.
2. JTH를 시간 기준 train/validation/test로 나누고, 후보자나 공고가 분할을 넘나드는
   누수를 점검합니다.
3. 다국어 임베딩 모델로 zero-shot 베이스라인을 만들고 Recall@K, NDCG@K를 기록합니다.
4. JTH 단계 라벨로 bi-encoder를 학습하고, ConFit v2 방식의 hard negative를 추가합니다.
5. Djinni를 넣은 경우와 뺀 경우를 비교해 대규모 비연결 텍스트의 효과를 검증합니다.
