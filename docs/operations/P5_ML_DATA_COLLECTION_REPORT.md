# P5 학과 연구 데이터 수집 결과

- 수집일: 2026-09-01
- 사용 범위: 학과 연구 프로젝트 전용
- 원본 위치: `var/ml-data/raw/`
- 수집 명세: `var/ml-data/manifest.json`

- AI Hub 수집 명세: `var/ml-data/raw/aihub/71592/manifest.json`
- AI Hub 품질 프로파일: `var/ml-data/raw/aihub/71592/data-quality-profile.json`

## 기술 요약

공개 접근이 가능한 Djinni와 JTH 원본 13개 파일과, 이용 승인을 받은 AI Hub
「채용면접 인터뷰 데이터」의 라벨 ZIP 56개를 수집했습니다. Djinni·JTH는
481,022,656바이트(481.0MB, 458.7MiB), AI Hub 라벨은
95,127,923바이트(95.1MB, 90.7MiB)입니다. 추천 모델에 필요하지 않은 AI Hub WAV
원천 데이터 약 162GiB는 수집하지 않았습니다.

표 형식 데이터에는 후보자 272,034명, 채용 공고 175,369건, 지원 과정 42,288건이
있습니다. 일곱 표를 단순 합산하면 489,691행입니다. 모든 표에서 기본 키의 누락과
중복은 0건이었고, JTH 지원 과정의 후보자·공고 외래 키 누락도 0건이었습니다.

Djinni는 744,262,901자의 채용·이력 텍스트를 제공하지만 후보자와 공고 사이의 실제
지원 또는 채용 연결 정보는 없습니다. JTH는 78,195개의 채용 단계 이벤트를 제공하므로
매칭 학습과 시간 순서 평가에 적합합니다. 첫 모델은 Djinni로 도메인 표현을 만들고,
JTH의 관측된 지원 과정으로 학습·평가하는 구성이 적절합니다. AI Hub 면접 답변은
후보자 프로필을 직접 제공하지 않으므로, 답변에서 검증 가능한 역량 근거 문장을
합성하는 보조 자료로만 사용합니다.

AI Hub 자료는 학과 연구 프로젝트 안에서만 사용하고 원본이나 파생 원문을 재배포하지
않습니다. 라벨 파일은 7개 직군, 신입·경력, 성별 조합으로 구성되어 있습니다. 공개된
파일의 모든 레코드에서 `info.date`가 2023-01-16으로 같으므로 실제 면접 시점을 뜻하는
열로 보거나 시간 분할에 사용하면 안 됩니다.

### AI Hub 면접 라벨

ZIP 56개는 모두 열렸고 JSON 엔트리는 총 76,106건입니다. 이 가운데 76,105건이
파싱되었으며, Training의 `ckmk_d_ict_m_n_337139.json` 1건은 원본에
`"raw": {1` 오탈자가 있어 파싱되지 않습니다. 원본 ZIP은 수정하지 않고 변환 단계에서
격리한 뒤, 해당 토큰만 명시적으로 보정한 레코드를 파생 데이터에 남겨야 합니다.

신입은 65,800건(86.459%), 경력은 10,305건(13.541%)으로 신입 답변에 크게 치우쳐
있습니다. 의도 대분류도 `attitude`가 59,425건으로 유효 레코드의 78.1%를 차지합니다.
직군별로는 PS 19,133건, BM 17,093건, SM 12,879건, MM 7,737건, ARD 7,338건,
ICT 6,571건, RND 5,354건 순입니다. 따라서 직군·경력·의도 범주별 가중치와 최소 표본
규칙 없이 전체를 섞으면 일반적인 태도형 신입 답변을 과도하게 학습할 가능성이 큽니다.

AI Hub 페이지에는 라벨 84,134건으로 표시되어 있으나 공개 Training·Validation 파일에는
76,106건만 있습니다. 차이 8,028건은 Validation 건수와 정확히 같습니다. 공개 파일 목록에
Test 묶음이 없다는 점을 함께 보면 약 10%의 비공개 Test 세트가 집계에 포함되었을
가능성이 높지만, 이는 파일 수치에 근거한 추론이며 AI Hub가 확인한 사유는 아닙니다.

## 모델 개발에 미치는 영향

1. Djinni만으로는 실제 매칭 정답을 만들 수 없습니다. 공고·후보자 텍스트 인코더의
   사전 적응, 기술 추출, 약한 양성 쌍 생성에 사용합니다.
2. JTH는 관측된 후보자–공고 쌍과 단계 라벨이 있어 매칭 모델의 주 학습·평가 자료로
   사용합니다. 날짜 기준 분할을 적용해 미래 정보가 과거 학습에 섞이지 않게 합니다.
3. JTH의 `llm_sex`, `llm_nationality`, `llm_age_bucket` 같은 추론 인구통계 특성은
   입력 특성에서 제외합니다. 공정성 점검용 분석 열로만 격리합니다.
4. 두 데이터셋 모두 한국 채용 시장을 직접 대표하지 않습니다. 첫 실험 결과는 모델
   파이프라인의 성립을 검증하는 값으로 해석하고, 한국어 성능 주장을 하지 않습니다.
5. 원본은 소스별로 분리한 채 유지합니다. 번역·정규화·약한 라벨은 별도 파생 디렉터리에
   쓰고, 원본과 섞지 않습니다.
6. AI Hub 면접 답변은 후보자 단위 식별자가 없으므로 여러 문답을 한 사람의 프로필로
   묶지 않습니다. 문답 1건을 하나의 근거 후보로 변환하고, 답변 원문·요약·의도 대분류를
   근거 출처로 보존합니다.
7. `intent.expression`은 76.2%가 비어 있으므로 감독 라벨에서 제외합니다. 질문·답변·요약을
   바탕으로 역량, 상황, 행동, 결과, 확신도를 합성한 뒤 원문 정합성 검사를 통과한 것만
   학습에 넣습니다.

## 재현 방법

다음 명령은 공개 원본을 다시 내려받고 무결성을 검증한 뒤 같은 품질 지표를 생성합니다.
원본과 생성 결과는 `var/` 아래에 있어 Git에는 올라가지 않습니다.

```powershell
pnpm ml:data:test
pnpm ml:data:collect
pnpm ml:data:profile
```

수집기는 완성되지 않은 파일을 `.partial`로 두고, 기대 크기와 SHA-256 또는 MD5가 모두
맞을 때만 최종 파일명으로 바꿉니다. 이미 검증된 파일은 다시 내려받지 않습니다.

## 다음 단계

첫 5080 실험은 원본 전체를 바로 미세조정하기보다 다음 순서가 적절합니다.

1. Djinni 공고·후보자의 텍스트 필드와 JTH 구조화 필드를 공통 스키마로 정규화합니다.
2. JTH를 시간 기준 train/validation/test로 나누고, 후보자나 공고가 분할을 넘나드는
   누수를 점검합니다.
3. 다국어 임베딩 모델로 zero-shot 베이스라인을 만들고 Recall@K, NDCG@K를 기록합니다.
4. JTH 단계 라벨로 bi-encoder를 학습하고, ConFit v2 방식의 hard negative를 추가합니다.
5. Djinni를 넣은 경우와 뺀 경우를 비교해 대규모 비연결 텍스트의 효과를 검증합니다.
6. AI Hub 문답을 `competency_evidence` 스키마로 변환하고, 질문 정규화 해시를 기준으로
   train/validation/test를 새로 나눠 동일 질문이 분할을 넘지 않게 합니다.
7. 직군·경력·의도 대분류별 층화 표본을 사람이 검수해 근거 충실도, 환각률, 역량 라벨
   일치도를 기록한 뒤 합성 데이터 전체 생성을 시작합니다.
