# 5. 화면(UI) 설계

화면 정의서는 `docs/Expresso Screens.dc.html`이다. **화면 정의서가 기준이고**, 본 절은
설계서 양식에 맞춰 옮긴 것이다. 둘이 어긋나면 화면 정의서를 따른다.

Expresso는 데스크톱 웹을 주 화면으로 설계했다. 양식은 모바일과 웹 중 하나를 골라 그
스타일을 지키라고 요구하므로, **웹 화면 규격**으로 작성한다. 공개 사이트(08)와 모바일 웹은
반응형으로 대응한다.

## 5.2. 초기화면(로그인 전화면) 설계

### 로그인 — 화면번호 10

> `[그림 5.2] 로그인 화면 — 화면 정의서 `docs/Expresso Screens.dc.html`의 10번 화면을
> 브라우저에서 열어 캡처한다. 브라우저 프레임이 함께 나오도록 한다.`

- 서비스에 접속하면 최초로 나타나는 화면이다.
- 이메일과 비밀번호를 입력하고 **[로그인]** 버튼을 누르면 Home 화면(00)으로 이동한다.
- **[Google로 계속하기]** 버튼을 누르면 Google 계정 선택 창이 열리고, 인증에 성공하면
  Home 화면(00)으로 이동한다. 처음 사용하는 계정이면 온보딩(10c)으로 이동한다.
- **[회원가입]** 링크를 누르면 회원가입 화면(10b)으로 이동한다.
- 인증에 실패하면 입력란 아래에 사유를 표시한다. 이메일과 비밀번호 중 무엇이 틀렸는지는
  구분해 알리지 않는다.
- 로그인 상태에서 이 주소로 오면 Home 화면(00)으로 자동 이동한다.

호출 API — `POST /v1/auth/login` · `POST /v1/auth/google`

## 5.3. 사용자 화면설계(웹)

화면 정의서에 정의된 사용자 화면 29개를 모두 설계한다. 각 화면은 다음 형식으로 쓴다.

```text
■ (화면명) — 화면번호 (번호)

  [그림] 화면 캡처 (브라우저 프레임 포함)

  · 화면의 목적 한 문장
  · [버튼명] 버튼을 누르면 (동작)한다.
  · (요소)를 (조작)하면 (결과)가 된다.
  · 예외 상황과 그때의 표시

  호출 API — (메서드) (경로)
  대응 기능 — (태스크 번호)
```


어느 쪽이 맞는지 먼저 정하고, 정의서를 고친 뒤 캡처한다.
