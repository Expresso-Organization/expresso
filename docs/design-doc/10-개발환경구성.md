### 인프라 실행

```bash
pnpm install
pnpm infra:up
cp services/backend/.env.example services/backend/.env
pnpm db:migrate
pnpm dev:backend
```

`pnpm infra:up`은 기존 로컬 서비스와 충돌하지 않도록 PostgreSQL을 55432, Redis를 56379로
고정해 띄운다. 두 인프라가 없어도 API 프로세스는 시작되지만 `/health/ready`가 503을
반환한다.

## 10.2. 소스디렉터리 구조

> `[그림 10.1] 디렉터리 구조 — 아래 트리를 PPT로 그려 캡처한다.`

`services/`에 두고, 둘 이상이 함께 쓰는 코드만 `packages/`로 올린다.

### 모듈 내부 구조

각 도메인 모듈은 같은 형태를 가진다. 파일 이름만 보고 어디를 열어야 할지 알 수 있게 하기
위해서다.

| 파일 | 책임 |
| --- | --- |
| `routes.ts` | HTTP 경로 등록 · 파라미터 파싱 · 응답 직렬화 |
| `service.ts` | 비즈니스 규칙 · 트랜잭션 경계 |
| `*.test.ts` | 단위 시험 |
| `*.integration.test.ts` | DB·Redis를 실제로 띄우고 하는 시험 |

## 10.3. 명칭표준안(변수, 함수, 파일명 등)

### 파일·디렉터리

| 대상 | 규칙 | 예 |
| --- | --- | --- |
| 디렉터리 | kebab-case | `job-analysis/`, `portfolio-editing/` |
| TypeScript 파일 | kebab-case | `build-app.ts`, `error-handler.ts` |
| React 컴포넌트 파일 | kebab-case | `record-panel.tsx` |
| 시험 파일 | `<대상>.test.ts` | `coverage.test.ts` |
| 통합 시험 파일 | `<대상>.integration.test.ts` | `generation.integration.test.ts` |
| 마이그레이션 | `NNNN_스네이크_설명.sql` | `0027_posting_requirements.sql` |
| Python 파일 | snake_case | `feature_extractor.py` |

### TypeScript

| 대상 | 규칙 | 예 |
| --- | --- | --- |
| 변수 · 함수 | camelCase | `requirementTokens`, `calculateRequirementCoverage` |
| 타입 · 인터페이스 · 클래스 | PascalCase | `GenerationEvidence`, `CoverageRecord` |
| zod 스키마 | PascalCase + `Schema` | `CreateCareerRecordSchema` |
| 상수 | UPPER_SNAKE_CASE | `API_PREFIX`, `REDACTED` |
| 열거 값(문자열 리터럴) | UPPER_SNAKE_CASE | `VALIDATION_ERROR` |
| 불리언 | `is` · `has` · `can` 접두 | `isRequired`, `hasMetric` |
| 라우트 등록 함수 | `register<도메인>Routes` | `registerCareerRoutes` |
| 서비스 인터페이스 | `<도메인>Service` | `JobAnalysisService` |
| 오류 클래스 | `<맥락>Error` | `GenerationValidationError` |

### 데이터베이스

| 대상 | 규칙 | 예 |
| --- | --- | --- |
| 테이블 | snake_case 단수 | `job_posting_requirement` |
| 컬럼 | snake_case | `extractor_version` |
| 기본키 | `id` | |
| 외래키 | `<대상테이블>_id` | `job_posting_id` |
| 시각 컬럼 | `<동사>_at` | `created_at`, `extracted_at` |
| 불리언 컬럼 | `is_` · `has_` 접두 | `is_system` |
| 인덱스 | `<테이블>_<컬럼>_idx` | `job_posting_requirement_axis_idx` |

TypeScript는 camelCase, DB는 snake_case를 쓴다. 경계에서 변환한다.

### REST API

| 대상 | 규칙 | 예 |
| --- | --- | --- |
| 경로 | kebab-case 복수 명사 | `/v1/job-analyses`, `/v1/generation-jobs` |
| 경로 파라미터 | camelCase | `/:portfolioId`, `/:sectionId` |
| 쿼리 파라미터 | camelCase | `?categoryId=&limit=` |
| JSON 필드 | camelCase | `usageRemaining`, `modelVersion` |
| 오류 코드 | UPPER_SNAKE_CASE | `PRECONDITION_FAILED` |

**동사를 경로에 쓰지 않는다.** 동작은 하위 리소스로 표현한다. 현재 형상의 위반 18건과
수정안은 7.2에 있다.

### Python (AI학습서버)

| 대상 | 규칙 | 예 |
| --- | --- | --- |
| 변수 · 함수 | snake_case | `extract_features`, `token_recall` |
| 클래스 | PascalCase | `CoverageClassifier` |
| 상수 | UPPER_SNAKE_CASE | `FEATURE_ORDER` |
| 특징 이름 | snake_case | `max_sent_cos`, `idf_weighted_overlap` |
| 데이터세트 버전 | `record-v<번호>` | `record-v1` |
| 모델 버전 | `record-v<데이터세트>-<일련번호>` | `record-v1-003` |

특징 이름은 `feature_spec.json`에 그대로 실린다. 이름을 바꾸면 배포된 모델과 어긋나므로,
이름 변경은 데이터세트 버전을 올리는 일과 같다(8.4의 오류코드 442).
