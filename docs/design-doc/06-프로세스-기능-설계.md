### 계층 책임

| 계층 | 책임 | 하지 않는 것 |
| --- | --- | --- |
| 라우트 | 요청 파싱 · 인증 확인 · 스키마 검증 · 응답 직렬화 | 비즈니스 규칙 |
| 도메인 모듈 | 비즈니스 규칙 · 트랜잭션 경계 | HTTP 세부사항 |
| 플랫폼 | DB · 큐 · 저장소 · LLM · 로깅 | 도메인 지식 |
| Worker | 오래 걸리는 작업 · 재시도 | 사용자 응답 |

### 동기와 비동기의 경계

사용자 요청 중 **초 단위로 끝나지 않는 것**은 큐로 넘긴다.

| 작업 | 처리 | 이유 |
| --- | --- | --- |
| 공고 분석 | 비동기 (`job-analysis`) | LLM 호출 수십 초 |
| 포트폴리오 생성 | 비동기 (`generation`) | LLM 호출 수 분 |
| 문서 내보내기 | 비동기 (`export`) | 렌더링·변환 |
| 방문 지표 집계 | 비동기 (`analytics`) | 배치 |
| 기록 CRUD | 동기 | DB만 |
| 공고 검색 | 동기 | DB만 |

비동기 작업은 `brew_job` / `generation_job` / `export_job`으로 상태를 남기고, 클라이언트는
작업 ID로 진행 상태를 조회한다.

### 트랜잭션 일관성

DB 커밋과 큐 발행이 따로 성공/실패하면 상태가 갈라진다. 이를 막기 위해 **Outbox 패턴**을
쓴다(`platform/outbox.ts`). 이벤트를 `platform_outbox` 테이블에 도메인 변경과 **같은
트랜잭션**으로 쓰고, 별도 폴러가 그것을 읽어 큐에 넣는다.

```text
 │        │◀─────────┤ 200 {kappa, 불일치 건수}        │
 │◀───────┤ κ < 0.6 이면 경고 표시 │          │
 │        │  "교사 프롬프트를 고치기 전에는 학습하지 않는다"
```

이 절차가 증류의 안전장치입니다. 교사가 사람과 어긋난 상태에서 학습하면 학생이 그 오차를
그대로 배우고, 성능 지표는 높게 나옵니다.
