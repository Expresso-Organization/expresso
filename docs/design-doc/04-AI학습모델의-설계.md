# 4. AI학습모델의 설계

## 4.1. 모델 파이프라인의 구성

AI학습을 위한 처리과정은 아래 그림 4.1과 같다. 실제 자료로 합성 프로필을 만들고, 교사 라벨링 · 데이터세트 생성 · 학습 · 검증 · 배포를 거쳐 서빙에 이른다. 두 학습 단위(Bi-Encoder+MLP와 Cross-Encoder)는 같은 데이터세트로 학습하고 모델 버전만 분리한다.

> `[그림 4.1 학습 파이프라인과 서빙 구성]` — HTML 본문의 SVG를 참조한다.

그림 4.1을 보면 교사 라벨링은 합성 프로필마다 후보 공고 10개를 묶어 교사에게 판정을 요청하고, 코드가 루브릭으로 점수를 계산하여 `fit-v1` 데이터세트로 적재한다. 학습은 먼저 네 인코더를 같은 조건에서 비교하여 인코더를 정하고, Bi-Encoder+MLP와 Cross-Encoder를 차례로 학습한다. 평가 분할에서 규칙 baseline과 대조하여 승인된 모델만 AI학습서버로 배포한다. 어느 모델도 배포되어 있지 않으면 서비스는 현행 규칙 함수로 동작한다.

## 4.2. AI학습 알고리즘의 선정

본 프로젝트의 학습 모델은 사전학습 문장 인코더를 기반으로 한다. 공고와 기록은 표기가 제각각인 자연어이므로, 표기가 달라도 의미가 가까운 문장을 가까운 벡터로 옮기는 사전학습 인코더가 문자열 비교의 한계를 해소한다. 적합도 예측은 두 구조로 나누어 학습한다.

### Bi-Encoder+MLP 적합도 모델

프로필 텍스트와 공고 텍스트를 가중치를 공유하는 같은 인코더로 각각 벡터화하고, 두 벡터의 비교 특징을 MLP에 넣어 적합도를 예측한다. 인코더는 동결하고 MLP만 학습한다.

> `[그림 4.2 Bi-Encoder+MLP 적합도 모델의 구조]` — HTML 본문의 SVG를 참조한다.

### Cross-Encoder 적합도 모델

공고와 관련 기록을 한 입력으로 이어 붙여 Transformer가 함께 읽게 한다. 공고와 기록의 토큰이 서로를 참조하므로 Bi-Encoder보다 세밀하게 비교한다. 입력 길이를 맞추기 위해 공고와 기록의 E5 코사인 유사도 상위 기록을 최대 8개까지 고른다. 앞쪽 층은 동결하고 마지막 4개 층과 점수 예측 헤드만 학습한다.

> `[그림 4.3 Cross-Encoder 적합도 모델의 구조]` — HTML 본문의 SVG를 참조한다.

### 두 모델의 단계적 활용

| 단계 | 사용 모델 | 처리 |
| --- | --- | --- |
| 01 스크리닝 | Bi-Encoder+MLP | 프로필 벡터와 저장된 공고 벡터로 전체 공고의 점수를 계산하고 상위 후보를 선별한다 |
| 02 리랭킹 | Cross-Encoder | 선별된 후보마다 공고와 관련 기록을 함께 읽어 적합도를 다시 평가한다 |
| 03 최종 추천 | — | 재평가한 점수순으로 공고를 제공한다 |
| 기록 추천 | Cross-Encoder 재사용 | 지원할 공고와 기록 1건의 쌍을 기록마다 채점하고, 선택 조합을 정한다 |

스크리닝 후보 수는 Recall@K 측정 결과로 정한다(9.2).

커리어 기록 추천의 선택 조합은 점수 순서만으로 정하지 않는다. 비슷한 프로젝트가 상위를 모두 차지하면 포트폴리오가 같은 강점을 반복하기 때문이다. 선택 점수는 기록의 관련도에 새로 충족하는 요건과 근거 강도를 더하고 기록 간 중복을 뺀 값이다(출처: `docs/채용-공고-커리어-기록-추천-모델-연구.html`). 각 항의 가중치는 검증 분할에서 정한다.

### ADR-001 · 적합도 모델의 구조

**배경** — 공고 목록은 한 번에 수백 건을 정렬하여야 하고, 재료 고르기는 공고 하나에 대해 사용자의 기록을 세밀하게 비교하여야 한다. 학습 데이터는 프로필–공고 10,000쌍이다.

**선택지**

- **규칙 기반** — 현행 방식이다. 표기가 다르면 판정하지 못하므로 baseline으로만 쓴다.
- **Bi-Encoder+MLP 단독** — 공고 벡터를 미리 계산하므로 빠르지만, 공고와 기록의 세부 대응을 보지 못한다.
- **Cross-Encoder 단독** — 토큰 간 상호작용으로 정확하지만, 쌍마다 연산하므로 전체 공고에 적용할 수 없다.
- **Bi-Encoder+MLP 선별 후 Cross-Encoder 재정렬** — 빠른 선별과 정밀한 비교를 단계별로 나눈다.

**결정** — 채용 공고 추천은 Bi-Encoder+MLP로 선별하고 Cross-Encoder로 재정렬한다. 커리어 기록 추천은 같은 Cross-Encoder를 재사용한다. 인코더는 네 후보의 비교 실험으로 정한다.

**근거** — 대규모 스크리닝에는 처리가 빠른 Bi-Encoder를, 상위 후보에는 정확한 Cross-Encoder를 적용하여 추천 정확도와 처리 비용의 균형을 맞춘다. 인코더를 동결하므로 공고 벡터를 수집할 때 한 번 계산하여 재사용할 수 있다.

**영향** — 커리어 기록 추천은 별도 학습 데이터 없이 동작하지만, Cross-Encoder는 공고와 기록 여러 건의 묶음으로 학습하고 기록 추천에서는 기록 1건과 짝지어 쓰므로 입력 분포가 다르다. 이 차이가 성능에 미치는 영향은 교사의 기록 단위 판정으로 따로 평가한다(9.2).

### 추천 근거의 제시

두 모델의 출력은 사용자에게 그대로 보인다. 화면 06은 「이 공고를 왜 위에 놓았는가」(T2.3.2)를, 화면 01b는 「이 기록을 왜 뺐는가」(T4.1.3)를 사용자에게 설명하여야 한다. 채용 공고 추천은 Cross-Encoder 입력으로 고른 관련 기록을 근거 기록으로 함께 반환한다. 커리어 기록 추천은 제외한 기록마다 점수와, 이미 선택된 기록과의 중복 또는 새로 충족하는 요건이 없음을 사유로 반환한다.

## 4.3. AI학습 파라메터 설정

학습 파라메터를 아래 표와 같이 설정한다.

| 파라미터 | Bi-Encoder+MLP | Cross-Encoder |
| --- | --- | --- |
| 기반 모델 | `multilingual-e5-base` (인코더 비교 후 확정) | `bge-reranker-v2-m3` |
| 입력 길이 | 텍스트당 최대 512토큰 | 공고 + 기록 최대 8개, 최대 1,536토큰 |
| 표현 차원 | 768 | 1,024 |
| 동결 범위 | 인코더 12개 층 전체 | 토큰 임베딩과 앞쪽 20개 층 |
| 학습 범위 | MLP — Linear 3,072 → 256 · GELU · Linear 256 → 1 | 마지막 4개 층과 점수 예측 헤드 |
| 출력 | Sigmoid → 적합도 0–100 | Sigmoid → 적합도 0–100 |
| 학습 목표 | 정답 점수에 가깝게, 더 적합한 공고를 더 높게 | 정답 점수에 가깝게 |
| 학습률 · 배치 크기 · 에폭 | 확정 전 | 확정 전 |

학습 목표의 예: 공고 A의 정답이 85점이면 예측도 85점에 가깝게, A가 85점이고 B가 60점이면 A의 예측 점수가 더 높도록 학습한다.

하이퍼파라미터는 검증 분할(900쌍)에서 탐색한다. 교사 프롬프트와 루브릭 버전은 데이터세트 메타에 기록한다. 루브릭이 바뀌면 라벨의 성격 자체가 바뀌기 때문이다.

## 4.4. AI학습 모델의 생성

학습의 최종 결과로 모델을 생성하는 과정은 아래 다섯 단계이다. 각 단계는 앞 단계가 통과하여야만 진행된다.

1. 데이터 검사 — 합성 기록 검증을 통과하지 못한 프로필과, 교사 점수와 루브릭 계산이 어긋난 라벨을 제외한다.
2. 인코더 비교 — 네 인코더로 Bi-Encoder+MLP를 학습하여 검증 분할에서 비교하고 인코더를 정한다.
3. Bi-Encoder+MLP 학습 — 정한 인코더로 학습 분할 전체를 학습한다.
4. Cross-Encoder 학습 — 마지막 4개 층과 점수 예측 헤드를 학습 분할로 미세조정한다.
5. 평가 · 승인 — 평가 분할에서 한 번만 평가하고 규칙 baseline과 대조하여 승인 여부를 판정한다. 평가 분할을 보고 파라메터를 고치면 평가가 사실상 검증이 되어 성능이 부풀려지기 때문이다.

| --- | --- |
| 학습 가중치 | MLP 가중치 · Cross-Encoder의 학습한 층과 헤드 가중치 |
