# 4. AI학습모델의 설계

이 장은 프로젝트 제안서의 자체 학습 모델 개발 계획을 구체화한다. 2026-09-28 현재 학습 아티팩트와 AI학습서버는 없으며, 서비스는 규칙 기반 추천을 사용한다. 아래 모델 크기와 학습 데이터 규모는 계획값이다.

## 4.1. 모델 파이프라인의 구성

```text
공고·커리어 기록 → 입력 정규화·합성 데이터 검증 → 교사 근거 판정·루브릭 점수
                → 학습·검증·평가 분할 → Bi-Encoder+MLP 선별
                → 상위 후보의 Cross-Encoder 재정렬 → 공고 추천
                → 공고별 커리어 기록 추천 → 재료 고르기
```

공고 추천은 전체 후보를 빠르게 선별한 뒤 상위 후보에만 정밀 비교를 적용한다. 프론티어 LLM은 공고 분석, AI 대화, 포트폴리오 생성과 오프라인 교사 라벨링에 사용한다. 자체 학습 모델은 반복 호출되는 추천과 적합도 예측에 사용한다. 두 추천 기능의 입력·출력과 평가 집단은 분리해 기록한다.

## 4.2. AI학습 알고리즘의 선정

| 단계 | 제안서의 모델 | 입력 | 출력 |
| --- | --- | --- | --- |
| 공고 후보 선별 | `multilingual-e5-base` 동결 인코더 + 학습 가능한 MLP | 프로필 텍스트, 공고 텍스트 | 공고별 적합도 0–100, 상위 후보 |
| 공고 후보 재정렬 | `bge-reranker-v2-m3` 기반 Cross-Encoder 부분 미세조정 | 공고와 관련 기록 최대 8개 | 후보별 적합도 0–100, 최종 순위 |
| 기록 추천 | 공고–기록 적합도 모델 | 지원 공고, 사용자 기록 목록 | 관련 기록 순위와 선택 근거 |

기록 추천의 독립 학습 구조와 후보 수는 제안서에 확정되어 있지 않다. 3장의 기록 라벨과 평가 집단을 구축한 뒤 모델 구성을 결정한다. 공고 추천 모델을 기록 추천 모델로 그대로 취급하지 않는다.

## 4.3. AI학습 파라미터 설정

| 항목 | 설계값 | 출처와 상태 |
| --- | --- | --- |
| E5 입력 | 프로필·공고 각각 최대 512토큰 | 제안서의 입력 설계 |
| E5 출력 | 입력별 768차원, 평균 풀링·L2 정규화 | 제안서의 임베딩 설계 |
| MLP 입력 | 프로필·공고 벡터와 두 벡터의 차이·원소별 곱을 연결, 총 3,072차원 | 제안서의 비교 특징 |
| MLP 구조 | `Linear(3072, 256)` → GELU → `Linear(256, 1)` → Sigmoid | 제안서의 학습 설계 |
| Cross-Encoder 입력 | 공고 + 관련 기록 최대 8개, 최대 1,536토큰 | 제안서의 재정렬 설계 |
| Cross-Encoder 학습 | 임베딩·앞쪽 20층 동결, 마지막 4층·점수 헤드 학습 | 제안서의 부분 미세조정 설계 |

배치 크기, 학습률, 손실 가중치, 선별 후보 수는 검증 실험에서 정한다. 제안서에 없는 값을 확정 파라미터처럼 적지 않는다.

## 4.4. AI학습 모델의 생성 및 서비스 적용

프로필마다 후보 공고 10개를 연결하고 루브릭 점수를 생성한다. MLP와 Cross-Encoder는 예측 점수와 정답 점수의 차이, 같은 프로필 안에서 공고의 상대 순서를 함께 평가한다. 학습 8,400쌍으로 파라미터를 학습하고 검증 900쌍으로 모델과 후보 수를 정한다. 평가 700쌍은 확정한 설정을 한 번 평가하는 데 사용한다.

공고 탐색에서는 캐시한 E5 벡터로 후보를 선별하고 Cross-Encoder로 상위 후보를 재정렬한다. 재료 고르기에서는 공고별 기록 추천 결과와 근거를 제시한다. 모델이 준비되지 않았거나 추론에 실패하면 현재의 규칙 기반 정렬을 사용한다. 모델 버전, 인코더 버전, 라벨·루브릭 버전, 평가 지표와 코드 커밋을 함께 보관한다. 학습 가중치·추론 코드와 학습·평가 재현 코드를 산출물로 저장한다.

임베딩 후보는 `multilingual-e5-base`, `KURE-v1`, `BGE-M3`, `Qwen3-Embedding-0.6B`다. 같은 분할에서 NDCG@10, MAE, 공고쌍 순서 일치율, 임베딩 생성 시간·처리량·메모리·저장 용량을 비교한다. 어느 후보도 아직 실측 우위가 확인되지 않았다. 평가 절차는 9.2에 기술한다.
