# 1. 프로젝트 개요

## 1.1. 개발목표와 범위

### 개발목표

본 설계서는 **웹 환경에서 커리어 기록과 채용 공고를 연결해 맞춤형 포트폴리오를 제작·배포하는 서비스**를
개발하기 위한 설계서다. 주 사용자는 이직·취업을 준비하는 개발자·디자이너 등 직군의
구직자이며, 데스크톱 웹 브라우저를 통해 접속해 사용하는 것을 전제로 한다. 모바일 웹과
공개된 포트폴리오 열람은 반응형으로 지원한다.

서비스는 커리어 기록에서 공개 포트폴리오까지 한 흐름으로 이어진다.

1. 경력·프로젝트·학력·자격·활동을 커리어 기록으로 축적한다.
2. 채용 공고를 탐색하고, 공고에 맞는 기록을 추천한다.
3. AI 대화로 경험을 보완한 뒤 레시피와 디자인을 정해 웹 포트폴리오를 제작한다.
4. 포트폴리오를 공개하고 방문 데이터를 확인해 구성을 개선한다.

생성 과정은 원천 자료를 곧바로 웹사이트 생성 모델에 넣지 않는다. 채용 공고, 회사 조사,
사용자 기록을 먼저 근거 중심의 설계안(`PortfolioPlan`)으로 정제하고, 여기에 사용자가
선택한 스타일 문법과 공통 디자인 원칙을 결합해 웹사이트를 생성한다. 상세는
`docs/architecture/portfolio-generation-methodology-v1.md`에 있다.

> `[그림 1.1] Expresso 서비스 전체 구성 — 클라이언트(웹/모바일/데스크톱) · API 서버 ·
> 비동기 Worker · AI 학습서버 · MongoDB · Redis · 로컬 미디어 저장소 · 공개 사이트 배포 경로를
> 한 장에 배치한다. PPT로 그려 캡처한다.`

### 개발필요성

구직자는 지원하는 회사가 바뀔 때마다 프로젝트 문서, 활동 기록, 개발 성과를 다시 모은다.
공고가 요구하는 역량에 맞춰 경험을 고르고 설명과 구성을 수정하는 작업도 반복한다.
한 번 정리한 경험을 다음 지원에 활용할 수 있도록 기록을 축적하고, 공고별 포트폴리오
제작까지 이어 주는 서비스가 필요하다.

Expresso는 커리어 기록을 한곳에 모으고 채용 공고와 관련된 경험을 추천한다. 구직자는
추천된 기록을 고쳐 선택하고, AI 대화에서 역할·행동·성과를 구체화한다. 레시피와 디자인을
정한 뒤 포트폴리오를 생성·편집·배포한다. 방문 수와 섹션별 체류 시간은 배포 후 구성
개선에 활용한다.

제안서의 자체 학습 과제는 **채용 공고 추천**과 **커리어 기록 추천**이다. 공고 탐색에서
사용자에게 적합한 공고를 올리고, 재료 고르기에서 지원 공고에 맞는 기록을 고른다.
현재 서비스는 두 추천에 규칙 기반 점수를 사용한다. 3·4장은 제안서의 학습 모델 개발
계획을, 9.2는 평가 계획을 기술한다.
