# 1. 프로젝트 개요

## 1.1. 개발목표와 범위

### 개발목표

본 설계서는 **웹 환경에서 구직자를 위한 채용 공고 맞춤형 웹 포트폴리오 생성 서비스**를
개발하기 위한 설계서다. 주 사용자는 이직·취업을 준비하는 개발자·디자이너 등 직군의
구직자이며, 데스크톱 웹 브라우저를 통해 접속해 사용하는 것을 전제로 한다. 모바일 웹과
공개된 포트폴리오 열람은 반응형으로 지원한다.

서비스는 세 가지를 한 흐름으로 잇는다.

1. **기록한다.** 사용자의 경력·프로젝트·학력·자격·활동을 구조화된 기록으로 축적한다.
2. **만든다.** 특정 채용 공고를 분석해, 그 공고가 요구하는 역량과 사용자의 실제 기록을
   연결한 웹 포트폴리오를 생성한다.
3. **잇는다.** 배포한 포트폴리오의 방문 데이터를 수집해 다음 행동으로 연결한다.

생성 과정은 원천 자료를 곧바로 웹사이트 생성 모델에 넣지 않는다. 채용 공고, 회사 조사,
사용자 기록을 먼저 근거 중심의 설계안(`PortfolioPlan`)으로 정제하고, 여기에 사용자가
선택한 스타일 문법과 공통 디자인 원칙을 결합해 웹사이트를 생성한다. 상세는
`docs/architecture/portfolio-generation-methodology-v1.md`에 있다.

> `[그림 1.1] Expresso 서비스 전체 구성 — 클라이언트(웹/모바일/데스크톱) · API 서버 ·
> 비동기 Worker · AI 학습서버 · PostgreSQL · Redis · 객체 저장소 · 공개 사이트 배포 경로를
> 한 장에 배치한다. PPT로 그려 캡처한다.`

### 개발필요성

구직자가 채용 공고마다 포트폴리오를 다시 만드는 일은 반복적이면서도 자동화가 어렵다.
같은 경력이라도 공고가 요구하는 역량에 따라 무엇을 앞세우고 무엇을 접을지가 달라지기
때문이다. 기존 도구는 두 극단에 있다.

- **템플릿 기반 빌더**는 배치만 제공하고, 어떤 내용을 넣을지는 사용자가 정한다.
  공고와의 연결은 사람이 한다.
- **생성형 AI 단독 사용**은 문장을 빠르게 만들지만, 사용자가 실제로 하지 않은 성과와
  수치를 지어낸다. 채용 문서에서 이는 치명적이다.

Expresso는 그 사이를 메운다. **공고 요구사항과 사용자 기록을 먼저 연결하고**, 연결된
근거 안에서만 문장과 수치를 만든다. 근거가 없는 수치는 생성 단계에서 기계적으로 거부한다
(`services/backend/src/modules/generation/validator.ts`).

이 연결 판정 — "이 요구사항은 이 사용자의 어떤 기록으로 충족되는가" — 이 서비스 품질을
좌우한다. 현재는 토큰 부분일치 규칙으로 판정하고 있으며, 본 프로젝트의 AI 학습 과제는
이 판정을 학습 모델로 대체하는 것이다(3장·4장·9.2 참조).

### 개발범위

| 구분 | 포함 | 제외 |
| --- | --- | --- |
| 클라이언트 | 웹(Next.js) | 네이티브 모바일 앱 · 데스크톱 앱은 껍데기까지 |
| 서버 | REST API · 비동기 Worker | — |
| AI 생성 | 공고 분석 · 레시피 · 포트폴리오 생성 · 편집 제안 | 다중 후보 생성 후 선별 |
| AI 학습 | 공고 추천 랭커(A) · 기록 추천 랭커(B) | 자체 LLM 사전학습 · 생성 모델 파인튜닝 |
| 배포 | 공개 사이트 배포 · 버전·롤백 · 내보내기 | 커스텀 도메인 자동 발급 |
| 분석 | 방문 지표 수집 · 대시보드 · 해설 | 외부 광고 플랫폼 연동 |
