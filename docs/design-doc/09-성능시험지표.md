# 9. 성능시험지표

## 9.1. AI서비스 성능평가지표

개발할 AI서비스의 성능을 측정하기 위한 평가지표를 아래와 같이 발굴하여 정의한다. 평가항목마다 시험내용 · 시험환경 · 시험절차를 함께 작성한다.

| 평가항목 | 단위 | 개발목표치 | 평가방법 |
| --- | --- | --- | --- |
| 근거 없는 수치 차단율 | % | 100 | 팀 자체시험 |
| 공고 추천 순위 품질 (모델 A · NDCG@10) | — | 확정 전 | 팀 자체시험 |
| 기록 추천 순위 품질 (모델 B · NDCG@10) | — | 확정 전 | 팀 자체시험 |
| 포트폴리오 생성 성공률 | % | ≥ 90 | 팀 자체시험 |
| 대표 read 경로 p95 | ms | ≤ 300 | 자동화 시험 |
| 대표 write 경로 p95 | ms | ≤ 300 | 자동화 시험 |
| 이벤트 수집 p95 | ms | ≤ 150 | 자동화 시험 |
| 큐 등록 p95 | ms | ≤ 200 | 자동화 시험 |

학습 모델의 개발목표치는 규칙 baseline과 기준 인코더(`multilingual-e5-base`)의 측정값을 얻은 뒤 정한다.

### 근거 없는 수치 차단율

본 서비스는 채용 문서를 생성한다. 지어낸 수치가 **단 한 건이라도** 공개되면 사용자에게 실질적인 피해가 발생하므로 목표치를 100%로 정한다.

1. 준비 — 수치가 3개 명시된 기록으로 레시피를 구성한다.
2. 유도 — 기록에 없는 수치를 포함하도록 유도하는 입력 50건을 작성한다.
3. 실행 — 각 입력으로 생성을 실행한다.
4. 판정 — 50건 모두 `GEN_UNGROUNDED_NUMBER`로 거부되면 통과이며, 1건이라도 통과하면 실패로 본다.

| 평가항목 | 단위 | 개발목표치 | 평가방법 |
| --- | --- | --- | --- |
| 공고 추천 순위 품질 (모델 A) | — | 확정 전 | 팀 자체시험 |

| 시험내용 | 모델 A가 매긴 공고 순위가 교사 적합도 라벨의 순위와 얼마나 일치하는지 측정한다. 평가 분할의 프로필마다 연결된 공고 10개를 모델 A의 점수로 정렬한 뒤 NDCG@10을 산출하고 프로필 전체의 평균을 낸다. 예측 점수와 교사 점수의 MAE와 공고쌍 순서 일치율을 함께 산출하며, 같은 시험을 규칙 baseline에도 수행하여 개선 폭을 확인한다. |
| --- | --- |
| 시험환경 | 평가 분할 700쌍 (프로필 70개, 프로필 단위로 분리된 것)학습이 완료된 `bi` · `cross` 모델과 `metadata.json`규칙 baseline — `match-score.ts`의 `calculateExplainableMatch()`지표 산출 스크립트와 공고 벡터 캐시결과를 확인할 PC 환경 |
| 시험절차 | 평가 분할에서 프로필 1건을 선택한다.그 프로필에 연결된 공고 10개를 모델 A로 채점한다(선별 후 재정렬).점수 내림차순으로 정렬한다.교사 적합도 라벨을 정답으로 하여 NDCG@10을 계산한다.같은 프로필 안에서 정답 점수 차가 5점 이상인 공고쌍의 순서 일치율과, 예측 점수의 MAE를 계산한다.모든 프로필에 대하여 1~5를 반복하고 평균을 낸다.같은 절차를 규칙 baseline으로 수행하여 두 값을 비교한다. |

| 평가항목 | 단위 | 개발목표치 | 평가방법 |
| --- | --- | --- | --- |
| 기록 추천 순위 품질 (모델 B · NDCG@10) | — | 확정 전 | 팀 자체시험 |

| 시험내용 | 모델 B가 (채용 공고, 커리어 기록 1건) 쌍에 매긴 점수 순서가 교사의 기록 단위 판정과 일치하는지 측정한다. 기록의 정답 관련도는 교사가 그 공고의 요구사항에 연결한 충족 점수 가운데 최댓값으로 하고, 어느 요구사항에도 연결되지 않은 기록은 0으로 둔다. Cross-Encoder를 학습 때와 다른 입력 단위로 쓰므로, 이 시험이 그 분포 차이의 영향을 확인하는 자리이다. |
| --- | --- |

| 시험절차 | 평가 분할에서 (공고, 프로필) 쌍 1건을 선택한다.그 프로필의 기록마다 모델 B로 (공고, 기록) 점수를 매긴다.점수 내림차순으로 정렬한다.교사의 기록 단위 판정을 정답으로 하여 NDCG@10을 계산한다.모든 쌍에 대하여 1~4를 반복하고 평균을 낸다.같은 절차를 규칙 baseline으로 수행하여 두 값을 비교한다. |

## 9.2. AI학습 성능 (ROC)

학습 모델의 성능은 추천 순위 · 후보 선별 · 점수 예측 · 처리 효율을 구분하여 평가한다. 주요 지표는 NDCG@10이며, 설계서 양식이 요구하는 ROC · AUC는 보조 지표로 함께 산출한다. ROC는 적합도 라벨 75점(루브릭의 직접 근거) 이상을 양성으로 두고, 예측 점수의 임계값을 바꾸어 가며 그린다.

| 평가 지표 | 무엇을 평가하는가 | 해석 방향 | 적용 범위 |
| --- | --- | --- | --- |
| NDCG@10 | 적합도가 높은 공고를 상위에 배치하는가 | 높을수록 좋음 | 주요 지표 · 모델 A · B |
| Recall@K | 적합한 공고를 스크리닝 단계에서 충분히 남기는가 | 높을수록 좋음 | 스크리닝 (`bi`) |
| MAE | 예측 점수와 교사 라벨 점수의 평균 절대 차이 | 낮을수록 좋음 | 점수 예측 |
| 공고쌍 순서 일치율 | 같은 프로필에서 더 적합한 공고에 높은 점수를 주는가 | 높을수록 좋음 | 순서 예측 |
| p95 지연 · 처리량 | 요청의 95%가 완료되는 시간과 단위 시간당 처리량 | 지연은 낮게 · 처리량은 높게 | 운영 효율 |
| ROC · AUC | 75점 이상 쌍을 나머지와 구분하는가 | 높을수록 좋음 | 양식 보조 지표 |

### 평가 조건

- 점수와 순위는 교사 라벨을 기준으로 평가한다.
- 공고쌍은 같은 프로필 안에서 정답 점수 차이가 5점 이상인 쌍으로 구성한다.
- Recall@K는 K보다 큰 후보 풀과 관련성 기준을 정해 측정한다. 프로필당 공고 10개 묶음 평가와는 별도로 구성한다.
- 인코더 네 종은 같은 데이터와 같은 평가 조건에서 비교하고, 임베딩 생성 시간 · 처리량 · GPU 메모리 · 임베딩 저장 용량을 함께 기록한다.
- 모델은 검증 분할에서 임계값과 하이퍼파라미터를 정하고, 평가 분할에서 한 번만 평가한다.
- 사람 평가와의 일치와 루브릭 가중치의 타당성은 라벨 구축 후 후속 검증으로 확인한다.
