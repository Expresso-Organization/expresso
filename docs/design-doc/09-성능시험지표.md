## 9.2. AI학습 성능 (ROC)

학습 모델의 성능은 추천 순위 · 후보 선별 · 점수 예측 · 처리 효율을 구분하여 평가한다. 주요 지표는 NDCG@10이며, 설계서 양식이 요구하는 ROC · AUC는 보조 지표로 함께 산출한다. ROC는 적합도 라벨 60점 이상을 양성으로 두고, 예측 점수의 임계값을 바꾸어 가며 그린다.

| 평가 지표 | 무엇을 평가하는가 | 해석 방향 | 적용 범위 |
| --- | --- | --- | --- |
| NDCG@10 | 적합도가 높은 공고를 상위에 배치하는가 | 높을수록 좋음 | 주요 지표 · 모델 A · B |
| Recall@K | 적합한 공고를 스크리닝 단계에서 충분히 남기는가 | 높을수록 좋음 | 스크리닝 (`bi`) |
| MAE | 예측 점수와 교사 라벨 점수의 평균 절대 차이 | 낮을수록 좋음 | 점수 예측 |
| 공고쌍 순서 일치율 | 같은 프로필에서 더 적합한 공고에 높은 점수를 주는가 | 높을수록 좋음 | 순서 예측 |
| p95 지연 · 처리량 | 요청의 95%가 완료되는 시간과 단위 시간당 처리량 | 지연은 낮게 · 처리량은 높게 | 운영 효율 |
| ROC · AUC | 60점 이상 쌍을 나머지와 구분하는가 | 높을수록 좋음 | 양식 보조 지표 |

### 순위 지표의 이해

추천은 점수 하나를 맞히는 일이 아니라 공고의 순서를 정하는 일이므로, 주요 지표로 순위 지표를 쓴다. NDCG@k는 상위 k개의 **순서**가 이상적인 순서에 얼마나 가까운지를, Recall@k는 적합한 공고를 상위 k개 안에 **빠짐없이** 남겼는지를 본다. 아래 그림 9.1은 두 지표가 추천 단계에서 각각 무엇을 평가하는지를, 그림 9.2는 공고 몇 건으로 두 지표를 직접 계산한 과정을 나타낸다. 두 그림의 숫자는 설명을 위한 예시이다.

> `[그림 9.1 순위 지표가 평가하는 것 (Recall@K · NDCG@10)]` — HTML 본문의 SVG를 참조한다.

> `[그림 9.2 순위 지표의 계산 예시 (NDCG@5 · Recall@k)]` — HTML 본문의 SVG를 참조한다.

**NDCG@k**(Normalized Discounted Cumulative Gain)는 0부터 1 사이의 값이며, 1이면 모델의 순서가 교사 점수 내림차순과 같다. 아래 세 단계로 계산한다.

1. gain — 공고마다 교사 적합도 점수를 그대로 gain으로 쓴다(선형 gain).
2. DCG@k — 모델이 매긴 순서대로 gain을 log2(순위 + 1)로 나누어 더한다. DCG@k = Σ(i=1…k) gain_i ÷ log2(i + 1). 1위는 1로, 2위는 1.585로, 3위는 2로 나누므로 같은 공고라도 위에 놓일수록 합에 크게 기여한다.
3. NDCG@k — 같은 공고를 교사 점수 내림차순으로 놓았을 때의 DCG(IDCG@k)로 나눈다. NDCG@k = DCG@k ÷ IDCG@k.

그림 9.2 위쪽에서 모델이 공고를 B(75) · A(90) · C(60) · E(10) · D(40) 순으로 놓으면 DCG@5는 181.56이고, 이상적인 순서 A · B · C · D · E의 IDCG@5는 188.42이므로 NDCG@5는 0.964이다. 모자란 6.86 가운데 1 · 2위가 바뀐 손실이 5.54, 4 · 5위가 바뀐 손실이 1.31이다. 이처럼 NDCG는 **위쪽 순위의 실수를 더 크게 깎는다**. 사용자는 목록의 위쪽부터 보므로 위쪽 순서가 더 중요하다는 점을 반영한 것이다.

선형 gain에서는 모든 공고의 점수가 0보다 크므로 순서를 완전히 뒤집어도 NDCG가 0이 되지 않는다. 예시의 다섯 공고를 E · D · C · B · A로 정반대로 놓아도 NDCG@5는 0.702이다. 따라서 NDCG 값 하나의 크기로 판단하지 않고, 같은 평가 분할에서 기준선(Char TF-IDF 등)과의 차이와 그 신뢰구간으로 읽는다. 아래 파일럿 결과에서 NDCG@10이 0.95 안팎으로 높게 나오는 것도 이 성질 때문이다. 본 설계서의 NDCG@10은 프로필마다 공고 10개를 모델 점수로 정렬하여 계산하고 프로필 전체의 평균을 낸다(9.1 시험절차).

**Recall@k**는 적합한 공고 전체 가운데 상위 k개 안에 들어온 비율이다. 적합한 공고는 교사 적합도 60점 이상인 공고로 보며, ROC의 양성과 MAP@10 · MRR@10의 기준과 같다. Recall@k = (상위 k개 안의 적합 공고 수) ÷ (후보 전체의 적합 공고 수). 그림 9.2 아래쪽에서 후보 20건 가운데 적합 공고 4건이 1 · 3 · 4 · 8위에 있으면 Recall@5는 3 ÷ 4 = 0.75, Recall@10은 4 ÷ 4 = 1.00이다.

Recall@k는 상위 k개 안의 순서를 보지 않는다. 적합 공고 4건이 1–4위에 있든 7–10위에 있든 Recall@10은 같다. 대신 **적합한 공고를 놓쳤는가**를 본다. 그래서 스크리닝 단계의 지표로 쓴다. 단계적 활용(그림 4.4)에서 Cross-Encoder는 Bi-Encoder+MLP가 남긴 상위 K개만 다시 평가하므로, 스크리닝에서 빠진 적합 공고는 재정렬 단계에서 되살릴 수 없다. 스크리닝 후보 수 K는 Recall@K가 충분히 높으면서 Cross-Encoder의 처리 시간이 허용되는 값으로 정한다. 스크리닝은 Recall@K로, 재정렬의 결과 순서는 NDCG@10으로 평가하는 것은 이 때문이다.

### 평가 조건

- 점수와 순위는 교사 라벨을 기준으로 평가한다.
- 공고쌍은 같은 프로필 안에서 정답 점수 차이가 5점 이상인 쌍으로 구성한다.
- Recall@K는 K보다 큰 후보 풀과 관련성 기준을 정해 측정한다. 프로필당 공고 10개 묶음 평가와는 별도로 구성한다.
- 인코더 네 종은 같은 데이터와 같은 평가 조건에서 비교하고, 임베딩 생성 시간 · 처리량 · GPU 메모리 · 임베딩 저장 용량을 함께 기록한다.
- 모델은 검증 분할에서 임계값과 하이퍼파라미터를 정하고, 평가 분할에서 한 번만 평가한다.
- 사람 평가와의 일치와 루브릭 가중치의 타당성은 라벨 구축 후 후속 검증으로 확인한다.
