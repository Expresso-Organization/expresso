사용자가 영구 보관하는 기록 저장소. 포트폴리오와 수명이 분리되어 있어, 포트폴리오를 만들지 않아도 단독으로 쓸모가 있어야 합니다. 취업 시즌에 몰아 쓰는 것이 아니라 평소에 쌓이는 구조가 이 도메인의 목표입니다.

F1.1카테고리 관리05 · 사이드바 · 필수

기록은 반드시 하나의 카테고리에 속합니다. 기본 7종은 제거할 수 없고, 카테고리마다 속성 스키마와 기본 뷰가 다릅니다.

태스크 동작 · 요구사항 제약 · 예외
T1.1.1
기본 카테고리 제공		가입 시 경험 · 프로젝트 · 학력·이력 · 자격증·수상 · 학술·집필 · 활동·리더십 · 스킬·도구 7종을 자동 생성한다. 사이드바 트리에 순서 고정으로 노출하고 각 카테고리의 기록 수를 함께 표시한다.7종은 삭제·이름 변경 불가. 순서 변경도 불가(전 화면에서 동일한 순서를 전제로 함)
T1.1.2
사용자 카테고리 추가		이름 · 아이콘 · 기본 뷰를 지정해 카테고리를 추가한다. 속성 스키마는 기본 7종 중 하나를 복제하거나 빈 상태로 시작한다.추가 카테고리의 기록은 AI 추천·일치도 계산에 참여하되, 스킬 자동 집계 대상에서는 제외
T1.1.3
카테고리별 속성 스키마		카테고리마다 고유 속성 집합을 가진다(예: 프로젝트 = 역할·기술·기간·성과, 학술 = 게재처·게재일·외부 지표). 사용자는 문서에서 속성을 추가할 수 있고, 추가한 속성은 같은 카테고리 전체에 적용된다.속성 삭제 시 값이 있는 기록이 있으면 건수를 알리고 확인을 받는다. 시스템 속성(상태·시기·사용처)은 삭제 불가
T1.1.4
트리에서 바로 추가		사이드바 카테고리 행에 마우스를 올리면 ＋가 나타나고, 누르면 해당 카테고리에 빈 기록을 만들고 문서 패널을 연 상태로 이동한다.제목 없이 3분 이상 방치된 빈 기록은 자동 삭제
F1.2기록 생성05–05e · 필수

기록을 만드는 경로는 직접 쓰기 · AI에게 맡기기 · 외부에서 가져오기 셋입니다. 어느 경로로 만들어도 같은 구조를 갖고, 출처만 다르게 남습니다.

태스크 동작 · 요구사항 제약 · 예외
T1.2.1
직접 만들기		[새로 만들기]는 제목만 있는 기록을 즉시 만들고 문서 패널을 연다. 본문은 블록 편집기(제목 · 문단 · 불릿 · 구분선)로 작성하고, /로 블록 명령을 부른다.저장 버튼 없음 — 입력 중단 후 1초 뒤 자동 저장, 헤더에 "저장됨" 표기
T1.2.2
AI로 만들기		[AI로 만들기]는 카테고리에 맞는 질문 3–5개를 던지고, 답변을 STAR(상황·과제·행동·결과) 구조로 정리해 기록을 만든다. 생성된 기록에는 AI 배지와 대화 출처가 남는다.답변에 없는 수치·사실을 채우지 않는다. 비어 있는 항목은 "아직 비어 있습니다"로 남긴다
T1.2.3
대화에서 자동 생성		AI 인터뷰(D5) 중 답변이 하나의 사건을 이루면 기록을 자동 생성하거나 기존 기록을 보강한다. 대화 화면에는 "기록에 담는 중"으로 진행을 표시한다.사용자 동의 없이 삭제·덮어쓰기 금지. 기존 기록 보강 시 어떤 항목이 채워졌는지 표시
T1.2.4
외부에서 가져오기		이력서 PDF에서 학력·이력을 추출해 항목 후보로 제시하고, 사용자가 선택한 것만 기록으로 저장한다. 학술·집필은 URL을 붙여넣으면 제목·게재처·게재일·외부 지표를 가져온다.가져온 값은 편집 가능해야 하며 원본 링크를 보존한다. 추출 실패 시 수동 입력으로 안내
T1.2.5
상태 자동 판정		기록은 비어 있음 / 초안 / 정리됨 중 하나를 자동으로 갖는다. 정리됨 = STAR 4항목 + 수치 1개 이상 + 역량 1개 이상. 목록 하단에 상태별 집계를 표시한다.상태는 사용자가 직접 바꿀 수 없다(조건을 채우면 바뀐다). 정리됨만 소스 자동 선택 대상
F1.3기록 문서 편집05–05e · 필수
태스크 동작 · 요구사항 제약 · 예외
T1.3.1
문서 패널 열기		목록에서 항목을 누르면 우측 패널이 열리고 목록은 유지된다. 패널 상태는 주소에 반영되어 새로고침·공유 후에도 같은 문서가 열린다. 전체 화면 확장도 지원한다.패널이 열려 있어도 목록 스크롤·필터는 계속 조작 가능해야 한다
T1.3.2
속성 편집		속성은 이름·값 쌍으로 나열하고 값 영역을 눌러 바로 편집한다. 태그형 속성은 기존 값 자동완성을 제공한다.시기 속성은 월 단위 이상만 허용(일 단위 불필요)
T1.3.3
AI 정리 블록		AI가 정리한 교훈·요약은 별도 블록으로 구분해 보여주고, 눌러서 바로 수정할 수 있다. 수정하면 그 블록은 사용자 소유가 되어 이후 재생성 대상에서 빠진다.AI 블록은 문서당 최대 2개(교훈 · 제안)
T1.3.4
문서 단위 AI 요청		패널 하단 입력창으로 이 문서에 대한 AI 작업을 요청한다. 카테고리별 빠른 액션을 제시한다(성과를 숫자로 · STAR로 재구성 · 이력서 문장으로 · 영문으로 번역 · 스킬로 올리기 등).결과는 항상 미리보기 후 적용. 적용 전후를 비교할 수 있어야 한다
T1.3.5
삭제와 영향 범위		기록 삭제 시 사용 중인 포트폴리오 수를 알리고 확인을 받는다. 삭제해도 이미 배포된 포트폴리오의 문장은 변경되지 않는다.삭제 후 30일간 휴지통 보관, 이후 완전 삭제
F1.4뷰 · 필터 · 정렬05–05e · 중요

같은 기록을 카테고리 성격에 맞는 방식으로 봅니다. 뷰는 카테고리마다 기본값이 다르고, 사용자가 추가할 수 있습니다.

태스크 동작 · 요구사항 제약 · 예외
T1.4.1
뷰 전환		테이블 · 갤러리 · 타임라인 · 보드 · 목록 5종을 제공한다. 기본 뷰는 경험=테이블, 프로젝트=갤러리, 학력·이력=타임라인, 스킬=보드, 학술=목록. 전환해도 필터·정렬은 유지된다.타임라인은 시기 속성이 있는 카테고리에서만 선택 가능
T1.4.2
뷰 저장		"＋ 뷰 추가"로 현재 필터·정렬·표시 속성 조합을 이름 붙여 저장한다. 저장한 뷰는 탭으로 노출되고 순서를 바꿀 수 있다.카테고리당 뷰 최대 8개
T1.4.3
필터 · 정렬 · 표시 속성		속성 기준 필터(다중 조건 AND), 정렬(속성 오름/내림), 테이블 표시 열 선택을 제공한다. 조건이 걸린 상태는 버튼에 개수로 표시한다.필터 결과 0건이면 조건을 요약해 보여주고 "조건 지우기"를 제공
T1.4.4
갤러리 카드 시각화		프로젝트 카드는 이미지가 없어도 비지 않아야 한다. 기록의 성과 수치 유형에 따라 적절한 시각 요소(성공률 격자 · 처리량 추이 · 전환 비율 등)를 자동 선택해 그린다.수치가 없으면 "성과 수치 없음"을 표시하고 채우기 액션을 건다
T1.4.5
목록 집계		목록 하단에 전체 건수와 상태별 집계, 그리고 보완 액션을 제시한다(예: "12개 · 성과 수치 없음 3 → 비어 있는 성과 채우기").보완 액션은 실제로 채울 대상이 있을 때만 노출
F1.5기록 간 연결과 사용처 추적05b, 05c, 05e · 중요
태스크 동작 · 요구사항 제약 · 예외
T1.5.1
기록 연결		프로젝트 ↔ 경험 ↔ 이력 ↔ 스킬 ↔ 학술을 서로 연결한다. 연결은 양방향으로 표시되고, 한쪽에서 해제하면 양쪽에서 사라진다.같은 카테고리 내 연결도 허용(프로젝트 묶기)
T1.5.2
사용처 표시		기록이 어떤 포트폴리오의 어느 섹션에 쓰였는지 "사용처 N곳"으로 표시하고, 누르면 해당 섹션으로 이동한다.배포된 포트폴리오와 초안을 구분해 표기
T1.5.3
인용 문단 추적		학술·집필 기록의 어떤 문단이 포트폴리오로 갔는지 표시한다. 원문을 수정하면 "포트폴리오에도 반영할까요?"를 묻는다.이미 배포된 포트폴리오는 자동 반영하지 않고 항상 확인을 받는다
T1.5.4
중복·병합 제안		기술 스택·기간이 크게 겹치는 기록이 있으면 문서 패널에 병합 제안을 1건 띄운다("두 기록을 묶어 한 편의 서사로 만들까요?").제안은 거절하면 같은 쌍에 대해 30일간 다시 띄우지 않는다
F1.6스킬 자동 집계와 수요 갭05d · 중요

스킬은 사용자가 나열하는 것이 아니라 기록에서 계산되는 결과입니다. 근거 없는 스킬은 포트폴리오에 올라가지 않습니다.

태스크 동작 · 요구사항 제약 · 예외
T1.6.1

제외 사유 제시		선택되지 않은 기록을 사유별로 묶어 건수와 함께 보여준다(역량 불일치 · 내용이 짧음 · 더 최신 기록으로 대체됨).사유를 특정할 수 없는 항목은 "기타"로 묶지 말고 사유 표시를 생략
T4.1.4
현장에서 기록 추가		이 화면을 떠나지 않고 기록을 새로 만들거나 AI 추천을 다시 실행할 수 있다.새로 만든 기록은 즉시 목록에 반영되고 자동 선택 규칙을 다시 적용
F4.2생성 모드와 분량 설정01b, 03 · 필수
태스크 동작 · 요구사항 제약 · 예외
T4.2.1
모드 선택		위임 모드(질문 6개에 답하면 나머지는 자동)와 공동 편집 모드(섹션마다 함께 작성) 중 하나를 고른다. 선택은 이후 단계의 개입 지점 수를 결정한다.공동 편집 모드는 유료 플랜 전용. 진행 중 모드 변경은 포트폴리오 레시피 단계까지만 허용
T4.2.2
분량 프리셋		3섹션 / 6섹션 / 상세(프로젝트별 하위 페이지·인터랙션 포함) 중 하나를 고른다. 프리셋에 따라 레시피의 섹션 수 상한이 정해진다.선택한 소스 수가 프리셋보다 적으면 프리셋을 낮추도록 안내
T4.2.3
마감 알림 설정		공고 마감일 기준 알림을 켜고 끌 수 있다. 기본값은 켜짐, 마감 이틀 전 발송.상시 채용 공고에는 알림 옵션을 노출하지 않는다
T4.2.4
사용량 확인		다음 단계로 넘어가기 전에 이번 달 남은 생성 횟수를 표시한다.횟수 소진 시에도 레시피 작성까지는 진행 가능(문서 생성만 차단)

D5AI 인터뷰

질문에 답하는 동안 기록이 생성·보완되는 것이 이 도메인의 목적입니다. 대화 자체는 산출물이 아니며, 세션이 끝나면 남는 것은 구조화된 기록과 레시피 근거입니다.

F5.1질문 생성과 배정02 · 필수
태스크 동작 · 요구사항 제약 · 예외
T5.1.1
질문 세트 구성		세션당 질문 6개를 만든다. 기록 없음 요건에 2개, 보강 필요 요건에 2개, 수치가 빈 선택 기록에 2개를 배정한다.배정 대상이 부족하면 질문 수를 줄이되 최소 3개는 유지
T5.1.2
질문 근거 표시		질문마다 왜 묻는지를 공고 근거로 한 줄 표시한다("이 공고는 '남긴 흔적'을 7번 언급했습니다").근거를 만들 수 없는 질문은 세트에 넣지 않는다
T5.1.3
질문 품질 규칙		한 질문에는 한 가지만 묻는다. 예/아니오로 끝나는 질문, 답이 뻔한 질문, 이미 기록에 답이 있는 질문은 생성하지 않는다.질문 길이는 40자 이내 권장
T5.1.4
질문 교체		사용자가 답하기 어려운 질문을 다른 질문으로 바꿀 수 있다. 교체해도 같은 요건을 다루는 대안이어야 한다.같은 요건에 대안이 없으면 다음 우선순위 요건으로 넘어가고 그 사실을 알린다
T5.1.5
남은 질문 미리보기		앞으로 무엇을 물어볼지 목록으로 먼저 보여준다. 진행률(답변 수 / 전체)을 항상 표시한다.남은 질문은 앞선 답변에 따라 문구가 바뀔 수 있음을 표시
F5.2응답 수집과 기록 생성02 · 필수
태스크 동작 · 요구사항 제약 · 예외
T5.2.1
답변 입력 수단		자유 텍스트 · 빠른 답변 선택 · 음성 입력 · 파일 첨부를 지원한다. 입력 안내는 "문장으로 다듬어 준다"는 점을 알려 부담을 낮춘다.빠른 답변은 그 자체로 완결된 답이 아니라 서술을 여는 실마리로만 사용
T5.2.2
실시간 기록 구성		답변이 들어올 때마다 우측에서 기록의 STAR 항목이 채워지는 것을 보여준다. 비어 있는 항목과 그것을 채울 질문을 함께 안내한다.답변에 없는 내용으로 항목을 채우지 않는다
T5.2.3
기록 확정과 저장		세션 중 완성된 기록은 즉시 커리어 저장소에 저장하고 목록으로 보여준다. 세션을 끝내지 않아도 기록은 남는다.저장된 기록에는 출처(세션 · 질문 번호 · 날짜)를 남긴다
T5.2.4
추가 질문(꼬리 질문)		답변이 모호하거나 수치가 빠지면 같은 주제로 한 번 더 묻는다. 꼬리 질문은 전체 질문 수에 포함하지 않는다.한 질문당 꼬리 질문은 최대 1회
T5.2.5
중단 · 재개 · 건너뛰기		언제든 중단할 수 있고, 다음 진입 시 마지막 지점에서 이어간다. 남은 질문을 건너뛰고 다음 단계로 갈 수도 있다.건너뛰면 해당 요건이 레시피에서 비어 있게 됨을 미리 알린다
T5.2.6
이전 대화 열람		앞선 문답은 접어 두고 필요할 때 펼쳐 본다. 이전 답변을 수정하면 그 답변으로 만든 기록도 함께 갱신할지 묻는다.사용자가 이미 손댄 기록은 자동 갱신하지 않는다

D6포트폴리오 레시피

제품의 중심 산출물입니다. 섹션 순서와 섹션별 컨텍스트 문서(무엇을 담고 무엇을 뺄지)를 확정하며, 이 단계에서는 완성 문장을 다루지 않습니다.

F6.1레시피 생성02b · 필수
태스크 동작 · 요구사항 제약 · 예외
T6.1.1
입력 통합		공고 분석 결과 · 선택된 소스 기록 · 인터뷰 응답 세 가지를 읽어 섹션 구성을 만든다. 무엇을 읽었는지 건수로 화면에 명시한다.공고가 없는 경우(목표 없이)에는 소스 기록과 응답만으로 구성
T6.1.2
섹션 목록 생성		분량 프리셋 범위 안에서 섹션을 만들고 순서를 정한다. 각 섹션은 담당 소스 기록을 하나 이상 갖는다.소스가 없는 섹션은 "비어 있음"으로 표시하고 자동 채우지 않는다(연락처 섹션 예외)
T6.1.3
컨텍스트 문서 작성		섹션마다 목표 · 담을 요점 · 쓸 수치 · 형식 · 톤 · 제외 6항목을 작성한다. 각 항목에는 작성 주체(AI / 사용자)를 표시한다.이 문서에는 완성 문장을 쓰지 않는다. 사용자가 문장을 쓰려 하면 다음 단계로 안내
T6.1.4
근거 경로 기록		"왜 이 구성인가"를 최소 3개 항목으로 남기고, 각 항목은 출처 → 대상 경로를 명시한다(공고 → 섹션 04 신설 등).근거 항목은 클릭하면 해당 원본으로 이동할 수 있어야 한다
T6.1.5
미사용 소스 처리		선택했지만 어느 섹션에도 배치되지 않은 기록을 사유와 함께 보여주고, 배치할 섹션을 찾아 주는 액션을 제공한다.미사용 소스가 절반을 넘으면 소스 선택 단계로 돌아가도록 권한다
T6.1.6
전체 재생성		레시피를 통째로 다시 만들 수 있다. 사용자가 편집한 섹션이 있으면 유지할지 함께 버릴지 선택하게 한다.재생성은 생성 사용량을 소모하지 않는다
F6.2레시피 편집과 공동 작업02b · 필수
태스크 동작 · 요구사항 제약 · 예외
T6.2.1
섹션 순서·추가·삭제		드래그로 순서를 바꾸고, 섹션을 추가·삭제할 수 있다. 키보드로도 같은 조작이 가능해야 한다.소스가 배치된 섹션을 삭제하면 그 소스는 미사용으로 돌아간다
T6.2.2
항목 단위 편집		컨텍스트 6항목을 각각 직접 수정하거나 AI에게 다시 쓰게 할 수 있다. 요점 항목은 순서를 바꿀 수 있고 항목마다 근거를 붙일 수 있다.사용자가 수정한 항목은 이후 재생성에서 유지된다(잠금)
T6.2.3
문장으로 수정 지시		"두 번째 섹션은 수치를 하나만 쓰자"처럼 문장으로 레시피를 고칠 수 있다. 결과는 변경 항목 목록으로 보여주고 되돌릴 수 있다.지시가 모호하면 실행 전에 되물어 확인한다
T6.2.4
변경 이력		레시피 단위로 변경 이력을 남기고 항목별로 되돌릴 수 있다. 누가(사용자/AI) 언제 바꿨는지 표시한다.이력은 최근 50건까지 보관
T6.2.5
완성도 요약		섹션 수 · AI 작성/사용자 수정 비율 · 배치된 소스 수 · 예상 읽는 시간을 요약해 보여준다.비어 있는 섹션이 있으면 다음 단계로 넘어가기 전에 경고

D7포트폴리오 생성

확정된 레시피를 실제 문장과 지면으로 바꾸는 도메인입니다. 지면은 준비된 목록에서 고르는 것이 아니라 이 사람 이 공고를 위해 매번 새로 짭니다. 후보는 내 내용이 채워진 상태로 비교하게 하고, 생성은 레시피를 벗어나지 않아야 합니다.

F7.1지면 생성03 · 필수
태스크 동작 · 요구사항 제약 · 예외
T7.1.1
내 내용으로 후보 비교		지면 후보는 레시피의 실제 섹션 내용을 채워 렌더한다. 더미로 그린 미리보기는 판단 근거가 되지 못한다. 어떤 섹션이 채워진 상태인지 목록으로 함께 표기한다.더미 텍스트 미리보기 금지. 내용이 부족하면 부족한 상태 그대로 보여준다
T7.1.2
후보 3안과 전체 보기		한 번의 생성으로 서로 뚜렷하게 다른 지면 3안을 내고, 하나를 전체 화면으로 크게 확인할 수 있다. 마음에 들지 않으면 다시 생성한다.3안은 서로 달라야 한다 — 팔레트만 다른 같은 지면은 후보가 아니다. 모든 안은 레시피의 모든 섹션 유형을 렌더할 수 있어야 한다
T7.1.3
기업 톤 반영		공고에서 추출한 톤 정보를 지면 생성 입력으로 넣고, 색 반영 여부를 켜고 끌 수 있다.기업 색을 쓰더라도 가독성 기준(본문 대비 4.5:1)을 만족해야 하며, 위반 시 자동 보정
T7.1.4
스타일 변형 지시		"여백을 더 넓게, 제목은 더 크게"처럼 한 문장으로 스타일을 조정한다. 조정 결과는 즉시 미리보기에 반영된다.간격·타이포·팔레트·밀도만 바꾸고 섹션 구조는 바꾸지 않는다. 되돌리기 제공
T7.1.5
선택 요약		고른 템플릿의 팔레트 · 서체 · 밀도를 요약해 보여주고 언제든 바꿀 수 있음을 알린다.유료 템플릿은 선택은 가능하되 생성 시 업그레이드를 요구
F7.2문서 생성 실행03 · 필수
태스크 동작 · 요구사항 제약 · 예외
T7.2.1
레시피 준수 생성		섹션별 컨텍스트 문서에 적힌 요점·수치·형식·톤을 그대로 따르는 문장을 만든다. 각 문장은 어떤 컨텍스트 항목에서 나왔는지 추적 가능해야 한다."제외" 항목 위반 시 사용자에게 보여주기 전에 1회 재생성. 컨텍스트에 없는 주장·수치 생성 금지
T7.2.2
진행 표시와 백그라운드		생성 단계를 순차로 표시하고 예상 소요를 알린다. 창을 닫아도 진행되며 완료 시 알림을 보낸다.완료 후 자동으로 편집 화면으로 이동
T7.2.3
사용량 차감과 복구		생성 성공 시 사용량 1회를 차감한다. 실패하면 차감하지 않거나 즉시 복구하고, 부분 결과는 초안으로 보존한다.재생성(같은 레시피 다시 만들기)은 24시간 내 1회 무료
T7.2.4
생성 직후 스냅샷		생성 완료 시점을 복원 지점으로 저장해, 이후 어떤 편집을 해도 최초 결과로 돌아올 수 있게 한다.복원 지점은 포트폴리오당 최소 5개 보관

D8포트폴리오 편집

생성된 결과를 다듬는 도메인입니다. 대화형 수정이 기본, 직접 조작이 보조이며, 두 방식의 결과가 하나의 변경 이력으로 합쳐집니다.

F8.1구조 편집04 · 필수
태스크 동작 · 요구사항 제약 · 예외
T8.1.1
섹션 순서·표시		섹션을 드래그로 재배치하고 개별로 숨길 수 있다. 숨긴 섹션은 이유(예: 공고와 무관)를 함께 표시한다.숨김은 삭제가 아니며 언제든 되살릴 수 있다
T8.1.2
순서 개선 제안		공고 요구나 방문 데이터를 근거로 섹션 순서 변경을 제안한다. 제안은 한 번에 하나만, 수락·거절 버튼과 함께 노출한다.거절한 제안은 같은 근거로 다시 띄우지 않는다
T8.1.3
