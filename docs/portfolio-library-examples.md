원본 코드를 확보한 Watermelon·경력·연구 항목 전체에 실행 예제를 연결하고, 모션 자료에는 공식 참고 영상을 추가했습니다.

- 실행 예제는 기존 120개에 970개를 추가해 총 1,090개입니다.
- 새 예제 970개 모두 브라우저에서 콘텐츠 표시와 초기 실행 오류 검사를 통과했습니다.
- 모션 자료 2,135개에는 공식 영상, 문서·도구 62개와 공급자 목록 380개에는 텍스트 미리보기를 연결했습니다.
- 이용 허락이 필요한 240개와 원본 접근이 막힌 18개는 사유를 유지했습니다. 이 258개에는 실행 예제가 없습니다.

## 1. 포털 사용

개발 포털의 **라이브러리 → 유형 카드 → 확보 상태 → 실행 예제 있음**에서 실행 가능한 항목을 모아 봅니다. 항목을 열고 **실행 예제 보기**를 누르면 샘플 입력이 들어간 화면을 직접 조작할 수 있습니다. **새 탭에서 크게 보기**는 예제를 전체 화면 폭으로 엽니다.

목록에는 실제 실행 결과를 캡처한 정적 화면을 표시합니다. 상세 화면에서 실행하면 입력·클릭·애니메이션이 활성화됩니다. 초기 화면은 1280px 기준으로 캡처했고, 상세의 실행 화면은 패널 폭에 맞춰 표시합니다.

**렌더링 예제 입력**에는 샘플 데이터와 원본 코드를 연결한 방법을 기록했습니다. 공급자의 기본 데모, 직접 작성한 입력, 외부 실행 환경을 대체한 부분을 확인할 수 있습니다.

모션은 **참고 영상 있음**으로 찾습니다. 상세의 **참고 영상 재생 / 영상 일시 정지** 버튼으로 조작하고, 재생이 어려우면 **원본 영상 열기** 또는 공급자 링크에서 확인합니다. 영상은 공식 외부 주소에 연결되며 원본 서비스의 가용성에 영향을 받습니다.

유형 선택은 상단 탭에서 카드 홈으로 옮겼습니다. 각 카드에는 Phosphor Regular 아이콘, 용도 설명, 항목 수를 표시합니다. 실제 실행 화면은 유형 안의 자료 목록과 상세에서 확인합니다. 카드를 누르면 목록으로 이동하고, **유형 선택** 링크로 홈에 돌아옵니다. 카드와 화살표는 호버·키보드 포커스에서 움직이며, 동작 줄이기 설정에서는 이동을 끕니다.

컴포넌트 1,277개는 섹션 193개, 콘텐츠 요소 260개, 기본 UI 767개, 페이지·앱 예제 57개로 나눴습니다. 원본의 페이지·대시보드 경로, 파일명 계열, 대표 구성의 코드를 검토해 탐색 규칙을 정했습니다. 원본을 확보하지 못한 공급자 자료는 상세에 임시 분류로 표시합니다. 전체 항목을 개별로 시각 평가한 결과와는 구분합니다.

기존 컴포넌트 목록 주소는 네 조립 단위의 카드로 연결하고 검색·확보 상태 필터를 유지합니다. 기존 상세 주소는 계속 열립니다. `/library`는 카드 홈, `/library/all`은 전체 검색 목록입니다.

## 2. 실행 예제 범위

| 대상 | 실행 예제 | 구성 |
| --- | ---: | --- |
| Watermelon | 1,073 | 기존 120개와 추가 953개. UI·블록·템플릿·보조 훅에 입력과 부모 컨텍스트를 제공했습니다. |
| Magic Portfolio·shadcn Timeline | 5 | 원본 React 컴포넌트에 경력·프로젝트·타임라인 예시 데이터를 전달했습니다. |
| al-folio Core·CV·Distill | 11 | 원본 Liquid 본문에 예시 데이터를 적용하고 문서 기본 스타일을 연결했습니다. |
| Magic Portfolio 상세 라우트 | 1 | 제목·본문·이전다음 구조를 브라우저용 데모로 재구현했습니다. |
| 합계 | 1,090 | 새로 추가한 970개와 기존 120개입니다. |

Watermelon의 차트·표·메뉴·대화상자·입력 폼에는 필요한 데이터와 조합을 제공했습니다. Tooltip·Router 등 부모 컨텍스트를 구성했고, 공급자에 데모 파일이 있으면 실제 데모를 연결했습니다. 직접 입력을 만든 항목은 데이터·조합 예제로 표시합니다.

Liquid 예제는 사이트 공통 include, 외부 인용 지표, Distill 스크립트를 제외하고 목차·참고문헌 태그에 예시 출력을 제공합니다. Next.js 이미지·링크·이력 데이터도 브라우저용 어댑터를 사용합니다. 원본 사이트 전체 환경의 동작은 별도 검증이 필요합니다.

샘플 경력·조직·연구 수치는 설명용입니다. 실제 사용자 경력, 성과 또는 외부 서비스 응답을 나타내지 않습니다. 일부 콜백은 화면 조작을 위한 예시이며 실제 저장·결제·API 전송은 연결하지 않았습니다.

## 4. 실행 환경과 재검증

원본은 2·3단계에서 고정한 저장소 판을 사용합니다. 원본 파일은 유지하고 실행 전용 엔트리에서 입력·컨텍스트·호환 어댑터를 연결합니다. 패키지 버전은 렌더러 전용 lockfile에 기록합니다.

아래 명령은 저장소 루트에서 실행합니다. 먼저 2·3단계 수집 저장소가 `artifacts/portfolio-library/`에 있어야 합니다.

```bash
(cd scripts/library/renderer && pnpm install --ignore-workspace --ignore-scripts)
node scripts/library/renderer/all-examples.mjs
node scripts/library/renderer/extra-examples.mjs
node scripts/library/renderer/dependency-notices.mjs
python3.13 scripts/library/verify_examples.py
```

검증 서버를 실행한 뒤 브라우저에서 `http://127.0.0.1:8919/scripts/library/renderer/check-all.html`을 열고 **검증 시작**을 누릅니다. 예제는 스크립트만 허용한 격리 iframe에서 실행하고, 표시된 DOM과 오류 상태를 저장합니다. 화면 캡처에는 실행 문서의 스타일을 그대로 연결합니다.

기본 검증은 이미 통과한 항목을 건너뜁니다. 예제를 수정한 경우 `?names=예제이름` 또는 쉼표로 구분한 이름을 붙여 해당 항목을 다시 검사합니다. 이름은 `build-results.json`의 `name`입니다. 결과 저장 실패는 화면에 표시하고 다시 저장할 수 있습니다.

```bash
python3.13 scripts/library/publish_examples.py
```

게시 스크립트는 새 예제 970개 전체의 검사 통과와 정적 화면 해시를 확인한 뒤 포털 manifest를 만듭니다. 외부 영상 파일은 복사하지 않고 주소를 연결합니다. 실행 번들에 쓰인 의존성의 라이선스 고지는 `dependency-licenses.txt`에 보관합니다.

## 5. 검증 결과

- 신규 실행 예제 970개: 브라우저의 초기 콘텐츠 표시·실행 오류 검사 통과.
- 포털: 초기 로딩, 실행 예제 필터, 차트 표시, 경력 아코디언 펼치기, 화면 폭에 맞춘 실행, 공식 영상 재생 확인.
- 초기 로딩 때 원본 DC 템플릿을 먼저 수정하던 경쟁 상태를 수정하고 회귀 검사를 추가했습니다.
- 라이브러리 Node 검사 25건 통과. Python 검사 12건은 실행 예제 구축 시 통과했습니다.
- `pnpm typecheck` 통과.
- `pnpm test`: 변경하지 않은 `PropertyValueEditor.test.tsx`의 기존 숫자 입력 검사 1건 실패. 기대 문자열 `숫자`, 실제 값은 빈 문자열입니다.

표시 검사는 모든 버튼의 기능, 모든 화면 크기, 실제 경력 데이터에 대한 디자인 품질을 보증하지 않습니다. 포트폴리오 생성에 사용할 후보는 실제 경력 입력으로 반응형·접근성·결과물 품질을 확인하고 제품 Registry에 등록해야 합니다.
