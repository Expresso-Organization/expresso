# 포트폴리오 생성용 컴포넌트 모션 선별

코드가 확보된 섹션·콘텐츠 요소 368개 중 이번 생성 조합에는 Componentry의 Orbit Card Stack과 Annotated Text를 추가한다.

- 원본 코드의 움직임 신호와 포트폴리오 역할을 점검했다. 이번 선별 전에는 생성 후보 9개, 선별 대기 350개였고, 두 항목을 추가한 뒤 각각 11개와 348개다.
- 두 항목은 가상 프로젝트 데이터로 실행하고, 짧은 구성 JSON의 `components.projectIndex`와 `components.heroAnnotation`으로 선택한다.
- 모션 감소, 키보드, 작은 화면, 저장용 단일 HTML에서 같은 내용과 링크를 유지한다.

## 선별 근거

| 수집 항목 | 생성 역할 | 채택한 동작 | 구현 방식 |
| --- | --- | --- | --- |
| `componentry-orbit-card-stack` | 프로젝트 목록 | 카드 선택 시 펼침·전면 배치 | 원본의 공간 배치와 반응 방식을 프로젝트 카드에 맞춰 조합. shadcn Card와 네이티브 라디오 사용 |
| `componentry-annotated-text` | 소개 제목의 핵심 문구 | 제목 등장 뒤 밑줄 그리기 | 수집한 Annotated Text 원본을 렌더링하고, 공통 모션 실행기가 SVG 획을 제어. 강조 문구가 제목에 없으면 첫 줄을 표시 |

수집된 원본의 독립 실행 예제는 라이브러리 상세에서 계속 볼 수 있다. 생성 페이지에는 실제 프로젝트 수와 제목·요약·이미지·사례 링크를 연결한다. 테스트 입력의 인물과 프로젝트는 모두 가상 데이터다.

Orbit 원본은 React 상태로 카드를 조작한다. 생성용 조합에서는 저장한 HTML도 동작하도록 네이티브 라디오와 CSS 선택 상태를 쓴다. 모션 프리셋 `none`과 시스템 모션 감소 설정에서는 전환 시간을 제거하며, 방향키로 라디오를 선택할 때도 즉시 반영한다. 프로젝트가 5개를 넘으면 처음 5개를 카드로 표시하고 나머지는 같은 섹션의 링크 목록에 표시한다.

## 보류한 표현

| 수집 항목 | 이번 조합에서 보류한 이유 |
| --- | --- |
| Case Study Flip Stack | 카드 수에 따라 여러 화면 높이의 스크롤 구간을 추가하며, 현재 페이지의 개별 사례 섹션과 내용이 겹침 |
| Sticky Scroll Cards | 문서 전체에 Lenis를 적용하고 카드마다 화면 높이를 차지해 기존 페이지 탐색 흐름에 영향 |
| Collection Surfer | 원본에 고정된 50,000px 스크롤 공간과 고정 화면이 있어 포트폴리오 본문에 그대로 넣기 어려움 |
| Kinetic Text Reveal | 원본의 초기 HTML은 문구를 숨기며 React 실행 후 표시함. 현재의 스크립트 없는 단일 HTML 출력과 충돌 |

368개에 대한 정적 점검에서 자체 애니메이션·스크롤·캔버스 효과 등의 코드 신호가 있는 항목은 240개, 전환·호버 중심은 103개, 뚜렷한 신호가 없는 항목은 25개였다. 이 숫자는 실제 사용 적합성이나 브라우저 재생 품질 판정이 아니다. 이름 기준 148개 계열 역시 구조적 중복 검증 전이다. 후속 선별은 생성 데이터 계약, 기존 섹션과의 중복, 모바일·키보드·모션 감소·저장 HTML 동작을 기준으로 진행한다.
