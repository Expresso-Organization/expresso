# 포트폴리오 생성 방식 비교

이번 결과에서는 구조화 생성이 더 정돈됐고, 자유 생성은 프로젝트 사례와 근거 자료를 더 풍부하게 표현했습니다.

- 자유 생성은 사례 설명 옆에 큰 이미지를 배치하고, 근거 내용을 단계와 목록으로 구성했습니다. 프로젝트를 설명하는 방식이 더 다양합니다.
- 자유 생성의 두 번째 사례에는 제목과 이미지가 서로 다른 그리드 행에 놓이는 배치 문제가 있습니다. 기본 자동 검사에서는 발견되지 않았습니다.
- 두 결과 모두 이름·제목·기간·역할·연락처·근거 제목 22개를 보존했습니다. 390·768·1440px에서 가로 넘침, 깨진 이미지, 끊어진 목차 앵커가 없었습니다.
- 구조화 JSON이 선택한 섹션 순서는 기존 예제와 같습니다. 현재 카탈로그의 선택 범위가 좁아, 이 결과로 AI의 디자인 능력이나 일반적인 비용 우위를 판단할 수는 없습니다.

## 시각 검토

| 관점 | 구조화 생성 | 자유 생성 |
| --- | --- | --- |
| 프로젝트 이미지 | 목록의 썸네일 카드로 빠르게 훑을 수 있습니다. 사례 상세에서는 이미지를 함께 보여주지 않습니다. | 사례마다 큰 화면 이미지를 배치해 결과물과 설명을 함께 살펴보기 좋습니다. |
| 사례 서술 | 문제·담당 작업·결과를 동일한 형식으로 반복해 일관성이 높습니다. 시각적 변화는 적습니다. | 역할·기간·태그와 사례 본문을 묶고 기여 문단을 강조합니다. 목록과 상세에서 요약 문장이 반복됩니다. |
| 근거 자료 | 한 목록에서 내용을 펼칩니다. 사례의 연결 문구가 ‘설계 근거 1’처럼 일반적입니다. | 프로젝트별로 자료를 묶고 실제 자료 제목으로 연결합니다. 긴 문장을 단계와 검토 목록으로 변환했습니다. |
| 데스크톱 배치 | 섹션 정렬과 간격이 일관되고 큰 의도치 않은 공백을 찾지 못했습니다. | 루멘 노트의 좌우 교차 배치에서 이미지가 다음 행으로 밀립니다. grid-column만 뒤집고 grid-row를 지정하지 않은 구성입니다. |
| 모바일 | 프로젝트 카드를 한 열로 정리하고 모든 본문을 유지합니다. | 정보와 이미지를 한 열로 표시해 읽을 수 있습니다. 프로젝트 설명 반복으로 전체 페이지가 더 깁니다. |
| 생성 범위 | 모델은 기존 부품의 순서와 데이터 참조를 출력합니다. 새 디자인과 내용은 만들지 않았습니다. | 모델이 HTML/CSS와 일부 설명 문구를 작성했습니다. 시각 검토 후 수정할 영역이 남았습니다. |

시각 평가는 이 한 쌍의 전체 페이지와 모바일 캡처를 검토한 관찰입니다. 구조화 부품은 미리 사람이 설계하고 검증했습니다. 자유 생성은 첫 출력이며 수동 수정이나 재생성 없이 비교했습니다. 특정 방식의 평균 품질·성공률을 증명하는 결과로 해석할 수는 없습니다.

## 실행 조건과 한계

같은 가상 데이터와 claude-opus-5로 각각 한 번 생성했습니다. 구조화는 기존 테마의 섹션 순서만 선택하며 자유 생성은 HTML/CSS·문구를 작성합니다. 구조화 부품의 사전 개발 비용은 모델 호출 비용에서 제외됐습니다. CLI 보고 추정 비용은 구독 청구액과 다릅니다. 캐시 상태와 요청 길이도 달라 일반적인 속도·비용 우위를 확정하는 벤치마크로 해석하지 않습니다.

제품의 AiPageGenerator와 소독·검토를 사용하되, 이번 호출은 공통 Opus 모델·useKit=false입니다. 제품 PageService의 Sonnet·키트 설정과는 별도의 통제 조건입니다. 두 결과는 같은 시스템 서체와 제공 이미지로 렌더링하고 배치·문구를 수동 수정하지 않았습니다. 실제 CV와 제품 DB를 사용하지 않았습니다.

## 개발 방향

다음에는 큰 이미지가 있는 사례 상세, 프로젝트별 근거 목록, 단계형 설명을 구조화 컴포넌트의 변형으로 추가할 것을 권합니다. 서로 다른 완성 지면을 만들 수 있는 선택지를 확보한 뒤, 같은 모델과 여러 가상 입력으로 반복 비교해 생성 방식을 결정하는 것이 적절합니다.

## 재현과 근거

- 실행 화면: [비교 문서](../portfolio-generation-comparison.html)
- 공통 입력과 원본 요청·응답: `docs/library/previews/comparison/`

생성기는 저장된 결과를 덮어쓰지 않습니다. 새로운 독립 표본이 필요하면 비교 디렉터리와 실행 ID를 먼저 분리해야 합니다.
