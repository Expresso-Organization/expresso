# 커리어 기록 편집기 구현 현황과 완성 계획

작성일: 2026-10-28
기준 커밋: `origin/main` `54e0c87b`
기준 문서: [노션형 커리어 기록 편집기 설계](career-record-editor-design.md),
[구현 계획](career-record-editor-implementation-plan.md)

이 문서는 커리어 기록 편집기가 설계 문서의 완료 경계에 얼마나 와 있는지 기록합니다.
코드를 읽은 결과와 실제 화면에서 확인한 결과를 구분해 적습니다. 마지막 절은 남은
작업을 의존 순서대로 정리합니다.

## 확인 방법

- `origin/main`을 읽기 전용 워크트리로 받아 웹 · 백엔드 · `packages/editor`를 읽었습니다.
- 같은 커밋으로 웹(3150) · API(4150) · Worker를 띄웠습니다. DB는 빈 검증용
  `expresso_career_audit`를 쓰고 `pnpm db:migrate`를 적용했습니다.
- AI 제안은 `CAREER_AI_DETERMINISTIC_TEST=true`로 결정적 어댑터를 써서 확인했습니다.
  실제 AI 공급자 경로는 확인하지 않았습니다.
- 저장 결과는 화면 새로고침과 MongoDB 직접 조회로 확인했습니다.

## 기준

「노션 수준」의 범위는 설계 문서의 포함 범위로 정합니다. 프로젝트가 승인한 노션형
정의가 이것뿐이기 때문입니다. 설계 문서가 비범위로 둔 노션 기능은 마지막 절에 따로
적고 완성도 계산에 넣지 않습니다.

| 영역 | 설계 문서 근거 | 가중치 |
| --- | --- | ---: |
| A. 블록 본문 편집 | 초기 블록 집합 11종, 편집 동작 7항목 | 25 |
| B. 저장 · 동기화 · 전환 | 저장 모델, 동시성 · 오류 처리, 기존 기록 전환 | 15 |
| C. 속성 | 속성 모델, 속성 삭제 영향 확인 | 15 |
| D. 저장된 뷰 | 다섯 뷰, 필터 tree, 다중 정렬, 그룹 | 20 |
| E. 관계 · 수식 · 롤업 | 관계형 속성, 수식과 롤업 | 10 |
| F. AI 협업 | 사용자와 AI의 편집 협업 | 10 |
| G. 편집 화면 · 반응형 · 접근성 | 편집 화면, Web과 접근성 검증 | 5 |

## 완성도

| 영역 | 가중치 | 달성률 | 점수 |
| --- | ---: | ---: | ---: |
| A. 블록 본문 편집 | 25 | 50% | 12.5 |
| B. 저장 · 동기화 · 전환 | 15 | 55% | 8.3 |
| C. 속성 | 15 | 80% | 12.0 |
| D. 저장된 뷰 | 20 | 45% | 9.0 |
| E. 관계 · 수식 · 롤업 | 10 | 75% | 7.5 |
| F. AI 협업 | 10 | 70% | 7.0 |
| G. 편집 화면 · 반응형 · 접근성 | 5 | 50% | 2.5 |
| **합계** | **100** | | **약 59%** |

달성률의 근거는 다음과 같습니다.

- A: 블록 11종 중 작성과 왕복 저장이 되는 것은 7종입니다. 편집 동작 7항목의 평균
  충족도는 약 64%입니다. 데이터 손상 결함 2건(표 · 줄바꿈)이 있어 50%로 낮췄습니다.
- B: 스냅샷 · 업데이트 원장, WebSocket 세션, 재전송, 이력 API, 전환 스크립트는
  동작합니다. 본문 병합, `bodyMd` 투영, 원격 변경 반영이 빠져 55%로 봤습니다.
- D: 테이블 90%, 갤러리 80%, 목록 60%, 보드 30%, 타임라인 20%입니다. 여러 뷰 관리와
  필터 · 정렬 화면이 10–30%라 45%로 봤습니다.

완료 판정 항목(설계 문서 「완료 기준」)으로 보면, 「표시 전용 버튼이 실제 동작」과
「새로고침 뒤 같은 상태 복원」 두 항목이 아직 충족되지 않습니다.

## 추가 구현이 필요한 기능

있지만 설계 기준에 못 미치거나 결함이 있는 기능입니다. 결함은 위험도 순으로 둡니다.

### 데이터 손상 · 화면 중단

| 결함 | 재현 | 원인 |
| --- | --- | --- |
| 표가 든 기록을 다시 열면 탭이 멈춤 | 슬래시 메뉴 「표」 삽입 → 새로고침 → 기록 열기 | 슬래시 메뉴가 머리글 행 표를 넣습니다([SlashMenu.tsx:17](../../services/web/src/features/career-editor/editor/SlashMenu.tsx)). 저장 변환이 `tableHeader`를 알 수 없는 블록 타입으로 저장합니다([extensions.ts:168](../../services/web/src/features/career-editor/editor/extensions.ts)). 다시 열 때 호환 블록이 `tableRow` 안에 들어가 ProseMirror 스키마 검사(`Invalid content for node tableRow`)에 걸립니다. |
| 줄바꿈이 새로고침 뒤 사라짐 | `Shift+Enter` 입력 → 새로고침 | `hardBreak`가 문단의 자식 블록으로 저장되고 위치를 잃습니다. 읽을 때 문단은 `text`만 써서 줄바꿈이 빠집니다. |
| 밑줄 단축키가 예외를 던짐 | 글자 선택 → `Cmd+U` | StarterKit이 `underline`을 켜지만 계약의 mark는 5종뿐입니다([document.ts:21](../../packages/editor/src/document.ts)). |
| AI 적용 결과가 열린 편집기에 반영되지 않음 | 제안 적용 → 본문 그대로 → 새로고침하면 반영 | 서버는 적용 뒤 `update` 프레임을 보냅니다([socket.ts:53](../../services/backend/src/modules/career-editor/socket.ts)). 클라이언트가 이 프레임을 합친 결과에 AI 문서가 남지 않습니다. 문서 전체를 Map 키 하나에 쓰는 구조에서 동시 쓰기 판정에 AI 쪽이 진 것으로 추정합니다. 원인은 확정하지 않았습니다. 이 상태에서 입력을 계속하면 문서 전체를 보내므로 AI 변경을 덮어씁니다. |

위 세 결함의 공통 원인은 Tiptap 스키마와 `CareerDocument` 변환을 손으로 따로
유지하는 구조입니다. Tiptap의 모든 노드와 mark를 왕복시키는 시험이 없습니다.

### 저장 · 동기화

- **본문 병합이 아닙니다.** Yjs 문서는 JSON 문자열 하나를 Map 키 하나에 씁니다
  ([yjs.ts:22](../../packages/editor/src/yjs.ts)). 두 작성자가 동시에 쓰면 한쪽 문서
  전체가 남습니다. 설계 문서의 「본문은 Yjs로 병합」을 충족하지 않습니다. 코드로
  확인했고 동시 편집 화면 시험은 하지 않았습니다.
- **입력마다 문서 전체를 보냅니다.** 키 입력마다 전체 JSON 업데이트를 만들고
  누적 업데이트를 다시 적용합니다([CareerEditorSession.ts:84](../../services/web/src/features/career-editor/session/CareerEditorSession.ts)).
  짧은 문서 하나에 업데이트 36건, 약 49KB가 쌓였습니다. 설계의 「입력 burst가 끝난
  뒤 전송」이 없습니다.
- **새 본문이 `bodyMd`에 반영되지 않습니다.** 편집 저장은 `documentVersion`만
  올립니다. 단건 조회만 문서를 Markdown으로 투영합니다. 목록 미리보기, 공고 매칭
  텍스트([record-text.ts:28](../../services/backend/src/modules/career/record-text.ts)),
  포트폴리오 생성, 인터뷰는 저장된 `bodyMd`를 읽습니다. 새 편집기에 쓴 본문은 이
  기능들에 전달되지 않습니다. 검증 DB에서 본문을 쓴 기록의 `bodyMd`는 빈 문자열이었습니다.
- **Markdown 투영 품질.** 목록 · 표 등은 `expresso-block` JSON 코드 블록으로
  직렬화됩니다([markdown.ts:88](../../packages/editor/src/markdown.ts)). 인라인 서식도
  빠집니다.

### 블록 편집 동작

- 슬래시 메뉴: 입력으로 거르지 못하고 커서 위치에 뜨지 않습니다. 제목은 1만 있고
  제목 2 · 3, 콜아웃, 이미지 · 파일, 근거 참조가 없습니다.
- 블록 손잡이: 본문 위 고정 툴바에 추가 · 복제 · 삭제만 있습니다. 끌어 옮기기,
  위 · 아래 이동, 타입 변환이 없습니다.
- 선택 툴바: 선택 위에 뜨지 않는 고정 툴바입니다. 링크는 `window.prompt`로 받습니다.
- 붙여넣기 정리는 `script` · `style` · `iframe` 정규식 제거뿐입니다. 설계의 allowlist가 아닙니다.

### 뷰

- 첫 번째 저장 뷰만 불러옵니다([page.tsx:88](<../../services/web/src/app/(app)/career/[categorySlug]/page.tsx>)).
  뷰 탭은 같은 뷰의 종류를 바꿀 뿐입니다.
- 「＋ 뷰 추가」는 뷰를 복제하고 「뷰를 복제했습니다」만 띄웁니다. 새 뷰로 갈 방법이
  없습니다. 뷰 이름 변경 · 삭제 · 순서 변경 화면이 없습니다. 순서 변경 API는 있습니다.
- 필터 화면은 속성 하나의 「값 있음」만 고릅니다. 정렬은 한 키뿐입니다. 백엔드는
  AND/OR 필터 tree와 다중 정렬을 지원합니다. 그룹 순서는 쉼표 텍스트 입력입니다.
- 보드: 끌어 옮기기가 없고 ← · → 단추에 동작이 없습니다. 그룹 머리에 `draft` 같은
  내부 값이 그대로 보입니다. 기록이 없는 그룹 열이 나오지 않습니다.
- 타임라인: 시간 축이 없는 세로 목록입니다. 기본 경험 카테고리에서 시작 날짜 속성이
  잡히지 않아 「날짜 없음」으로 나옵니다. ← · → 단추에 동작이 없습니다.
- 목록 · 갤러리 미리보기는 `bodyMd`를 읽어 본문을 쓴 기록도 「내용을 채워 주세요」로 보입니다.
- 패널에서 제목을 바꾸면 왼쪽 표 행은 새로고침 전까지 옛 제목을 보여 줍니다.
- 새로 만든 속성이 테이블 열에 나타나지 않습니다.
- 카테고리 안 검색 입력이 없습니다. 주소의 `q`만 읽습니다.

### 속성 · 계산

- 수식 편집기는 속성을 `prop("UUID")` 원문으로 넣고 보여 줍니다([FormulaEditor.tsx:42](../../services/web/src/features/career-editor/properties/FormulaEditor.tsx)).
- 수식 저장 직후 패널 값은 「비어 있음」이고 새로고침해야 계산값이 보입니다.
- 계약에 있는 `created_time` · `updated_time`을 속성 추가 메뉴에서 고를 수 없습니다.
- 속성 추가 목록이 화면 아래로 넘쳐 관계 · 수식 · 롤업이 채팅 입력란 뒤에 가립니다.

### 편집 화면 · 반응형

- 375px에서 필터 · 정렬 · 속성 · 새로 만들기 단추 글자가 두 줄로 꺾입니다.
- 머리말의 「공유」, 시계 아이콘, 「…」과 사이드바 「카테고리 추가」는 동작이 없습니다.
- 기록이 하나도 없는 카테고리에서 「조건에 맞는 기록이 없습니다」와 「전체 기록 보기」가
  나옵니다. 필터가 없는데 필터 결과 문구가 나옵니다.

## 완성 계획

순서는 의존 관계를 따릅니다. 각 단계는 구현 계획의 Task 번호를 함께 적습니다.

### 0단계 — 데이터 손상 · 중단 결함 (Task 8 보완)

1. Tiptap 스키마의 모든 노드 · mark를 `CareerDocument`로 왕복시키는 시험을 먼저 만듭니다.
   표 머리글, 줄바꿈, 밑줄, 중첩 목록, 표 셀 안 문단을 포함합니다.
2. `tableHeader`를 블록 타입에 추가하고 변환합니다.
3. 줄바꿈을 인라인으로 보존합니다. 텍스트 span 안 `\n` 또는 인라인 노드 중 하나로 정합니다.
4. mark 집합과 Tiptap 확장을 맞춥니다. `underline`을 계약에 넣거나 확장에서 끕니다.
5. 이미 `tableHeader` · `hardBreak`가 저장된 문서를 여는 복구 경로를 둡니다.

완료 확인: 표 · 줄바꿈 · 밑줄을 쓴 기록이 새로고침 뒤 같은 모양으로 열립니다.

### 1단계 — 본문 원본 일원화 (Task 5 · 6 · 7 보완)

A. 본문을 소비하는 기능에 새 본문을 전달합니다.

- 문서 저장 확정 시 `bodyMd`를 같은 트랜잭션에서 투영하거나, `careerRecordText`가
  문서를 읽게 바꿉니다. 둘 중 하나로 원본을 정합니다.
- Markdown 직렬화가 목록 · 서식 · 표를 Markdown 그대로 쓰게 합니다.
- 완료 확인: 새 편집기에서 쓴 본문이 목록 미리보기, 공고 매칭, 포트폴리오 생성 입력에 나옵니다.

B. 동시 편집 구조를 결정합니다. 사용자 결정이 필요합니다.

- 선택지 1: `y-prosemirror`로 블록 · 글자 단위 Yjs 병합을 구현합니다. 설계 문서와 일치합니다.
- 선택지 2: 작성자 한 명 + 버전 조건부 저장으로 설계를 낮춥니다. AI 변경은 제안 적용만
  허용합니다. 설계 문서의 동시성 절을 고칩니다.
- 열린 Spring 전환 스택(#71–#76)이 같은 쓰기 경로를 다루므로 함께 정합니다.

C. 원격 변경 반영과 전송 단위를 고칩니다.

- AI 적용 · 다른 탭의 변경이 열린 편집기에 반영됩니다.
- 입력 burst 뒤 전송하고 증분 업데이트만 보냅니다.

### 2단계 — 블록 편집 (Task 8)

- 슬래시 메뉴: 입력 필터, 커서 위치, 제목 2 · 3, 콜아웃, 이미지 · 파일, 근거 참조.
- 이미지 · 파일 업로드를 기존 media 계약에 연결합니다.
- 블록 손잡이: 호버 표시, 끌어 옮기기, 위 · 아래 이동, 타입 변환.
- 선택 위에 뜨는 서식 툴바와 링크 입력 팝오버.
- 붙여넣기 HTML allowlist.

### 3단계 — 뷰 (Task 11 · 12)

- 여러 뷰 탭: 만들기 · 전환 · 이름 변경 · 삭제 · 순서 변경.
- 필터 tree와 다중 정렬 화면. 그룹 순서를 끌어 옮기기로 정합니다.
- 보드: 카드 끌어 옮기기로 그룹 값 변경, 빈 그룹 열, 상태 표시 이름.
- 타임라인: 시작 · 종료 날짜로 시간 축 배치, 기본 날짜 속성 지정.
- 목록 · 갤러리 미리보기를 문서에서 읽습니다(1단계 A 이후).
- 패널 편집을 뷰 행에 바로 반영합니다. 새 속성을 표시 속성에 넣습니다.
- 카테고리 안 검색.

### 4단계 — 속성 · 계산 (Task 10 · 16)

- 수식 편집기에서 속성을 이름 토큰으로 보이고 저장은 UUID로 합니다.
- 저장 · 계산 완료 시 패널 값을 갱신합니다.
- 생성 · 수정 시각 속성을 메뉴에 노출합니다.
- 속성 추가 목록이 화면 안에 들어오게 배치합니다.

### 5단계 — 기록 관리 화면 (Task 5 · 13)

- 변경 이력 보기와 복원. 머리말 시계 아이콘에 연결합니다.
- 휴지통과 기록 복원.
- 사이드바 「카테고리 추가」를 기존 API에 연결합니다.
- 동작이 없는 「공유」 · 「…」은 연결하거나 지웁니다.
- 기록 0건 카테고리의 첫 화면.

### 6단계 — 반응형 · 회귀 시험 · 출시 게이트 (Task 18)

- 375 · 768 · 1280 · 1440px 화면을 맞춥니다.
- 이 문서의 결함마다 Playwright 회귀 시험을 둡니다.
- [출시 체크리스트](../operations/CAREER_EDITOR_RELEASE_CHECKLIST.md)의 게이트를 다시 돌립니다.
  2026-09-01 게이트는 이 문서의 결함 경로를 다루지 않았습니다.

## 계산에서 뺀 노션 기능

설계 문서가 비범위로 두었거나 언급하지 않은 기능입니다. 범위에 넣으면 완성도는 더 낮아집니다.

- 토글 블록, 다단 레이아웃, 동기화 블록, 임베드
- 페이지 안 하위 페이지, `@` 멘션과 백링크
- 블록 댓글
- 페이지 아이콘 · 표지
- 기록 템플릿
- 여러 사용자의 실시간 공동 편집
- 노션 가져오기 · 내보내기
