# 공고 적합도 cross-encoder v1

## 결정

Expresso의 추천 모델은 사용자의 합격 확률을 예측하지 않는다. 공고가 요구하는 내용과 현재
프로필에 기록된 경력 근거가 얼마나 부합하는지를 `matchScore` 하나로 0~100 사이에서
출력한다. 별도의 확률이나 두 번째 점수는 사용자에게 보여주지 않는다.

운영 경로는 다음으로 고정한다.

```text
신규 공고 수집
  -> LLM으로 요구사항 1회 분해
  -> 공고 원문·요구사항 저장과 캐시
  -> E5로 사용자별 후보 공고 Top-K 검색
  -> 관련 프로필 기록 선택
  -> cross-encoder로 0~100 적합도 재랭킹
```

LLM은 새 공고가 들어올 때 한 번만 사용한다. 프로필–공고 적합도 한 건을 계산할 때마다 LLM을
호출하지 않는다. 원문 해시, 분해 프롬프트 버전, 모델 버전이 같으면 저장된 요구사항을 다시
사용한다.

## 선행 조건

현재 30개 합성 프로필과 600개 합성 라벨은 모델 코드가 실행되는지 확인한 파일럿일 뿐이다.
cross-encoder 방향으로 확장하기 전에
[`synthetic-profile-generation-v4.md`](./synthetic-profile-generation-v4.md)의 청년패널 기반
경력 골격, 정규분포 기록 수, 본문 중심·희소 프로퍼티 규칙을 먼저 구현한다.

첫 학습 시작 조건은 다음과 같다.

- 합성 프로필 500개 이상
- 한국어 경력 기록 2,000건 이상
- 공고–프로필 또는 요건–근거 학습 쌍 10,000건 이상
- 사람 검수 적합도 사례 100건 이상
- hard negative 비율 30~50%
- profile family, 공고 군집, 원천 답변 군집의 split 누수 0건

30개 보강 배치와 600쌍은 데이터·모델 계약을 확인하는 개발 세트로는 계속 사용하되 성능 결론의
근거로 사용하지 않는다.

## 공고 요구사항 분해

공고 분해기는 자유로운 요약문이 아니라 다음 구조를 반환한다.

| 필드 | 의미 |
| --- | --- |
| `kind` | `must`, `preferred`, `responsibility`, `condition` |
| `quote` | 원문에서 그대로 보존한 근거 구절 |
| `normalizedText` | 비교에 사용할 짧은 정규화 문장 |
| `concepts` | 직무·기술·산업 개념 ID |
| `minimumYears` | 원문에 명시된 경우의 최소 연차 |
| `evidenceType` | 경력, 프로젝트, 학력, 자격, 활동 등 필요한 기록 종류 |
| `confidence` | 분해기의 구조화 신뢰도 |

원문에 없는 필수 조건이나 연차를 추론해 추가하지 않는다. `must`와 `preferred`를 구분할 수
없으면 `responsibility`로 낮추고 원문을 보존한다. 분해 실패 공고는 원문만 사용하는 기준선에는
남기되 cross-encoder 학습·평가에서는 별도 slice로 보고한다.

## 모델 입력

프로필 전체를 한 문자열로 이어 붙이지 않는다. 기록별 E5 임베딩을 캐시하고 각 요구사항과 가까운
기록을 고른 뒤 중복을 제거해 최대 8개만 cross-encoder 입력에 넣는다. 필수 요건과 연결된
기록을 먼저 배치하고, 남는 자리에 우대 요건·책임과 관련된 기록을 넣는다.

```text
[공고 원문]
...

[분해된 필수·우대·책임]
MUST | ...
PREFERRED | ...
RESPONSIBILITY | ...

[선택된 사용자 기록]
category | title
bodyMd
basic properties
...
```

추천 입력에는 `title`, `bodyMd`, 허용된 기본 `properties`만 쓴다. 원천 ID, provenance,
사람 검수 상태, 합성 여부, profile family ID는 넣지 않는다. 기록이 없거나 적은 사용자도
유효하며, 없는 근거를 빈 문자열이나 가상 기록으로 채우지 않는다.

첫 후보 모델은 다국어 `BAAI/bge-reranker-v2-m3`다. 최대 입력 길이는 1,536 token으로
시작하되, 긴 프로필은 기록 선택으로 제어한다. 더 작은 다국어 MiniLM은 지연 기준선으로 유지한다.

## 출력과 학습 목표

모델의 외부 계약은 다음 하나다.

```json
{"matchScore": 74}
```

`matchScore`는 현재 기록으로 공고 요건을 뒷받침하는 정도다. 채용 시장 경쟁, 회사의 숨은 기준,
지원자 수, 면접 결과를 반영하지 않으므로 합격 확률이 아니다.

교사 LLM은 같은 정의로 0~100 정수 라벨을 만든다. 내부 학습은 점수 회귀 손실과 같은 사용자
후보군 안의 pairwise ranking 손실을 함께 사용할 수 있지만, 제품에는 보정된 단일 점수만
내보낸다. 0~3 라벨을 0~100으로 단순 선형 변환하지 않고 새 rubric으로 다시 라벨링한다.

점수 기준은 다음 anchor로 고정한다.

| 구간 | 의미 |
| --- | --- |
| 0~19 | 기록된 근거가 거의 없거나 핵심 직무가 다름 |
| 20~39 | 주변 경험은 있으나 주요 요구를 직접 뒷받침하지 못함 |
| 40~59 | 일부 주요 요구에 근거가 있으나 중요한 공백이 큼 |
| 60~79 | 다수의 주요 요구를 직접 뒷받침하고 공백이 제한적임 |
| 80~100 | 필수 요구와 핵심 책임 대부분에 강하고 구체적인 근거가 있음 |

빈약한 프로필은 리젝하지 않는다. 모델은 관측되지 않은 역량을 없다고 단정하는 대신 “현재
기록으로 확인되는 적합도”를 낮게 산출한다. 사람 검수 화면에서도 같은 정의를 사용한다.

## RTX 5080 비용 검토

현재 30개 합성 프로필과 공고로 만든 600쌍을 RTX 5080 16GB에서 측정했다. 입력은 프로필,
공고 원문, 요구사항 view를 합친 것이며 token 길이는 중앙값 943, 95백분위 1,244,
최댓값 1,385였다.

| 모델 | 길이 | 잘림 | 추론 | 학습 | 학습 peak VRAM |
| --- | ---: | ---: | ---: | ---: | ---: |
| mMiniLMv2 0.1B | 512 | 100% | 1,787 pair/s | 225 pair/s | 1.48 GiB |
| BGE reranker v2 m3 0.6B | 512 | 100% | 195 pair/s | 33.8 pair/s | 5.30 GiB |
| BGE reranker v2 m3 0.6B | 1,024 | 36% | 95.5 pair/s | 15.9 pair/s | 5.35 GiB |
| BGE reranker v2 m3 0.6B | 1,536 | 0% | 88.2 pair/s | 11.5 pair/s | 5.33 GiB |

이 측정에서 BGE 1,536 token은 GPU forward만 계산하면 600쌍에 약 6.8초다. tokenization,
큐 대기, 네트워크, 평가, checkpoint 저장은 포함하지 않았다. 현재 합성 프로필이 실제 장기
사용자보다 짧으므로, v4의 긴 프로필에서 기록 선택 이후 token 분포를 다시 측정해야 한다.

처리량만 선형 환산하면 10,000쌍 3 epoch는 약 43분, 30,000쌍 3 epoch는 약 2.2시간,
100,000쌍 3 epoch는 약 7.2시간이다. 이는 순수 학습 step 하한이며 전체 실험 시간에는 검증과
저장이 더해진다. 5080 한 장에서 파일럿과 수만 쌍 학습은 현실적이지만, 모든 공고를 모든
사용자와 cross-encoder로 비교하는 구조는 피한다.

## 운영 비용 제어

- 공고 요구사항 분해는 공고 버전당 LLM 1회로 제한하고 결과를 영구 캐시한다.
- 공고·기록 E5 임베딩은 내용 해시와 encoder revision을 키로 캐시한다.
- cross-encoder는 E5 Top-K에만 적용하며 기본 `K=50`, 품질 비교용 상한 `K=100`으로 둔다.
- 프로필 입력은 요구사항별 상위 기록의 합집합 최대 8개로 제한한다.
- 같은 사용자·공고·프로필 버전·모델 버전 조합의 점수를 캐시한다.
- 새 기록, 공고 버전, 모델 버전이 바뀔 때만 관련 점수를 무효화한다.

온라인 SLO는 애플리케이션 경로에서 다시 측정한다. GPU forward 처리량을 API 응답 지연으로
간주하지 않는다.

## 평가

기준선과 cross-encoder는 같은 공고 후보군, 같은 split, 같은 0~100 라벨을 사용한다.

- 순위 품질: NDCG@10, MAP, Recall@10, MRR@10, pairwise accuracy
- 점수 품질: MAE, Spearman correlation, calibration error
- 검색 분리: E5 후보군 recall과 cross-encoder 재랭킹 개선량
- 사용자 상태: 0건, 1~2건, 3~8건, 9건 이상 기록 slice
- 입력 길이: token 길이와 잘림 비율 slice
- 비용: 공고 분해 호출 수, tokenization 포함 latency, pair/s, peak VRAM

최소 성공 조건은 사람 라벨 기준으로 TF-IDF/BM25와 고정 E5 cosine보다 NDCG@10이 높고,
동시에 MAE와 온라인 지연 예산을 통과하는 것이다. 합성 교사 라벨에서만 이긴 결과는 배포 근거로
사용하지 않는다.

## 구현 순서

1. 합성 프로필 v4와 0~100 교사 rubric을 확정한다.
2. 30개 보강 배치로 기록 선택과 1,536 token 입력 계약을 검증한다.
3. 프로필 500개, 학습 쌍 10,000개, 사람 라벨 100개를 만든다.
4. TF-IDF/BM25/E5 기준선을 같은 0~100 계약으로 다시 실행한다.
5. BGE cross-encoder를 회귀+순위 손실로 학습하고 score를 보정한다.
6. 긴 프로필, 빈 프로필, hard negative에서 오류를 분석한다.
7. Top-K와 최대 기록 수를 품질·지연 곡선으로 결정한다.
