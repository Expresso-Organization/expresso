# 합성 프로필 생성 v4

## 결정

다음 합성 프로필 배치부터 AI Hub 면접 답변만 묶어 한 사람을 만들지 않는다. 고용조사분석시스템
청년패널조사(YP2021)로 교육·취업·이직·훈련·자격의 경력 골격을 만들고, AI Hub 71592는
실제 경험을 한국어로 표현하는 서술 재료로 사용한다. LLM 렌더러는 완성된 경력 골격을
Expresso의 제목·프로퍼티·본문 기록으로만 바꾼다. 골격과 사실을 새로 판단하거나 보충하지
않는다.

생성 단계와 추천 모델 학습 단계는 분리한다. LLM은 합성 프로필과 교사 라벨을 만드는 오프라인
작업에 사용하되, 운영 적합도 추론에는 사용하지 않는다.

## 현재 데이터 진단

### 기존 Luna v3 배치

현재 30개 프로필은 AI Hub 답변 조각만 사용해 109개 기록을 만들었다. 프로필당 기록 수는
평균 3.63개, 표준편차 1.30개, 범위 1~6개다. 기록 하나에 들어간 프로퍼티는 평균 2.06개이며
109개 중 프로퍼티가 빈 기록은 4개뿐이다. 기록 본문 길이는 평균 121자, 범위 55~177자다.

이 분포에는 다음 문제가 있다.

- 모든 프로필이 짧아 가변 길이 입력과 긴 프로필의 기록 선택 문제를 시험하지 못한다.
- 프로퍼티가 지나치게 잘 정리되어 실제 사용자가 노션처럼 기록하는 모습과 다르다.
- 서로 다른 면접 답변을 한 사람의 이력으로 묶기 때문에 시간 순서와 인물 일관성이 약하다.
- AI Hub 직군과 질문 유형이 프로필 구성까지 결정해 원천 데이터 편향이 그대로 남는다.

## YP2021 활용 경계

YP2021은 한 응답자의 행을 그대로 자연어 프로필로 바꾸는 원천이 아니다. 다음 집계와 조건부
분포만 생성기에 제공한다.

- 최종 학력과 재학 상태에서 첫 일자리로 이어지는 전이
- 일자리 시작·종료, 재직·퇴직·이직의 시간 간격
- 산업과 직업 대분류의 결합 분포
- 경력 단계별 일자리·훈련·자격 사건 수
- 교육훈련 분야·기간과 자격 취득의 조건부 빈도
- 재학 중 일자리와 졸업 후 일자리의 구분

공개 빈도가 작은 조합은 그대로 사용하지 않는다. 최소 20명 이상의 셀만 조건부 분포로
게시하고, 그보다 작은 셀은 상위 직업·산업 분류나 전체 주변 분포로 후퇴한다. 하나의 합성
프로필이 특정 `sampid`의 전체 궤적을 복제하지 않도록 집계 전이표에서 새로운 사건 순서를
샘플링한다. 날짜는 프로필 안의 간격만 보존해 공통 오프셋으로 이동한다.

다음 필드는 원자료 결합과 분포 감사에만 쓰며 렌더러 입력, 합성 기록, 추천 특징에 넣지 않는다.

- `sampid`, `hid`와 원본 행 번호
- 성별, 출생 연월, 나이
- 시도·시군구 등 거주·근무 지역의 세부 위치
- 가구, 부모, 배우자, 건강과 그 밖의 가족 정보
- 임금, 소득, 자산, 부채와 지출
- 조사 가중치와 참여·탈락 상태

조사 가중치는 표본 분포를 모집단에 맞춰야 할 때 샘플러의 확률 보정에만 사용한다. 추천
모델이 읽는 값이 아니다.

## 생성 구조

### 1. 분포 프로파일

원자료에서 허용 변수와 특수 결측 코드를 명시한 버전형 프로파일을 만든다. 조사차수별 스키마가
다르므로 열 이름을 문자열 치환으로 맞추지 않고, 변수 라벨과 수동 매핑표로 같은 개념을
연결한다. 프로파일에는 행 수, 참여자 수, 결측률, 값 범위, 빈도, 최소 셀 크기와 원본
SHA-256을 기록한다.

### 2. 잠재 경력 골격

결정적 seed를 사용해 다음 중 존재하는 사건만 시간 순서대로 만든다.

- `education_history`: 학력 과정과 전공 계열
- `experience`: 재학 중 일자리, 현재·과거 일자리, 이직
- `certification_award`: 자격 취득
- `activity_leadership`: 직업교육훈련과 구직 과정의 실제 활동

YP2021에 직접 근거가 없는 프로젝트, 학술·집필, 수상, 구체적 기술은 이 단계에서 만들지
않는다. 이 네 카테고리는 AI Hub 근거 또는 별도 공개 원천이 있을 때만 뒤 단계에서 추가한다.
다만 재직 골격이 있는 합성 인물에는 직무 도메인의 일반 도구 사용 기록을 한 건 후보로 넣는다.
직종 분포는 YP2021 집계에 연결하고 실제 도구 사용 여부는 `syntheticFields: ["tool_usage"]`로
명시해 조사 사실로 오인하지 않게 한다. 기록 수가 짧으면 이 후보는 잘려 나갈 수 있다.

### 3. 서술 재료 배치

AI Hub 답변은 직군, 경력 단계, 사건 유형이 맞는 골격에만 배치한다. 하나의 답변을 그대로
복사하지 않고 상황·행동·결과 중 실제 답변이 제공하는 부분을 서술 제약으로 사용한다. 서로
모순되는 답변을 같은 프로필에 넣지 않으며, 같은 답변 atom을 train·valid·test의 서로 다른
프로필에 재사용하지 않는다. 직군별 원천량이 부족하면 다른 직군 답변으로 대체하지 않고 같은
split 안에서 같은 직군 atom을 제한적으로 다시 사용한다. 3,000개 배치에서 atom당 사용 상한은
3회이며, 원천 답변 family도 하나의 split에만 속한다.

### 4. LLM 렌더링

렌더러 입력은 한 사람의 완성된 잠재 골격, 기록별 서술 제약, 목표 기록 수, 본문 스타일과
프로퍼티 예산으로 제한한다. v4.2는 기록 하나를 호출 하나로 생성하고 코드가 프로필을 조립한다.
재시도도 실패한 기록에만 적용한다. 프로필 평균 길이 오류는 대상 기록의 교정 프롬프트에도
전달해 장문이 실제로 확장되게 한다. 사실 골격 생성과 문장 렌더링을 분리하고 짧은 컨텍스트를
사용해 호출당 판단 범위와 실패 비용을 줄인다.

렌더러가 지켜야 할 형식은 프롬프트 설명에만 맡기지 않는다. v4와 v4.1은 입력마다 기록 순서,
카테고리, 프로퍼티 키를 고정한 JSON Schema를 구조화 출력에 전달한다. v4.2 장문 생성은
Ollama의 엄격한 PEG 스키마가 유효 객체 뒤에서 토큰을 소진하며 HTTP 500을 내는 현상을 확인해
일반 JSON 모드와 코드 검증을 사용한다. 각 기록 입력의 `outputContract`에 고정 ID·카테고리·
프로퍼티를 명시하고, 구조 검증을 통과한 초안만 Expresso 프로필 객체로 조립한다.

v4.2부터 사실 골격과 창작 세부는 출력 필드도 분리한다. 입력 사건마다 코드가 `facts`를
`skeletonLead`로 고정하고, LLM은 숫자를 포함하지 않는 `detailMd`만 생성한다. 조립기가
`skeletonLead + detailMd`를 최종 `bodyMd`로 만든 뒤 `detailMd`는 버린다. 따라서 모델이 긴
본문을 쓰는 동안 조사에서 온 날짜·기간·개수·핵심 행동을 누락하거나 바꿀 수 없다. 사건별
길이 목표는 다양한 기록을 유도하는 생성 가이드이고, 자동 합격 여부는 기록 안전 상한과 프로필
전체 평균으로 판단한다.

각 호출의 `outputContract.detailLength`에는 골격 길이를 제외한 `detailMd` 전용 최소·목표·최대
글자 수를 전달한다. 프로필 평균 또는 길이 구간 오류가 발생하면 해당 오류를 모든 대상 기록의
교정 프롬프트에 전달해 짧은 출력을 실제로 늘리거나 경계 안으로 줄인다.

렌더러 인터페이스는 Qwen과 Luna가 같은 입력 계약을 사용하도록 분리한다. Qwen은 로컬 대량
생성 후보, Luna는 품질 기준과 어려운 샘플의 보정 후보로 둔다. 모델별 전용 프롬프트로 사실
범위를 바꾸지 않고, 동일 입력·동일 출력 계약에서만 품질을 비교한다.

## 렌더러 파일럿 결과

2026-09-02에 기록 수 5·9·14개의 동일한 세 골격, 총 28개 기록을 Qwen3 30B-A3B
Instruct Q4와 Luna에 각각 입력했다. 두 렌더러 모두 최종 스키마 통과율과 기록 완성률은
100%였고, 예정한 프로퍼티 분포 0개 18건·1개 8건·2개 2건을 정확히 지켰다. 입력에 없는
숫자와 중복 기록도 없었다.

| 지표 | Qwen | Luna |
| --- | ---: | ---: |
| 사실 토큰 보존율 | 0.7999 | 0.8761 |
| 이력서식 성과·효과 표현 감지 | 9건 | 0건 |
| 평균 본문 길이 | 85.13자 | 105.12자 |
| 로컬 생성 시간 | 63.44초 | 측정하지 않음 |

Qwen은 Windows RTX 5080의 Ollama에서 총 3,469 출력 토큰을 63.44초에 생성했다. Luna는
같은 로컬 추론 경로로 실행하지 않았으므로 속도를 숫자로 비교하지 않는다. 구조화 출력 계약을
입력별 스키마로 강화한 뒤 Qwen도 세 프로필을 모두 첫 시도에 통과했다. 반면 본문에는 입력에
없는 `성과 유지에 기여`, `시스템 안정성 유지에 기여`, `협업 문화 강화` 같은 결과 해석이
반복됐다. Luna도 일부 연결 문장을 만들었지만 입력 사실을 더 많이 보존했고, 개인 기록에 가까운
문체를 유지했다.

이 결과만 놓고 v4의 품질 기준 렌더러는 Luna였다. Qwen을 대량 렌더러로 쓰려면 근거에 없는
효과·성취·능력 획득을 막는 별도 조치가 필요했다.

### v4.1 재실험

v4.1은 각 출력 기록을 해당 사건의 `facts`와 대조한다. 효과·성과·능력 계열 표현이 출력에만
나오면 초안을 거부하고 한 번만 다시 생성한다. 짧은 사실을 40자 이상으로 늘리면서 생긴
`취득 시점은`, `관리 대상은`, `이수 기간은` 같은 반복도 별도 게이트로 막았다. 사실이 짧은
기록은 한 문장으로 끝낼 수 있도록 본문 최솟값을 20자로 낮췄다.

같은 세 골격으로 최종 v4.1을 다시 실행한 결과는 다음과 같다. `근거 없는 주장 마커`는 의미를
완전히 판정하는 모델이 아니라, 출력 표현이 해당 사건 사실에도 존재하는지를 확인하는 보수적인
규칙 지표다. 세 렌더러 출력에 같은 규칙을 적용했다.

| 지표 | Qwen v4 | Qwen v4.1 | Luna |
| --- | ---: | ---: | ---: |
| 스키마·기록 완성률 | 100% | 100% | 100% |
| 사실 토큰 보존율 | 0.7999 | 0.8952 | 0.8761 |
| 근거 없는 주장 마커 | 57건 | 0건 | 4건 |
| 반복 메타 문구 | 0건 | 0건 | 0건 |
| 입력에 없는 숫자 | 0건 | 0건 | 0건 |
| 평균 본문 길이 | 85.13자 | 53.30자 | 105.12자 |
| 로컬 생성 시간 | 63.44초 | 54.12초 | 측정하지 않음 |

v4.1은 28개 기록을 모두 첫 시도에 생성했고, Qwen v4에서 발견된 성과 확장을 제거하면서
사실 보존율도 Luna보다 0.0191 높았다. 사람 눈으로 28개 기록을 대조했을 때도 새 성과·능력·
효과를 주장하거나 같은 사실을 반복한 문장은 없었다. Luna는 문장이 더 길고 서술적이지만,
훈련 이수에서 능력 습득을 추론하거나 도구 사용에서 작업 순서 습득을 덧붙이는 사례가 남았다.

이 재실험에서 Qwen v4.1의 평균 본문 길이는 53.30자였다. 아래에서 정의한 초기 분포로 분류하면
세 프로필 모두 `매우 짧음` 구간이다. 따라서 이 결과는 짧은 개인 메모에서 Qwen v4.1이 Luna에
비견되거나 더 엄격하게 사실을 보존한다는 근거이며, 여러 길이의 프로필 전체에 대한 품질 증명은
아니다. Qwen을 기본 대량 렌더러로 확정하기 전에 네 길이 구간을 모두 포함한 배치를 생성해
구간별 사실 보존과 자연스러움을 확인한다.

### v4.2 장문 파일럿

v4.2는 Qwen이 기록별 `detailMd`만 일반 JSON 모드로 생성하고 코드가 사실 골격, 확정
프로퍼티, 문장 단위 길이 조정을 적용한다. 엄격한 PEG 스키마로 긴 프로필 전체를 만들던 초기
시도는 한 프로필에 429.1초를 쓰고도 JSON이 중간에서 끊겼다. 기록 단위 호출로 바꾼 최종
파일럿은 네 프로필 42개 기록을 220.16초에 생성했다.

| 길이 구간 | 목표 평균 | 실제 평균 | 기록 수 | 최종 게이트 |
| --- | ---: | ---: | ---: | --- |
| 매우 짧음 | 100자 | 93.00자 | 5개 | 통과 |
| 적당히 짧음 | 220자 | 224.67자 | 9개 | 통과 |
| 적당히 김 | 380자 | 378.57자 | 14개 | 통과 |
| 매우 김 | 520자 | 516.93자 | 14개 | 통과 |

최종 42개 기록에서 골격 숫자 누락과 새 정밀 숫자, 기록 중복, 동일 문장 반복, 미완성 문장,
한자 혼입은 모두 0건이었다. 프로퍼티 값도 LLM이 정하지 않고 골격 생성기가 확정한
`propertyValues`를 조립 단계에서 덮어쓴다. 매우 짧은 기록에서는 사실 골격만으로 목표에 더
가까우면 창작 세부를 붙이지 않는다. 긴 기록은 Qwen이 충분한 세부를 먼저 생성하고, 코드는 새
숫자나 반복 골격이 든 문장을 제거한 뒤 목표 길이에 가장 가까운 완결 문장 경계를 선택한다.

이 결과로 Qwen3 30B-A3B Q4를 v4.2 대량 렌더러로 사용할 수 있다. 다만 상황·작업 순서·회고는
의도적으로 창작된 합성 세부이므로, 조사에서 확인된 사실로 해석하거나 별도 특징으로 표시하지
않는다. 사람 검수는 자동 게이트를 통과한 표본의 자연스러움과 노션형 작성 감각을 판단한다.

## 프로필 길이

초기 생성 목표는 프로필당 전체 기록 수다.

```text
targetRecordCount = clip(round(Normal(mean=9, std=4)), min=1, max=20)
```

작은 배치에서 우연히 짧은 프로필만 뽑히지 않도록 독립 난수 대신 정규분포 분위수를 균등하게
배치하고, seed로 프로필에 섞어 할당한다. 30개 배치에서는 다음 기록 수를 한 번씩 배정한다.

```text
1, 2, 3, 4, 5, 5, 6, 6, 7, 7, 7, 8, 8, 8, 9,
9, 10, 10, 10, 11, 11, 11, 12, 12, 13, 13, 14, 15, 16, 18
```

총 271개, 평균 9.03개, 표준편차 4.06개다. 이는 실제 사용자 수치를 추정한 결과가 아니라
희소 프로필과 긴 프로필을 모두 시험하기 위한 초기 학습·부하 분포다. 실제 사용자 기록 수가
쌓이면 평균과 표준편차를 실측값으로 다시 정한다. 같은 반사실 profile family는 기록 수와 문체
분포를 같게 유지해 길이가 적합도 라벨의 지름길이 되지 않게 한다.

일곱 시스템 카테고리는 객체에 모두 포함하지만 기록이 없는 카테고리를 허용한다. 기록 수를
맞추려고 같은 사건을 여러 카테고리에 복제하거나 근거 없는 프로젝트·성과를 만들지 않는다.
골격과 서술 재료가 목표 수에 미달하면 실제 생성 수를 별도로 기록하고 프로필 자체는 유지한다.

### 프로필별 평균 본문 길이

기록 수와 별개로 사람마다 기록을 쓰는 상세도가 다르도록, 프로필 하나에 `bodyLengthPlan` 하나를
배정한다. 이 값은 기록 하나의 고정 길이가 아니라 그 프로필에 포함된 모든 `bodyMd`의 평균
목표다. 평균·표준편차와 상한은 서로 독립된 설정으로 둔다. v4.2 초기 분포는 다음과 같다.

```text
targetMeanChars = clip(
  Normal(mean=300, std=160),
  min=40,
  max=800
)
recordMaxChars = 1000
```

평균과 표준편차를 기준으로 네 구간을 나눈다.

| 구간 | 평균 본문 길이 목표 |
| --- | ---: |
| 매우 짧음 (`very_short`) | 40~139자 |
| 적당히 짧음 (`moderately_short`) | 140~299자 |
| 적당히 김 (`moderately_long`) | 300~459자 |
| 매우 김 (`very_long`) | 460~800자 |

30개 배치에서는 독립 난수로 우연히 한 구간에 몰리지 않도록 정규분포의 30개 분위수를 균등하게
뽑고 seed로 프로필에 섞는다. 정렬된 목표는 다음과 같으며 네 구간에 5·10·10·5개가 배정된다.

분포 매개변수와 배정 seed는 배치 manifest에 기록한다. 목표가 구간 전체에 퍼지도록 정규분포의
분위수를 사용하지만, 정규분포 특성상 모든 배치에서 절단 상한 800자 자체가 반드시 나오지는
않는다.

이 분포는 범위 밖 표본을 다시 뽑는 통계적 절단정규가 아니라 위 수식 그대로 경계에서 자르는
`clipped-normal-v2`다. 따라서 큰 배치의 실현 표준편차는 잠재 정규분포의 160자보다 작아질 수
있다. 배치 게이트는 잠재 모수 300·160과 직접 비교하지 않고, manifest에 실제로 배정된
`targetMeanChars` 집합과 생성 결과 집합의 평균·표준편차를 비교한다.

실제 프로필 평균은 목표에서 `max(30자, 목표의 15%)` 이내여야 한다. 30자는 문장을 중간에서
자르지 않는 렌더러의 문장 경계 오차를 반영한다. 목표와 실제 평균이 구간 경계의 양쪽에 아주
가깝게 놓였다는 이유만으로 개별 프로필을 실패시키지는 않는다. 대신 배치 전체에서 네 구간의
실제 비율과 계획 비율의 최대 편차를 5%p 이내로 제한한다. 기록 각각을 목표 길이에 맞추지는
않는다. 사건의 사실량에 따라 짧은 기록과 긴 기록을 섞고 프로필 평균만 검사한다.
단, 샘플링한 목표가 골격 문장 자체의 평균보다 짧으면 생성 전에 실행 가능한 최솟값으로 올린다.
원래 값은 `sampledTargetMeanChars`, 보정 여부는 `feasibilityAdjusted`, 실제 렌더링 목표는
`targetMeanChars`에 남긴다. 이 보정은 모델이 줄일 수 없는 고정 사실 때문에 정상 프로필을
실패 처리하는 것을 막는다.

### v4.2 뼈대 보존형 창작

v4.1은 모든 문장을 원천 `facts`에서 직접 확인하도록 제한해 짧고 균일한 기록을 만들었다.
v4.2는 합성 데이터의 목적에 맞게 경력 뼈대와 세부 묘사를 분리한다.

- 보존 대상: 사건 종류와 순서, 시점과 기간, 경력·학력·자격, 역할, 입력의 핵심 행동과 결과
- 창작 대상: 상황, 작업 과정, 판단 이유, 협업 방식, 일반적인 도구와 방법, 문제 확인·수정 과정,
  짧은 회고
- 창작 금지: 입력과 충돌하는 사건, 새 기관·자격·고객, 새 날짜·기간·인원·비율·금액·성과 수치

따라서 `적당히 김`과 `매우 김` 프로필은 원천 문장을 그대로 늘리는 방식이 아니라, 고정된 사건
안에서 현실적인 수행 과정을 합성해 만든다. 같은 사실을 반복하거나 이력서식 포부를 덧붙이는
것은 여전히 금지한다. 로컬 모델은 호출 비용 제한이 없으므로 길이·구조 게이트를 통과하지 못한
경우 최대 세 번까지 전체 프로필을 다시 생성한다. 사실 골격은 재생성하지 않는다.

`bodyLengthPlan`, `renderingPolicy`, 실제 평균은 최종 객체의 `datasetMeta`에 함께 저장한다.
이 값은 추천 모델의 특징이 아니라 생성 분포와 합성 범위를 감사하기 위한 메타데이터다.
동일한 YP2021 원자료 해시로 만든 집계 JSON이 있으면 대규모 배치 준비 시 이를 재사용할 수 있다.
원자료를 다시 읽는 경로와 집계를 재사용하는 경로는 같은 calibration 객체를 입력으로 받는다.

### v4.3 경험 근거 재서술

300개 체크포인트의 일부를 직접 읽은 결과, v4.2가 AI Hub 면접 답변 전체를 고정
`skeletonLead`로 붙이면서 실제 경험이 아닌 직무 상식·가정·포부까지 사용자 본문에 들어가는
문제를 확인했다. v4.3은 이 경로를 다음처럼 바꾼다.

- 실제 경험을 묻는 질문이면서 답변에 과거 행동 표현이 있는 atom만 사용한다.
- 가정형·지원 동기·지원자 호칭·미래 계획 표현이 있는 atom은 입력 단계에서 제외한다.
- YP2021에서 만든 학력·재직 골격은 기존처럼 고정 문장으로 보존한다.
- AI Hub atom은 원문을 본문 앞에 붙이지 않는다. Qwen이 핵심 사건·역할·행동·결과만 골라
  과거형 개인 기록으로 다시 쓰고, 원문 ID는 provenance에만 남긴다.
- 원문에 실패·성공·퇴사·이직·리더 역할·담당 역할이 있으면 의미군 보존 게이트로 누락을 막는다.
- 최종 출력에 면접 문투가 있거나 긴 원문 문장이 그대로 복사되면 자동 실패 처리한다.

세부 상황과 수행 과정은 골격과 모순되지 않는 범위에서 창작할 수 있다. 이렇게 해야 공개
면접 답변의 문체를 복제하는 대신, 사실 골격만 활용한 합성 프로필이 된다.

v4.3.1은 재서술 과정에서 성공·실패·역할 의미가 길이 조정으로 잘리는 문제를 보완한다. 필수
의미군을 첫 두 문장에 쓰게 하고 최초 기록 생성 직후 검사해, 프로필 전체를 만든 뒤 반복
교정하는 비용을 줄인다.

### v4.3.2 원천 정규화 캐시

실제 300개 체크포인트를 시작하며 정규식 선별만으로는 가족사·가정형 일반론·불완전한 답변을
모두 제거할 수 없음을 확인했다. 최종 대량 생성은 프로필 렌더링 전에 AI Hub atom을 한 번씩만
Qwen으로 정규화한다.

- 실제 직무·프로젝트·학업·자격·연구·활동 사건인지 `accepted/rejected`로 판정한다.
- 승인된 atom은 역할·행동·핵심 결과를 포함한 20~140자의 과거형 사실 골격 한 문장과 7개
  Expresso 카테고리 중 하나로 변환한다.
- 가족·건강·재산 등 비직무 개인사, 일반론, 포부, 가정형 답변은 제외한다.
- 성공·실패·탈락·퇴사·이직·리더·담당 의미군과 원문의 숫자를 검사하고 새 숫자를 막는다.
- 결과는 atom ID별 파일로 캐시해 장비 중단 시 이어서 실행하고, 동일 atom을 여러 프로필에서
  쓸 때 정규화 호출을 반복하지 않는다.
- 프로필 생성기는 정규화 골격을 고정 `skeletonLead`로 붙이고 Qwen에는 창작 세부만 맡긴다.
- 정규화 출력에 원문에 없는 성공·실패 등 결과 의미군이나 한자가 생기면 실패 처리하며,
  일상 생활 요령처럼 추천 근거가 되지 않는 개인 사건은 제외한다.

따라서 AI Hub 원문은 경력 사건을 찾는 근거로만 사용되고, 사용자 본문과 모델 학습 입력에는
정규화된 사실 골격과 그 안에서 창작한 세부만 들어간다.

### v4.4 단일 인물 앵커

AI Hub 71592는 질문 하나와 답변 하나가 파일 하나이며 동일 응답자를 여러 파일에서 연결할
식별자가 없다. 여러 atom을 임의로 한 프로필에 넣으면 같은 직무 대분류 안에서도 서로 다른
사람의 직장·직급·경력이 섞인다. v4.4는 프로필마다 승인된 AI Hub 사실 골격을 정확히 하나만
정체성 앵커로 사용한다.

- 한 프로필의 `narrativeEvidence` 사건은 한 건만 허용한다.
- 앵커에 적힌 경력 기간과 `EXPERIENCED` 여부로 프로필의 최소 경력 연수를 보정한다.
- 나머지 기록은 YP2021 학력·재직·훈련·자격 분포와 같은 직무권의 합성 골격으로 채운다.
- 완전 합성한 사건 골격은 `syntheticFields`에 `event_skeleton`을 기록해 공개 원천의 사실처럼
  보이지 않게 한다.
- 렌더러에는 `persona.anchorFact`를 매 기록마다 전달하고, 다른 직업·경력 연차를 새로 만들지
  않게 한다.
- 앵커는 모순 검사에만 쓰며, 현재 사건 골격에 없는 앵커의 갈등·인물·행동을 다른 기록의
  세부에 반복하지 않는다.
- 고정 골격을 세부 문장의 첫 문장에서 다시 요약하는 경우 문자 삼중항 포함 유사도로 제거한다.

이 구조에서 공개 데이터의 역할은 한 사람의 핵심 사건과 인구 수준 경력 분포를 제공하는 것이고,
로컬 Qwen의 역할은 그 둘과 모순되지 않는 개인 기록의 세부를 만드는 것이다.

## 노션형 기록 표현

사용자에게 보이는 기록은 `title`, `properties`, `bodyMd`만으로 구성한다. `claims`, 근거 ID,
기록 간 관계, 스킬 숙련도는 넣지 않는다. 출처 연결은 사용자 기록 밖의 `provenance`에만 둔다.

프로퍼티 개수는 배치 전체에서 다음 목표를 갖는다.

| 프로퍼티 수 | 목표 비율 |
| ---: | ---: |
| 0개 | 65% |
| 1개 | 30% |
| 2개 | 5% |
| 3개 이상 | 0% |

카테고리별로 다음 기본 프로퍼티만 후보로 허용하며, 기록당 두 개를 넘지 않는다.

| 카테고리 | 기본 프로퍼티 후보 |
| --- | --- |
| 경험 | `role`, `organization` |
| 프로젝트 | `role`, `technologies` |
| 학력·이력 | `institution`, `program`, `startMonth`, `endMonth` |
| 자격증·수상 | `issuer`, `issuedMonth` |
| 학술·집필 | `publication`, `publishedMonth` |
| 활동·리더십 | `role`, `organization` |
| 스킬·도구 | `group` |

`task`, `action`, `result`, `outcome`, `achievements`, `competencies`, `metrics`는 구조화
프로퍼티로 반복하지 않고 본문에만 쓴다. 기술 태그도 실제 서술 재료에 명시된 경우에만 넣는다.
프로퍼티가 비어 있어도 유효한 기록이다.

본문은 완성된 이력서 문장보다 개인 노트에 가깝게 만든다. 짧은 메모, 한두 문단, 불릿 목록을
섞고, 문장 종결과 상세도가 완전히 균일하지 않아도 된다. 다만 한 기록 안의 사건과 시점은
일관되어야 하며, 상투적인 교훈이나 포부로 길이를 채우지 않는다. 제목과 프로퍼티에서 빠진
핵심 역할·행동·결과·사용 도구는 본문에서 읽을 수 있어야 한다.

## 출처와 분할

사용자 기록 밖의 provenance는 기록마다 다음 세 층을 구분한다.

- `surveyCalibration`: YP2021 프로파일 버전과 사용한 분포 키
- `narrativeEvidence`: AI Hub atom ID 또는 다른 공개 서술 원천
- `syntheticFields`: LLM이 골격 안에서 새로 표현한 필드 목록

원본 `sampid`는 저장하지 않는다. YP 집계표, AI Hub atom 군집, profile family를 기준으로
train·valid·test를 먼저 나누고 나서 프로필을 생성한다. 같은 조사 궤적, 같은 답변 atom,
근접 문장 변형이 split을 넘지 않게 한다.

## 생성 게이트

다음 조건을 모두 만족한 배치만 적합도 라벨 생성으로 넘긴다.

- 목표 기록 수 분포의 평균 오차 0.5개 이하, 표준편차 오차 0.5개 이하
- 생성된 프로필 평균 길이 집합이 manifest의 배정 목표 집합 대비 평균·표준편차 각각 5자 이내
- 매우 짧음·적당히 짧음·적당히 김·매우 김의 실제 비율이 계획 비율에서 각각 5%p 이내
- 각 프로필의 실제 평균 본문 길이가 배정 목표의 허용 오차 이내
- 목표보다 적게 생성된 프로필의 비율과 원인 보고
- 프로퍼티 0·1·2개 비율이 목표에서 각각 5%p 이내
- 기록당 프로퍼티 3개 이상 0건
- 보호·민감 변수 또는 원본 조사 ID 노출 0건
- 시간 역전, 중복 사건, 서로 모순되는 재직 상태 0건
- 사용자 기록 안의 `claims`, 근거 ID, 기록 관계, 숙련도 0건
- 입력에 없는 새 정밀 수치와 입력 수치 누락 0건
- 시점·기간·대상·도구를 바로 뒤 문장에서 반복하는 메타 문구 0건
- 가정형·포부·지원자 호칭 등 면접 문투 0건
- AI Hub 원문 장문 복사 0건
- AI Hub 근거의 핵심 결과·역할 의미군 누락 0건
- 모든 기록에 외부 provenance 1개 이상
- profile family와 원천 군집의 split 누수 0건

사람은 표본의 자연스러움과 노션형 작성 감각을 직접 검수한다. 자동 검수는 사람의 승인 여부를
대신 판단하지 않고 분포·스키마·누수·금지 필드와 보수적인 근거·반복 마커만 차단한다.

## 실행 순서

1. YP2021 조사차수별 변수 사전과 특수 결측 코드 매핑을 확정한다.
2. 보호 필드 제거 후 집계 전이표와 최소 셀 크기 검사를 만든다.
3. 잠재 경력 골격 샘플러와 결정적 기록 수·평균 본문 길이 할당기를 구현한다.
4. 긴 프로필에 필요한 사건별 사실량을 골격 단계에서 확보하고 부족한 골격은 생성 전에 제외한다.
5. v4.3의 고정 골격·경험 근거 재서술 프롬프트와 입력별 구조화 출력 계약을 적용한다.
6. Qwen v4.3으로 네 길이 구간을 포함한 300개 체크포인트를 생성하고 구간별 길이·근거 재서술·프로퍼티·누수 보고서를 만든다.
7. Luna는 같은 골격의 소규모 문체 기준군 생성에만 사용한다.
8. 사람 표본 검수 뒤 첫 야간 shard를 생성한다.
9. 누적 3,000개 프로필을 목표로 300·1,000·3,000개 체크포인트를 만든다.
10. 1,000개 체크포인트부터 공고–프로필 0~100 적합도 교사 라벨과 cross-encoder 학습을
    병행하고, 이후 체크포인트마다 베이스라인 대비 성능 곡선을 비교한다.

## 대규모 생성 목표

이번 생성 목표는 **합성 프로필 3,000개**다. 평균 기록 수 9개를 적용하면 약 27,000개
경력 기록이다. 프로필당 공고 50개를 양성·음성 및 경계 사례로 배치하면 최대 150,000개의
적합도 학습 쌍을 만들 수 있다. 처음부터 전체 완료를 기다리지 않고 다음 체크포인트를 각각
품질 보고서로 고정한다.

| 체크포인트 | 용도 |
| ---: | --- |
| 300개 | 생성 속도, 재시도율, 길이·카테고리 분포와 표본 품질 점검 |
| 1,000개 | 첫 cross-encoder 학습과 TF-IDF·코사인 기준선 비교 |
| 3,000개 | 전체 학습 후보와 profile-family 분할 안정화 |

각 프로필은 결정적 seed와 shard ID를 가지며, 결과 파일이 이미 있으면 건너뛴다. Windows RTX
5080과 M4 Max 36GB는 겹치지 않는 shard를 생성하고, 장비별 처리량과 실패율을 manifest에
남긴다. 야간 런의 종료 조건은 고정 개수뿐 아니라 실행 시간으로도 둘 수 있어 중단 후 그대로
재개할 수 있어야 한다. 학습 분할은 생성 뒤 무작위로 나누지 않고 profile family 단위로
80:10:10을 먼저 배정해 근접 변형이 서로 다른 split에 들어가지 않게 한다.

`synthetic_profile_v4_batch.py prepare`는 10개 프로필을 하나의 family로 묶고 25개 단위
shard 120개를 만든다. 초기 실측 처리량에 따라 Mac 83개, Windows 37개 shard를 배정하되,
체크포인트 처리량을 본 뒤 남은 shard 소유권을 더 빠른 장비로 조정할 수 있다. `run`은 프로필
하나마다 결과·초안·메타데이터를 원자적으로 저장하고 이미 검증된 결과를 건너뛴다. `quality`는
누적 체크포인트의 누락, 길이 허용 오차, 프로퍼티 분포, profile family·atom·원천 family 누수를
검사한다.
