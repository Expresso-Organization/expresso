작성일: 2026-10-28
검증 브랜치: `spike/blocknote-editor` (편집기 코드는 이 브랜치에만 있습니다)
기준 문서: [구현 현황과 완성 계획](career-record-editor-status-2026-10-28.md),

## 결론

**교체를 권합니다.** 본문 편집기를 BlockNote 0.56.0으로 바꾸고 기존 저장 통로(WebSocket ·
`career_document_updates` 원장)를 그대로 쓰는 구성이 검증한 다섯 항목을 모두 통과했습니다.
2026-10-28 점검에서 나온 본문 결함 다섯 건 중 네 건이 해소됐습니다. 세 건은 같은 화면 조작으로 재현되지 않았고, 한 건(`bodyMd` 미반영)은 투영으로 해결했습니다.

교체하면 AI 변경 제안을 BlockNote 블록 기준으로 다시 만들어야 합니다. 이 작업이 남는 작업 중
가장 큽니다. 이번 검증 브랜치에서는 BlockNote 기록의 AI 제안을 409로 막았습니다.

## 검증 환경

- 웹 3160 · API 4160 · Worker, 호스트 `blocknote-spike.localhost`.
- DB `expresso_blocknote_spike`: 체험 DB `expresso_portfolio_trial`을 컬렉션 옵션 · 인덱스까지
  복사하고 `pnpm db:migrate`를 적용했습니다. 체험 · 운영 DB에는 쓰지 않았습니다.
- 계정 dev01(기록 23건).

## 구성

- 원본: Yjs 문서의 XmlFragment `document-store`. 글자 단위로 병합됩니다.
- 스냅샷: `schemaVersion: 2`, `content`에 블록 JSON, 새 필드 `state`에 Yjs 상태 전체. 0006 검증
  규칙이 추가 필드를 막지 않아 마이그레이션이 필요 없었습니다.
- 옮기기: v1 기록을 처음 열 때 v1 문서를 복원해 BlockNote 상태로 바꾸고 v2 스냅샷을 씁니다.
  v1 업데이트는 압축 처리합니다.
- 공용 스키마와 v1 변환은 `packages/editor/src/blocknote.ts` 한 곳에 있고 웹과 서버가 함께 씁니다.
- 웹 세션은 `Y.Doc`을 들고 로컬 업데이트를 300ms씩 `Y.mergeUpdates`로 묶어 기존 `update` 프레임으로 보냅니다.
- BlockNote 묶음은 기록 패널을 열 때만 받는 동적 청크입니다. 가장 큰 청크가 gzip 약 220KB입니다.

## 검증 중 드러난 문제

- **잘못된 옵션이 타입 캐스트에 가려졌습니다.** 0.56은 협업을 `collaboration` 옵션이 아니라
  `CollaborationExtension`으로 켭니다. 옵션 객체를 `as never`로 넘겨 컴파일러가 잡지 못했고,
  첫 화면 확인에서 업데이트가 하나도 나가지 않았습니다. 캐스트를 스키마 한 곳으로 줄여 고쳤습니다.
- **BlockNote 타입이 `exactOptionalPropertyTypes`를 통과하지 못합니다.** 스키마 생성과 블록 타입을
  넓은 타입으로 받습니다. 교체 시 이 경계를 한 파일에 가두는 규칙이 필요합니다.
- **`yjs`가 두 벌이면 BlockNote가 두 번 로드되어 중단됩니다.** `pnpm-workspace.yaml`에 `yjs` 13.6.33
  고정을 넣었습니다.
- **Tiptap이 두 판 공존합니다.** 기존 편집기 3.31.0, BlockNote 3.32.0. 기존 편집기를 지우면 하나가 됩니다.
- **서버 변환에 `react` · `react-dom` · `jsdom`이 백엔드 의존으로 들어옵니다**(`@blocknote/server-util`).
- **목록 카드 미리보기가 Markdown 원문을 보입니다.** 표 줄(`| 지표 | 값 |`)과 줄바꿈 기호(`\`)가 그대로 나옵니다.
- **슬래시 메뉴에 「기본 블록」 묶음 머리가 두 번 나옵니다.** 콜아웃 항목을 기본 항목 사이에 끼워야 합니다.
- **전체 페이지에 저장 상태 표시가 없습니다.** 패널에는 있습니다.
