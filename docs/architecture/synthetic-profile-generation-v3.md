# 합성 프로필 생성 v3

> 이 문서는 AI Hub 단독 30개 파일럿의 계약을 보존한다. 다음 생성 배치는 청년패널 기반 경력
> 골격, 정규분포 기록 수, 본문 중심·희소 프로퍼티를 정의한
> [`synthetic-profile-generation-v4.md`](./synthetic-profile-generation-v4.md)를 따른다.

## 목적

AI Hub 채용면접 답변에서 실제 수행 경험과 실제 학습만 골라 Expresso 경력 기록으로
변환합니다. Luna는 한 번만 호출하고, 코드 검증과 사람의 최종 판정으로 품질을
관리합니다.

## 생성 범위

Luna는 `careerProfile`과 0~6개의 `records`를 생성합니다. 사용자 기록의 내용은
제목, 프로퍼티, 본문으로만 구성합니다. 기록 수를 채우기 위해
가정, 포부, 관심을 경험으로 바꾸지 않습니다. 근거가 부족해도 프로필을 리젝하지
않고 기록이 적거나 없는 상태 그대로 생성합니다.

다음 값은 생성하지 않습니다.

- 기록 간 관계: `recordLinks`는 항상 빈 배열입니다.
- 합성 스킬 평가: `skills`는 항상 빈 배열이고 `skillEvidenceBySkillId`는 빈 객체입니다.
- 근거 없는 날짜, 수치, 기술, 회사, 역할, 성과

## 근거 추적

각 기록은 최상위 `recordEvidence`에서 하나 이상의 AI Hub 근거 조각과 연결합니다.
기록 객체 안에는 `claims`나 근거 ID를 넣지 않습니다. 모델에는 성별이 드러나는
파일명과 원본 ID를 보내지 않고 `e1`, `e2` 같은 임시 ID를 제공합니다. 조립 단계에서
임시 ID를 원본 atom ID로 되돌려 `provenance.recordLineage`에 저장합니다.

근거 추적 정보는 검수에만 사용하고 추천 모델의 입력 특징에는 포함하지 않습니다.

## 출력 계약

프로필, 기록, 기록별 근거 ID를 반환합니다. 가정형 답변, 지원 동기,
장래 계획만으로는 기록을 만들 수 없지만 빈 프로필은 허용합니다. 출력은 JSON Schema로 제한하며, 조립기는
허용되지 않은 근거 ID, 카테고리 프로퍼티, 미래·가정 중심 기록을 거절합니다.

입력에는 Expresso seed에서 읽은 카테고리별 프로퍼티 이름과 타입을 함께 제공해,
근거가 있는 역할·행동·결과를 프로퍼티로 구조화합니다. Expresso 객체에는 일곱
시스템 카테고리를 모두 포함하되 기록이 없는 카테고리를
허용합니다. 기록 본문과 프로퍼티만 추천용 프로필 표현에 사용합니다.

`datasetMeta.recordCoverage`는 기록 수에 따라 `empty`, `sparse`, `adequate`로
계산합니다. 이는 데이터 분할과 성능 분석에만 사용하고 추천 모델 입력에는 포함하지
않습니다.

## 파일럿 통과 기준

동일한 입력 5개를 사용해 버전 사이 결과를 비교합니다.

- 가정·포부를 경험으로 만든 기록 0건
- 모든 기록에 원본 근거 1개 이상
- `recordLinks` 0건
- 합성 스킬 평가 0건
- 사람 검토에서 5개 중 4개 이상 승인

위 기준을 통과하기 전에는 30개 생성으로 확대하지 않습니다.
