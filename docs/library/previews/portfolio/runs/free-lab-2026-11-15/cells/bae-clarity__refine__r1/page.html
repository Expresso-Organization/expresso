프로젝트 · 2020.06 – 2021.03

하루 늦던 홈 피드 후보를 1시간 안으로: Two-tower 도입

하루 한 번 계산하던 홈 피드 후보를 Two-tower 모델로 바꿔 신규 콘텐츠 반영 시간을 최대 24시간에서 1시간으로 줄였습니다.

문제

기존 홈 피드는 아이템 기반 협업 필터링 결과를 하루 한 번 계산해 썼습니다. 새 콘텐츠는 다음 날에야 후보에 들어갔고, 사용자의 당일 시청 이력은 반영되지 않았습니다.

제가 한 일

사용자 타워(최근 시청 50개 + 프로필)와 콘텐츠 타워(메타데이터 + 텍스트 임베딩)를 나눈 Two-tower 모델을 만들었습니다. 배치 내 네거티브에 인기도 보정을 넣었고, 콘텐츠 임베딩은 Faiss 인덱스로 서빙했습니다.

결과

오프라인 Recall@100은 0.284에서 0.371이 되었습니다. A/B 테스트(2주, 트래픽 20%)에서 시청 시간은 +6.3%, 클릭률은 +3.8% 올랐습니다.

프로젝트 · 2020.11 – 2021.05

목표 30ms 안에서 임베딩 검색 돌리기: Faiss 서빙

Two-tower 후보 생성을 실서비스에 붙이기 위해 재현율·지연·메모리를 맞추고, 인덱스를 1시간마다 무중단으로 교체하게 했습니다.

콘텐츠 임베딩 검색 서버를 만들었습니다. IVF-PQ 인덱스 파라미터(nprobe 등)를 바꿔 가며 재현율과 지연 시간을 맞췄습니다. 인덱스는 1시간마다 다시 만들고, 서빙 중단 없이 교체하게 했습니다.

1.2%p

Recall@100 손실은 정확 검색 대비, 메모리는 Flat 대비 IVF-PQ 기준입니다.

MLOps

지표가 떨어지면 배포되지 않는 학습 파이프라인

모델별로 흩어져 있던 학습 작업을 Kubeflow Pipelines로 모으고, 평가 지표 기준으로 배포를 막는 단계를 넣었습니다.

학습 작업이 모델별로 따로 돌고 있었습니다. 이를 Kubeflow Pipelines로 옮겨 하나로 통합했고, 평가 지표 기준에 못 미치면 배포를 막는 단계를 넣었습니다. 데이터 추출 작업의 스케줄링은 스트림온에서 Airflow로 했습니다.

세션 그래프 추천 연구에서 출발

추천시스템 연구실 석사 과정의 세션 그래프 추천 연구가 실무 추천 작업의 바탕이 되었습니다.

한결대학교 대학원 컴퓨터공학과 추천시스템 연구실에서 석사 과정을 밟았습니다. 학위논문은 「세션 그래프 기반 다음 아이템 추천」이고, 평점은 4.3/4.5입니다. 이 논문으로 우수학위논문상을 받았으며, 학과에서 한 해 2편을 뽑습니다. 재학 중 누리랩스 AI연구소에서 6개월 연구 인턴을 했습니다.
