CASE 01 · 2020.06 – 2021.03

하루 늦던 홈 피드 후보를 1시간 안으로: Two-tower 도입

문제를 모델 구조로 풀었고, 그게 실제 시청 시간으로 확인됐다.

문제

홈 피드는 아이템 기반 협업 필터링 결과를 하루 한 번 계산해 썼습니다. 새 콘텐츠는 다음 날에야 후보에 들어갔고, 사용자의 당일 시청 이력은 반영되지 않았습니다.

내가 한 일

사용자 타워(최근 시청 50개 + 프로필)와 콘텐츠 타워(메타데이터 + 텍스트 임베딩)를 나눈 Two-tower 모델을 만들었습니다. 배치 내 네거티브에 인기도 보정을 넣고, 콘텐츠 임베딩은 Faiss 인덱스로 서빙했습니다.

결과

오프라인 Recall@100 0.284 → 0.371. A/B 테스트(2주, 트래픽 20%)에서 홈 피드 1인당 시청 시간 +6.3%, 클릭률 +3.8%.

CASE 02 · 2020.11 – 2021.05

목표 30ms 안에서 임베딩 검색 돌리기: Faiss 서빙

재현율을 1.2%p만 내주고 지연 목표와 메모리를 모두 잡았다.

Two-tower 후보 생성을 실서비스에 붙이려고 콘텐츠 임베딩 검색 서버를 만들었습니다. IVF-PQ 인덱스 파라미터를 바꿔 가며 재현율과 지연 시간의 균형을 맞췄고, 인덱스를 1시간마다 다시 만들어 서빙 중단 없이 교체하게 했습니다.

정확 검색 대비 Recall@100 손실
1.2%p
서버 메모리 (Flat → IVF-PQ)
−40%

IVF-PQ 파라미터 조정과 무중단 인덱스 교체를 직접 운영했습니다.

지표가 떨어지면 배포되지 않는 학습 파이프라인
