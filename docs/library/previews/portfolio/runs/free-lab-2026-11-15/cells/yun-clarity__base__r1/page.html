02 상품 상세 App Router 전환 · 2024.04–2024.11

LCP 3.8초를 1.9초로

서버와 클라이언트의 경계를 비용 기준으로 다시 긋고, 그 결과를 배포 기준으로 고정했습니다.

문제. 오래된 CSR 구조에서 상품 상세 첫 렌더가 느렸습니다.

판단. 데이터 요청을 서버 컴포넌트로 올리고, 상호작용이 필요한 부분만 클라이언트 컴포넌트로 남겼습니다. Pages Router에서 App Router로 옮기는 동안에도 기존 주소와 SEO 메타는 그대로 유지했습니다.

재발 방지. 배포마다 Lighthouse CI로 성능 예산을 검사합니다. 데이터 요청 위치, 캐시 무효화, 점진 전환 방법은 글로 정리해 팀에 공유했습니다.

LCP는 가상 측정 값입니다. 막대는 각 지표 안에서 전환 전 값 대비 비율입니다.

03 사내 디자인 시스템 모아 UI · 2023.06–2024.03

같은 수정을 세 번 하지 않기 위해

화면을 통일한 일이 아니라, 반복 수정이 생기는 구조를 없앤 일입니다.

  1. 진단

    화면마다 버튼과 입력 모양이 달라, 디자이너와 개발자가 같은 수정을 여러 번 했습니다.

  2. 토큰 정리

    색 · 간격 · 글꼴을 디자인 토큰으로 먼저 정리했습니다.

  3. 배포

    Radix UI 기반 컴포넌트 48개를 Storybook 문서와 함께 내놓았고, 시각 회귀 테스트로 변경이 깨지지 않게 했습니다.

  4. 정착

    신규 화면의 공통 컴포넌트 사용 비율이 30%에서 80%가 됐고, 신규 화면 개발 기간은 평균 5일에서 3일로 줄었습니다(가상 집계).

접근성은 컴포넌트의 기본 속성으로 내려놓았습니다. 화면마다 따로 고치지 않아도 되는 쪽이 기본값입니다.

04 접근성

결제 화면의 접근성은 나중 일이 아니라 기본값

커머스에서 가장 민감한 결제 페이지를 WCAG AA 기준에 맞춰 고쳤습니다.

속도만 좋은 화면이 되지 않도록, 접근성도 한 화면의 수정으로 끝내지 않고 공통 컴포넌트의 기본값으로 다룹니다. 결제처럼 실패 비용이 큰 흐름일수록 이 기준이 먼저 지켜져야 한다고 봅니다.

06 사이드 프로젝트와 해커톤

필요하면 일단 만들어 봅니다

불편을 발견하면 작게라도 돌아가는 형태로 먼저 만듭니다.

개인 가계부 PWA (2025.06–2025.09). 지하철에서 결제 내역을 바로 적고 싶어 만들었습니다. 기록은 IndexedDB에 먼저 저장하고, 연결되면 서버와 동기화합니다. Service Worker 캐시 덕에 두 번째 실행부터 즉시 열리고, 홈 화면에 설치해 앱처럼 씁니다.
