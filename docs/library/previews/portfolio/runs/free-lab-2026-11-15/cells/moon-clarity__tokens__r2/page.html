3일 걸리던 실험 리포트를 반나절로: A/B 테스트 분석 표준화

2025.08 – 2026.02

문제

실험마다 분석가가 노트북을 새로 짜다 보니 결과 하나를 내는 데 3일 정도 걸렸습니다. 표본 크기 계산을 건너뛰는 경우도 있었습니다.

해결

실험 설계서 양식, 표본 크기 계산, 결과 리포트를 하나의 Python 패키지와 Streamlit 화면으로 묶었습니다. 사전 기간 매출을 공변량으로 쓰는 분산 축소(CUPED)도 기본 옵션으로 넣었습니다.

결과

실험 결과 리포트 작성이 3일에서 반나절로 줄었습니다. 분기당 실험 수는 6건에서 15건으로 늘었고, 필요 표본 크기는 평균 약 30% 줄었습니다.

2023.11 – 2024.04

문제

검색 후 상품 클릭 없이 나가는 세션이 많다는 문제 제기가 있었습니다.

한 일

검색어 유형별로 이탈을 나눠 보았습니다. 결과 0건 검색어 상위 200개를 정리해 동의어 사전 보강을 제안했습니다.

결과

결과 0건 검색 비율이 7.4%에서 4.1%로 내려갔습니다.

  2. 분해검색어 유형별로 이탈을 나눠 원인 구간을 좁혔다.

분석이 기대는 데이터 기반을 직접 만들고 운영합니다

주문 데이터 마트를 dbt로 옮기면서 모델 구조, dbt test, dbt docs를 운영했습니다. Airflow로 데이터 마트 일일 갱신과 발주량 예측 배치를 DAG로 작성했습니다. BigQuery는 파티션과 클러스터링 설정으로 대시보드 집계 비용을 줄였습니다. 분석에는 SQL(윈도 함수, CTE)과 Python(pandas, scikit-learn, statsmodels)을 쓰고, 고른마켓 판매자 대시보드는 Tableau로 만들어 운영했습니다.
