오래된 CSR 구조에서 상품 상세 첫 렌더가 느렸습니다. 데이터 요청을 서버 컴포넌트로 올리고 상호작용이 필요한 부분만 클라이언트로 남겼습니다. 기존 주소와 SEO 메타를 유지하며 점진 전환했고, 배포마다 Lighthouse CI로 성능 예산을 검사했습니다.

판단

리스크 관리

02 · 프로젝트

같은 수정을 세 번 하지 않기 위해: 모아 UI

화면마다 반복되던 수정을 디자인 토큰과 공통 컴포넌트로 모아 팀의 기본값으로 만들었습니다.

  1. 01

    진단

    화면마다 다른 컴포넌트로 같은 수정이 반복됐습니다.

  2. 02

    토큰 정리

    색·간격·글꼴을 디자인 토큰으로 먼저 정리했습니다.

  3. 03

    배포

    Radix UI 기반 컴포넌트 48개를 Storybook 문서와 함께 배포했습니다.

화면마다 버튼·입력·모달이 달라 디자이너와 개발자가 같은 수정을 반복했습니다. 색·간격·글꼴을 토큰으로 먼저 정리한 뒤, Radix UI 기반 컴포넌트 48개를 Storybook 문서와 함께 배포했습니다.

소개

결제 화면의 접근성은 나중 일이 아니라 기본값

결제 페이지를 WCAG AA 기준으로 점검해 고쳤습니다.

접근성을 화면별 수정이 아니라 공통 컴포넌트의 기본값으로 내려놓는 방식으로 다뤘습니다.
