하루 늦던 홈 피드 후보를 1시간 안으로: Two-tower 도입

2020.06 – 2021.03

하루 한 번 계산하던 홈 피드 후보를 Two-tower 모델로 바꿔 신규 콘텐츠 반영 시간을 최대 24시간에서 1시간으로 줄였습니다.

문제
기존 홈 피드는 아이템 기반 협업 필터링 결과를 하루 한 번 계산해 썼습니다. 새 콘텐츠는 다음 날에야 후보에 들어갔고, 사용자의 당일 시청 이력은 반영되지 않았습니다.
내가 한 일
사용자 타워(최근 시청 50개 + 프로필)와 콘텐츠 타워(메타데이터 + 텍스트 임베딩)를 나눈 Two-tower 모델을 만들었습니다. 배치 내 네거티브에 인기도 보정을 넣었고, 콘텐츠 임베딩은 Faiss 인덱스로 서빙했습니다.
결과
오프라인 Recall@100은 0.284에서 0.371이 되었습니다. A/B 테스트(2주, 트래픽 20%)에서 시청 시간은 +6.3%, 클릭률은 +3.8% 올랐습니다. 신규 콘텐츠가 후보에 들어가는 시간은 최대 24시간에서 1시간이 되었습니다.

목표 30ms 안에서 임베딩 검색 돌리기: Faiss 서빙

2020.11 – 2021.05

Two-tower 후보 생성을 실서비스에 붙이기 위해 재현율, 지연, 메모리를 맞추고, 인덱스를 1시간마다 무중단으로 교체하게 했습니다.

문제
Two-tower 후보 생성을 실서비스에 붙이려면 콘텐츠 임베딩 검색이 30ms 안에 끝나야 했습니다.
내가 한 일
콘텐츠 임베딩 검색 서버를 만들었습니다. IVF-PQ 인덱스 파라미터(nprobe 등)를 바꿔 가며 재현율과 지연 시간을 맞췄습니다. 인덱스는 1시간마다 다시 만들고, 서빙 중단 없이 교체하게 했습니다.
결과
p99 지연 시간은 18ms(목표 30ms)입니다. 정확 검색 대비 Recall@100 손실은 1.2%p였고, 서버 메모리 사용량은 Flat 대비 IVF-PQ로 40% 줄었습니다.
