    비교 결과

    초기 v0 구성의 비교 기록입니다. 이 페이지는 변형 확장 전의 결과를 보존합니다. 현재 확장된 구성안 보기 →

    • 자유 생성은 사례 설명 옆에 큰 이미지를 배치하고, 근거 내용을 단계와 목록으로 구성했습니다. 프로젝트를 설명하는 방식이 더 다양합니다.
    • 자유 생성의 두 번째 사례에는 제목과 이미지가 서로 다른 그리드 행에 놓이는 배치 문제가 있습니다. 기본 자동 검사에서는 발견되지 않았습니다.
    • 두 결과 모두 이름·제목·기간·역할·연락처·근거 제목 22개를 보존했습니다. 390·768·1440px에서 가로 넘침, 깨진 이미지, 끊어진 목차 앵커가 없었습니다.
    • 구조화 JSON이 선택한 섹션 순서는 기존 예제와 같습니다. 현재 카탈로그의 선택 범위가 좁아, 이 결과로 AI의 디자인 능력이나 일반적인 비용 우위를 판단할 수는 없습니다.
    비교 범위

    구조화 방식은 기존 섹션의 순서를 선택합니다. 자유 방식은 HTML/CSS와 문구를 생성합니다. 컴포넌트와 테마의 사전 제작 비용은 이번 호출 비용에 포함되지 않았습니다. 같은 모델과 가상 입력으로 각각 한 번 실행한 결과입니다.

    04

    시각 검토

    관점구조화 생성자유 생성
    프로젝트 이미지목록의 썸네일 카드로 빠르게 훑을 수 있습니다. 사례 상세에서는 이미지를 함께 보여주지 않습니다.사례마다 큰 화면 이미지를 배치해 결과물과 설명을 함께 살펴보기 좋습니다.
    사례 서술문제·담당 작업·결과를 동일한 형식으로 반복해 일관성이 높습니다. 시각적 변화는 적습니다.역할·기간·태그와 사례 본문을 묶고 기여 문단을 강조합니다. 목록과 상세에서 요약 문장이 반복됩니다.
    근거 자료한 목록에서 내용을 펼칩니다. 사례의 연결 문구가 ‘설계 근거 1’처럼 일반적입니다.프로젝트별로 자료를 묶고 실제 자료 제목으로 연결합니다. 긴 문장을 단계와 검토 목록으로 변환했습니다.
    데스크톱 배치섹션 정렬과 간격이 일관되고 큰 의도치 않은 공백을 찾지 못했습니다.루멘 노트의 좌우 교차 배치에서 이미지가 다음 행으로 밀립니다. grid-column만 뒤집고 grid-row를 지정하지 않은 구성입니다.
    모바일프로젝트 카드를 한 열로 정리하고 모든 본문을 유지합니다.정보와 이미지를 한 열로 표시해 읽을 수 있습니다. 프로젝트 설명 반복으로 전체 페이지가 더 깁니다.
    생성 범위모델은 기존 부품의 순서와 데이터 참조를 출력합니다. 새 디자인과 내용은 만들지 않았습니다.모델이 HTML/CSS와 일부 설명 문구를 작성했습니다. 시각 검토 후 수정할 영역이 남았습니다.

    시각 평가는 이 한 쌍의 전체 페이지와 모바일 캡처를 검토한 관찰입니다. 구조화 부품은 미리 사람이 설계하고 검증했습니다. 자유 생성은 첫 출력이며 수동 수정이나 재생성 없이 비교했습니다. 특정 방식의 평균 품질·성공률을 증명하는 결과로 해석할 수는 없습니다.

    05

    실행 조건

    한국어 프로덕트 디자이너의 가상 포트폴리오를 만듭니다. 모든 인물·조직·경력·프로젝트·성과는 시연용입니다. 목표: 처음 방문한 사람이 역할, 프로젝트 문제와 기여, 경력, 근거 자료, 연락처를 읽고 탐색할 수 있는 완성 페이지. 시각 방향: 차분한 편집형. 배경 #f7f6f1, 본문 #1c302e, 강조 #24654d. 넓은 여백과 명확한 글자 위계. 서체: Apple SD Gothic Neo, Malgun Gothic, system-ui, sans-serif. 별도 폰트 다운로드를 사용하지 않습니다. 가상 데이터 표시를 눈에 보이게 유지합니다. 출처에 없는 성과 수치나 회사·프로젝트를 추가하지 않습니다. 제목·이름·조직·기간·역할·연락처·근거 자료를 보존합니다. 설명 문장은 의미를 유지하며 정리할 수 있습니다. 휴대폰 390px, 태블릿 768px, 데스크톱 1440px에서 읽히고, 키보드 포커스와 모션 감소를 지원합니다. 목차, 프로젝트 상세, 근거 자료를 실제 앵커나 네이티브 details로 연결합니다. JavaScript가 없는 문서에서도 읽을 수 있어야 합니다.

    • 자유 생성: 제품의 AiPageGenerator, PageDraftSchema, sanitizePage, pageQa를 사용했습니다. 공통 Opus 모델과 useKit=false 조건으로 단독 호출했습니다. 제품 PageService의 Sonnet·키트 선택 설정과는 별도의 통제 조건입니다.
    • 구조화 생성: 같은 AI 클라이언트와 모델로 spec을 만들고 generationSchema와 콘텐츠 참조 검사를 거쳐 json-render에서 렌더링했습니다.
    • 두 결과의 제공 이미지는 같은 파일을 임베드했습니다. 공통 시스템 서체 조건을 사용하고 생성된 배치·문구에는 수동 수정을 적용하지 않았습니다.
    • 제품 데이터베이스와 실제 CV를 사용하지 않았습니다. 테스트 입력은 앞서 만든 가상 포트폴리오입니다.
